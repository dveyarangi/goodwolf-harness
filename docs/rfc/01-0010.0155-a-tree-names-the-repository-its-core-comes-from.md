# A tree names the repository its core comes from — implementation plan

**Authored:** 2026-09-23
**Last amended:** 2026-09-23

Implements [01-0010.0155](../tickets/01-0010.0155-a-tree-names-the-repository-its-core-comes-from.md):
the harness skill carries a `Repository:` line, the script derives its default `--from` from it,
an install stamps a recipient's line with the actual source, and the comparison sets the line
aside.

## Governing boundaries

- **The announce line is the revision, and it is the *ref*'s record, not the source's.**
  [harness.md](../../.agents/mechanisms/harness/harness.md) — a recipient's entry file reads
  `Entry contract: <repository>@<ref>, <date>`, where `<repository>` is the repository's *name*.
  The line this RFC adds is the *URL*, and the two are not a duplicate home: one records which
  commit a tree holds, the other where to go for the next one.
- **The installation edge.** [glossary.md](../../.agents/glossary.md) counts *a script's path and
  command* and *a behaviour a recipient's files rely on* as on the edge. After this lands, a
  recipient's `harness.py` relies on a line in a file the recipient holds, which is a new edge
  element — see *Limitations*.
- **Every refusal writes nothing**, and a refusal names its step
  ([harness/SKILL.md](../../.agents/skills/harness/SKILL.md)). Both refusals below are raised
  before any write.
- **The origin is never installed into.** `_work_tree_root` compares the target's `origin` against
  the source; with the default now read from core's own skill line, the comparison still names
  core's own repository and the refusal is unchanged.

## Impact

Run at `/plan` on the change described here: **proceed.**

**Must change.** [harness.py:55](../../.agents/scripts/gw/harness.py:55)'s `HOME` constant and
its use at [line 161](../../.agents/scripts/gw/harness.py:161); `Shipment.at`/`shipped`, which
today transform per file with only the `Ref` in hand and need the source's repository too;
`_differs`, which sets the local block aside and must set this line aside as well;
`.agents/skills/harness/SKILL.md`, which gains the line; and `test_harness.py`'s `seed_source`,
whose synthetic core has **no harness skill at all** and will need one.

**Must verify.** The whole behavioural suite, because the fixture's core gains a member; a live
install into a scratch tree with no `--from`; the recipient's own `--check` through
`_script_gate`, which runs the target's script as a subprocess and so must read the target's line.

**May simplify.** `_announced_ref` already refuses when the announce line's repository name
disagrees with `source.name`. With no `--from`, `source` now comes from the skill line, so that
existing comparison becomes a coherence check between a tree's two lines for free — no new code.

## Hidden edges

1. **The harness skill becomes a required manifest member.** Refusing a ref whose harness skill
   has no `Repository:` line makes that file load-bearing where today only `AGENTS.md` is
   (`Shipment.at` refuses only on a missing entry file). Every `TwoTrees` test builds a core
   without a harness skill and passes; all of them go red the moment the refusal lands, which is
   why the fixture change is inside the same stage.
2. **A local-path install carries a machine-local default.** *Resolved to its absolute form* keeps
   a recipient from holding a path relative to where somebody once stood, but an absolute path is
   still valid only on that machine. `--from` stays the escape; stated in *Limitations*.
3. **This is itself an edge change, landing before the thing that would record it.**
   [01-0010.0185](../tickets/01-0010.0185-an-edge-change-writes-its-line.md) builds the rule that
   writes an edge change's line as it is made. It does not exist yet, so this one is recorded
   nowhere but here.
4. **Reading the default eagerly would break the fixture.** `_parsed` sets `repository = HOME`
   before it knows whether `--from` was given. The read must be lazy — see *Shapes*.
5. **A local `--from` can trip the leak rule.** `PATH_LITERAL` in
   [docs_corpus.py:37](../../.agents/scripts/gw/docs_corpus.py:37) is `docs/\w[\w./-]*`, and
   `_refuse_leaks` runs over the *shipped* text. A source reached by a POSIX path containing a
   `docs/` segment — `/srv/docs/goodwolf-harness` — would be stamped into the skill and then read
   as a citation of a document only the origin has, refusing the install with a message about
   documents that names a path the person gave as a repository. Windows backslashes do not match,
   but git accepts forward slashes there too. Found at the second `/plan` pass; the fix is in
   *Shapes*.
6. **A source may itself be a recipient.** `--from <recipient path>` is a git tree with a copy of
   core, so it works and will be used — frost_map can serve a tree beside it. Its skill line names
   *its* source, and the stamp overwrites unconditionally, so a recipient-of-a-recipient names its
   immediate source and never the grandparent. No special case; stated so the behaviour is
   intended rather than incidental.

## Leave alone

- The manifest, the shear, the stamp of the entry file, the leak rule, the gate's three checks,
  and what a refusal deletes (nothing of the project's).
- **The root README's clone line.** A front page at the repository naming itself, never shipped.
  *Only authored home* means the only one the script derives from and the only one that ships.
- `repository_name()` and the announce line's format. Unchanged.
- `.0150`'s inventory and flow, and `.0195`'s eventual change to what the line *names* — that
  slice changes the value, not this mechanism.

## Shapes

### The line, and where it sits

One line in `.agents/skills/harness/SKILL.md`, the first line of the body after the front matter,
where the entry file keeps its announce line:

```
Repository: https://github.com/dveyarangi/goodwolf-harness.git
```

Matched anchored and whole-line, and required to occur exactly once. It is the URL's only authored
home in core: nothing else in the tree states it, and `HOME` is deleted rather than defaulted from.

### The read is lazy

`_parsed` stops defaulting. It returns the repository as `None` when `--from` was absent, and the
caller resolves it from the skill beside the script — `harness.py` sits at
`.agents/scripts/gw/`, the skill at `.agents/skills/harness/`, so the path is two levels up and
across, resolved from the module's own location and never from the working directory.

Laziness is load-bearing, not an optimisation: a run that was given `--from` must never need a
local skill, which is what lets the test fixture and any clone-less invocation keep working.

**Refusal, at that read:** the skill missing, or holding no line, or holding more than one, or
holding one with nothing after the colon, names the file it looked for and `--from` as the way
past. This is the *local* refusal — the script cannot tell where to go. It is raised **before the
clone**: the cheapest refusal comes first, and there is nothing to clone from yet.

### The shipped line is stamped

`shipped()` gains the source's repository alongside the `Ref` it already takes, and stamps the
harness skill's line as it already stamps the entry file's announce line — same position in the
pipeline, after the shear, so a wrapper can never have hidden the line.

What is stamped is the **actual** `--from`: a URL verbatim, a local path resolved to its absolute
form.

**A stamped source is not a citation, and `docs_corpus` settles it.** The repository line is a
machine fact, and a source path containing a `docs/` segment would otherwise be read as a
citation (hidden edge 5). The second pass put the blanking in `shipped()`; implementation moved
it into `docs_mentioned`, beside the fences, the straw-dog openings and the instance-owned block
it already blanks — because `mechanisms.py` runs its own citation scan **as a gate inside every
recipient**, and a fix living only in the ship pipeline would leave a tree installed from such a
path failing its own shape check forever. One home, three readers.

**Refusal, at the ship:** a ref whose harness skill has no such line is *not the harness*, in the
same words and at the same moment as a ref whose entry file has no announce line.

### The line is read, never compared

`_differs` already normalises line endings and sets the recipient's local block aside before
comparing. For the harness skill it sets this line aside too, on **both** sides — the recipient's
copy and the shipped text — so a `--check` run from a clone at another `--from`, or an `--update`
that changes the source, reads no edit in core. The update re-stamps it, exactly as it re-stamps
the announce line.

The line is to the source what the announce line is to the ref: the recipient's own fact, carried
in a core file, and therefore never evidence of an edit.

## Flows

**Install, no `--from`.** Parse → repository is `None` → read the line from the skill beside the
script → clone → resolve the ref → ship, stamping the entry file's announce line and the skill's
repository line with the actual source → refuse unless the target is empty → write → link →
inject → gate.

**A recipient's `--check`, no `--from`.** The target's own script reads the target's own skill
line → clones that repository → reads the announce line, whose repository *name* must match the
source's → compares every manifest file with the local block and the repository line set aside →
reports.

**`--check` from a clone at another `--from`.** Same, except the source is the given one. The
recipient's skill line names a different repository and is set aside, so the file is not reported
as an edit; the announce-line comparison still governs whether the *ref* agrees.

## Stages

1. **The line is authored and the default is read from it.** Add the line to the harness skill;
   delete `HOME`; make `_parsed` return `None` and the caller resolve lazily; add the local
   refusal. Green, on two separate grounds checked at the second `/plan` pass: every `TwoTrees`
   case passes `--from` and so never reaches the read, and `TheCommandLine` — which *does* call
   `main` with no `--from` — asserts only usage errors, where parsing fails before a repository is
   wanted. Its own test is a direct one: the resolved default equals the line authored in the
   skill, so the stage is not carried by the absence of a failure.
2. **The shipped line is stamped, and a ref without it is refused.** Add the stamp and the ship
   refusal, and in the same stage give `seed_source` a harness skill with a line. Red inside the
   stage between the refusal and the fixture, for the reason in hidden edge 1 — the fixture's core
   has no harness skill, so every `TwoTrees` case fails until it does.
3. **The comparison sets the line aside.** Extend `_differs` for that one path, both sides.
   Green throughout; stage 2's stamping is what makes this stage's test fail first.
4. **The live run.** Install into a scratch tree with no `--from`, and run the recipient's own
   `--check` with none.

## Tests

Behavioural, in `test_harness.py` against the two-tree fixture, each asserting the behaviour and
the failure's reason rather than that a path merely succeeded or raised:

- A URL `--from` is stamped into the recipient's skill verbatim.
- A local-path `--from` is stamped resolved to its absolute form — asserted against a source
  reached by a relative path, so a stamp that merely copied the operand fails.
- A ref whose harness skill has no `Repository:` line is refused at the ship, with the *not the
  harness* reason, and nothing is written.
- A recipient whose skill line names one source takes `--check` and `--update` from another
  `--from` without the skill being reported as an edit — and the same run still reports an edit
  when a *different* part of that file is changed, so the test cannot pass by the comparison being
  blind to the file.
- A recipient's own copy of the script runs `--check` with no `--from` and reports `arrived: true`.
- The local refusal: with no `--from` and no readable line, the message names the file and `--from`
  and nothing is written.
- A tree whose announce line names a repository the skill line does not is refused — the free
  coherence check, asserted so it cannot regress silently.
- The resolved default equals the line authored in the harness skill, asserted directly rather
  than inferred from a run that happened not to fail.
- A source reached by a path containing a `docs/` segment installs without a leak refusal **and
  with the recipient's own shape gate passing** — the second half is what caught the fix being in
  the wrong place. Its converse lives with the citation rule it belongs to, in
  `test_mechanisms.CoreStandsAlone`: a line that only looks stamped, with a real document named
  after the URL, is still a leak — so neither test can pass by the rule being switched off.

## Limitations and follow-ups

- **A recipient installed from a local clone holds an absolute path** valid only on the machine it
  was installed from. `--from` remains the escape. The ticket decided the resolved form; this RFC
  records the cost.
- **This edge change is recorded only here** until
  [01-0010.0185](../tickets/01-0010.0185-an-edge-change-writes-its-line.md) lands. When it does,
  this change owes the edge record a line, written retrospectively at that ticket's implement pass
  rather than invented from the commit log.
- **`.0195` changes what the line names**, to the core repository published by
  [01-0010.0190](../tickets/01-0010.0190-core-is-published-as-a-release.md). That is a one-line
  edit by this design, which is the point of it.
- **No TODO is owed in code.** Nothing here is a temporary shape dissolved by later work; the line
  is the destination, and `.0195` only changes its value.

## Resolved at `/plan`

- **Lazy versus eager read.** Eager keeps `_parsed` self-contained and was the first shape
  considered; it makes every invocation depend on a local skill, including the test fixture and
  any run given an explicit `--from`. Lazy, on the evidence that `--from` is always supplied in
  the suite and often by a person running from a clone.
- **One required member or two.** The ticket settled that a ref without the line is *not the
  harness*. This RFC does not soften it, and names the fixture cost rather than hiding it behind a
  tolerant read.
- **Where the line sits.** ~~First body line of the skill, mirroring the entry file's announce
  line.~~ **Corrected at `/implement`:** the first body line is not free. `mechanisms.py`'s
  `_claim` reads a skill's first non-blank body line as its `Mechanism:` claim, so the repository
  line sits below the opening paragraph, where it also reads better — it answers the sentence
  before it. Core's own harness skill makes no claim there, so nothing was displaced; the test
  fixture's harness skill needs both, and carries the claim first.

### Second pass, 2026-09-23

- **One helper, three call sites.** The first pass set the line aside in the comparison only.
  Probing the ship pipeline found the leak rule reading the stamped line as a citation when the
  source is a local path with a `docs/` segment. Rather than special-casing the leak rule, the
  same *set aside* helper serves the comparison's two sides and the citation scan.
- **Stage 1's green claim was wrong as written.** It said every existing test passes `--from`.
  `TheCommandLine` does not; it is safe for a different reason — its cases are usage errors that
  fail in parsing. Corrected, and the stage gained a direct test so it does not rest on nothing
  having broken.
- **Refusal ordering made explicit.** The local refusal precedes the clone. Nothing in the first
  pass said so, and the opposite order would pay for a clone before discovering the script cannot
  tell where to go.
- **Probed and left alone:** a source that is itself a recipient (the stamp overwrites, so the
  grandparent never leaks); `--at` with `--check` (already refused in parsing); the update's
  re-stamp (`_write` writes the shipped text, so the line is re-stamped exactly as the announce
  line is).

### At `/implement`, 2026-09-23

Three things the plan had wrong or missing, each found by a test rather than by reading:

- **The blanking belongs to `docs_corpus`, not to the ship.** See *Shapes*. Caught by the
  `docs/`-segment test failing on the **shape** gate rather than on a leak refusal: the ship was
  already clean, and `mechanisms.py` inside the recipient was not.
- **The first body line is spoken for.** See *Resolved at `/plan`*.
- **The line leaves with its own newline.** The pattern now ends `(?:\r?\n|\Z)` rather than `$`,
  so setting it aside yields the text either tree would hold without the line, and a line with
  anything after the URL is still not the line. Both are asserted.
- **A second source at another path must share the repository's *name*** for the set-aside to be
  what a test proves. The first draft of that test cloned to a differently-named directory and was
  refused by the announce-line comparison — a true refusal, but of the wrong thing. The test now
  holds the name steady so only the skill's line varies, and asserts no refusal before asserting
  no edit.
