# The mode is a setting the person sets — implementation plan

**Authored:** 2026-10-30

## What it keeps

[q-0037.0017.0005.0001](../questions/q-0037.0017.0005.0001-how-do-sessions-on-separate-branches-share-one-question-store-and-one-registry-of.md),
decision 12 and *Where it stands*: "Two modes, a setting of the tree the person sets"; its
default the one shared branch; read from main, since `local.rules.md` travels with every branch.

## The shape

**The declaration.** The session mechanism's rules file gains its settings table, in the form
[MECHANISM-FORMAT](../../.agents/skills/mechanism/MECHANISM-FORMAT.md) gives it:

| setting | values | default | set by |
|---|---|---|---|
| `branches` | `shared` · `per-session` | `shared` | the person |

`branches=shared` is the first mode, `branches=per-session` the second. No rule is conditioned
on it in this slice; `inject_rules.py --settings` lists it, `--set branches=…` refuses an agent
nothing — the host's refusal of a person's setting is
[01-0010.0125](../tickets/01-0010.0125-the-host-blocks-what-a-rule-forbids.md)'s, as the settings edge
record already says.

**The reading.** Until now a setting was read by the installer alone, from the tree it runs in.
This is the first read at run time, and it must not come from the session's own branch: a
branch's `local.rules.md` may carry another value. The session script gains the reading of the
mode — the value `inject_rules.read_settings` gives for the **main checkout**: the working tree
whose Git directory is the project's common one,
`git rev-parse --path-format=absolute --git-common-dir`, its parent. In the main checkout itself
that is the tree it runs in, and nothing changes. The working tree's file, not main's committed
blob: `--set` writes the local file and the person's change is in force before it is committed,
and it reads the person's folder whatever is checked out there. `read_settings` over the whole
tree costs about 24 ms on this one, measured 2026-10-30; it is read when a consumer asks, never on
import.

A common Git directory with no working tree around it — a bare repository with worktrees — has no
main checkout: the mode is then read from the session's own tree, as today, and a `TODO` naming
q-0037.0017.0005.0001 marks the fallback.

**Its consumers.** None in this slice; the first is the notice of
[.0020](../tickets/01-0010.0250.0020-the-harness-runs-in-a-worktree.md).

## Docs

- The session mechanism's doc, *How it works*: a paragraph on the two modes, what each means for
  where a session works and where the store and the rows are kept, the setting that chooses, and
  that it is read from the main checkout. Its *Relies on* already names the installer.
- The settings edge record, *Contract*: a setting read at run time is read from the main
  checkout's local file — a compatible change; `branches` needs no line of its own, the table
  being rendered, never committed.

## Stages

Each keeps the store's, the session's and the installer's tests green.

1. **Declared.** The settings table in `session.rules.md`; a test in `test_inject_rules` that
   `read_settings` declares `branches` with its values, its default and *the person*, and that
   the rendered table shows it at `shared` in a tree that sets nothing. The installer's check
   stays clean on this tree.
2. **Read from the main checkout.** The reading in the session script; tests in `test_sessions`
   over a repository with a linked worktree: the main checkout's local file sets `per-session`
   while the worktree's sets `shared`, and the worktree reads `per-session`; neither sets it, and
   both read `shared`; a common directory with no working tree reads the worktree's own. Each
   fails first for the reason it names: the reading taken from the worktree's file.
3. **Said.** The session doc's paragraph and the edge record's line.

## Impact

**Must change:** `session.rules.md` (a table, no rule); the session script (the reading);
`session.md`; `docs/edge/settings.md`; the two test files.
**Must verify:** the installer's check on this tree and a recipient's update add one row to
`--settings` and install nothing; `test_inject_rules`, `test_sessions`, `test_questions` green.
**Hidden edges:** `session.rules.md` stands changed and uncommitted in the shared checkout, another
session's work — the implementation edits its own lines and commits by path, after reading what
is there. A worktree's hook reading the main checkout's file reads outside its own folder; a
read, by a script the hook runs, not an agent's edit. xuanxue-cabinet's main checkout stands on a
detached HEAD (seen 2026-10-29): reading the person's folder holds there; *commits on main* in
decision 14 does not — carried to [.0030](../tickets/01-0010.0250.0030-a-session-in-a-worktree-opens-a-question-through-the-coordinator.md)'s
plan.
**Leave alone:** the `debug` setting; how the installer conditions rules; the hook.
