## The shape

**One seam: the scripts' own command lines.** Every call on the store is an argument list handed to
`questions.main(argv, root)`, its answer what it prints and its exit code; the session script's
`--hold`, `--take`, `--release`, `--end` the same through `sessions.main`. The coordinator is a small
server, Python's standard `http.server`, bound to `127.0.0.1` on a port the system gives, that takes
a call and runs that same `main` over the main checkout, one call at a time, and returns what it
printed and its code. A call carries, besides its argument list, what `main` reads from outside it:
the bytes of its standard input (the host's payload for `--hook`), and the variables it reads —
the host's session id (`CLAUDE_CODE_HOST_SESSION_ID`), the hook's notice (`GW_NOTICE`). The handler
puts each in place for that call alone, inside the one-at-a-time lock, and the coordinator's own
environment carries none of the host's. Whether a call is sent is decided once, at each script's
`__main__`; `main` itself never sends, so every test that calls `main` runs as it does today.

**Which calls are sent.** Every call, from any folder — the main checkout's included (decision 17) —
except where a mark says *do not send*: the copy a push is checked in, and an install's gate in a
recipient, whose environment carries it, and the tests. `questions.py --check` is sent: the store's
check is the coordinator's (decision 18). At a branch's push, the copy's other checks — tickets,
documents — read the store's truth from the coordinator through `read_store`, sent the same way;
the copy's own copy of the store is not checked.

**Where it runs, and whose code.** The coordinator's root is the main checkout, found in Python with
no process: the tree's `.git` read — a directory, or a file naming one — and that directory's
`commondir`; the main checkout is the common directory's parent when the directory is a checkout's
`.git`, else the working tree its `config` names in `core.worktree`. A common directory with no
working tree to be told — a bare one, a separate Git directory without `core.worktree` — has no
coordinator: the session's own tree is read, as today, and the window says so. Whoever raises it,
the coordinator starts the main checkout's scripts (decision 19); after each answer it compares
their fingerprint — the sizes and times of `.agents/scripts/gw/*.py` — with what it loaded and,
when they moved, stops after answering, the next call raising it anew.

**Raised on demand, one at a time.** A call that finds no coordinator answering starts one: on
Windows with `CREATE_NO_WINDOW`, `CREATE_NEW_PROCESS_GROUP` and `CREATE_BREAKAWAY_FROM_JOB` — a job
that refuses breakaway retried without it, said in the window; elsewhere in a new session — every
standard handle redirected, its Git environment cleaned of the caller's worktree, its output to a
log beside the address. It holds an operating-system lock on the lock file for its whole life
(`msvcrt.locking`, `fcntl.flock`): a second one finding it held exits, and a lock left by a killed
coordinator is free again. It binds, then writes the address file — port, process id, token —
through a temporary file and a rename, so a caller never reads half of one. The caller waits for the
address, a bounded wait well under the hook's 30 seconds. Each call carries the token, compared in
constant time; another program on the port is refused. It stops after thirty minutes with no call
and no push in flight, removing the address.

**When it does not answer.** Silent within the wait, or failing mid-call: a write is refused with
one plain line; a call failing mid-write reports what it completed and what it did not, as the
architecture's interruption contract asks. A read — the window, the wake — is drawn by the session's
own script over the main checkout's files on a named read-only path: no register, arrive, tend or
seen; the window memory keyed by the main checkout, as the coordinator keys it; marked
*coordinator not answering*. The next call raises it again.

**Seen.** The full window carries one line: the coordinator, since when, its root, and a push it
could not make. The one line of an unchanged window stays as it is.

**Commits.** After a write, `declare`'s write returns the paths it wrote, and the coordinator
commits them in the main checkout by name (S5) — the store's entries, and the citations a rename
or an archive repaired across `docs/`; a path it finds changed beyond what it wrote is left out and
named in the window. It commits only while the main checkout stands on the project's default
branch: on a detached head (the user, 2026-10-30) or, by the same reason, another branch, it does
not commit, and the window says the store's changes wait there. While the index is held — a merge under way — the
commit waits for the next write. Before committing it runs the store's check (decision 18); a
diagnostic holds the commit and is said. The rows stay outside its commits until
[.0090](../tickets/01-0010.0250.0090-the-rows-live-in-a-database.md) takes them out of git.

**Pushes.** The coordinator pushes every commit of its own, always — no setting, and nothing to
do with how a project or a session pushes its own work (decision 20). Pushes are coalesced: one in
flight, the next taking every commit made meanwhile. Whatever stands on the shared main may be
published (the architecture), so its push carries what else main holds. A refused push — the
remote moved — is said in the window's coordinator line and tried again after its next commit;
bringing main up to the remote stays the person's or a session's, in the main checkout.

**The sessions in the main checkout.** They go through the coordinator too; a body is still edited
as a file there until [.0070](../tickets/01-0010.0250.0070-a-body-is-edited-on-its-fingerprint.md),
the main checkout's files being the coordinator's own. A worktree session's counters and path read
the main checkout's tickets, as everything else does.

## Stages

Each keeps the store's, the session's and the harness's tests green; those calling `main` stay as
they are.

1. **The server and its client, in process.** The handler — argument list, input bytes, named
   variables, one at a time; the client — send, print, exit with the code; tests: two clients'
   `open`s at once give two ids; a `--hook` call tags the session its payload and variables name,
   not the coordinator's; output and code come back as `main` gave them.
2. **Raised and found.** Lock, address, token, the detached start, the idle stop, the restart on
   changed scripts; tests: none running, the first call raises one; two at once, one; a lock left by
   a killed one freed; a call without the token refused. The detached start observed on Windows —
   from a hook Git Bash launched — and on POSIX by someone who did not build it, the hook's process
   ended under it.
3. **Every call through it.** Sending at `__main__`; the *do not send* mark in the push copy, the
   install's gate and the tests; the read-only fallback, a test that it changes no file; the
   window's line.
4. **Commits and pushes.** The written paths; by name; the default branch alone; the held index; the
   check before; every commit pushed, coalesced; a refused push said.
5. **Said.** The session and questions mechanism docs.

## Impact

**Must change:** a coordinator script, `coordinator.py`, the session mechanism's (decision 6 of
q-0037.0017); `questions.py` and `sessions.py` (sending at `__main__`, the read-only path, the paths
`declare` wrote); `harness.py` (the mark in the push copy and the gate); the architecture; the mechanism docs; tests.
**Must verify:** every store and session test green; the window and its one unchanged line as
before; the pre-push copy's checks reading the store from the coordinator; a recipient's update
taking the script.
**Hidden edges:** a commit hook or a signing prompt in the main checkout can hold the one-at-a-time
server: commits run with no prompt and a timeout, a failure said, the calls served meanwhile. A host
that kills the hook's whole process tree takes the coordinator with it where breakaway is refused —
measured in stage 2. A session's `--hold` naming a question the coordinator's store does not hold
is refused as today.
**Leave alone:** bodies (.0070), the rows' storage (.0090), the networked mode, messages, the web
page.
