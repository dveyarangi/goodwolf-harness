## The shape

**The interpreter, one per clone.** `hook.sh` already holds `interpreter()` — the worktree's own
record, then the common directory's — for its `pre-push` branch; the host branch reads only
`--git-path gw-interpreter`, the worktree's own. The host branch takes `interpreter()` too. And
`_record_interpreter` writes the record at
`git rev-parse --path-format=absolute --git-common-dir`, as `_write_push_hook` already resolves its
place, where every worktree's hook finds it. In a main checkout the common directory is the one
`--git-path` named, so a tree that works today writes the same file; the tests that write
`.git/gw-interpreter` stand.

**The links, made by the session that lacks them.** The loader links are ignored by git and made
by the link step, so a new worktree has none. At a session's start — where the hook already tells
a start by the payload and runs the installer's check — the hook, in `sh`, tests for the link its
host reads: `.claude/skills` for `claude-code`, `.cursor/skills` for `cursor`; `codex` reads the
skills in place and has none (hosts record, *Codex*). Only where the tree holds `.agents/skills`
and `.agents/scripts/gw/harness.py`, and the host's link is missing, does it run
`harness.py . --links --line`: the links and their exclude entries alone — not the interpreter
record or the `pre-push` hook the full `--links` also writes, since a relative `core.hooksPath`
would put a hook inside the worktree — printing one line or nothing, in the form
`inject_rules.py --check --line` gives the installer's: *the skills are linked now and load from
this worktree's next session*, a host having read its skills before its start hook ran; or, where
the platform refused, the exact command, as an install's pending links are named. The link line
and the installer's line reach the wake in the one notice the hook hands it, joined on two lines.
A tree whose links stand starts nothing.

**Until the coordinator.** A worktree session turned on by this slice works with its own branch's
copy of the store until [.0030](../tickets/01-0010.0250.0030-a-session-in-a-worktree-opens-a-question-through-the-coordinator.md)
lands: its ids are minted from that copy and its row is written there. Its window says so in one
line while the tree has no coordinator, the line carrying
`TODO q-0037.0017.0005.0001.0005` for .0030 to remove.

**Nothing on the worktree's own branch changes.** The links and the record are outside every
commit; the exclude file the link step writes resolves to the common one.

## Stages

Each keeps the harness's, the store's and the session's tests green — the wrapper's exact-output
tests in `test_harness` among them, the start branch guarded on the files they lack.

1. **The record written in the common directory.** `_record_interpreter`; a test that `--links` in a
   linked worktree writes the record in the common directory. Fails first: written in the
   worktree's own.
2. **The host branch reads it.** `hook.sh`'s host branch through `interpreter()`, the worktree's own
   record first; a hook test in a linked worktree whose own directory holds none draws the window.
   Fails first: the no-interpreter notice.
3. **The links made at start.** `--links --line`; the start branch; tests: a worktree without the
   host's link gets it and the line, one with it gets neither, `codex` gets none, a refused symlink
   gives the pending command — the refusal stubbed, as the harness's tests already stub the
   platform; the two lines joined in the notice; the worktree's own store said in the window.
   Observed in this tree's `.claude/worktrees/` by someone who did not build it.

## Impact

**Must change:** `hook.sh` (the host branch; the start branch); `harness.py` (`_record_interpreter`,
`--links --line`); `questions.py` (the window's line until the coordinator); `test_harness`.
**Must verify:** the main checkout's hook unchanged; `pre-push` unchanged; an install and an update
in a recipient still record the interpreter and make the links; `.claude/worktrees/` copies out of
the corpus.
**Hidden edges:** on Windows without the right to make symlinks the link stays pending until the
person runs the command, and the line comes at each start until then, as the installer's check
says a drift.
**Leave alone:** sibling clones, which share no Git directory; the `pre-push` branch; the
installer's check at start.
