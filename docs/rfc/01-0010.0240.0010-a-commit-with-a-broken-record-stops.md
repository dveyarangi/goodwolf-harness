## Shapes and flow

```
git commit -- <files>
  └─ .git/hooks/pre-commit         one line, written by --links
       └─ sh .agents/scripts/gw/hook.sh pre-commit
            ├─ the commit's files: git diff --cached --name-only --no-renames
            ├─ matched against two groups of roots — none woken: exit 0, no interpreter
            ├─ no interpreter recorded: a warning, exit 0
            └─ "$python" .agents/scripts/gw/harness.py . --commit <woken groups>
                 ├─ the woken checks, each `--check`, side by side
                 └─ the verdict by the commit's files: refused (exit 1) or passed, warnings printed
```

**The two groups** keep decision 1 — a check runs when the commit carries a file it reads — at
the grain of roots, not of files: run side by side, a commit's time is its slowest check's (all
eight 2.6 s, four 2.9 s, 2026-10-26, within noise), so a finer map saves nothing and can be wrong.

| group | woken by a commit carrying | checks |
|---|---|---|
| `records` | `docs/questions/`, `docs/tickets/`, `docs/rfc/`, `docs/sessions/`, `docs/product.md`, `docs/edge/` | `questions`, `sessions`, `tickets`, `product`, `edges` |
| `core` | `.agents/`, `docs/mechanisms/`, `AGENTS.md`, `CLAUDE.md`, `local.rules.md` | `mechanisms`, `inject_rules`, `maintain` |

The first stage reads each check for the files it reads and fixes the roots by what it finds; a
test holds every root a check reads inside its group. The roots stand in `hook.sh` and the group
names in `harness.py`, with a `TODO q-0037.0006.0005.0001` at the roots: each mechanism's table of
its records, decided there, is to carry them (decision 1). Two reads fall outside their group on
purpose: `mechanisms.py` and `maintain.py` also read the question store, and are not woken by a
commit of records alone — their findings name no file (below), so waking them there would bring
back the false red decision 2 removes; a question a core file's straw dog binds, closed in a commit
of records alone, is CI's to catch (decision 1).

**The verdict** keeps decision 2. The commit's files are read in `harness.py` from the same
`git diff --cached --name-only --no-renames`, under the `GIT_INDEX_FILE` Git hands the hook. A
check that passes says nothing. A check that fails yields its `diagnostics` and `skipped`: an entry
with a `record` the commit carries refuses the commit; one with a `record` it does not carry is
printed as a warning; an entry with no `record` — `mechanisms`, `inject_rules` and `maintain` report
by mechanism, not by file — refuses it, since it cannot be placed; a check that printed no report,
having crashed, refuses it with its last lines, as the gate's `_diagnostics` already reads it. A
check's `findings`, which never fail it, are not shown. Each refusal and warning names the check,
the file and line where it has them, and the problem.

**Running side by side.** `_script_gate` runs one script and waits; `--commit` starts every woken
check before reading any, through the same `_python` and `_diagnostics`, so the gate and the
commit read a check one way.

**The mode.** `--commit` takes the target and the woken groups, no `--from`, no network, no
`Source`; it prints its refusals and warnings as lines — the person and the agent read them in the
commit's output — and exits 1 on a refusal, else 0. It is refused outside a tree that holds core,
as `--links` is.

**The hook** keeps decision 4. `link()` writes it after the interpreter record, at
`git rev-parse --git-path hooks/pre-commit`, so a `core.hooksPath` is honoured and every worktree
of the clone shares it; LF, executable bit set where the platform has one:

```sh
#!/bin/sh
# goodwolf: written by harness.py --links; the checks of the method's records at commit
exec sh .agents/scripts/gw/hook.sh pre-commit
```

Its second line is its mark: a file holding it is core's and is rewritten to the current form; a
file without it is another's and is left byte-identical, the report naming the one line to add and
where — `.husky/pre-commit` where `core.hooksPath` names husky's directory, `lefthook.yml` or
`.pre-commit-config.yaml` where one stands, else the hook file itself. The report gains a `hook`
entry: its path and `written`, `kept` or `beside`, with the line and its place for `beside`.

**Failure semantics.** With no interpreter the hook warns and passes: it cannot check, and CI is
the last gate (decision 1). A crash of `--commit` itself exits non-zero and Git refuses the commit:
a fault of core's is shown, not hidden. `hook.sh`'s host branches keep their promise never to fail
the host; the `pre-commit` branch is the one that refuses by design, and its comment says so.

**Windows.** Git for Windows runs the hook under its own `sh` from any shell (tried 2026-10-26,
the question's *On Windows*); the interpreter path is quoted, since it may hold spaces.

## Rollout, and what it reaches

- **Here.** The hook turns on for every session in this clone the moment `--links` writes it.
  The last stage runs it, after the user is told; a false red would stop every running session,
  which decision 2 is for, and removing `.git/hooks/pre-commit` turns it off.
- **Recipients.** A recipient that updates and runs `--links` before
  [.0030](../tickets/01-0010.0240.0030-an-install-wires-the-checks.md) lands gets the hook with
  only the report's `hook` line to tell it; the install's sentence comes with .0030.

## Stages

Each keeps the suite green; `/tdd` allocates the tests.

1. **The roots.** Read each check for the files it reads; fix the groups. A test that each check's
   reads lie under its group's roots.
2. **`harness.py --commit`.** The mode, side-by-side runs, the verdict. Tests on a fixture tree: a
   broken ticket the commit carries refuses it and names file and line; the same ticket not carried
   passes with a warning; a failure with no `record` refuses; a crashed check refuses with its last
   lines; a passing tree passes silently.
3. **`hook.sh pre-commit`.** The shell match, the missing interpreter, the hand-off. Tests through
   a real `git commit -- <file>` in a fixture clone whose recorded interpreter is a stub that logs
   its calls: a commit of code calls it never; a commit of a record calls it with `records`; a
   commit of a skill with `core`.
4. **`--links` writes the hook.** Tests: written where none stands; rewritten when it carries the
   mark; another's left byte-identical, the report's line and place right for husky's
   `core.hooksPath`; `hook.sh`'s host events unchanged (`test_questions.py`'s launch tests).
5. **The docs**, under `/mechanism`: the harness doc's moments — writing the clone's `pre-commit`,
   running the checks a commit wakes and ruling by its files — and *What it produces*, the clone's
   hook, made by the link step and never committed; mechanism-shape's moment for `hook.sh` choosing
   the woken checks. The shape check and the injector's pass.
6. **Live, here.** `--links` run in this clone; a commit's time measured with sessions running; the
   ticket's live criteria observed by a subagent that did not build it.
