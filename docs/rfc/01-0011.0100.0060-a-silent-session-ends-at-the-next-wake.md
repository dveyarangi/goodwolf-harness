# A silent session ends at the next wake — implementation plan

**Authored:** 2026-10-10
**Last amended:** 2026-10-10

Implements [01-0011.0100.0060 a-silent-session-ends-at-the-next-wake](../tickets/01-0011.0100.0060-a-silent-session-ends-at-the-next-wake.md).

## What shapes it

- **Who ends a row, when, and quietly** — the user, 2026-10-10, held in
  [q-0001.0024](../questions/q-0001.0024-when-does-a-session-row-that-stopped-running-read-ended-and-who-ends-it.md):
  three hours, the next wake, nothing said; the row's time to the minute.
- **A wake writes a line not its own** — [the architecture](../architecture.md#the-question-store),
  landed this pass as a straw dog bound to q-0034 beside *each session replacing its own line and
  no other*: safe because a silent session has no write of its own to meet.
- **The window's memory** — `questions.py`'s `_memory`: the fingerprint of a session's last
  window, kept outside the tree under the temporary directory, keyed by tree and session, so it
  never churns the store. It is the session's sign of life this plan reads; nothing new is kept.

## The sign of life

A session is **seen** when it writes its line or draws its window. Its line's time says the
first; its window memory's modification time says the second. Silence is measured from the later
of the two.

Why not write the line on every message: the sessions file is committed, and a line rewritten on
every message is a diff in every commit of every session, and one more write racing others
(q-0032). The window memory is already written beside every drawn window, outside the tree, by
the session it belongs to — it only needs to be written on every draw, the unchanged one too.

Probed 2026-10-10 in this tree: the memory directory holds a file per session that drew a window,
each modified when its session last drew one whole. All three hosts have one — Claude Code's
sessions, Codex's `01a1227f…` (memory and transcript both last moved 00:09, its message hook
drawing the window), and Cursor's `5fba085e…`. Cursor's was written once, at its start (00:01):
over four messages to 00:09 its agent drew no window by the rule and made one `at`. **The window
by the rule does not happen in Cursor**, so Cursor's sign of life cannot be the agent's window.

**Cursor's prompt hook records the sign of life.** Its `beforeSubmitPrompt` can only allow or block
— which is why the window reaches Cursor by the rule — but a hook runs on every message whatever it
may answer. Wired to the script, it writes the session's window memory and turns an ended line
running, and answers allow with nothing injected. Assumed, probed at stage 5: the hook's payload
carries `conversation_id`, as the start hook's does, and its run delays the message by no more than
the start hook's.

Where the memory is missing — a temporary directory cleared, a session on another machine (out of
reach of one sessions file anyway, q-0018.0015) — the line's time alone counts; a session ended so
turns running at its next window.

## Flows

**Cursor's message arrives** (`beforeSubmitPrompt`): the session is seen — its memory written, an
ended line turned running — and the hook answers allow, `{"continue": true}`, injecting nothing.
It answers allow on every path, a refused payload and a script fault included: the hook boundary
already never fails the host, and here a failure would hold back the person's message. A session
the hook has not seen start is registered, as Claude Code's message hook does today. Its entry joins Cursor's
on the questions skill's hooks shelf, merged into the host's file by the installer as the start
hook's is.

**A window is drawn** (`window`, from a host's message hook or `--window --session` by the rule):

1. The memory is written on every call, the unchanged one included — its content as now, its time
   the sign of life.
2. If the session's own line reads ended, it is rewritten running, its time now, its position
   kept. Nothing else in the window changes.

A compaction forgets the window by writing a memory that matches no fingerprint, rather than
removing it, so the next window is drawn whole and the session stays seen.

**A session starts** (`_started` for every host's start event but a compaction, and `--wake`):
after the session's own line is registered, resumed or turned running, every other running line
whose session was last seen three hours or more ago is rewritten ended — its position, recent ones
and time kept, its time being when it was last written. The wake's text is drawn after, and names
none of them: they read `ended` in the sessions list like any other. The waking session's own line
is never among them.

**A session writes its line** (`at`, registering, resuming, `--end`): the time is now, to the minute.

**A line is read**: `<tag> running|ended <YYYY-MM-DDTHH:MMZ> <q-id>|- [<q-id>,…]`; a line holding
the date alone still reads, as that day's 00:00Z, and the next write of it — its own session's or
a rename's — writes the time. The check admits both forms.

## Code shape

- The line's time is a UTC `datetime` where it was a `date`; `now` replaces `today` along the
  paths that write a line (the hook, `--wake`, `--end`, registration, the window's revival), as
  the store's calls already take it.
- The threshold is one constant of three hours, replacing the week's.
- `_session_findings` keeps the finding of a running session on a closed question and drops the
  week-silent one.
- Ending another's line goes through the same re-read-then-rename write a session's own line does:
  the file is read just before, only the silent lines change, every other line is kept as found.
- A `TODO q-0034` stands at the ending and at the revival: a session mechanism takes the sessions
  file.

Not prescribed: how the memory's time is read beside the line's, how the start paths share the
ending, and the names of helpers — `/tdd`'s.

## Stages

Each stage keeps the suite green.

1. **The time in the line.** Read both forms, write the new one; every writer passes `now`.
   Tests: a date-only line reads and a written line carries the time; the check admits both and
   refuses a malformed time; a rename rewrites a date-only line with a time and changes no position.
2. **Seen, and revived.** The window writes its memory on every call; a compaction keeps it; an
   ended own line turns running on the window. Tests: an unchanged window moves the memory's time;
   a window drawn for an ended session leaves its line running with its position and every other
   line byte-identical; after a compaction the next window is whole and the memory is still there;
   Cursor's `beforeSubmitPrompt` payload moves the memory, revives an ended line and answers allow
   with nothing injected, and a malformed one still answers allow.
3. **The wake ends the silent.** Tests, each with `now` and the memory's time set: a line last
   seen three hours ago is ended at another's start, its position kept; one seen two hours fifty
   ago stays running; a line written long ago whose memory is fresh stays running — the session
   answering messages with no store write; the waking session's own stale line is not ended; a
   compaction's start ends nothing; `--wake` ends as the hook does; the wake's text holds no
   sentence about an ending; a line another session wrote between the read and the write is kept.
   The week-silent finding's test is replaced by one that no such finding remains.
4. **The words.** The questions skill's sessions-file paragraph: when a row ends and who ends it,
   a straw dog bound to q-0034; the `What removes a row` clause loses the week. The questions
   doc's moments, if a row names the wake's read only as a read.
5. **Live.** This tree's own file: the check before and after, a date-only row rewritten with its
   time on its session's next write. In each of Claude Code, Codex and Cursor, a session's row
   ended by hand reads running after one message, and Cursor's message is not held back. Cursor's
   payload is read first, before the stage-2 code is relied on.

## Impact

**Must change:** `questions.py` — the line's form and reader, the writers' `now`, `window`, the
start paths, the findings, Cursor's host taking a message event; Cursor's hook file on the
questions skill's shelf; `test_questions.py` and the hook tests where a line's date is written
literally; the questions skill's paragraph. A recipient takes Cursor's new hook entry on its next
update, by the merge that already carries the start hook. **Must verify:** the three hosts' window paths; this
tree's sessions file across the change.

**Hidden edges.** *The memory is per machine.* Two sessions in one tree share a machine, which is
the only case the sessions file serves. *Clock.* The line's time and the memory's are both read on
the one machine that writes them. *Lost update.* A session writing its line in the moment a wake
ends it — possible only for a session seen by nothing for three hours yet writing now, mid-turn on
a long autonomous run — loses either the ending or its own write; the next message heals both.
*The window by the rule in Cursor* is not drawn in practice; this plan stops leaning on it for
the sign of life, and the window itself still reaches Cursor only by the rule — rule failure 28. *The sessions list in the wake* still names every ended row; shortening it is
archiving's, out of this ticket.

*A concluded session spoken to again* — a message after `/conclude` — turns its line running:
the session is running again, which the line should say.

**Leave alone.** `--end`'s meaning; resume detection (q-0001.0006); the window's drawing and its
fingerprint; who owns the file (q-0034).

**Recommendation.** Proceed as one AFK slice.
