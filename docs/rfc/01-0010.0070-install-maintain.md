## Hidden edges

The [source evidence](../research/maintenance-findings.md) establishes several adaptations:
historical citers are currently skipped; duplicate sources are accepted; a second-move
failure leaves a partial close; Windows absolute links are corrupted by relative rewriting.
The source `docs_corpus` and guard suites also embed archive exemptions, a different queue
table, session conventions and repository-size assertions that do not govern this project.

The source also truncates a record before completing its content rewrite; see
[evidence](../research/maintenance-findings.md). Account for this in helper implementation.
Git supplies a recovery baseline for committed or staged content, not a guarantee of
recovering overwritten unstaged edits.

The existing repository mixes LF and CRLF. Preserve untouched bytes and line endings, and
test that semantic history, code examples, link labels and fragments remain unchanged.
Directory loader links must not produce duplicate skill inventories or escape the root.

The current operative temporary statement is the pacer block in `docs/process.md`.
An inventory of `AGENTS.md`, `docs` and `.agents` found no remaining operative `/edge` block;
the queue's earlier claim was stale. Inline examples and historical descriptions are not
operative blocks. The first use will normally report the unmet pacer condition; fixtures
must demonstrate expired-statement removal as well.

### Corpus and references

Discover tracked and untracked, unignored files through Git; handle deleted entries and
deduplicate names. Inspect Markdown at root, under `.agents`, and under `docs`, including
historical records; include other repository Markdown when searching for affected inbound
citations. Do not recursively traverse loader aliases. Surface Git/read/decoding failures;
an empty or partially unreadable scan cannot be reported as complete coverage.

Resolve relative references against each citing file. Classify local absolute paths and
`file:` URIs separately from external URIs. If a local absolute reference resolves to a
selected source inside this repository, retarget it to that source's destination while
preserving its absolute-path or URI form. Preserve external references and unmapped absolute
references unchanged. This includes distinguishing an external `D:/Dev/...` source link
from an absolute path to the record being moved; syntax alone cannot determine exemption.

Preserve fragments, titles and labels; redepth outgoing relative references when the citing
file moves. Decode percent-encoded local paths for identity matching and preserve equivalent
encoding when emitting the changed target. Reject path escapes for move operands, including
escapes through symlinks or junctions, before writing.

Inline Markdown links/images, multiline labels, angle-bracket destinations and reference
definitions are real citation forms. Code spans and fenced examples are not rewritten.
Recognized operative temporary `ticket` attributes are root-relative references and follow
a moved owner; examples of the syntax do not. Unsupported affected reference syntax must
be reported before mutation rather than silently claiming all citations were repaired.
Bare filenames in historical prose/code examples are not automatically rewritten.

Use synthetic assertions with independently specified expected destinations; a validator
sharing the same parser is supplementary evidence, not the only proof of correctness.

### Paired mover

Retain the CLI shape `move_doc.py SRC DST [SRC DST ...]`, with root-relative operands.
Add a read-only preview (`--dry-run`) that reports selected moves and affected citers.
The caller supplies eligibility; the script never changes checkboxes, status prose or dates.

Before mutation, read the affected files and derive the complete change set. Refuse missing
sources, duplicate sources/destinations, existing destinations (including untracked or
ignored filesystem entries), self-moves, overlapping mappings, non-Markdown operands,
case-equivalent collisions and resolved paths outside the repository. Refusal changes
neither files nor the Git index. Check expected file contents and destination absence again
before applying changes; detected interference is a failure, not permission to overwrite it.

Adapt the source to ordinary filesystem moves and writes, leaving the Git index untouched;
Git can identify renames when the caller later stages the reviewed change. Preserve all
unrelated working changes. UTF-8 decode failures are refusals, and unchanged files are not
rewritten. Read/write with newline preservation. This is one operation over the complete
mapping, so mutual links resolve against both final homes.

Leave the per-file writing technique to implementation. Preserve unrelated content and
working changes, and report failures through the agreed interface. No additional recovery
mechanism or prescribed replacement protocol is part of this RFC.

Successful output lists completed moves and rewritten files; postconditions verify selected
sources are absent, destinations exist, and affected references target their final homes.
Check every moved outgoing reference and every rewritten incoming reference. Existing
unrelated defects are reported with ownership without converting this into whole-tree repair.

Failure behavior follows [architecture](../architecture.md#interruption-and-recovery).
Complete preflight precedes writes. On an I/O error, stop and report completed operations,
pending operations and the failed path with a nonzero exit. Do not automatically roll back
or claim a successful close. Report operation attempts and completions as they occur; after
abrupt termination, the last attempted operation requires filesystem inspection. The caller
recovers under the repair policy. This is not an atomic transaction or a concurrent-writer
guarantee. Git is the caller's recovery fallback for available committed or staged versions;
inspect working changes before restoring anything. Tests distinguish unchanged preflight
refusal from partial failure after writes.

### Temporary statements

Provide `temporary_statements.py PATH [PATH ...]` for a declared file/directory scope, with
deterministic JSON output containing block records and diagnostics: path, opening/closing
line, condition, owning ticket, nesting and the full file's SHA-256 byte fingerprint.
Return discovered blocks alongside diagnostics for missing
bindings, missing conditions, unresolved owner paths, malformed tags and unbalanced nesting.
Any diagnostic yields nonzero status; zero operative blocks is
an explicit successful result when all selected input was read.

Recognize operative wrappers outside code examples, including nested and multiline tags;
ignore inline syntax examples such as AGENTS.md's definition. Do not execute `until` text.
The skill evaluates conditions from observable evidence and records its disposition.

Provide removal as `temporary_statements.py --remove FILE:LINE --expect HASH`; parse the
line from the final colon so Windows drive paths remain usable. Resolve paths inside the
repository and refuse escapes as for the mover. Re-read and reject a changed full-file
fingerprint before writing; remove only the confirmed obsolete statement,
preserving all surrounding content and line endings. The tool removes one complete matched
block only. Refuse an outer block containing any nested block, regardless of its written
condition: the tool has no authority to infer that the child expired. Refusal changes no
bytes. The maintainer disposes of children first and rescans after each change, since the
line positions and fingerprint can change. An active child or an enduring agreement must
be preserved in its maintained home before removing its enclosing obsolete statement;
unclear disposition follows the existing `/align` rule. Fixture tests prove this mechanical
path; the live pacer statement remains until its actual condition holds.

## Delivery stages and proof

Use [TDD](../../.agents/skills/tdd/SKILL.md): each behavior below is an individual red-green
increment, followed by refactoring with the set green. Do not write the entire test suite
before implementation. The RFC fixes behavioral priorities; private helper shapes are free.

1. The failure contract is resolved in maintained architecture. Establish the runtime
   command and register script checks in
   [Verification](../process.md#verification) when they actually exist.
2. First tracer: close a synthetic mutual ticket/RFC pair through the mover's public
   interface and verify exact resulting references and unchanged prose. Package only the
   corpus support needed for this path, with no imports from tests.
3. Incrementally prove historical incoming links, outgoing/mutual links, fragments and
   supported reference forms. Prove that internal absolute paths and local `file:` URIs
   follow the mapping, including encoded paths, while external references, literal code
   examples, line endings, unrelated files and Git index remain unchanged. Use a disposable
   Git repository to prove tracked/untracked discovery and independence from caller cwd.
4. Prove each preflight refusal by its specific cause and byte-identical files/index.
   Exercise preview without writes, duplicate-source input, filesystem destination
   collisions and symlink/junction escape where available. Inject a second-move/write
   failure and interference to prove the selected failure contract, not just an exception.
   Verify content preservation and reported write failure through the helpers' public
   behavior. Tests should exercise the chosen implementation without requiring a particular
   replacement protocol or a recovery subsystem.
5. Prove temporary scanning and removal through their public interface: operative, absent,
   nested, multiline, unbound, malformed, example-only and expired inputs; malformed input
   remains visible and changed fingerprints refuse removal. An outer removal with a nested
   child must fail for nesting with byte-identical input. After an explicitly expired child
   is removed, prove that a rescan permits its obsolete parent to be removed; the original
   fingerprint cannot authorize either subsequent selection.
6. Install the composed skill and callers, update `.agents/README.md` and AGENTS.md's local
   installed list. Move the procedure's step rules from process into the skill and retain
   policy/architecture ownership by reference. Replace TICKET-FORMAT's manual fallback with
   the packaged mover invocation. No entry-contract bump is needed for a local installed-list
   update alone. Inspect source capability coverage and all new links.
7. Obtain actual discovery in a fresh host session; a file or working loader link alone
   does not satisfy the ticket. Record what the host actually supplied. Until observed,
   discovery stays unchecked; other independent verification may proceed.
8. Run `/maintain` once on the agreed `0040` scope: inspect its contracts and dependencies,
   record coverage and findings, enumerate applicable temporary statements, confirm prior
   verification and current eligibility, preview and execute the two-record close, then
   verify moved/outgoing/incoming references. Preserve the queue row and its Done date;
   citation changes are mechanical. Record first-use evidence on this install ticket.
9. Run `/verify` on this install against every criterion, this RFC, governing docs and
   the now-populated verification set. Record unresolved scope and actual evidence; keep
   the ticket unfinished while a required observation or check is missing.
