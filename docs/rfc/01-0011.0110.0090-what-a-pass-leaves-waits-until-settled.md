## Governing boundaries

- **The marks are the maintenance mechanism's one record**, written only by `maintain.py`, read by
  its check at every pass; a malformed row fails the check
  ([MARKS-FORMAT.md](../../.agents/skills/maintain/MARKS-FORMAT.md)).
- **What waits is a fixed field a script reads, never prose a model reads**, shown by the wake only
  while it holds anything, put to the person by a rule the maintenance mechanism installs in
  `/recall`, gone when settled, not when read (q-0037.0010.0009.0009, decision 3).
- **Scripts enumerate and transform, and decide nothing**
  ([Responsibilities](../architecture.md#responsibilities)): the script lists what waits; the agent
  puts it to the person.
- **A mechanism's rule reaches a skill only as an installed block** (R5, R8).

## Raised for the person

Decision 3 has a wait go when its settler *writes the mark again with the field empty*. Read
literally, any re-mark clears the field — including a pass that re-checked the level for another
reason and settled nothing. Two forms:

- **A. The mark replaces the field** with what the call names. Simple; a wait outlives only the
  passes that remember to name it again.
- **B. Recommended: a wait stands until it is cleared by name.** `--mark` adds what the call names
  to what already waits; `--settle <mechanism> <level> <n>` drops the *n*th, rewriting no
  fingerprint. A wait goes only by the act that settles it, which is what decision 3 asks.

The plan below is written to B.

## Stages

Each stage ends green; the tests run, scripts changing.

1. **The marks, red first** in `test_maintain.py`: a mark naming two decisions writes them in the
   row's sixth cell and `--check` lists both, numbered; a later mark of that level naming none keeps
   them, one naming a third adds it; `--settle` drops the one named and touches no fingerprint;
   settling a number that is not there refuses; an item holding `|` or ` · ` refuses; a
   five-column header reads with nothing waiting, and the next mark writes six; a six-column row
   with five cells fails the check. Then `maintain.py`.
2. **The wake**, in `test_questions.py`: a tree whose marks hold a wait shows the section with it,
   after the path; one with none shows no heading; six waits show five and *and 1 more*. Then
   `questions.py`.
3. **The instructions**: `MARKS-FORMAT.md`, F4, the doc's record paragraph and moment row, M3 in
   the rules file and installed; `inject_rules.py --check` and `mechanisms.py --check` green.
4. **This tree's marks** carry the column: the maintenance mechanism's levels, due after stages 1–3,
   re-checked and marked, which rewrites the file whole.
5. **Read live**: a subagent with none of this session, started as a session on this tree with one
   wait written by `--mark`, writes its first report under `/recall`; a judge who did not build it
   reads whether the wait is put to the person as a decision. The wait is then settled and the
   wake read again for no section.
