# A test pays only for what it proves — implementation plan

**Authored:** 2026-09-26
**Last amended:** 2026-09-27

Implements [01-0011.0080 a-test-pays-only-for-what-it-proves](../tickets/01-0011.0080-a-test-pays-only-for-what-it-proves.md).

## The decision it follows

**A test builds a real repository only when Git, or a child process, is what it proves; every
other test runs in a plain folder, and a guard refuses it any process at all** — landed in
[the mechanism shape's Testing Decisions](../spec/01-0011-mechanism-shape.md#testing-decisions) and
[the install spec's](../spec/01-0010.0130-harness-installs-into-another-tree.md#testing-decisions),
*(the user, 2026-09-27)*. Of the scripts only `harness.py` starts a process, so the guard also
carries what the index snapshot used to.

And **prune first** *(the user, 2026-09-27)*: an audit of all 342 tests, each read against the code
it exercises, found 11 that cannot fail on the regression they name and 51 that repeat another
test; they go before anything moves, but for three whose guard is real.

## What the code does today

| where | what starts a process | per |
|---|---|---|
| `docs_corpus.corpus()` | `git ls-files` | every script call that lists the tree — `tickets`, `mechanisms`, `inject_rules`, `move_doc`, and `harness`'s gate |
| `harness.Source` | `git clone`; `rev-parse`, `describe`, `rev-parse --short`, `log` per `resolve`; `archive` and `cat-file` per ref read | every `harness.main` call — an update reads two refs |
| `harness._git_in` | `rev-parse --show-toplevel`, `remote get-url` | every `harness.main` call |
| `harness._script_gate` | a child Python per check script, each with its own `git ls-files` | two per install, update or check |
| `repository.py` | `git init` once; `git add` and `git commit` per `commit()`; `ls-files --stage` per `snapshot()` | the tests themselves |

No script but `harness.py` starts a process of its own; each imports `corpus` by name from
`docs_corpus`.

## Stages

Each stage leaves the suite green.

**0. Measure.** The suite is timed three times on an idle machine and the median is recorded on the
ticket, with `harness.py --check` on ai-game-1 saved to compare against at the end. *Why idle:* on
2026-09-26 the same test took 5.2 s and then 10–16 s with a game holding two and a half cores; the
ticket's "in-suite doubling" may be that, and the baseline must not be.

**1. Prune.** A test that cannot fail on its regression goes; a test another already proves folds
its one distinct assertion, if any, into that test — as a `subTest` where only the input differs.
Every removal is named in the commit with what now proves its behaviour. Classes defined after a
file's `if __name__ == "__main__"` move above it.

Three the audit called unable to fail guard a real line whose input never reaches it — a removal
path outside the repository, an external reference in a move, a refused write keeping its content.
They stay, and
[01-0011.0090 a-test-catches-what-its-name-promises](../tickets/01-0011.0090-a-test-catches-what-its-name-promises.md)
makes them reach it; deleting them would leave the guard untested. Each of the eight that go was
read against the line it names before it went.

**2. The guard.** The test base refuses a process start from any case not marked as proving Git or
the gate. Every existing class is marked, so nothing changes yet; a guard test plants a process
start in an unmarked case and sees it fail, and a marked one pass.

**3. Plain folders for tests whose subject is not Git.** An unmarked case's root is a plain
temporary folder, and every script's `corpus()` call reaches a listing of that folder — every file
beneath it, `.git` excluded, sorted — at one place in the test base. The classes of `test_tickets`,
`test_mechanisms`, `test_straw_dogs`, `test_inject_rules`, `test_citations`, `test_command_line`,
`test_paired_close`, `test_refusals` and `test_failure_contract` lose their mark, their `commit()`
calls, and the index half of `snapshot()`; the bytes half stays, and is what their refusals prove.
The tests whose subject is `corpus()`'s Git listing — exact case under a case-folding tree,
untracked files included, ignored ones not — stay marked.

**4. The harness's source in memory.** `Source.files` keeps the choice of what ships — the core
directory, the entry file, the host stub, the license read apart — and reads those paths through
one method, so a test's `Source` can answer the same request from memory: the fixture's `commit()`
takes a snapshot of the source folder as a ref, `tag` names one, and `resolve` answers `HEAD`, a
tag, a commit or its short form, or refuses as today. The fixtures' `git rm`, `git mv` and
`git tag` become file operations on the folder. `harness.main` builds its `Source` as today; the
test's replaces it for the case.

**5. The gate in-process.** For an unmarked harness case, the gate's two checks call
`inject_rules.main(["--check"], root=target)` and `mechanisms.main(["--check"], root=target)`, and
report the same passed, exit and last lines. That stands for the child only because the fixture's
target holds copies of the live scripts; a case whose target holds other scripts stays marked.

**6. The target's Git questions.** For an unmarked harness case the target is a plain folder, the
top of its own tree, with no origin.

**7. What stays real, and the close.** Marked, with real Git and the real gate:
- a tagged ref announced by its tag and an untagged one by its short commit — `Source.resolve`
  against a real repository;
- the target refusals Git decides: not the top level of a work tree, and the source itself by its
  origin;
- a recipient holding its own clone of the source;
- a ref read under the rules it shipped with, and the license a ref may lack — `Source.files`
  against a real repository;
- the recipient's own files under core, found by `corpus()`;
- one install, one update and one check end to end.

The scripts' move is not here: every update's gate runs the target's scripts where they stand, so
that test's one distinct assertion — emptied directories are pruned — folds into stage 1.

The suite is timed as in stage 0 and both medians go on the ticket; `harness.py --check` on
ai-game-1 is compared with stage 0's.

## Impact

- **Must change:** `repository.py`; the harness fixture and its cases in `test_harness.py`; the
  other test modules' marks, commits and snapshots; `harness.Source.files`, split without a change
  in behaviour; both specs' Testing Decisions.
- **Must verify:** every test that passes today still passes or is named with its replacement;
  `harness.py` run for real against ai-game-1 reports as before.
- **May simplify:** `snapshot()`'s index half, once only marked cases can reach Git.
- **Hidden risk:** a test's `Source` that answers differently from `git archive` — held off by
  keeping the choice of paths in `harness.py` and the end-to-end cases real; a script that later
  imports `corpus` somewhere the listing does not reach — the guard fails its unmarked tests, which
  is the signal; the in-process gate standing for a child whose scripts differ — only the marked
  case exercises that.
- **Historical only:** session 13's template `.git`, which stays for the marked cases.
- **Probably unaffected:** every script's behaviour outside tests.

## Leave alone

Production's `Source`, gate and `corpus()` behaviour; the scripts' command lines; the verification
set's command; recipients' verification sets.
