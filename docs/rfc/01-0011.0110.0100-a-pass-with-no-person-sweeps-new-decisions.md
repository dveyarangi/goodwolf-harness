**Planning state:** authored 2026-10-26 against

landed* from history: by path, renames and archives read as new; by id, a re-parent renamed whole
subtrees; by rule, a removed rule went unseen and an old file's format stopped the listing; and the
first run faced a week of three hundred commits. The oscillation had one cause: the plan asked a
script to judge what a decision is, which is the agent's, and no decision of the question asked
it. This pass gives the script what it can tell — which files in the decisions' homes changed
between two commits, and how — and the agent the reading; and it starts the record at the
landing, so no first run has a backlog. These two choices are the plan's, not the person's: the
commits that wrote them carry the session's usual attribution, which names the person who asked
for the work, not one who decided them. A fourth validation found no block and a dozen places to
sharpen, answered below.

## Governing boundaries

Each stands on a line of the question's `Where it stands` or a decision of it.

- **The sweep crosses mechanisms** (decision 1): what changed is read from the tree at the mark
  against the tree at the commit read through, every decisions' home alike.
- **Since the last pass is one tree-wide mark** (decision 2): the commit swept through, moved only
  by the pass that closes the sweep; a failed pass leaves it where it was.
- **The instruction is `/maintain`'s**, a section for a pass with no person; the host's task is one
  line (decision 4).
- **Below the dial a pass repairs by subagents briefed with its bounds; in another running
  session's work it tells that session; at or above the dial it leaves a question asking the
  person, with its options and a recommendation** (M2; the store's `ask`; Q2).
- **A commit or a push follows the project's way of working with git** (Autonomy), never the
  skill.
- **Scripts enumerate; the agent judges** ([Responsibilities](../architecture.md#responsibilities)).

**Must verify.** This tree's marks read with and without the row; the verification set green.

**Hidden edges.**

- **The decisions' homes** are the question store (live and `done/`), the rules files —
  `local.rules.md` among them — and the entry file: where q-0037.0010.0009.0009 says decisions
  land. The architecture, ADRs and glossary hold decisions landed from a question, so the
  question's change is listed already.
- **`--landed` lists files, never decisions**: `git diff -z --name-status --find-renames` between
  the two commits over those homes — added, modified, deleted, renamed with its similarity — read
  NUL-separated, so a path in the person's own script stays whole. A rename at full similarity
  carries nothing to read and the agent passes it; an archive whose close changed the body comes as
  a deletion and an addition; a link the mover rewrote, a re-parent's new ids, each is a listed
  change the agent reads in its diff and finds carries no decision. A removed rule or rules file is
  listed as deleted or modified. Nothing is parsed, so no old format can stop it. On a day of many
  changes the agent reads each file's diff, not the file whole.
- **The working tree is never read** by `--landed`: both ends are commits, so another session's
  uncommitted draft is no landed decision.
- **No row is no sweep**: with none, `--landed` refuses and names the call that starts the record,
  and the pass starts it at the head, sweeping nothing that night — the landing does so for this
  tree, a recipient's first pass for its own. A commit the history lacks — after a rebase, a
  squash, a shallow clone — refuses too: the pass does not start over it silently, but leaves a
  question asking the person whether the gap is to be swept, and marks nothing. The check reads the
  row's form only, and runs no process.
- **The mark** resolves the commit given to its full hex and refuses a ref name, a short hash
  that is not unique, a commit that is not an ancestor of the head, or one older than the commit
  already marked; a decision committed between the listing and the mark stands past it and is
  listed next time.
- **`*` is no slug a mechanism can take**, so no declaration reserves it; a level's mark keeps the
  row by its key, as `_kept` would drop an undeclared mechanism's; the check lists it nowhere as
  undeclared; in a recipient it is the recipient's own; the writer orders it after every mechanism.
  `*` takes no other level, and no mechanism takes `decisions`.
- **Its outcome** is one of the three: *amended* where it brought a text to a landed decision —
  the sweep's usual repair — *repaired* where it brought a thing to its record, *nothing to change*
  where it only left questions asking or found nothing.
- **A question it leaves asking** carries in its body the decision, the text that contradicts it
  with its place, the options and a recommendation; it is the open question that holds the matter
  already, else one opened under the lowest question that contains it — with no person to ask
  where, never left uncharted. In another running session's work, the pass tells that session and
  writes nothing there.
- **A file holding another session's uncommitted change** is that session's work: the pass tells it
  and commits nothing of that file. When that file is the marks themselves, the pass cannot mark,
  says so, and leaves the sweep for the next — which sweeps it again, safely.
- **A refused commit or push**: a commit the project's hooks refuse leaves the pass's repairs
  undone — it discards them, leaves each as a question asking the person, and marks nothing; a
  refused push leaves the sweep unmarked, its commits standing for the next push.

**Leave alone.** Dueness and the mechanisms' levels; the store; `/recall`; `mechanisms.py`.

## Stages

Each stage ends green; the tests run, a script changing.

1. **The row and the listing, red first** in `test_maintain.py`; the tests of `--landed` and
   `--mark '*'` marked as spawning a process, the check's run with processes refused:
   - `--mark '*' decisions amended <commit>` writes its full hex; a ref name, an ambiguous short
     hash, a commit off the head's history, one older than the commit marked, `*` at a level, a
     mechanism at `decisions`, and `--mark '*'` with no commit, refuse; a level's
     mark keeps the row, after the mechanisms; the check passes on it with no process run, lists it
     nowhere as undeclared, and passes in a recipient; a malformed row fails it;
   - with no row, and with a row whose commit the history lacks, `--landed` refuses and names the
     call that starts the record;
   - after commits that change an entry, archive one through the store, re-parent one, rename one
     whose words are in Cyrillic, change and delete a rule's text, delete a rules file, change the
     entry file, and edit a ticket — and with an uncommitted change in another entry — `--landed`
     lists each changed file in the homes with its kind and, for a rename, its similarity, the
     Cyrillic path whole, the ticket and the uncommitted change not, naming the commit it read
     through — an archive as a rename or as a deletion and an addition, either read;
   - `--landed` writes nothing, and twice without a mark lists the same.

   Then `maintain.py`.
2. **The section, tried before it lands**: a git clone in the scratchpad of the commit carrying
   stage 1, its `origin` replaced by a bare remote of its own and its committed session rows
   removed by a commit there, so nothing it does reaches this tree, its upstream or a running
   session; its record started by a mark at that commit; then two decisions committed, one
   contradicting a sentence of a mechanism's doc — below both dials — and one contradicting a
   rule's text — at the self-improvement dial. A subagent with none of this session, told it is
   the scheduled pass, taking its wake by the call a host with no hook leaves it to, and given the
   proposed section beside the clone's `/maintain`, runs the pass there, doing itself what G1 gives
   subagents where it cannot start one. A judge who did not build it reads the clone after: the
   doc's sentence amended, the rule left as a question asking the person whose body names the
   contradiction, the options and a recommendation, the mark at the commit read through, nothing
   pushed but to the clone's remote. A second run in a fresh copy, its commit refused by a hook
   planted for the trial, leaves the sweep unmarked and its repairs asked of the person. Then the
   section, the description, the marks format, the doc and the decisions' homes land;
   `mechanisms.py --check` green; this tree's record started by a mark at the landing commit.
3. **The host's task**, shown to the person and cut to one line on their word.
4. **Read live**: the next scheduled run, its session left to finish; its commits, the questions it
   left asking and the next session's wake read by a judge who built none of it.
