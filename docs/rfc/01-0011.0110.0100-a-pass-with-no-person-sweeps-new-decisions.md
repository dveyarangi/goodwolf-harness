## Governing boundaries

Each stands on a line of the question's `Where it stands` or a decision of it.

- **The sweep crosses mechanisms** (decision 1): what landed is read from the whole history since
  the mark, not from any mechanism's dueness.
- **Since the last pass is one tree-wide mark** (decision 2): the commit the decisions were last
  swept to, moved only by the pass that closes the sweep; a failed pass leaves it where it was.
- **The instruction is `/maintain`'s**, a section for a pass with no person; the host's task is one
  line (decision 4).
- **Below the dial a pass repairs by subagents; in another running session's work it tells that
  session; at or above the dial it leaves a question asking the person** (M2; the store's `ask`).
- **What a script can tell, a script tells** (decision 3 of the question, its form superseded, its
  ground standing): the listing of what landed is the script's; whether a text contradicts it is
  the agent's.

## Impact

**Must change.**

- `.agents/scripts/gw/maintain.py`: the marks' tree-wide row, `tree` at the level `decisions`,
  whose fingerprint cell holds the commit swept to; `--mark tree decisions <outcome>` writing the
  current commit; `--landed`, listing what landed since that commit.
- `.agents/scripts/gw/test/test_maintain.py`: the cases below.
- `.agents/skills/maintain/MARKS-FORMAT.md`: the tree-wide row.
- `.agents/skills/maintain/SKILL.md`: a section, *A pass with no person*.
- `.agents/mechanisms/maintain/maintain.md`: the record's tree-wide row; the moment of a pass with
  no person; its authority.
- The host's scheduled task, outside the tree: cut to one line — shown to the person before it is
  written.

**Must verify.** This tree's marks read with and without the tree-wide row; `--landed` on this
tree lists the day's decisions; the verification set green.

**Hidden edges.**

- **`tree` is no declared mechanism**, and a mark drops the rows of undeclared mechanisms
  (`_kept`); the tree-wide row is kept by name. `tree` is refused as a mechanism's slug.
- **Its fingerprint is a commit, forty hex**, where a level's is sixty-four; the reader takes forty
  for this row alone, and a commit the history does not hold is a diagnostic.
- **A lost row is safe**: the marks are rewritten whole, and a concurrent mark may drop the row;
  the next pass then sweeps from the earlier commit or, with no row, as below. Sweeping more never
  misses a decision.
- **With no row**, `--landed` lists the last seven days, the window the session rows already
  keep, and says so; the first pass's mark starts the record.
- **What landed** is read from `git diff <commit> HEAD` over the store, the rules files and the
  entry file: an entry whose `## Decisions` gained an item, one closed, a rules file or the entry
  file changed — each by its path and what changed, never the model's reading of it. A commit's
  subject is never read: it is the project's convention.
- **The mark is written after the sweep's own repairs are committed**, so the next listing starts
  past them; the mark's own commit is listed next time and is nothing to sweep.
- **A wait it leaves** goes to the open question that already holds it, else one opened under the
  question whose decision it contradicts; `ask` on it. Two passes find one drift twice: the second
  finds the question asking already and writes nothing.

**Leave alone.** Dueness and the mechanisms' levels; the store; `/recall`.

## Stages

Each stage ends green; the tests run, a script changing.

1. **The tree-wide row and the listing, red first** in `test_maintain.py`, on a fixture repository
   with commits:
   - `--mark tree decisions repaired` writes the current commit, and a level's mark keeps the row;
   - a row whose commit the history lacks fails the check; `tree` at another level, too;
   - `--landed` after a commit that adds a decision item to an entry, one that closes another, and
     one that changes a rules file lists all three by path, and nothing else; after the mark, none;
   - with no row, `--landed` lists the last seven days and says so.

   Then `maintain.py`.
2. **The instructions**: the marks format, the section of `/maintain`, the doc's record, moment
   and authority; `mechanisms.py --check` green.
3. **The host's task**, shown to the person and cut to one line on their word.
4. **Read live**: the scheduled task run now, its session left to finish; its commits, the waits it
   left and the next session's wake read by a judge who built none of it: did it find what
   contradicts the decisions landed since its mark, repair what it could, ask the rest.
