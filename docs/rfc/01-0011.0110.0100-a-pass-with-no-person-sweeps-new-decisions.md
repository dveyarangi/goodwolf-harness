## Governing boundaries

Each stands on a line of the question's `Where it stands` or a decision of it.

- **The sweep crosses mechanisms** (decision 1): what landed is read from the tree as it stood at
  the mark against the tree now, not from any mechanism's dueness.
- **Since the last pass is one tree-wide mark** (decision 2): the commit the decisions were last
  swept through, moved only by the pass that closes the sweep; a failed pass leaves it where it
  was.
- **The instruction is `/maintain`'s**, a section for a pass with no person; the host's task is one
  line (decision 4).
- **Below the dial a pass repairs by subagents briefed with its bounds; in another running
  session's work it tells that session; at or above the dial it leaves a question asking the
  person** (M2; the store's `ask`).
- **A push follows the project's way of working with git** (the entry file's Autonomy), never the
  skill.
- **What a script can tell, a script tells**: the listing of what landed is the script's; whether a
  text contradicts it is the agent's.

## Impact

**Must change.**

- `.agents/scripts/gw/maintain.py`: the marks' tree-wide row, keyed `*` at the level `decisions`,

- `.agents/skills/maintain/MARKS-FORMAT.md`: the tree-wide row.
- `.agents/skills/maintain/SKILL.md`: its description names the pass with no person; a section, *A
  pass with no person*.
- `.agents/mechanisms/maintain/maintain.md`: the record's row; the moment; the authority; a row in
  *Relies on* for the store's reading of an entry's decisions.
- The host's scheduled task, outside the tree: cut to one line — shown to the person before it is
  written.

**Must verify.** This tree's marks read with and without the row; `--landed` on this tree lists
the day's decisions and no archived or renamed question as new; the verification set green.

**Hidden edges.**

- **What landed is read by question, never by path.** The mover rewrites the links inside a moved
  entry and in every entry citing it, and an archive, a re-parent or a reword moves files; git's
  rename detection misses some of them here. So the listing reads the store as it stood at the
  mark — each entry by `git show <commit>:<path>` — and the store now, and matches entries by id,
  their decision items compared after the store's own reading (`_decisions`, `ARROW`), each link
  reduced to its text and the `→` that lands it dropped:
  - an entry with a decision item added or changed;
  - an entry closed since the mark;
  - in a rules file — `local.rules.md` among them — each rule added or changed, by id and text;
  - in the entry file, its authored text changed, installed blocks left out;
  - the architecture, an ADR or the glossary changed.

  A commit's subject is never read: it is the project's convention.
- **The mark writes the commit the listing read through**, resolved to its full forty hex; a ref
  such as `HEAD`, a short hash, or a commit that is not an ancestor of the head refuses. A decision
  committed between the listing and the mark stands past that commit and is listed next time; the
  pass's own repairs too, found then already agreeing.
- **The row's form is the check's, its history `--landed`'s.** `--check` and a level's mark read
  the row as any row — `*`, `decisions`, forty hex, a date, an outcome — and run no process; a
  malformed row is a diagnostic as any other. Only `--landed` runs git: a commit the history lacks
  — after a rebase, a squash, a shallow clone — is listed from the row's date and says so; with no
  row, the last seven days, a reversible choice of this plan, named to the person. `--mark *`
  writes over either.
- **`*` is no slug a mechanism can take**, so no declaration reserves it; a level's mark keeps the
  row by its key, as `_kept` would drop an undeclared mechanism's; the check lists it nowhere as
  undeclared; in a recipient, whose clock holds none of core's mechanisms, it is the recipient's
  own; the writer orders it after every mechanism.
- **Its outcome** is one of the three: *repaired* where it repaired, *amended* where it brought a
  record to a landed decision, *nothing to change* where it only left questions asking.
- **A wait it leaves** goes to the open question that already holds it, else opened under the
  lowest question that contains it, as Q1 places a new one — with no person to ask where, never left
  uncharted; `ask` on it. A second pass finding it writes nothing.
- **A pass commits only what it changed**, staged by name: in a shared tree a file may carry
  another session's uncommitted hunks, and those are that session's work.

**Leave alone.** Dueness and the mechanisms' levels; the store; `/recall`; `mechanisms.py`.

## Stages

Each stage ends green; the tests run, a script changing.

1. **The row and the listing, red first** in `test_maintain.py`, on a fixture repository with
   commits, each test marked as one that spawns a process:
   - `--mark '*' decisions repaired <commit>` writes the commit's forty hex; `HEAD`, a short hash
     and a commit off the head's history refuse; a level's mark keeps the row, after the
     mechanisms; the check does not list it as undeclared, runs no process, and passes in a
     recipient;
   - a malformed row fails the check; a well-formed row whose commit the history lacks passes it,
     and `--landed` lists from its date and says so; with no row, seven days, said;
   - after commits that add a decision to an entry, change one, only land one with `→`, close an
     entry, archive a closed subtree and reword an entry through the store's own calls — the mover
     rewriting their links — change a rule in a rules file and in `local.rules.md`, change the
     entry file's authored text, reinstall a block in it, and edit a ticket: `--landed` lists the
     added, the changed, the closed, the two rules by id and the entry file's change, and nothing
     else, naming the commit it read through;
   - `--landed` writes nothing, and twice without a mark lists the same;
   - a decision committed after `--landed` and before the mark is listed by the next.

   Then `maintain.py`.
2. **The section, tried before it lands**: a git clone in the scratchpad of the commit carrying
   stage 1, given a bare remote of its own and no running session rows, so nothing it does reaches
   this tree or its upstream; in it, a decision committed that contradicts a text in another
   mechanism below the dial, and one at or above it. A subagent with none of this session, told it
   is the scheduled pass and given the proposed section beside the clone's `/maintain`, runs the
   pass there. A judge who did not build it reads the clone after: the first text repaired, the
   second left as a question asking the person, the mark at the commit read through, nothing
   pushed but to the clone's own remote. Then the section, the description, the marks format, the
   doc land; `mechanisms.py --check` green.
3. **The host's task**, shown to the person and cut to one line on their word.
4. **Read live**: the scheduled task run now on this tree — the night's run stood in for by a run
   on demand — its session left to finish; its commits, the questions it left asking and the next
   session's wake read by a judge who built none of it.
