## Governing choices

The [accepted design](../questions/q-0037.0012.0009-how-is-an-amendment-to-an-instruction-tested-before-it-lands-against-which-cases-chosen.md#where-it-stands), accepted 2026-10-21, supplies the chain: capture the situation where a failure is noticed; link it from the register; prepare an amendment's test later. Its Cases paragraph supplies the message, necessary context, loaded instructions, expected behaviour and relation to the failure. Its Runs and Judging paragraphs keep expected answers and condition labels away from executors. The [ownership decision](../questions/q-0037.0012-how-does-the-harness-amend-its-own-rules-by-stated-meta-rules.md#decisions), the user, 2026-10-25, assigns this work to mechanism-shape.

The original failed response is evidence of what happened. A fresh standing-condition response is a separate observation and can pass. Neither a synthetic fixture nor a stored response alone proves live reproduction. A captured failure may also need tools or state the current text-only experiment cannot replay; capturing it does not establish executability.

## Scope and flow

One new standard-library script, `capture.py`, freezes a supplied failure draft into `docs/cases/<slug>/failure.json`. It records the original message; ordered, role-labelled context; loaded instruction snapshots with paths and actual contents; the observed result; expected behaviour and rules in play; the observing session and register link; and explicit reconstruction labels. The script adds its capture time, format marker and content digest. It validates before creating the destination, refuses overwriting an existing record and offers a read-only format check of live captures. It neither reads guessed instruction paths nor claims that supplied text was loaded merely because that path exists now. Contents supplied from the session, including uncommitted text, are preserved.

The format is owned beside the mechanism skill. A capture is historical evidence, not an unfinished executable experiment. No amended instruction, calibration specimen, host prompt or verdict is invented at capture time. A separately prepared experiment can point to the capture and its digest in provenance and use the existing `amendment.py`; the existing executor receives only its selected instructions and continuation. Passing a capture directly to that runner is refused with a clear preparation error.

The instruction reaches the detection moment through the entry file and the mechanism skill. The latter owns the capture act and command; its description names that occasion. The entry rule is authored in mechanism-shape's rules file. The installer allows one block per owner in a target, so its existing AGENTS anchor moves from Project-local to Self-improvement. Existing R7 moves with that block unchanged. Retract under the old anchor, amend the source, then reinstall under the new anchor; no installed block is hand-edited. The three existing self-improvement paragraphs and the autonomy ladder retain their authored homes and meanings; their wider migration belongs to other work.

A format-check rule reaches maintain and verify through the same source. The declaration names the act, script, tests, format and records. Core names the record directory and register, never an individual project case. No Stop hook, transcript scanner, case selector, model adapter or mandatory amendment gate is added.

## Hidden edges

At detection time the remedy and calibration may not exist. They are absent from the capture, not plausible placeholders. A digest validates the saved bytes, not the truth of the writer's account; an independent reader still assesses that account. Snapshotting current disk after an edit cannot establish what was loaded before that edit. Explicit reconstruction labels prevent that substitution from being reported as exact evidence.

One owner cannot be installed twice in AGENTS; changing the installer for this slice would add unnecessary general machinery. Moving its one block is the bounded alternative. No dial value changes. The new capture rule is the feature the user authorised; other rules keep their meaning.

The live criterion requires the next genuinely noticed failure, a contemporaneous capture and an actual standing-condition run. An artificial trial can establish the capture act's behaviour but does not satisfy that criterion. If no genuine failure is encountered, the green implementation stage is committed with that acceptance box open; the ticket is not archived or called complete.

## Leave alone

Earlier experiment artifacts and their hashes; other sessions' work; the broad failure taxonomy; case selection and standing-result reuse; automatic amendment gating; the self-improvement ladder and rules migration outside the new capture requirement.

## Recommendation

Proceed with one capture record and the existing experimental boundary. A single cold reader acting from the installed instructions in a disposable fixture can falsify the capture behaviour before a production failure is claimed. No second runner or general event recorder is needed.

## Stages and verification

1. A public capture test proves preservation without an amendment or model call, red then green. Add independently falsifiable checks for missing snapshots, ordered roles, reconstruction labels, corruption, overwrite refusal and live-record scanning. No mocked reader stands for preservation of actual file contents.
2. Install the narrow capture/check rules through their owner; register the new parts and outputs. A test proves that an observation-only capture cannot enter the experiment path.
3. A fresh independent reader receives the installed entry and a clearly synthetic scenario, with no instruction to capture beyond what a normal session would read. Preserve its artifact and evaluate it against the input. This is an instruction trial, not a production failure.
4. Independently review the code, record format, installed instruction and actual evidence. Run the whole project verification set and capture check. Commit the green stage; close only when the genuinely observed standing-failure criterion also holds.
