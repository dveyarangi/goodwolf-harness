## The shape

**One writer.** The session script's row functions — register, arrive, tend, seen, end, hold,
take, release, the reading of the rows — run inside the coordinator, as every call does under
.0030, and work over the `sessions` table of `gw.sqlite`. So the database has one writer and its
calls come one at a time; the plain rollback journal serves, with no `-wal` or `-shm` file beside
it. The only other opener is a session's own script drawing its window while the coordinator does
not answer (decision 10): it reads, and never writes.

**Where the file is.** Found in Python, with no process: the tree's `.git` read — a directory, or a
file naming one — and its `commondir`; `gw.sqlite` sits in the common directory beside
`gw-interpreter`. A tree with no `.git` keeps it at `<tree>/.gw.sqlite`. Tests set the path through
the session script's seam, as `WINDOW_MEMORY` sets the window memory's today. The function that
opens it lives in the session script and carries `TODO q-0037.0006.0024.0003`, whose cut may move
it; another owner's table opens it the same way.

**The table.** One row per session: the row's fields as columns — tag, running or ended, the time
it last wrote, the position, up to four recent, the unit held, the unit taken and by whom — and
`seen`, the sign of life. A held and a taken unit never stand together, held by the table. A
`meta` table keeps the schema's version and the mark that the old rows were carried in. A script
meeting a version it does not know says so in one line and writes nothing — worktrees on older
branches run older code against one shared file. `ROW_FORM` stays the form a row is shown in;
`sessions.py --rows` prints every row in it. A diagnostic names a row as `gw.sqlite: sessions/<tag>`.
The names `meta` and `<tree>/.gw.sqlite` wait on the person's word. The version guard matters only
if a branch's code can serve the shared file — which .0030 settles.

**Writes by field.** Each write changes the fields it means and no other: `seen` writes `seen`;
`at` the position and the recent ones; `tend` ends a row with one update conditioned on its
`seen` being older than the limit, so a session that spoke meanwhile is not ended; `hold` checks
and writes in one transaction, as `take`, which moves a unit and marks the holder, does; a rename
rewrites the ids in the fields that name them.

**The sign of life.** `seen()` writes the row's `seen`, `last_seen()` reads it. The window memory's
fingerprint and counted memory stay files in the temp folder, `sessions.memory()` naming them; only
their time stops meaning anything to another session.

**Renames.** The question script's rename calls the session script to rewrite the ids the rows
name; `sessions.records()`, which listed row files for it, retires.

**The checks.** Rows are no longer in any commit, so no check of a commit reads them. The store's
check stops calling `sessions.check`, and `read_store` stops loading rows — the window and the wake
load them; `sessions` leaves the pre-push checks. `sessions.py --check` checks the table through
the coordinator: a row against its form, a position naming no entry as a finding; it stays
`/maintain`'s to run (S3's first half), and a bad row is repaired by `--end` or the session's next
`at`. A rows' folder found in a tree after the carry-over is a finding naming the `git rm` that
removes it.

**Carried in once.** From a write, never a read: the first write the coordinator makes to a
database whose `meta` holds no carried mark reads every row from the old places —
`docs/sessions/rows/`, and the older `docs/questions/sessions.d/` and `docs/questions/sessions` —
into the table, a tag already there left as it is, then writes the mark; it deletes nothing. An
older branch's checkout that still holds the folder brings nothing back. The files leave git by a
commit: in this tree, the implementing one; in a recipient, the folder's finding names the
`git rm`, and `/maintain`'s pass, which runs the rows' check, makes that commit. The update writes
no row — one carry-over, the coordinator's.

**Retired.** S3's second half — the maintain pass committing rows another wake changed — from
`session.rules.md`, reinstalled out of `/maintain`. The painted door for `docs/sessions/rows/`
stays among a store from before's, since the carry-over and the finding still name it.

## Stages

Built in a worktree of its own — the shared checkout's hooks run its working scripts on every
message — once .0020 and .0030 have landed. Each stage keeps the store's, the session's and the
harness's tests green.

1. **The table.** The file found, opened, versioned; the row functions over the table, by field;
   `--rows`; tests through the script, not files: each test that read a row file fails first for
   the reason it names. A take all or nothing; a `tend` that does not end a session which spoke
   meanwhile; a coordinator killed mid-write leaving the table as before the write.
2. **The sign of life.** `seen` and `last_seen` over the row; a session silent past the limit is
   ended by a wake from the main checkout or a worktree, one that keeps talking is not.
3. **Renames and checks.** The rename through the session script; `records()` retired; the store's
   check and `read_store` without rows; `sessions` out of the pre-push checks; the rows' check over
   the table and the folder's finding.
4. **Carried in.** The carry-over at the first write, once; a test with rows in each old place and
   an older checkout's folder bringing none back; the folder's finding after it. This tree's
   folder deleted in the stage's commit. The worktree's branch merges only after this stage, so
   the shared checkout never reads a table the old rows were not carried into.
5. **Said.** The architecture first, then the docs; S3's second half retired and reinstalled; the
   skills' text, shown to the person.

## Impact

**Must change:** `sessions.py`; `questions.py` (the check, `read_store`, the rename, the interrupted
write); `harness.py` (the pre-push checks); `session.rules.md`;
`session.md`; `docs/architecture.md`; `docs/edge/hosts.md`; `/conclude`, `/questions`, `/maintain`
through the installer; `test_sessions`, `test_questions`, `test_harness`.
**Must verify:** the window drawn and its one unchanged line as before; the wake's read; holds and
takes; `--end`; a recipient's update; the questions' 249 tests, the sessions' 128.
**Hidden edges:** `session.rules.md` stands changed and uncommitted by another session — its own
rule edited, committed by path. SQLite wants a local disk; a clone on a network share is not
promised. Every connection is closed after its call, or Windows will not remove a test's folder. A fresh clone has no database, as the
rows are meant to be; the session records stay in `docs/sessions/`.
**Leave alone:** the window memory's cache; the session record `/conclude` writes; the row's fields
and lifetimes; the store; messages between sessions; a question's counters,
[q-0037.0001.0026](../questions/q-0037.0001.0026-do-a-question-strike-count-and-last-time-stay-in-its-file.md).
