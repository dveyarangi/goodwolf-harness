## No code

No script changes. Placing a message is the agent's act; the script still parses the same
declared line. A closed entry is repointed by declaring `closes` on it again. The writer replaces
the state and answer, and keeps a suspect flag (`questions.py` `_closes`, read while planning). A
`decided` answer's link is checked down to its anchor, so the repointing comes after the section
it points to exists. No test pins Q1's text or the contract version (searched while planning). No
stage needs `/tdd`, and the suite stays green throughout.

**2. The skill and the doc.**

- [The questions skill](../../.agents/skills/questions/SKILL.md): the section *Placing a message
  that answers nothing near* becomes **A raised question**, holding the whole flow in four short
  paragraphs:
  1. **Look it up first** (46): what *the docs* cover — the architecture, ADRs, the glossary, the
     mechanism docs, the code, and the decisions landed in live tickets, where a decision sits
     until it reaches its home. Found: point to it and open nothing; a settled question is not
     reopened without new evidence against its answer. No search of `done/` is needed, since a
     decided entry links to what holds its answer (43).
  2. **Who settles what is not found** (51): the agent settles a decision that is not load-bearing
     in the turn and reports it, as `repair=report` does. A load-bearing decision is the person's:
     settled in the turn, it goes to its home; unsettled, it is opened. When unsure whether a
     decision is load-bearing, treat it as load-bearing.
  3. **A request** (52): *build X* is a proposed answer. It leans on the question X answers — *what
     is X for?* — or opens that question when none is held. *How to build X?* opens under it once
     X is accepted, and the ticket's plan answers it. A trivial request is settled by doing it.
  4. **Where to open it**: the existing placement text, led by the newcomer test that leaves Q1.

  Nothing links to the old heading's anchor (searched while planning). The skill's description is
  unchanged: it already sends the agent to the skill for a declared line's other forms.
- [The mechanism doc](../../.agents/mechanisms/questions/questions.md), *How it works*:
  - A **Rights** paragraph (49): an agent's rights over the store come from the role it starts
    with, which also grants its permissions and its skill set. The harness has one role, the HITL
    session, driven by a person and holding every right, so the store checks none. What a role is,
    and which mechanism keeps roles, is an open question. Core may not name the entry for that
    question, since a particular record in `docs/` is the instance's.
  - The **Three levels** paragraph (48) gains: whether a question is load-bearing, or hides parts,
    is the judge's to judge, since the agent fails at both; without a judge, the instruction stands
    where the agent reads it, and the agent tries.
