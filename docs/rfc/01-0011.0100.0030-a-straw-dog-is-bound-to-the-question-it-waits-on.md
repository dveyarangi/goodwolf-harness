# A straw dog is bound to the question it waits on — implementation plan

**Authored:** 2026-10-04
**Last amended:** 2026-10-04

Implements [01-0011.0100.0030 a-straw-dog-is-bound-to-the-question-it-waits-on](../tickets/01-0011.0100.0030-a-straw-dog-is-bound-to-the-question-it-waits-on.md).

## What governs it

- The ticket's decisions 1 to 9: a straw dog is provisional text bound to a question, never a
  question itself; it binds to the question whose answer will rewrite its text and carries no
  `until`; it is due when that question is closed and its `answer` links to a file other than
  its `owner`'s; the binding is `question="q-N"`, rewritten by every rename; the rebinding is
  reviewed by family in this RFC; the question needs no owner; a narrow `until` becomes its own
  question; a `not yet` row's reason is its question's words; a question closed against a
  decision that has not landed is first assigned to the record holding it.
- Parent decisions 30 (the store is core's own record; the ticket method is swappable), 38 as
  amended by decision 1, 43 (a closed question links to its answer) and 50 (a closure follows
  its decision home, and is repointed when the decision lands).
- The entry file's *Core and instance*: core names a record of `docs/` only where a mechanism
  declares it, and today a ticket only in a straw dog's binding — which decision 4 turns into a
  question, and no ticket anywhere.
- [The architecture's *Straw dogs*](../architecture.md#straw-dogs), landed at this plan: a straw
  dog binds to a question, never a ticket; dueness is derived from the store; a rename carries
  every binding.
- `.0018`'s rename: ids nest, a re-parent renames a subtree, `_rewrite_ids` carries the renames
  through `docs/` only (`questions.py`, `_rewrite_ids`).

## Shapes

- **The binding syntax lives in `docs_corpus.py`**, as it does today: the `question` attribute,
  the TODO's `q-N`, and the retargeting function, which turns from re-aiming a ticket path on a
  move into re-aiming an id on a rename. At the end `_BINDING` and
  `with_owner_bindings_retargeted` are rewritten, not kept beside: the ticket forms live beside the
  question forms through stages 1 and 2 only, while the tree still holds them, and leave at
  stage 3. Only operative bindings are re-aimed — outside fences and code spans, as the listing
  reads them — so an example of the syntax in prose keeps its id.
- **Dueness is the store's**: one predicate in `questions.py`, read per closure kind, every entry
  live and archived, since a decided question is usually already in `done/`:
  - `decided` — due when no link of its `answer` cites the file its `owner` cites, both
    resolved from the entry's own file as `_resolves` does, so an archived entry reads the same;
    with no owner (decision 6), any cited answer is elsewhere — which is why a question closed
    against a decision that has not landed is first assigned to the record holding it (decision 9);
  - `moot`, `pruned` — due: the question no longer stands, so the text that waited on it is
    re-read;
  - `merged`, `superseded` — never due: the binding follows the successor, and the listing
    reports it as *rebind to q-N*, the successor read from the `answer` and followed to the end
    of a chain;
  - `deferred` — never due: its `answer` is a condition, not a home;
  - open or suspect — never due.
- **Who imports whom**: `questions.py` imports `move_doc` and `docs_corpus`, as now;
  `straw_dogs.py` and `mechanisms.py` import `questions.py` for the store and the predicate, as
  `tickets.py` already does. `harness.py` reaches it through both, and nothing `questions.py`
  imports reaches back. No cycle.
- **The wake**: a section after *deferred*, `straw dogs due:`, one line per straw dog —
  `<path>:<line> → <the question's window line>`. It reads bindings through `docs_corpus`, over
  the same scope `/maintain` lists: `docs`, `AGENTS.md`, `local.rules.md`, `.agents`,
  `README.md`. A path of that scope the tree lacks is skipped, never refused — a recipient may
  hold no `local.rules.md` — since a host's hook never fails the host
  ([architecture](../architecture.md), *the questions mechanism*); the listing, which a person
  runs over a scope they declared, keeps refusing a path that names nothing.
- **The rename** rewrites, beside the bare ids under `docs/` it rewrites today, every binding in
  that scope — the `question=` attribute in a document, the `q-N` on a TODO line in code — and
  nothing else in core: a prose id in core is not a binding, and core names no other record.

## Settled at `/align` during this plan

The ticket's decisions 7 and 8, the user's, 2026-10-04: a narrow `until` becomes its own
question, an existing entry only where it is the same question and never a broader one; a
`not yet` row's reason is the words of the question it waits on, read from the store, and a

Settled here and reported, not load-bearing:

- A `# TODO q-N` loses its `q-N` at ship, as a ticket path does today: a recipient's store does
  not hold this tree's ids.
- A `not yet` bound to a due question is a diagnostic of `mechanisms.py --check`, as a `not yet`
  bound to an archived ticket is today — the rule *never the ticket declaring the mechanism*
  needs no successor: that row comes due when the declaration lands.
- The two straw dogs that stand in an archived ticket (`done/01-0011.0060`) are operative and
  rebound like any other.

## Stages

Each keeps the verification set green except where noted.

1. **The predicate, the reader and the rename.** In `docs_corpus.py`, the `question` attribute
   and the TODO's `q-N` are parsed beside the old attributes, and the retargeting function
   re-aims ids. In `questions.py`, the dueness predicate, and `_rewrite_ids` rewriting bindings
   across the scope. Tests: an entry closed against a decision in its owner's file is not due,
   one repointed elsewhere is, an archived one reads the same, an open or suspect one is never
   due; a re-parent rewrites a binding in `.agents/`, `AGENTS.md` and a `.py` TODO, and leaves a
   prose id in core and an id in a fenced block as written. No record changes.
2. **The listing and the wake.** `straw_dogs.py` reads `question`, reports `due`, and diagnoses
   *unbound*, *unknown question*, *old binding*, and *rebind to q-N* for a binding to a merged or
   superseded question; `--guess` treats a TODO naming `q-N` as
   bound. The wake's `straw dogs due:` section. Tests per diagnostic, each failing for its own
   reason; the wake listing exactly the due ones. *The listing reports 102 old bindings until
   stage 3 — it is `/maintain`'s, not in the verification set.*
3. **The rebinding.** The tables below, as accepted: the 29 new entries — N1 to N9, the 18
   S-*x*, S-glossary and S-practice — opened by `questions.py open` under their parents,
   each straw dog's tag rewritten to `question="q-N"`, each TODO to `# TODO q-N:`, by hand with
   the edit tools, file by file. In the same stage the old form leaves the code:
   `mechanisms.py` reads the question (decision above), `harness.py` shears a TODO's `q-N`,
   `move_doc.py` stops re-aiming bindings, `docs_corpus.py` drops `until`, `ticket` and the TODO
   excusal, `straw_dogs.py` keeps *old binding* as the diagnostic a recipient's update meets.
   The tests that build a straw dog as a fixture move to the new syntax; those that assert the
   old behaviour are inverted or removed, each named in the commit. A reconciliation, run once
   and kept in the stage's report: every place before maps to its table row and every place after
   to one row, the questions are the table's, and the only differences are the ones the tables
   name — `mechanisms.py:71` split into seven, `questions.md:86` removed — so 102 before is 107
   after.
4. **The texts.** The entry file's *Straw dogs* — `<straw-dog question="q-N">`, *find the
   question, or open one* — and *Core and instance*, whose clause names a particular record, so
   an id in a core example stays an example: core names a particular record of this tree only in
   a straw dog's binding, and that record is a question. The contract moves to v25 once, with its
   findings line, covering stage 3's rebound tags in the entry file too;
   the method glossary's *Straw dog*, and its *Due*, which gains the straw dog's sense — derived at
   every look, as a mechanism's is; Q2, so the wake's report names the due straw dogs beside the
   deferrals, reinstalled into `/recall`; `MECHANISM-FORMAT.md`'s `not yet` section and the
   *Mechanism: not yet* line; R5 and R6 in the shape's rules file, reinstalled; P7 in the ticket
  mechanism's rules file and the questions skill's closing section, both carrying decision 9, P7
