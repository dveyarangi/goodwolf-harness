# A mechanism is re-checked when what governs it moves — implementation plan

**Authored:** 2026-09-27
**Last amended:** 2026-09-27

Implements [01-0011.0060 mechanism-rechecked-when-governing-moves](../tickets/01-0011.0060-mechanism-rechecked-when-governing-moves.md).

## What this builds

`/maintain` learns which mechanisms are due for a re-check from a script, instead of from whatever
scope the pass happened to declare. Every decision below is the ticket's *Decided at the align*
and its `/plan` additions, 2026-09-27; this RFC cites them and adds only shape.

| level | what is due | when, since its mark |
|---|---|---|
| `rules` | every mechanism's doc | the meta-rules moved |
| `output` | a mechanism's records | its own doc, rules file or skill directory moved |

A mechanism is maintained only when `/maintain` writes its row; no edit counts. Records churning
is not a trigger here — handed to [01-0017 io-graph-coherent](../tickets/01-0017-io-graph-coherent.md).
Announcing the due list unasked is not built here — handed to
[01-0010.0120 host-delivery-surfaces](../tickets/01-0010.0120-host-delivery-surfaces.md).

## Shape

### The script — `.agents/scripts/gw/maintain.py`, owned by the maintain mechanism

Names approved by the user at `/plan`. Standard library only
([ADR-0004](../adr/0004-scripts-run-on-the-standard-library-alone.md)); starts no process.

- **`maintain.py --check`** reads every declaration and the marks, and reports each declared
  mechanism at each level as **due**, with why — *meta-rules moved*, or *its doc, rules file or
  skill moved* — **current**, or **never maintained**. It also reports a malformed row, and a
  surface it cannot fingerprint. **Exit 1 only for a malformed row or an unfingerprintable
  surface; a due mechanism never fails it.** It writes nothing, so a conforming marks file is left
  byte-identical. A row for a mechanism no longer declared is reported and does not fail.
- **`maintain.py --mark <mechanism> <level> <outcome>`** fingerprints that level's surface as it
  stands, and writes or replaces that one row with today's date. It refuses, writing nothing, a
  mechanism not declared, a level other than `rules` or `output`, and an outcome other than
  `amended` or `nothing to change`. The same write drops rows of mechanisms no longer declared. It
  is the only writer of the marks. The file is created on first mark, its parent made on the way
  in; a fresh tree has none and reads *never maintained*. Nobody backfills.
- **No other mode**; a bare invocation prints usage and exits 2, like its siblings.
- **Never maintained counts as due** wherever the skill acts on the report: nobody backfills, so
  the first re-check is one the clock raises.
- **In a recipient**, told as the shape check tells it — `docs_corpus.announced(root)` reads an
  entry file announcing `<repository>@<ref>` — the clock covers the recipient's own mechanisms
  only *(the user, 2026-09-27, at this plan)*. A mechanism under `.agents/mechanisms/` came with
  core and is maintained where core is made: `--check` does not derive it and says so once, and
  `--mark` refuses it, writing nothing. Where a recipient's own mechanisms live is not settled, so
  its set is empty today and `--check` exits 0 over it. The origin's marks never ship: they live
  in `docs/`, which the harness never copies.

### What a level is checked against

Read from the declarations `mechanisms.py` already parses, through **one function both callers
use**: `check` reads the declarations first, and that reading is extracted as `declarations(root)`
— the name approved by the user at this plan —
which `check` then calls and `maintain.py` imports. So the clock and the shape check share one
derivation, as the ticket requires, and the clock starts no process — `check` itself also lists
the corpus through `git ls-files` for its core-cite pass, which the clock has no use for. A
mechanism directory with no doc is not a declaration; `mechanisms.py --check` reports it.

- **`rules`**, the same for every mechanism: `AGENTS.md`; the rules file of the mechanism
  `mechanism-shape`; every file in the directory of `mechanism-shape`'s instruction file.
- **`output`**, per mechanism: its doc; its rules file where it has one; every file in the
  directory of its instruction file.

A file named `EVIDENCE.md` inside a skill directory is excluded: R2 excludes evidence, and a skill
declared from an older tree may still carry one — `.agents/skills/discover/EVIDENCE.md` does
today, undeclared.

### The fingerprint

SHA-256 over the surface's files in path order, each contributing its repository-relative path
and its text **with line endings normalised to LF and every installed block retracted** — R2,
installed in `/maintain`. Retraction reuses `inject_rules.py`'s `locate` and `without_block`, the
installer's own inverse, so installing or retracting a block cannot move a fingerprint. A block
`without_block` refuses — spaced by hand — makes that surface unfingerprintable: a diagnostic,
never a guess. So is a declared file that is missing — `mechanisms.py --check` already reports the
part — a file that is not UTF-8, and a tree that declares no `mechanism-shape`, which leaves
`rules` with nothing to read.

### The marks — `docs/mechanisms/maintenance.md`

The instance's record, in `docs/`, which an update never touches. A heading, one line pointing at
the format in `/maintain`'s skill, and one table:

| mechanism | level | fingerprint | date | outcome |
|---|---|---|---|---|

One row per declared mechanism per level; `level` is `rules` or `output`; `fingerprint` is 64
lowercase hex; `date` is `YYYY-MM-DD`; `outcome` is `amended` or `nothing to change`. Rows are
written sorted by mechanism, then level, LF-terminated. **This format is written in `/maintain`'s
skill, as a *Marks* section `maintain.md` points at** — never in the doc.

### `/maintain`'s body

- **A4** keeps *Read dueness from the clock* and names the command; its straw dog is removed.
- **A due or never-maintained mechanism joins the pass, whatever scope was declared** — its doc at `rules`; its
  records at `output`, the live ones, and historical ones where a mechanical change stays in the
  tree, never records on a remote board. The ticket's purpose B; B3 is the precedent for a duty
  that overrides the declared scope.
- **Marking closes a re-check**: after re-checking a level, mark it with its outcome; mark nothing
  not re-checked (B2). F2's report names the marks written.
- **Marks** — the format above, in the skill.

Rule ids and wording are `/implement`'s; each new rule's attribution goes into `maintain.md`'s
table as the user's, 2026-09-27.

### `maintain.md`

The three straw dogs bound to this ticket go, each replaced by what is then true. *Knowing a
re-check is due* becomes instructed by the skill; *moving a mark* is a moment instructed by the
skill. Parts gain the script and its tests; relied-on gains `inject_rules.py`
(`mechanism-shape`). *What it produces* gains the marks — read by `--check` at every pass — and
`--check`'s report, read by `/maintain` and by `/verify` through the verification set. The
marks-race and the unannounced list are stated where a reader meets them. *Not yet at the shape*
loses the marks paragraph.

### Around it

- **`mechanisms.py`'s `PAINTED_DOORS`** gains `docs/mechanisms/maintenance.md`, with a `TODO` bound
  to 01-0017, like the rows beside it: core names the path in the script and the skill, and a
  hand-held door leaves when records are declared where a script reads them. The door also

- **The verification set, L3 in `local.rules.md`**, gains `maintain.py --check`; reinstalled with

- **`.agents/glossary.md`** gains *mark* — the row `/maintain` writes when it has re-checked a
  mechanism at a level, holding what was checked, the date and the outcome; no edit is one — and
  *due* — what governs a level moved since its mark, or it has none. Approved by the user at this

- **A `TODO` naming 01-0017** where the levels are defined in the script: the churn trigger is

## Stages

Each through `/tdd`, red then green, the suite green at the end of each. New tests in
`test/test_maintain.py`, in plain folders under the no-process guard: none of this is Git.

1. **Never maintained.** `declarations(root)` is extracted from `check`, the shape check's tests
   unchanged and green. `--check` over a fixture tree with declarations and no marks reports every
   mechanism at both levels as *never maintained*, in words distinct from *current*, exit 0. The
   painted door lands here, since the script names the path from this stage on;
   `mechanisms.py --check` stays clean.
2. **Mark and current.** `--mark` writes the row; `--check` then reads it *current*. Refusals —
   an undeclared mechanism, a bad level, a bad outcome — write nothing, the file byte-identical.
   A row for a mechanism no longer declared is dropped at the next mark and reported, not failed,
   by `--check`. In a fixture whose entry file announces `<repository>@<ref>`, `--check` derives
   no built-in mechanism, says why, and exits 0; `--mark` refuses a built-in one, the tree
   byte-identical.
3. **What moves a level.** Each proven against a marked fixture: editing the `/mechanism` skill,
   `mechanism-shape`'s rules file, or `AGENTS.md` outside its blocks makes every mechanism due at
   `rules` and none at `output`; editing a mechanism's doc, rules file, instruction file or a
   shelf beside it makes that mechanism alone due at `output`; editing an evidence file makes
   nothing due; flipping line endings makes nothing due; installing and retracting a block
   through `inject_rules.py` makes nothing due; editing an `EVIDENCE.md` inside a declared skill's
   directory makes nothing due. Each assertion names the reason `--check` gives.
4. **What cannot be read.** A malformed row of each kind — columns, level, fingerprint, date,
   outcome, a duplicate — is a diagnostic, exit 1, the file untouched. A hand-spaced installed
   block, a missing declared file, a non-UTF-8 file and a tree without `mechanism-shape` are each
   unfingerprintable, exit 1, and name what they could not read.
5. **The live marks stay the tree's.** The test harness's case fails any test after which this
   tree's `docs/mechanisms/maintenance.md` differs from what it was before the test — present or
   absent — so the offending test is the one named; watched failing once by pointing a test at
   the live root.
6. **The mechanism's text.** `/maintain`'s body, `maintain.md`, the glossary entries, L3 and its
   reinstall; `mechanisms.py`, `inject_rules.py` and `tickets.py --check` clean;
   `straw_dogs.py` lists no block bound to this ticket.

## After it lands

The first `--check` in this tree reports all four mechanisms *never maintained* at both levels.
That is true: nobody backfills. The close's `/maintain` is the first pass to re-check them and
write their rows.

## Limitations

- **The project's own rules are in no surface.** `local.rules.md` is read by nothing here, and
  its blocks are retracted before fingerprinting under R2; a local override changing makes
  nothing due.
- **Two branches that both mark conflict in the table.** One writer per tree is what this
  harness supports today; teams are later, after coherence.
- **A mark clears what moved between the re-check and the mark.** Stated in `maintain.md`,
  narrowed by marking in the step that closes the re-check.
