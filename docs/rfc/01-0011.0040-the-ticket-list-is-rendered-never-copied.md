## The list

`tickets.py --list` prints a markdown table to standard output, the live tickets in the order
`_live_tickets` already yields — by name, which is id order with a parent before its children,
since `-` sorts before `.`. The names come from `docs_corpus.corpus`, tracked and untracked alike,
so a ticket minted this session is listed before it is staged:

```md
| Ticket | Status | Type | Outcome | Question |
|---|---|---|---|---|
| [01-0011.0040 the-ticket-list-is-rendered-never-copied](docs/tickets/01-0011.0040-the-ticket-list-is-rendered-never-copied.md) | Ready | AFK | The ticket list is rendered, never copied | [q-0020 how-does-the-queue-stay-true-to-the-tickets-it-lists](docs/questions/q-0020-how-does-the-queue-stay-true-to-the-tickets-it-lists.md) |
```

- **Ticket** — a link to the record, its text the basename with the first `-` after the id made a
  space: id and slug.
- **Status** — the status word alone; the qualifier stays in the ticket. A value the status grammar
  does not match is printed as written: whether it is right is `--check`'s to say.
- **Type** — as written.
- **Outcome** — the ticket's title line, without its `# `.
- **Question** — the entry `Answers` links, resolved the way `_answers_problems` already resolves
  it, its text the entry's basename made id and slug the same way.
- A field the header lacks, or an `Answers` that resolves to no entry, prints `—`. The list shows
  what the header says; `--check` reports what is wrong with it.
- Links are relative to the repository root, where the script is run from and where its readers —
  an agent's reply, a terminal — resolve them.
- A `|` inside a cell is escaped, so a title cannot break its row.
- **A ticket that cannot be read is reported, not left out**: the reasons `_read` already gives a
  `Skipped` are printed under the table, one line each, naming the record and why, and the exit
  status is 1. Every readable ticket is still listed. With nothing skipped the exit status is 0.
- Usage becomes `tickets.py --check | --list`; anything else prints it and exits 2, as now.

The title is read where the header is: `Ticket` carries it, since `_read` already holds line one.
Whether `as_record` adds it to `--check`'s JSON is `/implement`'s choice; nothing reads that JSON
by field. The module docstring, which says what the script does and that its exit status is the
verdict, says what `--list` prints and what its exit status means.

the anchor the questions mechanism already installs there, and `.agents/skills/ticket/SKILL.md` at

put it after the slices are minted; step 1's end puts it before any slice is drafted. It names the occasion only: how
the queue is ordered stays q-0027's, how a task finds its ticket q-0024.0011's.

**P8 retires.** Its section leaves the rules file, wrapper and all, and `inject_rules.py ticket
--install --overwrite` re-renders `/maintain`'s block without it. A list read from live records
drops a closed ticket by construction; the rule existed only because a person kept the rows.

## Flows

- **Ordering, in `/recall`.** The queue gives the order and the candidate; reordering is put to
  the user; P12 has the session read `--list` first, so the reorder is weighed against every live
  ticket's status, type and question rather than against a copy.
- **Minting, in `/ticket`.** P12 has the session read `--list` before drafting slices, so a task
  that belongs to a live ticket is seen there. How that match is made is not this plan's.
- **Closing, in `/maintain`.** The mover moves the pair; nothing deletes a row, because no row
  exists; the next `--list` no longer shows the ticket.

## Stages

Each stage keeps the verification set green.

1. **The list, test first.** In
   [test_tickets.py](../../.agents/scripts/gw/test/test_tickets.py), on the fixture tree it already
   builds:
   - every live ticket listed in id order with the five cells, the qualifier dropped from the
     status, the question cell a link by id and slug, no `done/` ticket among the rows;
   - a title or status edited in a ticket appears in the next list with no other edit;
   - a ticket with no title line is named under the table with its reason, exit 1, and the other
     tickets still listed;
   - a field missing from a header prints `—` and does not stop the list;
   - a `|` in a title is escaped;
   - an unknown flag prints the usage and exits 2.

   Then `--list` in `tickets.py`. Each test fails first for the reason it names.
2. **The rule.** P12 in the rules file, the two targets in its table, P8 out; install with
   overwrite. `inject_rules.py --check` passes, `/maintain`'s block holds no P8, `/recall`'s and
   `/ticket`'s hold P12, and `/ticket`'s stands before `### 2.`.
3. **The copy goes.** The queue's table, the arrival state's table header, the five format sites
   and the filename sentence, the mechanism doc, process.md, product.md's row, the front page's
   example and the edge line. `mechanisms.py`,
   `tickets.py`, `maintain.py` and `straw_dogs.py` checks pass; the harness tests still find an
   arrival state.
4. **The whole set**, then `/verify`.

### Hidden edges

- **Running sessions read the old format.** A session that minted from `TICKET-FORMAT` before this
  lands may add a row to a queue that has no table. It is a hand edit to a hand-written file,
  visible in its diff; the next read of the format or of P12 stops it.
- **Recipients keep their tables.** The arrival state is written only into a tree that has none,
  so the study tree's queue keeps its table and its own `Last updated`; nothing here migrates it,
  and the user decided a recipient keeps looking at its own.
- **The file is still called *Delivery status*.** Its heading, the arrival block's fence name and
  `harness.py`'s `DELIVERY_STATUS` now name a file that holds order, not status. Renaming crosses
  the installer and every recipient; it is left, and named under *Limits*.
- **The front page's context figure is already stale.** Its *15,000 of work queue, most of it a
  history log*, a straw dog bound to q-0024.0009, predates the history's removal this morning, and
  the table's removal shrinks the queue again. The figure is measured afresh after this lands and
  the straw dog put to its question, not guessed here.
- **The list's links resolve from the repository root**, not from the queue's folder — right for a
  reply or a terminal, wrong if pasted into a record under `docs/`. Nothing pastes it.

### Leave alone

Closed tickets and session records citing the old table; the queue's ordering prose and its straw
dog bound to q-0027; the mechanism format's example row *ordering the queue*; recipients' queues.

### Recommendation

Proceed. The change removes more than it adds: one table, one rule and five copy instructions go;
one flag and one rule arrive. It is already narrow — the ordering process and the ticket-finding
process stay with their questions.
