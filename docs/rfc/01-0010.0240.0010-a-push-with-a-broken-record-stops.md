## Shapes and flow

```
git push
  └─ .git/hooks/pre-push <remote> <url>     one guarded line, written by --links
       └─ sh .agents/scripts/gw/hook.sh pre-push   (stdin: <local ref> <local sha> <remote ref> <remote sha>…)
            ├─ the carried files: every commit the push sends, a merge read against its first parent
            ├─ none under the method's roots: exit 0, no interpreter
            ├─ no interpreter recorded: a warning, exit 0
            └─ "$python" .agents/scripts/gw/harness.py . --pre-push   (the carried files handed on)
                 ├─ the eight checks, each `--check`, all started before any is read
                 └─ the verdict by the carried files: refused (exit 1) or passed, warnings printed
```

**Why the push** (decision 7): `pre-commit` runs under the shared index's lock, so every other
session's `git add` and `git commit` fail while it runs; `pre-push` holds none — tried 2026-10-29,
a `git add` beside a running `pre-push` going through. Here every commit is pushed as it lands
(L2), so a broken record still never reaches the shared main; a refused push leaves its commits in
the clone, mended by the next commit.

**What the push carries.** Git hands `pre-push` one line per ref; a line whose local sha is all
zeros, a deletion, carries nothing. The commits are `<remote sha>..<local sha>`, or, for a ref the
remote does not have, `<local sha> --not --remotes`; their files are
`git -c core.quotepath=off log --no-renames --diff-merges=first-parent --name-only --format=`, so a
path in any script is read as written and a merge's resolution is counted. The shell reads that list
for its match; `harness.py` reads the same commits with `-z`. The carried files reach the mode as
the shell hands them on — by its arguments or its standard input, the implementation's choice.

**What wakes the checks** keeps decision 1 by its reason, *a push of code pays nothing*: a push
whose carried files include one under the method's roots — `docs/`, `.agents/`, `AGENTS.md`,
`CLAUDE.md`, `local.rules.md` — runs all eight checks; one with none runs nothing. Side by side a
push costs its slowest check whatever runs (all eight 2.6 s, four 2.9 s, 2026-10-26, within noise),
and since the push holds no lock, waking a check whose files did not move costs a processor and no
session's time. A finer map was tried at the first validation and could not be made true: the
checks read past any fixed roots — `questions.py` follows a decided answer's links into any file
(`_resolves`, `is_home`), `tickets.py` its header links, `inject_rules.py` every `.md` for installed
blocks, `edges.py` the validator paths its records name. Reads outside the roots — a project's own
test file an edge record names as a validator — are CI's to catch (decision 1). The roots stand in
`hook.sh` with a `TODO q-0037.0006.0005.0001`: each mechanism's table of its records, decided
there, is to carry them.

**The verdict** keeps decision 2. The mode reads each check's own report, `diagnostics` and
`skipped` both — not through the gate's `_diagnostics`, which returns `diagnostics` alone and whose
`said` the gate's report keeps as it is. An entry with a `record` the push carries refuses the push;
one with a `record` it does not carry is a warning. An entry with no `record` — `mechanisms` reports
by mechanism, `inject_rules` and `maintain` by string — refuses only when the push carries a file
under that check's own roots, else is a warning (decision 7):

| check | its own roots, for an entry with no `record` |
|---|---|
| `questions`, `sessions`, `tickets`, `product`, `edges` | `docs/` |
| `mechanisms`, `inject_rules`, `maintain` | `.agents/`, `docs/mechanisms/`, `AGENTS.md`, `CLAUDE.md`, `local.rules.md` |

A check that exits non-zero with no entry it can place — it crashed, or printed nothing it can read
— refuses the push with its last lines: a check that cannot be read is never taken as clean. A
check's `findings`, which never fail it, are not shown. Each refusal and warning names the check,
the file and line where it has them, and the problem. A record a move or a deletion leaves behind —
a ticket's RFC, a question an `Answers` link named, an answer a question cited — is reported on the
file the push does not carry, so a move or a deletion that breaks another record is only a warning;
that follows from decision 2, and CI catches it once
[.0020](../tickets/01-0010.0240.0020-this-trees-ci-runs-every-check.md) lands.

**Running side by side.** The mode starts every check before it reads any, through `_python`.
`_python` sets `PYTHONUTF8=1` for the child: the recorded interpreter writes a piped stdout in the
platform's code page on Windows, so a check printing *—* gave its parent no stdout at all, and one
printing a character outside that page crashed — a fix the gate takes too.

**The mode.** `--pre-push` takes the target and the carried files, no `--from`, no network, no
`Source`, the parser taking its operands; it prints refusals and warnings as lines and exits 1 on a
refusal, else 0. It is refused outside a tree that holds core, as `--links` is.

**The hook** keeps decision 4:

```sh
#!/bin/sh
# goodwolf: written by harness.py --links; the checks of the method's records at push
[ -f .agents/scripts/gw/hook.sh ] || exit 0
exec sh .agents/scripts/gw/hook.sh pre-push "$@"
```

The guard lets a branch without core, or a tree the harness was removed from, push. The second line
is the mark: a file holding it is core's and is rewritten to the current form; a file without it is
another's and is left byte-identical. `link()` writes it after the interpreter record, in LF with
the executable bit where the platform has one, at `git rev-parse --git-path hooks/pre-push` — and
only when that path lies inside the Git directory. A `core.hooksPath` naming a directory of the work
tree — husky's `.husky/_`, or any tracked directory — gets nothing written, since a hook there would
be committed; the report names the one line to add and where: `.husky/pre-push` for husky,
`lefthook.yml` or `.pre-commit-config.yaml` where one stands, else the hook file. The report gains a
`hook` entry: its path and `written`, `kept` or `beside`, with the line and its place for `beside`.
The install and the update do not call `link()`; they reach the hook with
[.0030](../tickets/01-0010.0240.0030-an-install-wires-the-checks.md).

**Worktrees.** `hooks/pre-push` resolves to the common Git directory, shared by every worktree; the
interpreter record is per worktree. The `pre-push` branch reads the worktree's record, then the
common directory's, so a push from a linked worktree is checked.

**Failure semantics.** With no interpreter the hook warns and passes: it cannot check, and CI is the
last gate (decision 1). A crash of the mode exits non-zero and Git refuses the push: a fault of
core's is shown, not hidden. The host branches of `hook.sh` keep their promise never to fail the
host; its header says that the `pre-push` branch is the one that refuses by design, and no longer
that every hook is launched by a Git alias.

**Windows.** Git for Windows runs the hook under its own `sh` from any shell (tried 2026-10-26, the
question's *On Windows*); the interpreter path is quoted.

## Rollout, and what it reaches

- **Here.** The hook turns on for every session in this clone the moment `--links` writes it. The
  last stage runs it, after the user is told; removing `.git/hooks/pre-push` turns it off.
- **Recipients.** A recipient that updates and runs `--links` before .0030 lands gets the hook with
  only the report's `hook` line to tell it; the install's sentence comes with .0030.

## Stages

Each keeps the suite green; `/tdd` allocates the tests, each proving its behaviour and its reason.

1. **`_python` decodes as it should.** `PYTHONUTF8=1`; a test whose child prints *—* and a
   character outside cp1252 reads both back; the gate's `--check` report unchanged on this tree.
2. **`harness.py --pre-push`.** The parser, the side-by-side start, the verdict. Tests on a fixture
   tree: a broken ticket carried refuses and names file and line; not carried, a warning and exit 0;
   a failure only in `skipped` refuses; a string entry of `inject_rules` refuses when a skill is
   carried and warns when only a record is, without a traceback; an edges directory entry
   (`docs/edge/<dir>/`) warns; a non-zero exit with nothing readable refuses with its last lines; a
   passing tree passes silently; every check started before any is read, shown by stub checks that
   meet at a barrier, not by timing.
3. **`hook.sh pre-push`.** Tests through a real `git push` to a bare repository in a fixture clone,
   its recorded interpreter a stub that logs its calls: a push of code calls it never; a push of a
   record calls it; a ref deleted calls it never; a new branch reads only commits the remote lacks; a
   merge's resolution is counted; a non-ASCII record path is read; no interpreter recorded warns and
   passes; `hook.sh` absent passes; through the hook, a push of a sound record beside another
   session's broken unstaged one warns and exits 0; from a linked worktree the common record is
   used; a `git add` started while the hook runs goes through.
4. **`--links` writes the hook.** Tests: written where none stands; rewritten when it carries the
   mark; another's left byte-identical; `core.hooksPath` at `.husky/_` and at a tracked directory
   writes nothing and reports `.husky/pre-push` or the hook file; `hook.sh`'s host events unchanged
   (`test_questions.py`'s launch tests).
5. **The docs**, under `/mechanism`: the harness doc's moments — writing the clone's `pre-push`,
   running the checks a push wakes and ruling by its files — and *What it produces*, the clone's
   hook, made by the link step and never committed; mechanism-shape's moment for `hook.sh`'s
   `pre-push` branch and its line on the wrapper; `hook.sh`'s header. The shape check and the
   injector's pass.
6. **Live, here.** `--links` run in this clone; a push's time measured with sessions running, and
   whether any other session's Git failed during it; the ticket's live criteria observed by a
   subagent that did not build it.

## Impact

Must change: `hook.sh`, `harness.py` (`_python`, `_parsed`, `main`, `link()`, the mode, the
report), their tests, the harness and mechanism-shape docs. Must verify: every host event still
launches through `hook.sh`; the gate's `--check` reads checks as before. Hidden: the checks' reads
past any fixed roots (all eight run); entries with no file (placed by the check's roots); a move or
a deletion that breaks another record warning only, until .0020; recipients taking the hook before
.0030; the guard of [01-0010.0125](../tickets/01-0010.0125-the-host-blocks-what-a-rule-forbids.md)
refusing the agent's commit for its own reason, earlier. Leave alone: the checks themselves, the
host hooks' merge, any project hook. Recommendation: proceed.
