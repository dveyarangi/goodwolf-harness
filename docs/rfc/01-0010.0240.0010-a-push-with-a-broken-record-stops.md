## Shapes and flow

```
git push
  └─ .git/hooks/pre-push <remote> <url>          one guarded line, written by --links
       └─ sh .agents/scripts/gw/hook.sh pre-push  (stdin: <local ref> <local sha> <remote ref> <remote sha>…)
            ├─ the carried paths of every pushed ref, listed
            ├─ listed, and none under the method's roots: exit 0, no interpreter
            ├─ no interpreter recorded: a warning, exit 0
            └─ the ref lines handed on → "$python" .agents/scripts/gw/harness.py . --pre-push
                 for each distinct local sha the push sends:
                   ├─ git worktree add --detach <copy> <sha>
                   ├─ the eight checks, each `--check` in the copy, all started before any is read
                   └─ git worktree remove --force <copy>, whatever the checks did
                 any finding: refused (exit 1), each named; else exit 0
```

**What the push carries** (decisions 1 and 8). Git hands `pre-push` one line per ref; a line whose
local sha is all zeros is a deletion and sends nothing. The commits are `<remote sha>..<local sha>`,
or `<local sha> --not --remotes=<remote>` for a ref the remote lacks, `<remote>` the hook's first
argument; their paths are `git -c core.quotepath=off log --no-renames --diff-merges=first-parent
--name-only --format=`, so a path in any script is read as written and a merge's resolution counts.
The list decides only whether anything is woken, so listing too much costs a check and never a false
refusal. A listing that fails — a remote sha this clone never fetched, a Git older than 2.31 that
lacks `--diff-merges` — wakes the checks rather than passing: what cannot be listed is checked.

**What wakes the checks** (decision 8). A carried path under `docs/`, `.agents/`, `AGENTS.md`,
`CLAUDE.md` or `local.rules.md` runs all eight; none runs nothing. The roots stand in `hook.sh` with
a `TODO q-0037.0006.0005.0001`: each mechanism's table of its records, decided there, is to carry
them. A read past the roots — a project's own test file an edge record names as its validator — is
CI's to catch (decision 1).

**The copy** (decision 8). For each distinct local sha the push sends, `git worktree add --detach`
makes a copy in a fresh folder under the system's temporary directory, whose path stays within the
128 the tree's names are fitted to; the checks run with the copy as their working directory, so
what is judged is what is sent, by the checks the push itself carries, and no other session's
unfinished write is in it. The copy is removed with `git worktree remove --force` in a `finally`,
then `git worktree prune`; a copy a killed hook left behind is pruned by the next run. The copy
writes its own index and takes no lock on the clone's — measured 2026-10-29, a `git add` beside it
going through.

**The children's environment.** In a linked worktree Git exports `GIT_DIR` to its hooks; the mode
clears `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` for the checks, so each finds the copy's own
repository. `_python` sets `PYTHONUTF8=1`: the recorded interpreter writes a piped stdout in the
platform's code page on Windows, so a check printing *—* gave its parent no stdout, and one printing
a character outside that page crashed — a fix the gate's `--check` takes too, its report otherwise
unchanged. The mode reconfigures its own stdout and stderr to UTF-8, as `questions.py` and
`sessions.py` do, since it prints the paths its checks name, through the pipe an agent's tool
reads.

**The verdict.** Every entry a check reports under `diagnostics` or `skipped` refuses the push —
read by the mode itself, not through the gate's `_diagnostics`, which returns `diagnostics` alone
and whose report the gate keeps as it is. A check that exits non-zero with nothing the mode can
read, one whose output it cannot decode, or one past its time limit refuses with its last lines: a
check that cannot be read is never taken as clean. A check's `findings`, which never fail it, are
not shown. Each refusal names the check, the file and line where the entry has them, and the
problem; entries of `inject_rules` and `maintain` are strings, and `mechanisms` names a mechanism,
so they are printed as they come.

**Running side by side.** The mode starts every check before it reads any; `_python` gains the
starting form beside its waiting one, through the same environment.

**The mode.** `--pre-push` takes the target, reads the ref lines from its standard input — a push of
hundreds of files would not fit an argument list — and lists each ref's commits itself with `-z`;
no `--from`, no network, no `Source`, the parser taking the mode. It is refused outside a tree that
holds core, as `--links` is.

**The hook** (decision 4):

```sh
#!/bin/sh
# goodwolf: written by harness.py --links; the checks of the method's records at push
[ -f .agents/scripts/gw/hook.sh ] && [ -f .agents/scripts/gw/harness.py ] || exit 0
exec sh .agents/scripts/gw/hook.sh pre-push "$@"
```

The guard lets a branch without core, or a tree the harness was removed from, push. The second line
is the mark: a file holding it is core's and is rewritten whole to the current form; a file without
it is another's and is left byte-identical. `link()` writes it after the interpreter record, in LF
with the executable bit where the platform has one, at `git rev-parse --git-path hooks/pre-push` —
only when that path lies inside the common Git directory (`--git-common-dir`), so a linked worktree
writes the clone's one hook. A `core.hooksPath` naming any other folder — husky's `.husky/_`, a
tracked directory, a global one — gets nothing written; the report names it and gives the line to
add and where:

| standing tool | where the line goes | the line |
|---|---|---|
| husky | `.husky/pre-push` | `[ ! -f .agents/scripts/gw/hook.sh ] \|\| sh .agents/scripts/gw/hook.sh pre-push "$@"` |
| lefthook | `lefthook.yml`, a `pre-push` command with `use_stdin: true` | `sh .agents/scripts/gw/hook.sh pre-push` — handed no remote's name, the listing takes `--not --remotes` |
| another hook file in the Git directory | that file | the husky line |
| the pre-commit framework, or a global hooks folder | — | none: it hands no ref lines, so the report says only CI checks this clone |

A line beside another's hook carries no `exec` and no `exit`, so the hook it joins runs on. The
report gains a `hook` entry — its path and `written`, `kept` or `beside`, with the tool, the line and
its place for `beside` — and `beside` leaves `--links`'s exit as it was: it is a line for the
person, not a failure. The install and the update do not call `link()`; they reach the hook with
[.0030](../tickets/01-0010.0240.0030-an-install-wires-the-checks.md).

**Worktrees.** The `pre-push` branch of `hook.sh` reads the worktree's interpreter record, then the
common directory's, so a push from a linked worktree is checked.

**Failure semantics.** With no interpreter the hook warns and passes: it cannot check, and CI is the
last gate (decision 1). A crash of the mode exits non-zero and Git refuses the push: a fault of
core's is shown, not hidden. The host branches of `hook.sh` keep their promise never to fail the
host; its header says that the `pre-push` branch is the one that refuses by design, and no longer
that every hook is launched by a Git alias.

**Windows.** Git for Windows runs the hook under its own `sh` from any shell (tried 2026-10-26, the
question's *On Windows*); the interpreter path is quoted.

## Rollout, and what it reaches

- **Here.** The hook turns on for every session in this clone the moment `--links` writes it. The
  last stage runs it, after the user is told; removing `.git/hooks/pre-push` turns it off. A broken
  commit any session leaves on the shared branch refuses every session's push until a commit mends
  it — the gate doing its work, the refusal naming the record.
- **Recipients.** A recipient that updates and runs `--links` before .0030 lands gets the hook with
  only the report's `hook` line to tell it; the install's sentence comes with .0030.
- **Removal.** [01-0010.0200](../tickets/01-0010.0200-a-project-can-remove-the-harness.md) removes
  the hook among what the install made; until it lands, the guard lets a tree without core push.

## Stages

Each keeps the suite green; `/tdd` allocates the tests, each proving its behaviour and its reason.

1. **`_python`.** `PYTHONUTF8=1` and the starting form; a test whose child prints *—* and a
   character outside cp1252 reads both back; the gate's `--check` report unchanged on this tree.
2. **`harness.py --pre-push`.** Tests on a fixture clone with a bare remote, ref lines on stdin: a
   commit carrying a broken ticket refuses and names file and line; the same tree with the ticket
   mended passes silently; a broken record only in the working tree, uncommitted, passes; a record
   whose fix is on disk but not in the commit refuses; a failure only in `skipped` refuses; string
   entries print without a traceback; a non-zero exit with nothing readable refuses with its last
   lines; a hung check refuses at its limit; every check started before any is read, shown by stub
   checks that meet at a barrier; the copy is gone after a pass, a refusal and a crashing check, and
   a copy left behind is pruned; a warning naming a Cyrillic path prints through a piped stdout; a
   linked worktree's exported `GIT_DIR` does not reach the checks; several refs check each distinct
   sha once.
3. **`hook.sh pre-push`.** Tests through a real `git push` to a bare repository, the recorded
   interpreter a stub that logs its calls: a push of code calls it never; a push of a record calls
   it; a deletion calls it never; a new branch lists only commits the remote lacks; a merge's
   resolution is listed; a non-ASCII path is listed; a force push over an unfetched remote sha calls
   it; no interpreter recorded warns and passes; `hook.sh` or `harness.py` absent passes; from a
   linked worktree the common record is used; a `git add` and a `git commit` started while the hook
   runs go through.
4. **`--links` writes the hook.** Tests: written where none stands, LF, executable; rewritten when it
   carries the mark; another's left byte-identical; `core.hooksPath` at `.husky/_`, at a tracked
   directory and at a global folder writes nothing and reports each one's line and place; from a
   linked worktree the common directory's hook is written; `hook.sh`'s host events unchanged
   (`test_questions.py`'s launch tests).
5. **The docs**, under `/mechanism`: the harness doc's moments — writing the clone's `pre-push`,
   checking a push in a copy of what it sends — and *What it produces*, the clone's hook, made by
   the link step and never committed; mechanism-shape's moment for `hook.sh`'s `pre-push` branch and
   its line on the wrapper; `hook.sh`'s header. The shape check and the injector's pass.
6. **Live, here.** `--links` run in this clone; a push's time measured with sessions running, and
   whether any other session's Git failed during it; the ticket's live criteria, the PowerShell run
   among them, observed by a subagent that did not build it.

## Impact

Must change: `hook.sh`, `harness.py` (`_python`, `_parsed`, `main`, `link()`, the mode, the
report), their tests, the harness and mechanism-shape docs. Must verify: every host event still
launches through `hook.sh`; the gate's `--check` reads checks as before. Hidden: the copy's folder
depth on Windows; `GIT_DIR` exported to a linked worktree's hooks; a broken commit on the shared
branch refusing every session's push until mended; recipients taking the hook before .0030; tools
that hand a hook no ref lines; the guard of
[01-0010.0125](../tickets/01-0010.0125-the-host-blocks-what-a-rule-forbids.md) refusing the agent's
commit for its own reason, earlier. Leave alone: the checks themselves, the host hooks' merge, any
project hook. Recommendation: proceed.
