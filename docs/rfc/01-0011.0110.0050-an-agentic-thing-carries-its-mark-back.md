## What it changes

A mechanism's doc names every file it is made of, and since 01-0011.0110.0080 the clock watches
them. The other direction is missing: no script names the doc that governs it, and a skill a
declaration names says nothing of it, while an unclaimed skill already opens with
`Mechanism: not yet`. The decisions of
[q-0024.0009.0004](../questions/q-0024.0009.0004-how-does-a-thing-an-agent-edits-carry-the-mark-back-to-the-record-that-governs-it-inside-core-and-instance.md)
*(the user, 2026-10-11)*: every skill, script, test and hook a mechanism owns opens with
`Mechanism: <slug>`, and the shape check holds it equal to the parts table.

## Shape

**Which files carry the line.** A mechanism's instruction file, and every part of its *Install
adds, uninstall removes* table under `.agents/scripts/` — 6 skills and 26 scripts, tests and the
hook wrapper today. Nothing else: the doc and the rules file sit in the mechanism's own directory;
a format shelf or an arrival shelf sits beside the skill that names it; the entry file, the host
stub, the licence and `.gitattributes` are files whose place says what they are, and the JSON hook
shelves hold no comment. A part elsewhere is not read for a line.

**Where the line sits.** In a skill, the first body line after the frontmatter — the place an
unclaimed skill's `Mechanism: not yet` already holds, read by the same reader. In code, the file's
first line as a comment, `# Mechanism: <slug>`, after a shebang where there is one: the module
docstring keeps its summary first, as `/improve-comments` asks, and the line stays outside it.

**What the shape check says.** For every declaration: its instruction file and each carrying part
open with the line naming its slug, or the part is reported — *names no mechanism*, *names
<other>*. A file under `.agents/scripts/` whose line names a mechanism whose table does not list it
is reported too, so the line cannot claim what the table does not. A skill named by a declaration
and opening with `Mechanism: not yet` stays a diagnostic, as today; one opening with its own slug
is what the check now asks. The reader of the skill's line is `_claim`'s, extended to read a slug
as the part's claim; the kinds `not yet` and `unowned by design` keep their meaning.

**The format.** `MECHANISM-FORMAT.md`'s *A skill's claim* becomes *A part's claim*: one grammar,
`Mechanism:` then a slug for a part a declaration names, or `not yet` / `unowned by design` for a
skill none does; which files carry it, where it sits, and what the check reports. The text is shown
before it lands.

**The architecture's *Installing*.** It restates the install contract in 1,138 words, and the
harness mechanism's doc holds part of it: of eight facts spot-checked — `git init` into an empty
folder, dubious ownership, the clone's exclude file, a retired `<project-local>` block among them
— four are in the architecture alone. The section becomes a pointer only after each fact it states
is in the harness doc; the paragraph *The edge, and what crosses it* stays, being this project's
view of the edge and not the harness mechanism's contract. The live record citing
`architecture.md#installing` is repointed; a dated impact in a question's body names it as it
stood, and stays.

## /impact — 2026-10-11

**Impact.** `mechanisms.py`: the claim reader, the skill problems, a part's line, its docstring;
`test_mechanisms.py`, whose fixture skill and parts take the line; `MECHANISM-FORMAT.md`; the six
owned skills and 26 code files, a line each; `harness.md` and `docs/architecture.md`; the line in

**Hidden edges.** The line moves every carrying file, so every mechanism's `parts` falls due and
every `output` whose skill moved — news for the next `/maintain`, not a defect. The installer
writes blocks at anchors, never at a file's first line, so the line and a block never meet. The
harness's shear touches straw-dog wrappers and `TODO` bindings, so the line ships as written, and a
recipient's shape check reads it at arrival — the shipped core carries it, so arrival stays green;
a recipient's own mechanism, which none has yet (q-0018.0019), would be held to it. *Found by another session's validation pass, 2026-10-12, and taken:*
the shape's R6, installed into `/skill-up` and `/mechanism`, told a writer that only an unnamed
skill carries the line, and the shape doc's output bullet said the same, so both move with the
format in stage 2; `test_harness.py`'s fixture names its `keeper` skill by the `sample` mechanism
and runs the shape check over it, so the keeper opens with `Mechanism: sample` wherever it is
written. *Found at the landing:* that fixture copies the real scripts while declaring `sample`
alone, so a copied script's line would name a mechanism declared nowhere there; the fixture takes
it out as it copies.

**Leave alone.** The installed-block owner and the straw-dog binding; `maintain.py`'s reading of a
surface; the leak check, which already holds core off `docs/` and is clean; a project's own code,
[01-0011.0110.0055](../tickets/01-0011.0110.0055-a-projects-code-names-what-governs-it.md)'s.

**Recommendation.** Proceed, in three stages, the third the largest: moving the install contract's
facts into the harness doc is a doc migration, not a line.

## Stages

Red first; the suite green at the end of each.

1. **The check.** Tests: a declared skill opening with its slug passes, with none or another is
   reported; a script part with its line passes, without it is reported; a script whose line names a
   mechanism whose table omits it is reported; a named skill claiming `not yet` stays reported; an
   unclaimed skill's `not yet` and `unowned by design` read as before. The fixture's skill and parts
   take the line. Then the 32 files take theirs, and the live check is clean.
2. **The format.** *A part's claim* in `MECHANISM-FORMAT.md`; R6 in the shape's rules file,
   re-installed; the shape doc's output bullet; `mechanisms.py`'s docstring.
3. **The install contract.** Each fact of *Installing* is found in `harness.md` or moved there;
   the section becomes a pointer with the edge paragraph kept; the two citations repointed; the
   recipients' line written.

## Limits

A file under `.agents/scripts/` that no mechanism lists is not reported here: every one is listed
today, and nothing holds that it stays so — a follow-up for the shape check. A project's own code
is `.0055`'s.

## Verification

The verification set; then by hand: remove the line from one script and see the check name it,
change a skill's slug and see it named.
