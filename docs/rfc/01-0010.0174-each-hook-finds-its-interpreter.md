# Each hook runs in every clone, finding its interpreter without uv — implementation plan

**Authored:** 2026-10-09

Implements [01-0010.0174 each-hook-finds-its-interpreter](../tickets/01-0010.0174-each-hook-finds-its-interpreter.md).

## Governing decisions

- [Architecture — Installing](../architecture.md#installing): the link step records the
  interpreter that ran it in a file of the clone's own, named in the clone's exclude file; every
  core hook runs through a wrapper that reads it; a clone without the record is told which step
  makes it. Landed in this pass *(the user, 2026-10-09)*.
- Same section: core's hooks are the questions mechanism's shelf at each host file's path, merged
  beside the project's own; an update removes an entry the previous ref wired and this one does not
  ([`.0173`](done/01-0010.0173-an-install-merges-cores-hooks-into-each-hosts-file.md)).
- `questions.py --hook` never fails the host and answers in each host's own form
  ([questions — Delivery](../../.agents/mechanisms/questions/questions.md)); the wrapper keeps both.

## The facts this rests on, and which are unverified

| fact | source | status |
|---|---|---|
| Claude Code runs a hook's command under `sh -c` on macOS and Linux, Git Bash on Windows, PowerShell where Git Bash is absent | its hooks documentation, read 2026-10-09 (q-0018.0020.0005) | documented; the PowerShell fallback unseen here |
| Codex gives a hook a Windows command of its own, `commandWindows`, and runs commands in the session's working directory | its hooks documentation, same day | documented; the shell either runs in is not |
| Cursor runs commands from the project root; its Windows shell is undocumented, its staff advise `cmd /c` | its documentation and forum, same day | **unverified** |
| A Windows Store `python` stub runs nothing | this machine, 2026-10-09 | observed |

The unverified rows decide the commands, so the first stage is a probe, not code.

## Shape

### The record — the link step's

- `--links`, and the link step inside `--install` and `--update`, write `sys.executable` — the
  interpreter running the installer, which by that fact runs — to `.agents/interpreter`, one line,
  and name that path in the clone's exclude file beside the links. Excluded, it is no file of the
  tree: Git's listing, and so `corpus`, the ref gate's *own* list and the shape check never see it.
- A record already naming an interpreter that exists is left alone; one naming a missing path is
  rewritten. The report says which, as it does for a link.
- The origin takes it the same way: `harness.py . --links` in this tree.

### The wrapper — two files, one contract

`.agents/scripts/gw/hook.sh` (POSIX sh) and `.agents/scripts/gw/hook.cmd` (Windows `cmd`), each
taking the host's name as its one argument:

- found from its own location, the tree's root, then the record;
- with an interpreter that exists, it runs `questions.py --hook <host>` under it, passing the host's
  payload on stdin through and its exit status back, so the store's script stays the only thing
  that answers;
- without one, it prints one line naming the step — `python .agents/scripts/gw/harness.py . --links`
  — in the host's own form (plain for `claude-code` and `codex`, `{"additional_context": …}` for
  `cursor`, the forms `questions.hook` already writes) and exits 0, so a missing record never holds
  back the person's message.

Two files rather than one polyglot: each shell reads its own, and which host calls which is the
probe's answer, written into the shelf. A third shell the probe finds is a third file, not a
branch in these.

### The commands — the shelf's

The three shelf files under `.agents/skills/questions/hooks/` take the wrapper's commands in place
of `uv run …`; the probe decides the form per host, its default:

| host | command |
|---|---|
| Claude Code | `sh "${CLAUDE_PROJECT_DIR}/.agents/scripts/gw/hook.sh" claude-code` |
| Codex | `command`: `sh .agents/scripts/gw/hook.sh codex`; `commandWindows`: `.agents\scripts\gw\hook.cmd codex` |
| Cursor | the form the probe shows runs on both platforms |

This tree's host files follow by the origin test `.0173` added. A recipient's update removes the
`uv` entries through the previous ref's shelf. A recipient whose announced ref predates the shelf
(the study tree, at `b048a88`) has no previous shelf to remove them by: updating first to a ref
holding `.0173` and then to this one removes them; a single jump leaves both sets running.

## Impact

**Impact.** `harness.py`'s link step gains the record and its exclude line; two wrapper files and
their tests; the three shelf files change their commands and this tree's host files with them;
the harness skill is left as it is *(the user, 2026-10-09)*; the architecture's *Installing* gained its sentence in this pass. The straw dogs bound to
q-0018.0020.0005 in `docs/product.md` and the front page retire once the live boxes are checked,
since `uv` was their only remaining caveat.

**Hidden edges.** Codex re-asks trust for each changed command, once. A clone moved to another
machine carries no record (it is excluded), so it gets the notice, as a fresh clone does. A record
naming a virtualenv that is later deleted gets the notice on the next prompt, not a failure. The
wrapper's own failure modes — `sh` absent under Claude Code's PowerShell fallback — are what the
probe exists to see; if they hold, that host is recorded as running hooks only with Git Bash.

**Leave alone.** `questions.py --hook` and its answers; the merge; the gate's reporting
([`.0176`](../tickets/01-0010.0176-a-failed-gate-says-why.md)); `uv` as the habit of the
verification set.

**Recommendation: proceed**, the probe first.

## Stages

1. **Probe** *(HITL)* — a throwaway hook in each host on this Windows machine writing which shell
   ran it, its working directory, and whether `sh` and `cmd` resolve, to a scratch file — Codex
   started from a subfolder too, since its relative command depends on that; Claude Code with Git Bash, then
   with `CLAUDE_CODE_GIT_BASH_PATH` pointing nowhere; Codex; Cursor. The person starts the Codex
   and Cursor sessions. The results go into the ticket and fix the command table. Nothing is
   committed from this stage but the ticket's record of it.
2. **The record** — `test_harness`: `--links` writes the interpreter running it and names the file
   in the exclude file once; a record naming a live interpreter is left; one naming a missing path
   is rewritten; the ref gate's *own* list does not hold it. Then the step.
3. **The wrapper** — tests run `hook.sh` under `sh` and, on Windows, `hook.cmd` under `cmd /c`,
   with a record naming the running interpreter in a fixture tree: the store's window comes back
   for a payload, stdin intact; with no record, the one-line notice in each host's form, exit 0.
   Then the two files.
4. **The commands** — the shelf files take the probed commands; this tree's host files follow;
   `harness.py . --links` here; the origin test, the shape check, the injector's check, the suite.
5. **Live** *(HITL)* — on a clone with no `uv` on the path, each host's session-start hook, and
   the prompt hook where the host has one, delivers the window; on Windows each host's shell named
   in the ticket.

## Out of scope

- A wrapper for hosts beyond the three.
- Removing `uv` from the verification set and the harness's own habit.
