# An install that will refuse writes nothing — implementation plan

- **record of** what it intends to become

**Authored:** 2026-10-13

Implements [01-0035.0020 an-install-that-will-refuse-writes-nothing](../tickets/01-0035.0020-an-install-that-will-refuse-writes-nothing.md).

## What governs it

The harness mechanism's doc, `.agents/mechanisms/harness/harness.md`: **Every refusal writes
nothing**; a run that fails after it began writing stops, reports what it wrote, what was pending
and the path that failed, and rolls nothing back. [Interruption and recovery](../architecture.md#interruption-and-recovery):
a preflight refusal changes no files. The harness skill promises the same.

## What breaks it today

`run` copies core, stamps the queue, seeds the store and writes the hosts' wiring before `_inject`
installs the rules files. A malformed `local.rules.md`, or an override naming no rule, is refused
by the injector only then — after the target was written. The refusal can be known before: it
depends on the rules files and the files they target, all of which the run already has in hand.

## The change

1. **The injector's refusal is asked before the copy.** A new preflight beside
   `_refuse_unless_empty` and `_refuse_unless_updatable`, `_refuse_unless_injectable`, runs the
   very installation `_inject` will run, over a scratch directory holding what the target will
   hold once the copy is done: every rules file — the shipped ones, the recipient's own
   mechanisms' that stay, the local file — and every file their anchor tables target, each as the
   copy will leave it (a file the target already holds as shipped stays as it stands, its
   installed blocks included; any other is the shipped text; a file leaving the manifest is
   absent). A refusal there is the run's refusal, before a byte of the target is written, and
   says so: nothing was written, fix the file and run again. It reuses the injection itself, so no
   second reading of the grammar exists to drift from the first.
2. **`_inject` and the preflight share one loop**, the rules files in order, local last; it
   returns the first refusal by its rules file's slug rather than raising, and each caller words
   it for where it stands. The refusal after the copy keeps its resume — a failure the preflight
   could not foresee is still reported, never rolled back.
3. **A tree a run stopped in is named.** `_refuse_unless_empty` meeting core already present says
   a previous install stands, whole or stopped partway, and names `--update --overwrite`, which
   completes either; a file of the person's alone keeps today's refusal.

## Stages

1. **Red.** In `test_harness.py`: a first install over a target holding a malformed
   `local.rules.md`, and one whose override names no rule, are refused with the target's bytes and
   index as before (`ARefusal.assert_refused`); today both write the copy first. The existing update
   case `test_an_injector_refusal_is_unfinished_and_names_the_resume` becomes the update's same
   assertion — its target unchanged, the refusal saying nothing was written — since the contract
   it encoded was the defect.
2. **Green.** The preflight and the shared loop.
3. **Red, then green.** A second `--install` over a tree holding core is refused naming
   `--update --overwrite`, and that command, the local file fixed, completes with every gate
   passing.

## Impact

**Impact.** `harness.py`'s `run`, `_inject`, `_refuse_unless_empty`; installer tests. Every install
and update now rehearses the injection once — a scratch tree of the rules files and their targets,
tens of files, a fraction of the copy's cost.

**Hidden edges.** The rehearsal must hold what the real injection will meet: a file kept as it
stands carries the blocks the recipient's installer put there, and the injector installs over them
without `--overwrite`. Reading the anchor tables of a malformed rules file fails; its targets are
then left out and the rehearsal's own parse gives the refusal. A recipient's own mechanism, never
shipped, takes part as it does in `_inject`.

**Leave alone.** The gate; the link step, whose refused symlink is the one step a person finishes
by hand; the I/O-failure report.

**Recommendation.** Proceed.
