## What it changes

A mark today keeps one fingerprint of a level's whole surface, so a due level can say only *its
doc, rules file or skill moved*. The re-check then guesses which file to read, and a guess is
cheaper to skip than to make. Decision 6 of
[q-0024.0009.0006](../../questions/done/q-0024.0009.0006-how-is-a-record-paired-with-the-thing-it-is-of-so-that-drift-between-them-is-noticed.md)
*(the user, 2026-10-11)*: a mark keeps a fingerprint per file, and a due level names the files
that moved, were added or went since it.

## Shape

- **The marks keep a second table.** The first is unchanged — one row per mechanism per level,
  its fingerprint of the whole surface — and still alone decides `current` or `due`, by the same
  formula, so every row written before this slice reads as it did. Beside it, `--mark` writes one
  row per file of the surface it marked: `| mechanism | level | file | fingerprint |`, each file's
  fingerprint taken of its authored text exactly as the whole-surface one is (LF endings, installed
  blocks out). Nothing but `--mark` writes either table.
- **A due level names what changed.** Its standing carries the files that `moved` (both sides, the
  fingerprints differ), were `added` (on the surface, not in the mark) and are `gone` (in the mark,
  not on the surface), each list present when it holds a file. A due level whose mark has no file
  rows — written before this slice — says it moved since a mark that named no files, and names
  none; it names them from its next mark on.
- **Failure.** A file row that does not read, or names a level with no mark row, is a diagnostic
  as a malformed mark row is today, and refuses every mark until repaired. A marks file holding the
  first table alone is well formed.
- **No migration.** This tree's rows gain their files at their next mark. A recipient clocks none
  of the mechanisms it received with core (`maintain.py`, `_received_core`), so it holds no row of
  either table and no line goes to the edge record.

## /impact

**Impact.** `maintain.py`: the reading, the writing and the standing of a mark; its docstring.
`test_maintain.py`. `MARKS-FORMAT.md`, the maintain mechanism's doc where it names the marks and
the clock's report, and `/maintain`'s B4, which gains the reading — its text shown before it
lands. **Hidden edges.** `_read_marks` takes every line opening `|` as one table; it must read the
two apart. The marks file grows by one row per file per marked level, near a hundred here, written
and read by the script alone. **Leave alone.** The levels and what each is checked against — the
next slice's; the outcomes; the whole-surface fingerprint's formula, which keeps old rows current.
**Recommendation:** proceed.

## Stages

Red first; the suite green at the end of each.

1. **A mark keeps its files, and a due level names them.** Tests: after marking, moving one file
   of a surface names it under `moved`; a file appearing in a skill's folder is `added`; a file
   leaving it is `gone`; nothing moved is nothing due, as today. `--mark` writes the second table,
   `--check` reads it and names.
2. **An old mark and a bad row.** Tests: a marks file with the first table alone checks clean and
   its levels stand as before — current while nothing moved, due without names once something
   did; a file row that does not read, and one for a level with no mark, are each a diagnostic and
   refuse a mark.
3. **The words.** `MARKS-FORMAT.md` declares the second table; the maintain doc's marks and the
   clock's report say the report names what moved; `/maintain`'s B4 reads the named files; the
   script's docstring.
