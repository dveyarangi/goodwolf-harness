## What already holds

- The window is `questions.window(root, tag, full)`: it reads the store, and either draws the whole
  window or, when the session's position and every entry are as at its last window, one line
  saying so. Its memory is one file per session outside the tree, `_memory(root, tag)`, holding the
  fingerprint; `_forget_window` empties it after a compaction, and its time is the session's sign of
  life. Every host's prompt hook prints `window`; Cursor's agent calls `--window` by the rule.
- The store already reads every straw dog for the wake: `docs_corpus.question_bindings(root)` lists
  the bindings of the straw-dog scope — documents and `TODO q-N` lines in code — the same 170 the
  straw-dog listing counts today. In-process it takes about 450 ms, `git ls-files` 120 ms of it.
- What a live ticket is, is the ticket mechanism's: `tickets._live_tickets(names)`, a record
  directly under `docs/tickets/` that is not the queue. `tickets` imports `questions`, so
  `questions` cannot import it at load.
- Stdout is UTF-8 (`questions.main`), so the emoji print on every host.

## The shape

**One counters line, appended to both forms of the window.** `window` computes it after reading
the store and before choosing its form, and the line ends either form: the store's *unchanged* is
about entries and position, and a ticket or a straw dog moves without them.

```
🎫 34 (+1/−0) · ❓ 154 (+3/−1) · 🐕 170 (+2/−0)
```

With nothing remembered for the session the line gives the totals alone, `🎫 34 · ❓ 154 · 🐕 170`
*(amended after the landing: the user refused a note saying there was nothing to compare)*.

**What is counted, by what name.**

| | the set | a member's name |
|---|---|---|
| 🎫 | the live tickets, by `tickets.live_tickets` | its file name |
| ❓ | the store's open entries | its id |
| 🐕 | every binding of the straw-dog scope | `(record, question)`, counted as a multiset |

Came is what the set holds that the last window's did not; went, the reverse. A straw dog's line
number is not its name: an edit above it would read as one going and one coming. A question
re-parented takes a new id and reads as one going and one coming: the id is what the store and
every reply name it by.

**`live_tickets` becomes public.** `_live_tickets` is renamed `live_tickets`, its one caller with
it: the window asks the ticket mechanism what a live ticket is rather than restating it. The
import is made inside the counting function, where both modules are loaded.

**The straw-dog scan, cached.** `question_bindings`' per-file reading is lifted into
`docs_corpus.bindings_in(name, text)`, with `read_text` beside it, and `question_bindings` loops
over them, unchanged in output. The count walks the straw-dog scope with `os.scandir`, taking each
record's size and time from the directory's own listing — no record is stat'ed again — and
re-reads only one whose size or time differs from what the memory holds. *(Amended at
implementation: the plan's `os.walk` and a `stat` per record cost 116 ms a turn, over the ticket's
tenth of a second.)* Measured: 16 ms a turn in-process, about 50 ms in a hook's fresh process with
the ticket script's import; the first window's full read about 450 ms, once — the question's body
holds the measure.

**The memory.** A second file beside the window's, `_memory(root, tag)` with `.counted` added,
JSON: the three sets' names and, per scoped record, its size, its time and its bindings. It is
written only when it moved, since closing a written file cost more than the rest of the count.
`_forget_window` leaves it alone: a compaction empties the conversation's
copy of the last window, not what the tree was then, so the next window's counts stay true against
it. The ticket's third criterion is amended to match — the totals alone are the session's first
window, not a compacted one.

**The reply's row.** The entry file's reply rule, the straw dog bound to q-0037.0009.0021 since the
rule moved there, gains the row: copied from the window, after `🪶 Commits`, before the head table.

## Limitations

- The walk reads every file in the scope, ignored or not; `git ls-files` skips ignored ones. No
  record in this tree's scope is ignored today, so the two agree on 587 files; a tree that ignores
  a scoped record counts its straw dogs here and not in the listing.
- The counts are at the turn's start: the reply shows the previous turn and its neighbours, this
  turn's own moves in the next reply — the user's choice, in the question's decisions.

## Stages

1. **`live_tickets` public, `bindings_in` lifted.** Rename and extract, no behaviour moved; the
   suite green as it is.
2. **Counting, tested first.** Tests in `TheWindow` and the hook's cases: a ticket minted, a
   question opened, a straw dog wrapped — each `+1`; one closed, decided or removed — `−1`; one
   going as another comes — `(+1/−1)`; a straw dog added while no entry moved — on the *unchanged*
   line; the first window — the totals alone; a compaction between two windows — the counts
   still compared. Each test reads the line's numbers, not its presence. Then `window` and the
   memory file; green.
3. **The cache.** A test that a record whose size and time are unchanged is not re-read — a record
   altered with its time restored keeps its old bindings in the count, which proves the cache is
   what answered. Then the cache; green. The window drawn with and without the counters on this
   tree, nothing moved, ten times each; the difference recorded in the question's body.
4. **The words.** The questions mechanism's doc says the window carries the counters; the entry
   file's rule places the row, the contract's version raised with its line in the findings.
   Checks only for this stage's files, the suite run for the stages before.
