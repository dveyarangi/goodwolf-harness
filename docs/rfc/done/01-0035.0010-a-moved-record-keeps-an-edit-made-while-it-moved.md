# A moved record keeps an edit made while it moved — implementation plan

- **record of** what happened

**Authored:** 2026-10-13

Implements [01-0035.0010 a-moved-record-keeps-an-edit-made-while-it-moved](../../tickets/done/01-0035.0010-a-moved-record-keeps-an-edit-made-while-it-moved.md).

## What governs it

[Interruption and recovery](../../architecture.md#interruption-and-recovery): expected contents are
re-checked before a change is applied, detected interference is a failure and never authority to
overwrite, and a failure after writing began is reported — completed, pending, failed — without
rollback. The mover already keeps this for a staying record's citations (`_Repair.apply` compares
the record with the text it read) and for a destination that appears mid-run; the moved record's
own source is the one write it does not re-check.

## The change

A move carries the source text it was derived from, beside the text it will write, and its
`apply` re-reads the source first: a source that differs is `Interference`, named by the source
path, raised before the destination is written or the source removed. Raised as `OSError`, it
reaches `perform`'s existing handling and is reported as a `CloseInterrupted` — the earlier
operations completed, this one failed, the rest pending — exactly as a changed citer is today.
A source deleted mid-run fails its read with an `OSError` and takes the same path.

No new noun, no new flow: the move gets the same before-text check the repair has. Nothing in
the command line, the preflight `refusal` or the postcondition `unfinished` changes.

The check and the unlink are not one atomic step; an edit landing in that instant is not caught.
The architecture does not promise safe simultaneous writers, and locks nothing; the check closes
the window the audit demonstrated — an edit after the change set is derived — down to that
instant.

## Stages

1. **Red.** In `test_failure_contract.py`, a close of the ticket and its RFC whose RFC is edited
   after the ticket's move — through the `announce` hook, so the edit lands after the change set
   was derived, the audit's interleaving — must stop with the RFC's edit standing in its source,
   its destination absent, the ticket's move reported completed, and the source named in the
   failure. It fails today: the stale RFC text is written to `done/` and the edited source is
   removed.
2. **Green.** `_Move` carries its before-text and re-checks it in `apply`. The new test and the
   mover's suites (`test_failure_contract`, `test_paired_close`, `test_refusals`,
   `test_command_line`, `test_citations`) pass.

## Impact

**Impact.** `move_doc.py`'s `_Move` and `_change_set`, its one constructor; the failure-contract
tests. Callers — `/maintain`'s paired close through the command line — see a new failure only
when a source changed under them, in the report form they already handle.

**Hidden edges.** A record whose line endings the reader normalised would compare unequal to
itself; `_read` opens with `newline=""`, so before and now are read alike. The move's text is its
re-aimed, re-marked form and cannot serve as the comparison, hence the separate before-text.

**Leave alone.** The preflight `refusal` (it runs before the change set and cannot see a later
edit); the destination check already in `apply`; the questions store's own move, which has its
own re-read.

**Recommendation.** Proceed.
