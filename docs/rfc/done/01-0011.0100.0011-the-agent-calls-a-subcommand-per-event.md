## What the code does today

- `main` matches `argv` by hand, one branch per mode.
- `--declare "<line>" --session <tag>` → `parse` → a list of `Clause` → `declare(root, tag,
  clauses, today)`. `declare` applies the clauses to a `_Draft`, checks `at` against the result,
  rechecks interference, writes the entries, then writes the session's line.
- `_Draft._opens` refuses an id that is not the next free one. `recheck` refuses an id another
  session wrote meanwhile: "declare it again with the next free id".
- `_drawn` prints `next free id:` in every window, and the `FORMS` text names it.
- `Clause` is the writer's one front door. The judge (`.0040`) will hand it typed values without
  parsing. That seam stays.

## The shape

**The calls**, each ending in `--session <tag>`:

| call | the `Clause` it builds |
|---|---|
| `at q-N` | `at` |
| `open "<question>"` · `--under q-P` · `--between q-U q-L` | `opens`, with no id: the draft assigns it |
| `move q-K --under q-P` · `move q-K --to-root` | `moves` |
| `depend q-A --on q-B` · `undepend q-A --on q-B` | `depends` · `undepends` |
| `close q-N <kind> ["<pointer>"]` | `closes` |
| `suspect q-N` · `clear q-N` | `suspects` · `clears` |
| `lean q-N "<line>"` | `leans` |
| `assign q-N <path>` | `assigns` |

- The event calls are parsed by the standard library's argument parser. A malformed call prints
  that call's usage and exits 2, writing nothing. The parser's own exit is caught, so `main` still
  returns its status to a caller in the same process.
- The read and lifecycle flags (`--check`, `--window`, `--wake`, `--tree`, `--end`, `--hook`) keep
  their hand-matched branches. The impact left them alone.
- **Settled and reported** (decision 51, not load-bearing): `--on` names the question depended on.
  The sketch at the align was positional, `depend q-A q-B`, which leaves a reader guessing which
  waits for which. `--to-root` mirrors the old `to root`.
- **`undepend` comes here from `.0015`**, since the ticket lists it among the calls. Its writer
  clause removes one listed dependency, refuses one that isn't listed, and drops the part when the
  list empties. `.0015`'s stage 3 dissolves into this slice.
- **`open` with no id.** The draft takes `_next_free` of its own index, and the call prints the
  written record and `opened q-N`. When the recheck finds that another session wrote that id in
  the meantime, `declare` reads the store again and applies the call anew, so the next free id is
  taken. The retry is bounded at a few tries before it refuses, so a store that keeps moving can't
  loop forever. The other session's entry is never touched.
- **The window loses its `next free id:` line.** Nothing reads it any more.
- **`;` is no longer special.** Free text is one argument.
- **`declare` keeps its name and its list of clauses.** *Declare* stays the act's name, and the
  judge's seam takes a list. Its docstring and `Clause`'s stop speaking of a line.

## Stages

Test-first under `/tdd`. Each stage leaves the suite green.

**1. The calls beside the line.**

- Add the event subcommands. `--declare` still works, so no test breaks yet.
- The draft assigns an id when `opens` carries none, and the `undepends` clause exists.
- Tests, through `main`:
  - each call writes what its clause writes, for every row of the table;
  - `open` prints its id;
  - `at` on a closed question is refused and writes nothing;
  - a call missing `--session`, an unknown subcommand, and a bad id are each refused with a usage
    message, and the store is byte-identical;
  - `undepend` covers one of two dependencies, the last one (removing the part), and an absent one
    (refused);
  - `open` raced: the other session writes the next free id between read and recheck, and this
    call takes the id after it, leaving the other entry as that session wrote it. This one goes
    through `declare` with a `Clause` list, not `main`, since the hook that acts as the other
    writer, `between`, is on `declare` alone.

**2. The line removed.**

- Delete `--declare`, `parse`, `_clause`, `_CLAUSES`, `FORMS`, the one-`at` rule, the `;` ban,
  the refusal of a wrong id, and "declare it again with the next free id".
- Remove the window's `next free id:` line, and the three tests' assertions of it (`TheWindow`,
  `TwoSessions`).
- The user-facing strings that speak of a line change:

    becomes *the first `at` call places it*;
  - the recheck's *changed since this line was read; read it again and declare anew* becomes
    *changed since this call read it; call it again*.
- Migrate every test that builds a line: the `Declared` helper becomes a call helper, and
  `Interference`, which reaches `declare` with `questions.parse`, builds its `Clause` lists
  directly. Tests of
  the grammar itself (`go to q-0001.0004 is not a clause`, the `;` ban, the wrong next id) are removed

## Impact

The parent's record names the layers this slice changes. Re-read against this plan, it adds:

- **`undepend` moves here from `.0015`.** `.0015`'s validation pass drops its stage 3, and closes
  q-0001.0002 with two calls.
- **`.0012`'s validation pass** rewrites its Q1 sentence against the new Q1, moves its contract
  version to v20, and repoints by `close` calls. q-0001.0003, q-0001.0004 and q-0001.0003.0002 to q-0001.0005 now sit in
  `docs/questions/done/`, and the writer finds them there.
- **`AGENTS.md`'s general rules change in two places in one version:** Q1's installed block and
  the authored rule.
- **The argument parser's exit is caught**, or a malformed call would end a test run in the same
  process. It prints its usage to stderr, so the usage tests read both streams.
- **A write without an `at` no longer moves the session's line.** The old grammar forced an `at`
  into every line, so every write refreshed the session's date. Now only `at` does, and Q1 makes
  one every turn, so the stale-session finding keeps its footing.
- **The sessions file and the entries don't change format.** Nothing to migrate.
