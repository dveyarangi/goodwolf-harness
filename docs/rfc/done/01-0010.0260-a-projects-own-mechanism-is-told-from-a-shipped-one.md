## The mark

A header bullet of the declaration, after `record of`, in the header's own form, a name and its
value:

```md
- **owner** core
- **owner** local
```

Required, one of the two: `core` ships, `local` stays. `local` is the word the method already
has for what is the project's own — the local rules file, and the local block, which the entry
file calls the installed block whose owner is `local` — so the mark adds no term, and reads the
same at an origin and in a recipient *(the user, 2026-11-16: `local`, over a first wording that
spelled the project out; a name with a value, over the bare word; `core` said as plainly as
`local`)*. A declaration that names no owner is a diagnostic, never read as core's: the day the
person had every skill owned, nothing is whose it is by silence. Refused: `scope` as the name, a
word an open question is still settling; a third `state`, since `state` says how the parts table
reads and a local mechanism is installed or always on like any other; a bullet naming a
consequence — never ships — which says nothing in a tree that ships nothing.

## What each reader does

**The shape check, `mechanisms.py`.**

- The declaration read carries its owner; none, or one that is neither `core` nor `local`, is a
  diagnostic.
- *A file of a local mechanism* is: any file in its directory; any file in the folder of a skill
  whose claim names it and which its declaration names; a part of its parts table that opens with
  its claim. The claim is already held to the declaration both ways, so a file that names a marked
  mechanism which does not list it is a diagnostic and stays core's.
- A path under `docs/` named by such a file stands as *local*: no leak, and listed under its
  own key of the report's `core cites`, beside the painted doors, the skipped and the leaks.
  An unmarked file is sorted as before.
- A declared part is held to its claim wherever it stands: every part under the scripts' folder,
  as now, and every part outside the core directory unless it is a document (`.md`), a data file
  (`.json`, `.jsonl`, `.csv`) or not text. The claim is read after a shebang, past the comment
  leader — `#`, `//`, `--` or `;`. Core's own parts outside the core directory are the entry file
  and the host stub, documents both, so no shipped declaration changes standing.
- In a recipient the pass on an unbound `not yet` is narrowed to what the shear leaves: the kind
  alone, unwrapped. Words after it, a wrapper that binds nothing and a longer word are the tree's
  own writing and fail. The bare line on a skill of the tree's own still passes, and waits on
  [q-33npqk](../../questions/q-33npqk-in-a-recipient-how-is-an-unbound-not-yet-on-the-trees-own-skill-told-from-one-core-shipped-sheared.md).
- A core declaration that names a file of a local mechanism — a part, a relied-on part, a
  moment's instruction or referent — is a diagnostic: core would ship leaning on what stays.

**The installer, `harness.py`.**

- The transformation leaves out every file of a mechanism the ref's declarations mark — its
  directory, the folders of its skills, its parts under the core directory, and any script there
  that opens with its claim — and takes its installed blocks out of what ships, by the reading
  that takes the origin's local blocks out. It is transformation, not refusal, so an earlier ref
  is read under it too; no ref that exists holds a marked mechanism, so no recipient reads an edit.
- A ship is refused, before anything is written, where a declaration that ships still names a
  file left out.
- The update is untouched: a recipient's own block is told by its rules file standing in the
  tree and never shipped, its own files by their absence from the manifest. The gate's shape
  check is the tree's own script, so a recipient's marked mechanism passes it once the tree
  holds a core with the mark.

**The maintain clock, `maintain.py`.** In a recipient it reads the marked mechanisms and holds
the rest as come with core; at an origin it reads every declaration, as now.

## Stages

Each keeps the suite green; tests first, each watched failing for the reason it names.

1. **The check reads the mark.** `test_mechanisms.py`: a marked declaration is read; a wrong value
   fails; a marked mechanism's doc, skill, shelf and claimed script naming a record under `docs/`
   pass and are listed as local; the same path in an unmarked file is a leak; a skill
   claiming a marked mechanism that does not name it stays a leak; the report carries four

2. **A part is held wherever it stands.** A part outside the core directory without its claim

3. **An origin's own stays.** `test_harness.py`, the origin fixture given a marked mechanism with

   of them and no block, and its gate passes; a shipped declaration naming a part left out

4. **A recipient's own stands through an update.** The recipient fixture, made by an install,

   check and the update leave it, report it as the recipient's own, and the gate passes — the
   shape gate included, which is what fails today.
5. **The clock, and the narrowed pass.** `test_mechanisms.py`, in a recipient: the bare kind
   passes; a reason after it, an unbound wrapper and a longer word fail. `test_maintain.py`: in a recipient a marked mechanism is clocked and a shipped
   one refused as come with core.
6. **The docs**, then the verification set.

## Amended on the judge's reading, 2026-11-16

A judge that did not build the work read it; what its findings changed:

- A rule a local mechanism installs into a core file is the instance's, as the local block is:
  what it names under `docs/` is skipped and reported, at the origin and in a recipient.
- Every file a local mechanism names under the core directory is told as its own by its place
  or its claim, or the check says it would ship; so *its parts stay behind* holds wherever the
  origin's check passes.
- Leaning is read from a core rules file's targets as well as from a declaration, by the check
  and by the ship. A core skill's prose that links a local skill is read by neither.
- A file of a local mechanism that is not text stays without refusing the ship; a part that is
  not text carries no claim, and `.txt` and `.tsv` join the formats that carry none.
- At the origin a bound claim that says why in its body is a diagnostic, as a row's is: sheared,
  it would be refused in every recipient.
- The maintain clock reads a declaration that names no owner as neither the tree's nor core's.
- The two decisions the mark amends say so: what travels, and what is excluded from the leak
  rule.

Left open, each at its home: a mechanism declared local after it shipped leaves its block in
every recipient, an older defect of the update
([q-4xda6k](../../questions/q-4xda6k-how-does-an-update-take-a-mechanism-that-left-core-out-of-a-recipient-the-block-it-installed-included.md));
