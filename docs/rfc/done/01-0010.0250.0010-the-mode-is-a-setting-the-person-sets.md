## The shape

**The declaration.** The session mechanism's rules file gains its settings table, in the form
[MECHANISM-FORMAT](../../../.agents/skills/mechanism/MECHANISM-FORMAT.md) gives it:

| setting | values | default | set by |
|---|---|---|---|
| `branches` | `shared` · `per-session` | `shared` | the person |

`branches=shared` is the first mode, `branches=per-session` the second. The names, and *the
main checkout* for the folder whose Git directory is the common one, are the user's word,
2026-10-30. No rule is conditioned on it in this slice.

**The main checkout.** Found in Python, with no process started — the hook reads it on every
message from [.0020](../../tickets/01-0010.0250.0020-the-harness-runs-in-a-worktree.md) on, and the
store's and the session's tests run in plain folders that refuse a process: the tree's `.git` is
read — a directory is the Git directory, a file names one with `gitdir:` — then that directory's
`commondir`, if any, gives the common one. The main checkout is the common directory's working
tree: its parent when the directory is a checkout's `.git`, else the `core.worktree` its `config`
names. A tree with no `.git`, a bare common directory, or one whose working tree cannot be told —
a submodule's or a separate Git directory's without `core.worktree` — has none: the session's
own tree stands in, as today.

**The reading.** The first setting read at run time, and not from the session's own branch. The
declaration is read from the session's own tree — the code that reads the value is its own — and
only the value from the main checkout's `local.rules.md`; a value unset there, or one the
declaration does not hold, reads as the default, and says nothing. The working file, not a
committed blob: a `--set` is in force before it is committed, and whatever the main checkout has
checked out — a branch, a detached head — the person's folder is what is read. A checkout switched
in the main checkout to a branch whose local file sets another value changes the mode for every
session; that is the person's act in their own folder, said in the question's body. Reading costs
little — the whole tree's settings took about 24 ms on this one, 2026-10-30; this reads one file.

**Setting it from a worktree.** `inject_rules.py --set branches=…` run in a linked worktree is
refused, naming the main checkout, since the local file it would write is not the one read; and
`--settings` shows, for `branches`, the main checkout's value. Every other setting is read and set
in its own tree, as today.

## Stages

Each keeps the store's, the session's and the installer's tests green.

1. **Declared.** The settings table in `session.rules.md`; a test in `test_inject_rules` that
   `read_settings` declares `branches` with its values, its default and *the person*, and the
   rendered table shows it at `shared` in a tree that sets nothing; the installer's check stays
   clean on this tree.
2. **The main checkout found.** Tests over plain folders laid out as Git directories — a checkout,
   a linked worktree whose `.git` file and `commondir` lead back, a bare common directory, a
   submodule's — each giving the main checkout, or none and the own tree.
3. **Read.** The reading in the session script; tests: the main checkout sets `per-session` while
   the worktree sets `shared`, and the worktree reads `per-session`; neither sets it, both read
   `shared`; the main checkout's file sets a value its declaration lacks, or the main checkout's
   tree predates the declaration, and the worktree reads the default. Each fails first for the
   reason it names: the value taken from the worktree's own file.
4. **Set and shown.** `--set branches` refused in a linked worktree, naming the main checkout;
   `--settings` there shows the main checkout's value; both as they are in the main checkout.
5. **Said.** The session doc's paragraph and the edge record's lines.

## Impact

**Must change:** `session.rules.md` (a table, no rule); the session script (the main checkout,
the reading); `inject_rules.py` (`--set` and `--settings` for this setting in a worktree);
`session.md`; `docs/edge/settings.md`; `docs/architecture.md`; the test files.
**Must verify:** the installer's check on this tree and a recipient's update add one row to
`--settings` and install nothing; `test_inject_rules`, `test_sessions`, `test_questions` green.
**Hidden edges:** `session.rules.md` stands changed and uncommitted in the shared checkout, another
session's work — the implementation edits its own lines and commits by path. A worktree's hook
reads a file outside its own folder: a read, by a script the hook runs, not an agent's edit.
xuanxue-cabinet's main checkout stands on a detached head (seen 2026-10-29): the reading holds
there; *commits on main* in decision 14 does not — carried to
[.0030](../../tickets/01-0010.0250.0030-a-session-in-a-worktree-opens-a-question-through-the-coordinator.md)'s
plan.

## Validation, 2026-10-30

A reviewer who did not write it read the first pass against the code and found: the main checkout
taken as the common directory's parent, wrong for submodules and separate Git directories and
blind to bare ones; the whole tree's settings read from the main checkout, which raises on a tree
whose core predates the declaration; `--set` and `--settings` in a worktree disagreeing with the
reading; the ticket's *the value main holds* against a working file whatever is checked out; the
run-time reading absent from the architecture; no case without Git, where the tests' folders
refuse a process; nothing calling the reading in this slice. Each is amended above.
