# An empty folder becomes the repository it is installed into — implementation plan

**Authored:** 2026-10-07
**Last amended:** 2026-10-07

Implements [01-0010.0171](../../tickets/done/01-0010.0171-an-empty-folder-is-initialised-on-install.md):
an install into an empty folder inside no repository runs `git init` there first and arrives in
one run; a folder with files of its own is refused naming `git init` and the root; a subfolder of
a repository is refused naming the parent; the harness skill's refusal list says so.

**Planning state:** authored 2026-10-07 from the ticket's align of the same day, against
`harness.py`, its suite and the architecture. Validated once in the same pass. **Implemented and
verified 2026-10-07** as planned, with one shape the work chose: the init is a step of its own
before the work-tree check, run by `--install` alone, so the check stays one function reading
Git's answer and no mode flag reaches it.

## Governing boundaries

- **The decision** — [architecture § Installing](../../architecture.md#installing) *(the user,
  2026-10-07)*: a target is a repository because every script reads a tree through Git's
  listing; an empty folder inside no repository is initialised; anything else that is not the top
  level is refused with the step. Not reopened here.
- **Every refusal writes nothing** — the install contract. The init is not a refusal; it is the
  run's first write, and it happens only where the run then continues.
- **The work-tree check** — `_work_tree_root` in `harness.py`, which since
  [01-0010.0172](../../tickets/done/01-0010.0172-a-first-install-says-what-stopped-it.md) reads
  Git's whole answer and already tells the ownership refusal apart. This slice adds the two
  remaining cases Git's answer distinguishes.
- **The link step runs the same check** with no source. An empty folder is never a tree holding
  core, so `--links` reaches the no-core refusal there; initialising in `--links` is not wanted
  and does not happen: the init is `--install`'s alone.

## `/impact`, 2026-10-07

**Impact.** `_work_tree_root` and its callers' modes; three new tests, two of them process cases;
the skill's refusal list; the architecture already carries the decision.

**Hidden edges.** In-process cases stub Git's answer with one that always finds a repository, so
the empty-folder and subfolder cases are process cases where Git is real. `git init` in a folder
whose parent is a repository never happens: Git answers the parent's top level for such a
folder, which is the subfolder refusal, before any init. The init writes `.git` and nothing else;
no commit, no setting, no remote.

**Leave alone.** The ownership refusal and its tests. The source-itself refusal. The link step.
`.0170`'s last-step sequence, which runs after this and decides the switches.

**Recommendation.** Proceed; one branch in one function, each case with its proof.

## What changes

### The work-tree check, by Git's answer

`rev-parse --show-toplevel` answers one of four ways, and the check now reads each:

| Git says | The target | The run |
|---|---|---|
| dubious ownership | — | refused with Git's command *(landed in `.0172`)* |
| `not a git repository` | empty, and the mode is `--install` | `git init` there; the run continues from the new top |
| `not a git repository` | holds anything, or the mode is not `--install` | refused: `target: <path> is not a git repository; run git init there, or install at the root you mean, then run again` |
| a top level other than the target | — | refused: `target: <path> is not the top level of a git work tree; <top> is — install there, or a workspace of several is refused` |

"Empty" is a directory with no entries at all. A hidden file counts as content: it is the person's.

The init is `git init --quiet` run in the target, through the same runner; a failure of the init
itself is a refusal carrying Git's words, and nothing else was written before it. Reported as a
note, `git init: <path> was not a repository and is now one`, so the person reading the report
sees the write that was not in the manifest.

The check learns which mode runs it: a parameter, since `run` and `link` both call it and only an
install initialises.

### The words

The harness skill's refusal list: *A folder that is not a Git repository* — empty, the install
initialises it and says so; holding files, refused with the step, since where the root goes is
the person's decision; *a subfolder of a repository* — refused naming the top level; install
there, or one tree per installation.

## Stages, by `/tdd`

1. **The subfolder refusal names the parent.** The existing in-process refusal case asserts the
   top level is named; the stub's answer already carries it. Then the wording.
2. **A non-empty folder that is no repository is refused with the step.** A process case: a
   temporary folder holding one file, `--install`, refused naming `git init` and the root, nothing
   written. Then the branch.
3. **An empty folder is initialised and the install arrives.** A process case: a temporary empty
   folder, `--install`, the note present, `.git` present, the three gates passed. Then the init.
4. **`--links` in an empty folder initialises nothing.** A case asserting the no-repository
   refusal, not an init, with no `.git` afterwards.
5. **The words**, then the verification set and `/verify`.
