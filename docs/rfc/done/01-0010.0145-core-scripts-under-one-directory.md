# Core's scripts cannot collide with a project's own — implementation plan

**Authored:** 2026-09-21
**Last amended:** 2026-09-21

Implements [01-0010.0145](../../tickets/done/01-0010.0145-core-scripts-under-one-directory.md): every
script core ships, and its tests, move from `.agents/scripts/` to `.agents/scripts/gw/`; each
finds the tree's root one level deeper; the gate runs a recipient's scripts at the new path;
every live citation follows; and frost_map's update is the grade and the first strike for
[01-0010.0160](../../tickets/01-0010.0160-harness-edge-changes-reach-an-update.md).

**Planning state:** authored 2026-09-21 from the ticket, against the seven scripts, their
suites, the four declarations and every live file naming the path. **Validated once**, the same
pass. It found the one thing that could go wrong: a recipient that runs the update **from its own
copy** runs the *old* script, whose gate looks for the injector and the shape check at the old
path — which the update has just deleted — so that run reports `arrived: false` on two gates
that could not be found, with every file correctly landed; a `--check` from the new copy then
passes. That is not a defect to fix here; it is the migration the ticket exists to produce, and
the RFC says how the grade meets it. Nothing else in the tree reads the path except through the
constants named below.

## Governing boundaries

- **The ticket** — [what to build](../../tickets/done/01-0010.0145-core-scripts-under-one-directory.md#what-to-build):
  the directory over the prefix, one root change, every live citation, archived records left.
  The name `gw` is the user's *(2026-09-21)*.
- **The install contract** — [architecture § Installing](../../architecture.md#installing): the
  manifest is *every file under the core directory* — so the scripts travel wherever they sit,
  and an update *deletes what left the manifest*, which is how the old paths leave a recipient.
  Nothing there names `.agents/scripts/`; the architecture's one mention is the overview's, and
  it follows.
- **Every script computes its root as two levels above itself** —
  [the install spec](../../spec/01-0010.0130-harness-installs-into-another-tree.md#what-the-installer-does-in-order),
  step 1, the reason a workspace is refused. It becomes three; the reason and the refusal are
  unchanged.
- **The shape** — [`/mechanism`](../../../.agents/skills/mechanism/SKILL.md): a part is where its
  declaration says; `mechanisms.py --check` fails on a parts table naming a path that is not
  there, so the four declarations move in the same stage as the files.
- **Core stands alone** — [`.0140`](../../tickets/done/01-0010.0140-core-stands-alone.md): the
  leak check exempts the tests directory by prefix; the prefix moves with them.
- **ADR-0004** — standard library alone; a bare `python` still runs each script from its new
  path, and the ADR's one sentence naming the directory follows.
- **The mover** — [`move_doc.py`](../../../.agents/scripts/gw/move_doc.py) moves markdown records and
  repairs link citations; scripts are not records and a code-span path is not a link. This move
  is `git mv` and hand repair, and nothing is added to the mover for it.

## Shapes

### One directory, one constant

`.agents/scripts/gw/` holds the seven scripts and `test/` beneath it. `docs_corpus.py` gains
`SCRIPTS = ".agents/scripts/gw/"` beside its other path constants; `mechanisms.py`'s `TESTS`
becomes `SCRIPTS + "test/"`; `harness.py`'s `_script_gate` runs `target / SCRIPTS / script`.
Nothing else in code spells the path. The usage lines in the docstrings — the one place a path
is text rather than a constant — are rewritten by hand, six of them.

### Root, one level deeper

The five scripts that compute a root — `inject_rules`, `mechanisms`, `move_doc`, `straw_dogs`,
`tickets` — change `parents[2]` to `parents[3]`, each keeping its `root or` override for the
tests. `harness.py` computes no root: it takes a target. `test/repository.py`'s `SCRIPTS =
parents[1]` is the scripts directory relative to the tests and does not change; the tests import
as they did.

### The recipient's old copy

A recipient updating from its own copy runs the old `harness.py`: it clones the new ref, deletes
the old script paths as what left the manifest — its own file among them, which is fine once
Python has read it — writes the new ones, injects with the in-process injector, and then gates
with `target/.agents/scripts/inject_rules.py` and `.../mechanisms.py`, which are gone. The report
reads `arrived: false`, the two gates each saying the file was not found, the ref gate passing,
the links reported beside it. Everything has landed; `python .agents/scripts/gw/harness.py
. --check` then passes. Updating from a fresh clone of the new ref instead — `python
<clone>/.agents/scripts/gw/harness.py <target> --update` — arrives in one run, since the gate
path is the new script's. The `/harness` skill already says a run may come from either; this RFC
adds nothing to the skill for it, because saying *what a recipient must amend and why* is
[`.0160`](../../tickets/01-0010.0160-harness-edge-changes-reach-an-update.md)'s whole question and
a sentence here would be its first home in the wrong place.

### The citations

Live files naming the path, repaired by hand to the new one, `.agents/scripts/gw/…`: the four
declarations' parts and *relies on* tables; `/harness`'s command lines; `TICKET-FORMAT.md`'s
mover command; `MECHANISM-FORMAT.md`'s *where the parts live*; `local.rules.md`'s verification
set, then `inject_rules.py local --install --overwrite` so `/verify`'s block follows;
`.agents/README.md`'s two links; the root README's three commands; ADR-0004; the architecture
overview; `docs/process.md`; the two live specs; the parent ticket; the queue's prose;
`maintain.evidence.md`; `.0150`'s RFC. Archived records — `rfc/done/`, sessions, research —
keep the path as it was. The ticket `.0145` names both paths by design.

## Flows

**Install into an empty tree**, from the moved repository: unchanged but for the gate's path —
`Shipment.at` reads the manifest under `.agents/` wherever the scripts sit, writes them at
`.agents/scripts/gw/`, and `_gate` runs the two checks there.

**Update across the move**, from a fresh clone: `_refuse_unless_updatable` compares the old
ref's files as installed; `_write` writes the new manifest, then deletes every old-path script
and test as what left the manifest, and prunes the empty `test/`; the gate runs at the new
path; `arrived: true`, `deleted` naming every old path.

**Update across the move, from the recipient's own copy**: as above until the gate, which the
old script runs at the old path — two gates not found, `arrived: false`, files landed. The
person runs `--check` from the new copy.

## Stages

Tests first; each stage leaves the set green, run from wherever the tests then sit.

1. **The move.** `git mv .agents/scripts/*.py .agents/scripts/gw/` and `test/` with them;
   `SCRIPTS` in `docs_corpus.py`; `TESTS` derived; the gate path; the five roots; the six usage
   lines. `local.rules.md`'s set names the new discovery path and script paths, and the local
   block is reinstalled with overwrite. `test_mechanisms.py`: the case that plants a test file
   under the tests prefix to prove the leak exemption plants it under the new prefix — the
   exemption is proved by the prefix, not the old path. `test_harness.py`: the fixture seeds the
   live scripts and the arrival test under the new path. One new case in `AnUpdate`: the source
   holds ref A with the scripts at `.agents/scripts/` and ref B with them under `gw/`; install at
   A (the gate fails at the new path, files land), update to B from the live installer → `deleted`
   names every old script and test path, nothing else is deleted, and `arrived: true` — the
   move as a recipient meets it, proved at the seam the hidden edge names. The whole set green
   from `-s .agents/scripts/gw/test`.
2. **The declarations and the citations.** The four parts tables; every live file under *The
   citations*. `mechanisms.py --check` green over the moved tables; `straw_dogs.py` unchanged in
   count; a grep for `.agents/scripts/` over live files finds only the ticket, the RFC and the
   `gw/` paths.
3. **The install proved.** `harness.py <empty tree> --install` from a local clone of the
   committed move: `arrived: true`, the gate's two subprocess lines naming `gw/`. Then push.
4. **The grade**, frost_map, by the user: `python .agents/scripts/harness.py . --update` from
   its own copy, then `python .agents/scripts/gw/harness.py . --check`. Recorded on
   [`.0160`](../../tickets/01-0010.0160-harness-edge-changes-reach-an-update.md): the update's
   report as the old script wrote it, the check's report, and the state of frost_map's
   verification set — which names the old paths and which nothing told it to amend.

## Tests

Behavioural, in the suites' shapes. The new update case costs one clone and two gates, like the
gate cases today, and proves the reason: `deleted` is asserted as the exact list of old paths,
so a deletion beyond the move would fail it; the install at the old-layout ref is asserted to
fail its injector gate — the gate looks under `gw/`, which that ref lacks — and the update to
arrive, with the old directory gone and the new script present. *(Amended at `/verify`: the
gate's `said` lines are the check's JSON tail and never name a path, so arrival and the files
are what the case reads.)* The leak-exemption case asserts a planted citation under the new
tests prefix is not a leak *and* the same citation one directory up is — both polarities, as
before.

## Limitations and follow-ups

- **The recipient's old copy reports two gates missing.** Named above; the report is honest and
  the files are right. What to tell the recipient is `.0160`'s.
- **A recipient's own verification set** names the old paths until someone amends it; nothing
  here can, and the grade records that it did not.
- **`__pycache__`** at the old location stays in a recipient that ever ran the old scripts
  without `PYTHONDONTWRITEBYTECODE`; ignored by git, invisible to the corpus, harmless.
- **The name `gw`** is a fact of this repository; a fork that wants another edits one constant
  and its citations, which is the same edit this slice makes.
- **Historical records** keep `.agents/scripts/x.py`; a reader following one lands on nothing.
  Accepted: they are dated snapshots, and the mover repairs record moves, not script moves.

## Resolved at `/plan`

- **The gate runs from the script that runs the update.** `_script_gate` builds the path from a
  constant in the running script, not from the shipment; so an old copy checks the old path
  after deleting it. Considered and refused: having the gate read the shipment for where the
  scripts are — a change to the old script cannot reach a recipient that already holds it, so
  it would fix nothing for this move and only the next one. The cost is one false `arrived`
  per recipient per move, read correctly once `.0160` says what a migration is.
- **Directory, not prefix.** Chosen at the `/impact`: it namespaces `test/` and `__pycache__`,
  and costs one root change; a prefix would leave the tests directory shared and rename every
  module import.
- **No generalisation of the mover.** A code-span path is repaired by hand this once; a second
  script move would be the second shape.
