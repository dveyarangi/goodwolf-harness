## Scope and flow

One case folder contains source provenance, the reconstructed continuation, the actual returned discovery, the two instruction snapshots, the judge's questions and calibration answers. An explicit case path is the input; the executor never receives that folder or its path.

The immutable common context contains the historical `/align` text and entry-file paragraph **A reply speaks the method** from the amendment commit's parent. These active instructions are the ones the failure register identifies. The returned discovery and description of failure 53 were first recorded in the amendment commit itself: `docs/questions/q-0037.0012.0009-how-is-an-amendment-to-an-instruction-tested-before-it-lands-against-which-cases-chosen-how-run-with-no-instruction-the-standing-one-and-the-new-one.md`, section **The outside view, 2026-10-19**, and `docs/rule-failures.md`, section **53. A discovery was filed and an align opened on it, and the person was told nothing of what it found — 2026-10-19**. The original initiating user message is not preserved there: the continuation is explicitly reconstructed as a request to propose how instruction amendments should be checked after the returned study. No current entry file, live question body, later amendment or personal context is added. The case manifest fingerprints every input. This is a reconstruction of the recorded failure with its named active instructions, not a claim to replay an unavailable full transcript.

One executable runner stages the public inputs separately for every execution, invokes the host without a shell, captures its events and result, and records failures and timeouts. An existing output directory is refused rather than overwritten. A health failure leaves its evidence and starts no experiment runs.

The adapter disables personal instruction and memory loading without copying credentials or changing HOME. Its first real probe establishes that staged inputs are reachable and that material outside the stage is inaccessible. The adapter's observed host version, model and configuration are recorded. A model mismatch between conditions invalidates attribution.

After calibration, nine executor runs are assigned anonymous IDs. The judge receives each response, the common situation, the original returned discovery and the same questions, without mode names, instruction snapshots or paths that reveal a mode. It can therefore check fidelity to the source rather than the presence of words alone. The four questions concern: all eight families explained faithfully; their meaning for this case; the assumptions introduced by the research tasking; and the material preceding a proposed decision. The ordering question passes when there is no proposed decision; the other questions still measure absent material. Each yes carries exact supporting quotations from the response and a brief evidence statement. Each quotation is checked against the actual response; malformed or unsupported judging is an error. The private key reconnects the results to modes only in the report.

The report keeps each response's answers and quotations, failures excluded from denominators and the three mode counts. The verdict compares the standing and amended vectors of per-question yes counts. With three valid judgements in both arms, componentwise improvement with no decline gives `helped`, decline with no improvement gives `hurt`, equality gives `no observed effect`, and improvements and declines together give `confounded`, with the conflicting dimensions named. A difference outside the intended instruction paragraph, common-input fingerprints or model also gives `confounded`. An incomplete arm gives an incomplete report with no verdict; in particular a zero denominator never becomes `no observed effect`. The no-instruction arm is reported as the behavioural floor, separate from the standing-versus-amended verdict.

For four questions the planned invocation count is `1 health/isolation probe + 2 × 4 calibration judges + 3 × 3 executor runs + 3 × 3 response judges = 27`. Calibration uses one hand-written near-miss pair per question, judging only that question; the negative differs in the behaviour that question checks. Accounting reconciles expected and observed invocation IDs by purpose, rejects duplicates, and sums the captured tokens and duration. A stopped run reports planned and actual counts with its stopping reason; it does not assert completion. Any price is the host's actual reported value; absent monetary accounting remains absent.

## Stages and verification

1. The chosen host passes a bounded health/isolation probe; its event grammar is observed rather than guessed.
2. A public runner test proves one case is staged without its rubric, then implementation makes that test pass. Each following test adds one behaviour: preservation/refusal, host failure/timeout, calibration, quotation validation, blinding, nine-run accounting and report verdicts.
3. The fixture records the historical source and the exact difference, plus labelled reconstruction and hand-labelled calibration answers.
4. The live experiment calibrates the judge, executes the nine runs, checks accounting and writes its report. An independent reader checks the staged inputs and actual access evidence.
5. Independent review, the project's verification set, then commit. Completion and paired archive require every ticket criterion, including the live observation.
