# Each hook runs in every clone, finding its interpreter without uv — implementation plan

**Authored:** 2026-10-09
**Last amended:** 2026-10-09

## Governing decisions

- [Architecture — Installing](../../architecture.md#installing): the link step records the
  interpreter that ran it in the clone's Git directory, which no commit carries; every
  core hook runs through a wrapper that reads it; a clone without the record is told which step
  makes it. Landed in this pass *(the user, 2026-10-09)*.
- Same section: core's hooks are the questions mechanism's shelf at each host file's path, merged
  beside the project's own; an update removes an entry the previous ref wired and this one does not
  ([`.0173`](01-0010.0173-an-install-merges-cores-hooks-into-each-hosts-file.md)).
- `questions.py --hook` never fails the host and answers in each host's own form
  ([questions — Delivery](../../../.agents/mechanisms/questions/questions.md)); the wrapper keeps both.

Every shell the hosts were seen to use has `git` on its path, and every tree core reaches is a Git
repository by the install's own contract — so `git` launches the wrapper, and one command serves
every host and platform.

## Shape

### The record — the link step's

- `--links`, and the link step inside `--install` and `--update`, write `sys.executable` — the
  interpreter running the installer, which by that fact runs — to `gw-interpreter` in the clone's
  Git directory, one line, located by `git rev-parse --git-path` as the exclude file is. Inside
  `.git` it is no file of the tree and needs no exclude line: Git's listing, and so `corpus`, the
  ref gate's *own* list and the shape check never see it, and no commit can carry it.
- A record already naming an interpreter that exists is left alone; one naming a missing path is
  rewritten. The report says which, as it does for a link.
- The origin takes it the same way: `harness.py . --links` in this tree.

### The wrapper — one file, launched by Git

`.agents/scripts/gw/hook.sh`, POSIX sh, taking the host's name as its one argument, run by Git's
alias from the tree's top level:

- the record found by `git rev-parse --git-path gw-interpreter`, from the working directory Git
  has made the tree's root;
- with an interpreter that exists, it runs `questions.py --hook <host>` under it, passing the host's
  payload on stdin through and its exit status back, so the store's script stays the only thing
  that answers;
- without one, it prints one line naming the step — `python .agents/scripts/gw/harness.py . --links`
  — in the host's own form (plain for `claude-code` and `codex`, `{"additional_context": …}` for
  `cursor`, the forms `questions.hook` already writes) and exits 0, so a missing record never holds
  back the person's message.

No `cmd` twin and no per-platform command: Git's `sh` is the one shell every host reaches. The
alias is named `gw-hook` — Git's own `hook` command would shadow an alias of that name.

### The commands — the shelf's

The three shelf files under `.agents/skills/questions/hooks/` take one command form in place of
`uv run …`, the host's name its last word:

    git -c "alias.gw-hook=!sh .agents/scripts/gw/hook.sh" gw-hook <host>

This tree's host files follow by the origin test `.0173` added. A recipient's update removes the
`uv` entries through the previous ref's shelf. A recipient whose announced ref predates the shelf
(the study tree, at `b048a88`) has no previous shelf to remove them by: updating first to a ref
holding `.0173` and then to this one removes them; a single jump leaves both sets running.

## Impact

**Impact.** `harness.py`'s link step gains the record; one wrapper file and
its tests; the three shelf files change their commands and this tree's host files with them;
the harness skill is left as it is *(the user, 2026-10-09)*; the architecture's *Installing* gained its sentence in this pass. The straw dogs bound to
q-0018.0020.0005 in `docs/product.md` and the front page retire once the live boxes are checked,
since `uv` was their only remaining caveat.

**Hidden edges.** Codex re-asks trust for each changed command, once. A clone moved to another
machine carries no record (no commit holds it), so it gets the notice, as a fresh clone does. A record
naming a virtualenv that is later deleted gets the notice on the next prompt, not a failure. A
machine whose shells lack `git` on the path runs no hook at all — the same machine could not have
run the install. Windows PowerShell 5.1 pipes the payload in its own output encoding, which can
mangle non-ASCII; Cursor's start payload carries none, and the window is the hook's output, not
its input.

**Leave alone.** `questions.py --hook` and its answers; the merge; the gate's reporting
([`.0176`](../../tickets/done/01-0010.0176-a-failed-gate-says-why.md)); `uv` as the habit of the
verification set.

**Recommendation: proceed.**

## Stages

1. **Probe** *(HITL, done 2026-10-09)* — a throwaway folder whose three host files wrote which
   shell ran each hook and from where; Claude Code and Cursor run by the person, Codex not signed
   in; then the `git` alias tried by hand in the three shells the hosts use. Its findings are the
   table above.
2. **The record** — `test_harness`: `--links` and an install write the interpreter running them
   into the clone's Git directory; a record naming a live interpreter is left; one naming a
   missing path is rewritten. Then the step.
3. **The wrapper** — tests run the shelf's own command through `git` in a fixture repository,
   from a subfolder, with a record naming the running interpreter: the store's answer comes back
   for a payload, stdin intact; with no record, the one-line notice in each host's form, exit 0.
   Then the file.
4. **The commands** — the shelf files take the one command form; this tree's host files follow;
   `harness.py . --links` here; the origin test, the shape check, the injector's check, the suite.
5. **Live** *(HITL)* — on a clone with no `uv` on the path, each host's session-start hook, and
   the prompt hook where the host has one, delivers the window; on Windows each host's shell named
   in the ticket.

## Out of scope

- A wrapper for hosts beyond the three.
- Removing `uv` from the verification set and the harness's own habit.
