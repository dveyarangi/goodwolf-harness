# A failed install gate says why it failed — implementation plan

**Authored:** 2026-10-10

Implements [01-0010.0176 a-failed-gate-says-why](../../tickets/done/01-0010.0176-a-failed-gate-says-why.md).

## Governing decisions

- [Architecture — Installing](../../architecture.md#installing): arrival is the check — the ref
  compared, the injector's check, the shape check, run as the target's own scripts. Nothing here
  moves that; only what the report carries of a script gate changes.
- Both scripts print one JSON report whose `diagnostics` list is the reason a check fails:
  `inject_rules.py --check` exits 1 exactly when that list is non-empty; `mechanisms.py --check`
  lists its `{mechanism, problem}` records there.

## Shape

`_script_gate` keeps `passed` and `exit` and fills `said` from the script's own report: its
`diagnostics`, whole and in order. A passing gate's list is empty, so its entry is shorter than
today's three closing lines. Output that is not a JSON object with that list — a crash, a
traceback — keeps today's fallback, its last lines, so a gate that died still says something.

No new field: `said` already means what the script said, and the person reads it in the same place.

## Impact

**Impact.** One function in `harness.py`, its tests. No contract, record or doc moves; the
architecture names the gates, not the shape of their entries.

**Hidden edges.** A diagnostic list can be long; it is the reason, and the report is read by the
person who must act on it, so it is not truncated. The ref gate already lists what differs and is
untouched.

**Recommendation: proceed.**

## Stages

1. `test_harness`: an install whose shape check fails carries each shape diagnostic in
   `gates.shape.said`; a `--check` over a recipient whose installed block was edited carries the
   injector's `drifted` diagnostic in `gates.injector.said`; a passing install's script gates say
   nothing; a script whose output is not JSON keeps its last lines. Then `_script_gate`.
2. The verification set.

## Out of scope

- The ref gate's entry, which already names each differing file.
