## The shapes

1. **The fit reads a clone's room.** `_fitted_slug` cuts while the entry's `done/` path, measured
   from the longer of this tree's root and a constant room for a clone's folder, `CLONE_ROOM =
   128`, passes `PATH_LIMIT`, or its file name passes `NAME_LIMIT`, 255 UTF-8 bytes: at a word
   boundary, and inside the one word left, which a script written without spaces needs. Every
   write already goes through it (`open`, `reword`, `move`). The check accepts `_slug`, the fitted
   slug, or the fit from the tree's own root alone that names were written by before, so the names
   already written in this tree and in any recipient stay valid and nothing is renamed: in this
   tree 110 entries pass the new fit in their `done/` form. `SLUG_LENGTH` stays as the cut ten of
   them carry.
2. **A slug is written in any script.** `_words` keeps letters, digits and the marks written on
   them, everything else a separator, in the question lower-cased and composed (NFC), so a name
   reads the same from a filesystem that decomposes. `_ENTRY_NAME` reads a slug's words as
   anything between separators, and leaves their content to the slug comparison. Its other user,
   twin detection, gains words; its stopwords stay English.
3. **The hook says why the store is short.** On a machine that stops paths at `PATH_LIMIT` —
   Windows with `LongPathsEnabled` off, read from its registry — any store name `HEAD` holds past
   the limit from this root was never checked out, or cannot be read if it was. Before drawing
   anything at a start or a message, `hook` refuses when there is one; `docs_corpus.committed`
   reads `HEAD`'s names from the commit, since the index may never have been written. Elsewhere
   nothing is refused, so an entry a close moved and no commit has carried yet never reads as a
   short checkout. The refusal goes through the existing boundary, so it reaches the agent in the
   host's form, a start's with the installer's line kept, and names the count, the longest path's
   length, and the remedy — a shorter clone folder, or long paths on in Windows and in Git and a
   fresh clone. The test fixture rebinds `committed` to the folder's own listing, as it rebinds
   `corpus`.
4. **The skill names the `py` launcher.** Under the harness skill's command block: on Windows a
   bare `python` may be the Microsoft Store stub, which runs nothing; run the commands with the
   `py` launcher (`py -3`). The closing sentence that says a bare `python` works is corrected.
   `hook.sh` already runs the recorded interpreter; its notice for a clone with none names the
   launcher too.

## Impact

Narrow: the store's naming and its hook, one helper in `docs_corpus`, one fixture binding, one

changes; an installed tree takes the change at its next update. Proceed.

## Out of scope and follow-ups

- Renaming the 110 entries past the new fit — through the store's move, on the person's word;
  until then a clone of this tree into a folder deeper than about 55 characters is cut short on a
  machine without long paths, and the hook now says so.
- A Store-installed real Python records a path under `WindowsApps`; whether Git's `sh` sees it as
  a file is not checked here.
- Windows with long paths on but Git's `core.longpaths` off: Git is reasoned, not probed, to cut
  the checkout short there too, while the hook reads the machine as unlimited and stays silent.
- The citation reader (`docs_corpus.PATH_LITERAL`) stops a store name at its first combining
  mark, so a Hindi or Thai entry's citation reads cut short.
- Windows counts its limit in UTF-16 units and the fit in code points: a question in characters
  past the basic plane can still pass the limit.
- Twin detection's stopwords are English, so two Russian questions sharing `как`, `что`, `в` and
  `и` read as twins — a finding, never a failure.
