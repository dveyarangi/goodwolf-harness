## What changes

### The license travels

`Source.files` reads the root license apart from the archive and places it at `.agents/LICENSE`
among the files it returns; a comment there says why. Apart, because `git archive` refuses a
pathspec that matches nothing —
`git archive 1475df1 -- .agents AGENTS.md CLAUDE.md LICENSE` exits 128 — and every ref before this
one has no root license: naming it in the archive would refuse every existing tree's update and
check, [rule failure 9](../../rule-failures.md)'s class. Read as the commit's blob, so no line-ending
conversion touches it; absent, nothing is added.

Everything else follows from the existing machinery and needs no new flow:

- `shipped` passes it through verbatim — neither `.md` nor `.py`.
- An install writes it, and refuses when the target already holds a file there, as for any
  manifest path.
- An update replaces it, and a later ref that drops it deletes it, as what left the manifest.
- `--check`'s ref gate compares it like any core file, so an edited one fails the gate.
- `Shipment.earlier` over a pre-license ref reads none and refuses nothing.

The harness skill's *What a run does* names it beside the entry file and the host stub. The harness
doc's parts table gains no row: the license lives at two paths — the source's root and a
recipient's `.agents/` — which one row cannot name, and the shape check reads every row in every
tree; the prose under the table says so, as it does for the loader links.

### The page

The root `README.md` becomes this text, as the front-page align settled it — *Not yet*'s items
aside, which are the ticket's bindings table:

```markdown
# GoodWolf Harness

Coding agents are capable engineers who forget everything when the session ends — and a different
one arrives next time. The harness gives that workforce an institutional memory in the repository:
what was decided and why, what is unfinished, what was verified and against what. Each session
reconstructs where the project stands from those records, not from a chat that is gone.

The harness is yours to change. Your project's own rules — its test commands, whether the agent may
commit without asking — go in one local file that every install and update applies last; to change
a shipped rule, you override it there by name. You can add skills of your own: `/mechanism`, the
skill for declaring one, walks you through it, and the same checks then hold your skill as hold the
shipped ones. And when a rule was in place but the agent didn't follow it, the case is written down
and the rule reworded — a postmortem aimed at the instructions instead of the code.

## How it works

A session starts with `/recall`, which reads the project's records and finds where the work
stopped. `/align` settles with you whatever needs deciding, and the work picks up from there — one
step or several, through as many pieces of work as the session holds — until `/conclude` writes
down what the next session needs. A piece of work moves `/ticket` → `/plan` → `/implement` →
`/verify` → `/maintain`: it becomes a ticket with checkable acceptance criteria, gets a written
plan, is built test-first where it can be, and is verified against its ticket, its plan and the
project's own checks. Whenever a step needs a decision, it goes back to `/align`. `/maintain` is a
separate step for drift: it checks that the repository's documents still agree with each other and
with the code, and repairs what doesn't.

![The session ring joined at /align to the delivery ring, around the project's records](dev-skills-readme.png)

Decisions live in the architecture, ADRs and glossary; open work lives in tickets; session records
are history, never the authority on what is still open. What each record looks like is in its
format file: tickets, ADRs, architecture, glossary.

Where a person has to say yes is a switch — commit, push, start the next piece of work, split work
into tickets — each `ask` or `auto`, and one more for whether a clear rule violation is fixed and
reported or shown to you first:

    commit=ask · push=ask · next-cycle=ask · breakdown=ask · repair=report

The loop and its rules are in AGENTS.md, every skill under `.agents/skills/`, and the harness's
vocabulary in `.agents/glossary.md`.

## What holds it together

- **Two looks before a decision.** `/impact` looks inward: what a change touches in this project,
  and whether a mistake there would break one part or several. `/discover` looks outward: it hands
  the question to a separate agent that hasn't read the project, so you get an outside view of what
  the thing is and how things like it usually go wrong before settling on your own.
- **One home per rule.** A rule is written once, in its owner's rules file, and copied into every
  skill that reads it — in AGENTS.md you can see such a copy, `<installed by="ticket">`, whose
  source is `ticket.rules.md`. A copy that drifts from its source, or that nothing owns, fails the
  check.
- **Rules that fail get reworded.** When a rule was in place and the agent didn't follow it, the
  case is written down — which rules were in play, why this one didn't fire, how it is reworded —
  and the next time the situation comes up shows whether the rewording worked.
- **Every part of the method says what it is.** A skill that other work relies on is declared
  through `/mechanism`: its parts, the moments a person acts on it, what it produces and who reads
  that. A script checks the declaration is true.
- **The checks travel.** An install ends by running them inside your project, and your project can
  keep them in its own verification.

## Where it stands

**Works today:** the skills, for Claude Code, Codex and Cursor; installing into a project, updating
it to a later version, and checking that the installed copy is intact, with your project's own
rules applied last; one home per rule, with drift detection; checks on the harness's own records
and declarations. The harness is developed with itself.

**Not yet.** In the source of this page, each item below is wrapped as a *straw dog* —
`<straw-dog until="…" ticket="…">` — naming the condition that retires it and the ticket that will. That is how the harness marks anything
provisional, in its own rules as much as here; a script lists every one, so nothing provisional
passes for settled.

## Use it

    git clone https://github.com/dveyarangi/goodwolf-harness.git

From your project's root, have your coding agent read `.agents/skills/harness/SKILL.md` in the
clone and follow it. It installs the harness, reports what arrived, and sets up your project's own
rules with you — its checks and its switches. What it runs is one script,
`python <clone>/.agents/scripts/gw/harness.py . --install`, which writes nothing if it refuses and
says why. Updating to a later version and checking the installed copy are in the same skill.
Python 3.12 or later, standard library only. MIT licensed.
```

Its links, all into core: `AGENTS.md`,
`.agents/skills/`, `.agents/glossary.md`, the four format files

## Impact

**Must change:** `Source.files` and its docstring; `test_harness.py`'s source seed, which gains a
root license so every two-tree case ships one; the harness skill's *What a run does*; the harness
doc's note under its parts table; the root README; `/maintain`'s T1; the queue's verification-set
line.

**Must verify:** `ATreeInstalledUnderEarlierRules` — an earlier ref without a license updates and
the update writes one; `AnUpdateAcrossTheScriptsMove`; every install assertion over `written` or the
manifest, which gains one path; the three gates in a real install from the pushed ref.

**May simplify:** nothing.

**Hidden edges:**

- **An update writes a new manifest path over whatever the recipient holds there.** An install
  refuses on such a file; an update compares only the paths the *previous* ref shipped. Neither
  real recipient holds `.agents/LICENSE` (checked 2026-09-26), and the gap is general to any path a
  later ref adds — [01-0010.0150](../../tickets/01-0010.0150-harness-meets-a-tree-with-a-method.md)'s
  collision class, not this slice's.
- **An edge change.** Every recipient receives a new file at its next update; it owes the edge
  record a line when [01-0010.0185](../../tickets/01-0010.0185-an-edge-change-writes-its-line.md)
  builds it, as the repository line and the delivery status do.
- **The page quotes live facts no check reads** — the switch line and the installed-block example.
  A renumbered rule or a new switch leaves it stale in silence; accepted, since the page is read
  every time it matters and the adoption panel at a release reads it cold.
- **Whether GitHub hides the inline tags** is unverified; the page's own line says the tags are in
  its source, so a render that shows them is still true, only noisier.

**Leave alone:** the manifest's other members, the shear, the stamp, the leak rule; the harness
doc's *the README is not a part*; `.0190`'s published front page.

**Recommendation:** proceed.

## Stages

1. **The license travels — red, then green.** In `test_harness.py`, before the code:
   - an install places `.agents/LICENSE` byte-identical to the source's root `LICENSE`, and a
     target's own root `LICENSE` is byte-identical after it;
   - an update after the source's license changes carries the new text;
   - `--check` over an edited `.agents/LICENSE` fails the ref gate and names it;
   - an install at a ref with no license arrives and writes none;
   - `ATreeInstalledUnderEarlierRules`' update names `.agents/LICENSE` among what it wrote;
   - an install into a target already holding `.agents/LICENSE` refuses and writes nothing.

   Each fails for the named reason on today's code — the last because today's install would not
   refuse at all, so its assertion names the path — except the target's own root `LICENSE`,
   which passes today and is kept as a guard that the new write never reaches the root. Then
   `Source.files`. The whole suite green.
2. **The docs.** The harness skill's line and the doc's note. `mechanisms.py --check` and
   `inject_rules.py --check` clean.
3. **The page and the listing.** The README, T1 and the queue's line. `straw_dogs.py docs
   AGENTS.md local.rules.md .agents README.md` lists the eight, each bound, with no diagnostic; each
   relative link in the README names a file that exists.
4. **Live.** After the push: the README as GitHub renders it, and an install from the pushed ref
   into a scratch tree holding `.agents/LICENSE`, with `arrived: true`.
