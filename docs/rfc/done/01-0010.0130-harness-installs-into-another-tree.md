## Shapes

### The source: a repository at a ref

`--from <repository>` is a git URL or a local path, defaulting to `https://github.com/dveyarangi/goodwolf-harness.git`,
a constant in `harness.py`; `--at <ref>` is a branch, tag or commit, defaulting to the clone's
`HEAD`. Every mode clones `--from` whole and without a checkout into a temporary directory,
resolves `--at` to a full commit, and reads everything through git: `ls-tree -r --name-only <ref>`
for the manifest, `show <ref>:<path>` for each file's committed bytes, `log -1 --format=%cs` for
the commit's date, `describe --tags --exact-match` for a tag. A working tree is never read, so
what ships is what a commit holds. The clone is removed when the run ends.

The repository's **name** is the last segment of `--from` without `.git`. A ref that does not
resolve in the clone refuses, naming both.

### The manifest

At the ref: every path under `.agents/`, plus `AGENTS.md` and `CLAUDE.md`. Nothing else travels —
not the root README, which a recipient has its own of; not `local.rules.md`; not `docs/`; not the
loader links, which the installer makes rather than copies. The gate `.0050` left is the reverse
pass at the origin: every skill directory is claimed or named, so what ships and what is claimed
stay one question. The ticket's step 2 is corrected to this at `/implement`.

### What ships is transformed in memory before a byte is written

For each `.md`, in this order, on the code-blanked text so an illustration in a fence or a code
span is never touched:

1. **Local blocks removed** — every `<installed by="local">` block with the newline the injector
   added, through the injector's `locate` and `without_block`.
2. **The shear** — every operative `<straw-dog …>` opening and `</straw-dog>` closing tag removed,
   at any depth: a tag alone on its line takes the line; an inline tag leaves the text joined as
   written. Found by the lister's tag walker; the shear itself is new code in `harness.py` on that
   parser. Idempotent: text with no wrapper passes unchanged, so a pure core repository is one more
   `--from`.
3. **The leak gate** — `docs_mentioned` over the sheared text; a path that is neither a painted
   door nor inside an instance-owned block refuses the run naming file, line and path. It cannot
   fire on a ref whose origin check passed; it is here so an unchecked ref cannot ship one.

For each `.py`: a comment line beginning `TODO` loses its ticket path and the space before it —
`# TODO docs/tickets/x.md: words` becomes `# TODO: words` — and a `docs/` literal that remains is
a leak and refuses. Test files are sheared and never read for leaks, as the check reads them.

For `AGENTS.md`, one more: **the stamp** — the announce line becomes
`Entry contract: <name>@<ref>, <date>.` with the tag where the commit has one, the short commit
otherwise, and the commit's own date. A ref whose entry file has no announce line is not this
harness and refuses. `CLAUDE.md` ships verbatim.

**The transformation is part of the contract.** A recipient's copy is compared against the
transformed content of its announced ref, produced by the `harness.py` doing the comparing; a
change to the shear, the stamp or the local-block strip therefore reads as an edit in every
recipient installed before it, until `--update --overwrite` brings the copy to a ref that carries
the change. Stated here so a later change to any of the three is made knowing its reach.

### The announce line is the revision

`docs_corpus.ANNOUNCE` reads `^Entry contract: (.+), (\d{4}-\d{2}-\d{2})\.$` and
`docs_corpus.announced(root)` returns the `<name>@<ref>` pair or `None` where the line has no `@`.
Both `harness.py` and `mechanisms.py` read through it. No other record is written: a recipient's
line is what its sessions announce, and it is what `--check` and `--update` read to know what was
installed. A line whose name differs from `--from`'s name refuses: *the tree announces
`goodwolf-harness`; `--from` names `other`*.

### The target, and what is refused before anything is written

The target operand is required in every mode; `.` is fine. It must be the top level of a git
work tree — `git rev-parse --show-toplevel` equal to it — so the scripts' root and the corpus's
`git ls-files` both hold; a workspace holding several repositories is not one and is refused as
such. A target whose `origin` remote is `--from` is **the source** and is refused: the origin is
never installed into, and its line never gains an `@`.

- **`--install`** refuses a target where any manifest path already exists: *a previous install takes
  `--update`; anything else is the recipient's to move first*.
- **`--update`** refuses a target without `.agents/`; one whose entry file holds a
  `<project-local>` block, read through `without_code` — *move its content into `local.rules.md`
  first*, since the block is the project's and the file is overwritten; and, where the line
  announces a ref, one whose core file differs from that ref's — local blocks removed, line endings
  normalised — unless told `--overwrite`, and then every such file is replaced and named in the
  report. Where the line announces no ref, `--overwrite` is required and nothing is deleted.
Every refusal writes nothing and names its step. The loader links are not a refusal: they are
the one step a person may have to finish, below.

### Copy, delete, stamp

Every manifest file's transformed bytes are written to the target, `\n` as committed. Under
`--update` with a previous ref, a path in the previous manifest and not in the new one is deleted;
a path under `.agents/` in neither is the recipient's own, left alone and reported. `.agents/README.md`
is in the manifest and says what the links are; the recipient's own `README.md` at the root is
never touched. A write that fails partway follows the mover's contract — done, pending, the
failed path, nothing rolled back — and the resume is `--update --overwrite` once the cause is
fixed. `harness.py` sets `sys.dont_write_bytecode` before its imports, so a run from inside a
recipient leaves no `__pycache__` beside its scripts.

### The loader links

`.claude/skills` and `.cursor/skills`, each to `../.agents/skills` — both required, observed
2026-09-21 ([ADR-0003](../../adr/0003-one-physical-home-for-skills-reached-by-link.md)). Made after
the files are written and before injection. A symlink already resolving to the skills directory
is left untouched; one resolving elsewhere is repointed; a junction —
`st_reparse_tag == IO_REPARSE_TAG_MOUNT_POINT` — a real directory or a file is refused by name as
the recipient's own; nothing there is created. **Where creation is refused by the platform**
(`WinError 1314`, the case on every Windows machine without Developer Mode), the run does not
stop: it records the link as pending, carries on to inject and the gate, and the report ends with
the exact command for the person to run once in an elevated prompt, with the target's absolute
path filled in:

```
mklink /D "D:\x\.claude\skills" "..\.agents\skills"
mklink /D "D:\x\.cursor\skills" "..\.agents\skills"
```

The target is relative, so the link is the same one git tracks; on a platform other than
Windows the line is the equivalent `ln -s`. `arrived` is false until `. --check` finds the links
resolving. Nothing is substituted and Developer Mode is asked of nobody *(the user, 2026-09-21)*. The skill tells the agent running the install to present that
command to the person verbatim. The installer never touches the target's git index or
`core.symlinks`; where that setting is `false` it reports that a fresh clone will check the links
out as text.

### Inject, in the target

For each rules file under the target's `.agents/mechanisms/*/`: `inject_rules.install(target,
rules, overwrite=False)` — `present` by construction. Then, if `local.rules.md` sits beside the
target's entry file, `overrides_resolve` and `inject_rules.install(target, local, overwrite=False)`.
A refusal — an override naming a rule the new core no longer sends there, a local anchor a new
core anchor now follows — is reported verbatim and the run is unfinished; the resume is *fix the
local file, `inject_rules.py local --install`, then `harness.py . --check`*. The local file is read
and never written.

### The gate, which is `--check`

Three gates, each reported with its evidence, `arrived` true only when all hold *(five as
planned; the links and the shipped suite left the verdict at the live run — the user,
2026-09-21: an install is seconds, and a pending link is already the report's one instruction)*:

1. **The ref**: every manifest file's transformed content at the announced ref compared with the
   target's, local blocks removed from the target's side and line endings normalised on both; a
   differing or missing file named; a file under `.agents/` outside the manifest reported as the
   recipient's own.
2. **The injector's check**: `<target>/.agents/scripts/inject_rules.py --check` clean.
3. **The shape check**: `<target>/.agents/scripts/mechanisms.py --check` clean.

Beside the verdict, `links_resolve`: per loader link, whether a symlink stands there and reaches a
directory holding a `*/SKILL.md`. It decides nothing. The shipped suite is not run: it costs
minutes, and a recipient that wants it names it in its own verification set.

Gates 2 and 3 run the target's own scripts as subprocesses with `PYTHONDONTWRITEBYTECODE=1`,
so what is checked is what arrived and nothing is left behind. After an install or update the gate
reuses the run's clone; `--check` alone makes its own. Whether a host reads the link is reported
as unverified; the recipient's first session announcing the stamped line is the evidence a person
reads. The exit status is 0 only when `arrived` is true, 1 for a refusal or an unfinished run,
2 for usage, as the other scripts do.

### The recipient rule in `mechanisms.py`

`check(root)` reads `announced(root)` once: in a recipient a `not yet` — a moment row or a skill's
claim — with no binding draws neither *unbound* nor *does not say why*, since the shear removed
both; at the origin both stand. The `TODO` beside the unbound diagnostic goes, its fact now real.
Nothing else changes: a recipient's own skill still claims or fails, its own leak still fails.

row, an entry file with the announce line and a straw dog, and the host stub. The gate cases
cost a few seconds each for their clone and two subprocesses; the shear, stamp, manifest and
refusal cases run no gate. Each case proves the reason: a refusal names its step and
path; the gate's report names the failing gate; gate 1 names the file; the shear case asserts the
joined text; the skip for symlinks records why, so a recipient's run of the suite says it too.

## Limitations and follow-ups

- **The links are the one step a person may finish by hand**, on every Windows machine without
  Developer Mode, this one included; the script says so with the command and nothing else stops.
  frost_map's links exist, so its update creates none. Both links are needed: observed
  2026-09-21, on ADR-0003.
- **Painted doors are not created in a fresh tree.** No declaration parses its records yet;
  creating an empty `docs/cicd.md` from a holding list would be a guess. A `not yet` row bound
  to 01-0017.0010.
- **A recipient's own skill under `.agents/skills/`** survives an update and fails its reverse
  pass until it claims — `.0050`'s edge, as designed.
- **An install needs the network** unless `--from` is a local clone; `--check` too. The price of no
  record file, by the rule that landed at v14.
- **Releases** are tags, read by `--at`; nothing about cutting one is built. **Removing one
  mechanism** and **contribution back** stay 01-0010's and the spec's.
- **Two mechanisms name `AGENTS.md`** — the file the harness mechanism's, two lines mechanism-shape's — and the
  check does not ask about overlap; the doc says so.
- **A change to the transformation reaches every recipient** as a reported edit until it updates;
  stated under *The stamp*, not guarded.
- **The links are not parts of the harness mechanism.** Listed as parts, a pending link failed
  the recipient's shape check for the absence the report already named — seen at the live run,
  and the reason they left the parts table and the verdict.
- **Reading a ref is one `git archive`**, not one `cat-file` per file: sixty-five spawns cost
  seven seconds, more than the clone. The archive is read with `core.autocrlf` off, since
  `archive` smudges like a checkout and a Windows clone would otherwise ship carriage returns.

## Resolved at `/plan`

Local, reversible, stated so `/implement` does not choose again:

1. **The clone is whole and without a checkout**, refs read through git plumbing: a short commit
   cannot be fetched by itself from GitHub, and a checkout would translate line endings on Windows.
2. **The previous ref is read from the same clone.** One clone per run.
3. **The shear lives in `harness.py`** on the lister's tag walker; a second caller moves it to
   `docs_corpus.py`.
4. **A `TODO` keeps its words and loses the space and path**; the guesser in a recipient lists it
   as a candidate, which is what an unbound `TODO` is.
5. **Local blocks are stripped through the injector's own functions**, both when shipping and when
   comparing.
6. **A link that resolves is left alone**, and a link the platform refuses is pending, not a
   refusal: the files, the injection and the gate are worth more to the person than a clean stop,
   and the command in the report is the whole remaining work.
7. **The target is always explicit**; the other scripts' *the tree I live in* convention does not
   fit a script that acts on another tree, and `.` costs one character.
8. **The origin is refused by its remote**, since its line looks like a release's.
9. **The gate runs the target's scripts as subprocesses**, so what is checked is what arrived; and
   without bytecode, so nothing is left in the recipient.
10. **The entry file's straw-dog sentence is not reworded**: a recipient has no wrapper in core
    for it to misapply to, and its own `docs/` straw dogs are rightly governed by it.
11. **The root README is the repository's front page, not a part.** Declared nowhere, named in
    the doc's prose, and kept to what an agent needs to get to the skill.
12. **A ref with no announce line is refused**, rather than stamped into a file that never had
    one: a core without the line is not this harness.
