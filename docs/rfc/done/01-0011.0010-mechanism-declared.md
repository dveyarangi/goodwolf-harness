## Shapes

### `/mechanism` — the skill

`.agents/skills/mechanism/SKILL.md`. Body carries the shape and nothing else: the membership test
(reliance, not code; a system, never a file); the three homes and the instruction→doc→evidence
chain; the directory layout; injection and retraction; the moments taxonomy with its four kinds of
absence and the rule that **every row states why, in a clause** — a label alone is a verdict, and a
verdict nobody can check is what this mechanism exists to abolish; incept and amend, incept opening
with `/align` on what the mechanism is in plain terms and closing on *name what retires it* and
*name what will grade it, and it is not you*; and the four rules the direct read added — watch it
fail both polarities, run it over what already exists, absence is not clearance, one canonical home
per fact.

**Its description is tier 1** and carries the trigger: *before building or amending a mechanism,
use `/mechanism`*. It does two jobs at once — narrate the use case, which `/skill-up` requires, and
route to the skill — and that is the case the spec already names as where the tier heuristic
breaks: one file spanning two tiers. Both jobs fit one description or the trigger is not tier 1.

**The `AGENTS.md` copy goes in *General rules*, not under *Helpers*.** That section already holds
the rules about how shapes are treated, it is read before the loop, and `/mechanism` is not a
helper of the delivery ring — it governs how the harness's own parts get built. `Helpers` lists
`/impact`, `/discover` and `/dream`, all of which serve a ring step; putting a meta-rule there
would misfile it as a fourth of those. And — the part worth copying from Life — **the line is
declared as a part of the mechanism**, so retracting the mechanism removes its own trigger.

**`/skill-up` governs the body's writing and constrains it in one way this plan must respect:** *a
fact the set already states in one skill is referenced from there, not restated.* The glossary owns
**Mechanism**, **Skill**, **Moment**, **Doc**, **Evidence**, **Provenance**, **Authority**,
**Tier** and now **Part**. The body **uses** those terms and defines none of them; what it owns is
the taxonomy and the rules, which the glossary does not hold. Provenance stays inline on each rule,
per the spec — that is not the *evolution logic* `/skill-up` bars, and the two rules do not
collide.

**The body ends with a siblings paragraph**, as Life's does and as `/skill-up` requires of any
intentional overlap: `/skill-up` writes a skill's text where this governs the system; `/impact`
traces consequences where this asks whether a mechanism is sound at both ends; `/maintain` applies
mechanism rules and owns none; `/align` is called by incept before anything is built. Naming them
is what stops the next reader from merging two of them.

`.agents/skills/mechanism/MECHANISM-FORMAT.md`, the format shelf: the directory and filename
convention, the doc's sections, the two tables' headers and their cell vocabularies. Mirrors
`TICKET-FORMAT.md`, which exists for the same reason — what a script parses needs one exact
statement. It also declares the record shape for mechanism directories, since with no register
file the directories are the records.

### The doc — `.agents/mechanisms/mechanism-shape/mechanism-shape.md`

Life's shape, which is tighter than the one this plan first proposed:

```
# mechanism-shape — <what it is, in one line>

- **instruction** `<path>` — what it holds
- **state** always on
- inside a `<project-local>` block, both optional: **evidence** `<path>`,
  **declared by** `<ticket path>`

## How it works        prose; never parsed

## Moments             | moment | instructed by | kind, and why |

## Install adds, uninstall removes    | part | where |

## Relies on, and does not own        | part | where | owner |

## Not yet at the shape               prose; the honest gaps

## What retires this

## What would show it working, graded by someone who did not build it
```

**Moments** is three columns, not four. `instructed by` is a backticked path or `—`; `kind, and
why` is empty when instructed, else one of `elsewhere`, `embedded`, `unowned by design`, `not yet`
followed by a clause and, for the first two and the last, its referent. `not yet` carries a
markdown link to a ticket that exists — **never this mechanism's own migration ticket**, which
closes when the mechanism reaches the shape and cannot carry a change of behaviour.

**`declared by` is what makes the *never its own migration ticket* rule checkable.** Both it and
the evidence path sit in the same `<project-local>` block, so the check reads one block and core
still names no `docs/` path of its own.

**Both are optional, because a recipient replaces that block** — and a mechanism with no evidence
yet, or none declared by a ticket, is a legitimate state, not a defect. **An absent `declared by`
therefore disables one diagnostic, and the check says so in its output rather than passing
quietly.** A skipped check reported as a clean one is *absence is not clearance* committed by the
tool that exists to enforce it.

`mechanism-shape`'s rows:

| moment | disposition |
|---|---|
| deciding whether a thing is a mechanism | instructed — `/mechanism`, routed from `AGENTS.md` |
| incepting one | instructed — `/mechanism` |
| amending a declared one, including editing a skill that is one's instruction file | instructed — `/mechanism` |
| checking a declaration is true | instructed — `/mechanism`, and the project's verification set runs it |
| installing a mechanism's rules into skills it does not own | `not yet` → [.0020](../../tickets/done/01-0011.0020-rules-one-home.md) |
| retracting them | `not yet` → [.0020](../../tickets/done/01-0011.0020-rules-one-home.md) |
| re-checking a mechanism when what governs it changed | `elsewhere` → `/maintain`'s instruction file |
| writing or changing a skill's text | `elsewhere` → `/skill-up`, a sibling mechanism's subject |
| finding a mechanism's doc for lifecycle work | `unowned by design` — the directory is a routing table; looking a path up needs no rule |

**Install adds, uninstall removes** is the parts table, and its title is its definition. `part` is
a role name, repeatable; `where` is a backticked repo-relative path, optionally with an anchor.
Counter-test: **if uninstalling would not remove it, it is not a part.**

**And this mechanism has no installer, which the title must not pretend away.** `mechanism-shape`
is always on — nothing can install or uninstall the thing that defines what installing means — so
for it the table is *what a person moving this between trees takes*, which is what Life's own
always-on doc says of the same table. The title states the rule for mechanisms in general; the
`state` bullet is what tells a reader which reading applies. A table whose title describes an
operation the mechanism cannot perform would be the first thing a reader distrusts.

**Two tables, not one with an owner column** — corrected on the second pass. A relied-on part is
by definition *not* added by install, so putting it in that table contradicts the table's own
title. Relied-on parts get their own short list, **Relies on, and does not own**, each naming its
owner. `docs_corpus.py` and `tests/harness.py` go there, owned by nobody removable, per the spec's
shared-parts rule. This is what satisfies the ticket's *names every part with its owner*.

**An anchor is `path → "literal phrase"`, and the phrase is checked verbatim.** Life checks paths
and not anchors; that leaves the `AGENTS.md` trigger deletable with the check still green, which
is unacceptable in the one slice whose subject is checkable declaration. A verbatim substring is
cheap and catches deletion. Its cost is real and stated: rewording the trigger means editing two
places, which is exactly the duplication [.0020](../../tickets/done/01-0011.0020-rules-one-home.md)'s
injector removes. Interim, and named as one.

**Cells split on unescaped `|`; a literal pipe is `\|`.** A row whose cell count differs from the
header is a diagnostic, not a silent misparse.

**What would show it working** is pre-registered, in a form a later session can answer without
asking what was meant, and this session does not answer it. Draft: *the next mechanism declared —
`/maintain` at `.0022` — either passes the check unedited, or the check has to be changed to admit
it, and which of those happens is the shape's first real test. A declaration hand-fixed until the
check went quiet is this mechanism failing.*

### The check — `.agents/scripts/mechanisms.py`

Standard library only, explicit repository root, matching the two existing scripts' exit contract:
**0** clean, **1** diagnostics found, **2** usage error or refusal. Reuses `docs_corpus.target_of`
so a citation in a doc is read by the code that repairs one.

Two modes, and **no default** — a bare invocation prints usage and refuses, per the spec's rule
taken from Life's reversal:

- `mechanisms.py --check` — JSON: every mechanism, its parts, every moments row with its
  instruction or its kind of absence, the diagnostics, and any check it **skipped** with why.
  No path operands: it always covers `.agents/mechanisms/`, and tests reach a synthetic tree
  through the `root` parameter the other two scripts already take. Scoping with no consumer is
  the generalisation the entry file forbids.
- `mechanisms.py --index` — the register, rendered from the directories. Never written to a file.

Diagnostics, each with a test that asserts the reason and not merely a non-zero exit:

- a `where` path that does not resolve, or an anchor phrase absent verbatim from the file it names
- no `instruction` bullet, no doc, or the two naming the same file
- a `kind` outside the vocabulary, or one with no clause
- a row with both an instruction and an absence, or neither
- `elsewhere`, `embedded` or `not yet` whose referent is missing or does not resolve
- `not yet` naming the ticket the doc's `declared by` names
- `unowned by design` carrying a referent
- a directory with no doc, a doc with no moments table, or a table missing a column
- a table row whose cell count differs from its header
- a doc with no *what would show it working* section

`--index` is tested too, and the spec's index rules are what it is tested against: rows match the
directories on disk, a doc edit shows on the next render, a doc it cannot parse is **reported
rather than omitted**, and it reads no committed copy of its own output — there is none to read.

Prose, the taxonomy's correctness, and whether a moment *should* exist are judgment. The script
records them and never rules on them.

### Delivery — the gap, and what closes it

Life's check fires at every `SessionStart`. This tree has no hooks, so ours runs when someone types
it, which is indistinguishable from one that passes. The existing answer is the **verification
set**, already defined as *"this project's typechecker, tests, and any other commands required of
landed work"* — `mechanisms.py --check` joins it, so `/verify` runs it every slice. Derived, not
remembered, and nothing new invented. That it is a project facet, and belongs to the answer
[01-0010.0110](../../tickets/01-0010.0110-project-facets-injected.md) will build, is noted there.

**This is a substitute, and it now has an owner.**
[01-0010.0120](../../tickets/01-0010.0120-host-delivery-surfaces.md), minted from this gap,
establishes what each host can place in front of an agent unasked. Whatever it concludes, the
verification-set answer stays right for this slice; what changes is whether a better one exists.
Its `/impact` found the same gap under `.0030`, whose ratchet is *loud when it rises* with no
channel to be loud on.

## Limitations and follow-ups

- **One declared mechanism is weak evidence.** `.0022` falsifies it cheaply before three slices
  depend on it, and the grading section names that as this mechanism's test.
- **The check runs at `/verify`, not at wake.** Better than remembering, weaker than Life's hook,
  and hooks stay out of scope. If this tree ever gains `.claude/settings.json`, the announcement
  shape — including the mandatory *quiet when*, since a silence with no declared meaning reads as
  an absence — is worth taking whole.
- **Absence is not clearance.** A clean run means nothing was caught. It never means the tree
  obeys, and the doc says so where the check is named.
- **`discover/EVIDENCE.md` stays at a forbidden path** with no allowlist until `.0050`.
- **The contraction rule is prose the check cannot enforce.** A retired mechanism's directory is
  removed by a person following a stated rule; mechanising it needs a second retirement to look
  at, and `mechanism-shape` is always on.
- **The four re-aimed citations are hand edits.** `move_doc.py` repairs paths, not anchors.
- **`docs/README.md` is a curated list of entry points, not an index**, so
  `docs/mechanisms/` — evidence files, read only when amending — does not belong in it and is not
  added. Noticed while checking: `docs/dreams/` landed last session and is in no list either. That
  is a real omission and it is nobody's; flagged here rather than swept into this slice.
