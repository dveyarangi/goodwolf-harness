## What it changes

The tracer through three layers, on [q-0037.0018](../../questions/q-0037.0018-what-is-a-projects-product-document-to-the-method-and-which-of-the-methods-mechanisms-keeps-it-and-the-projects-work-in-agreement-both-ways.md)'s
decisions and [the spec](../../spec/01-0040-a-projects-account-stays-in-agreement-with-its-work.md):
a question carries a trace link to answers of the product document; the document's answers carry
an id and a name; a new mechanism, `product`, renders each answer's coverage from the questions
that realize it. The link's form and which questions realize are
[q-0037.0018.0006](../../questions/done/q-0037.0018.0006-how-is-an-answers-coverage-read-from-the-questions-that-realize-it.md)'s
decisions 1 and 2.

## Shape

**The trace link, in the store** — `questions.py`, the store side's deep module.

- A new optional part, `realizes`, written after `answer` and before `lean`:
  `- **realizes** A7 "The question store", A12 "A session resumes at its step"`, or
  `- **realizes** derived`. The store checks form only: each item a reference token
  (`[A-Za-z0-9][A-Za-z0-9._-]*`) and a quoted, non-empty name with no quote inside, items
  comma-separated, no reference twice; or `derived` alone. It never resolves a reference or a
  name — the development method knows nothing of the product (q-0037.0018, decision 4). A malformed
  part is a diagnostic, like every part's form.
- A new call, `realize q-N '<value>'`, one text argument as `lean` takes: it replaces the whole
  part, and refuses a malformed value, writing nothing. It writes on any entry the store holds,
  open or closed, live or in `done/`, since coverage reads closed questions and this tree's
  migration links past work.
- One public function, `realizes(index, identity)`: the question's own part, else its nearest
  ancestor's, else none — trace propagation computed on read, never copied. The product script
  reads the store through it and `read_store`, as `mechanisms.py` already imports `questions`.
- The window, the wake and the tree do not draw the part: every session would pay for it every
  message. A test holds that.
- The questions skill gains the call's row, the part in its sample entry and one sentence in the
  parts' prose; the script's docstring and usage list the call.
- Optional, so every entry written before reads unchanged. No edge line is written: the occasion
  rule is [01-0010.0185 an-edge-change-writes-its-line](../../tickets/01-0010.0185-an-edge-change-writes-its-line.md)'s, unbuilt, and it replays this change.

**The product document's format** — `PRODUCT-FORMAT.md` beside the `/product` skill, declaring
the record `docs/product.md`.

- Pains, goals (`G<n>`), causes (`C<n>`), answers. An answer is a row of the answers table whose
  first cell opens with its bold lead, `**A<n> <name>**`: the id never renumbered and only
  retired, the name what a trace link quotes word for word. A row whose first cell alone is filled
  is a group heading. The last column, *waits on*, is empty for a decided row, which points
  nowhere, and holds a straw dog bound to a purpose question for an undecided one. A pain has no
  closed state.

**The script** — `product.py`, the mechanism's deep module: a tree in, findings and coverage out.

- `--check`: the document's form — every answer has an id and a name, no id twice. JSON with
  `diagnostics`, as its peers print; a diagnostic exits 1.
- `--coverage`: one line per answer in the document's order — its id and name, its coverage, the
  questions realizing it. Rendered on request, never committed.
- Coverage, by decision 2: a question realizes while open (deferred counts as open) or closed
  decided. *Absent*: none realizes; *in progress*: one that realizes is open; *present*: every one
  that realizes is decided.
- No `docs/product.md`: both modes print nothing they found and exit 0.
- The findings — orphan, unrealized answer, a link naming no answer or an outdated name, a row's
  binding — are [01-0040.0020](../../tickets/done/01-0040.0020-drift-between-the-document-and-the-work-is-found.md)'s.

**The mechanism declared** to the mechanism shape.

- `.agents/mechanisms/product/product.md`: state `installed`, instruction `/product`. Moments:
  coverage asked for, instructed by `/product`; the document checked, by U1; a purpose decision
  landing, the README derived and a release note gathered, each `not yet` bound to
  q-0037.0018.0008, q-0037.0018.0005 and q-0037.0006.0020.0002.0002. Relies on `questions.py`, its `realizes`,
  owned by the questions mechanism.
- `.agents/mechanisms/product/product.rules.md`: one rule, **U1**, into `/maintain` at
  `## Installed from other mechanisms` — check the product document with `product.py --check`,
  form never content. The prefix U: P is the ticket's, and A, C and G are the document's own ids.
  *Found at stage 3:* a rule's body may hold no straw dog, and the condition *where a project keeps
  a product document* needs none there, since the script finds nothing in a tree without one; the
  straw dog bound to q-0037.0006.0024 (q-0037.0018, decision 11) stands in the mechanism's doc instead.
- `/product`: its description names its uses — keeping the product document, seeing each answer's
  coverage; its body the act and the format's pointer. The README's and the release note's
  formats come with their slices.
- `docs/product.md` joins `PAINTED_DOORS` in `mechanisms.py`, so core may name the record;
  `product.py` joins the harness skill's list of the scripts that serve every project.
- The verification set does not take `product.py --check` yet: this tree's document has no ids
  until [01-0040.0040 this-trees-account-runs-on-the-mechanism](../../tickets/01-0040.0040-this-trees-account-runs-on-the-mechanism.md),
  so it would guard nothing. It enters with `.0020`'s findings.

## Stages

1. **The store.** Tests red: a link written and read back by a sub-question as its own; derived;
   a malformed value refused with nothing written; an archived entry written; every entry written
   before the part reading unchanged; the part not drawn. Then the part, its form, the call,
   `realizes`, the skill's text. The suite green.
2. **The script.** Tests over fixture trees red: no document — nothing printed, exit 0; three
   answers realized by no question, an open one and only decided ones — absent, in progress,
   present; one realized only by a pruned question — absent; an id twice and an answer with no
   name — diagnostics. Then `product.py`. Green.
3. **The declaration.** The doc, the rules file, the skill and its format; `PAINTED_DOORS`, the
   harness's list; U1 installed. The shape check and the install check clean. `product.py` run over
   this tree, its output recorded.
4. **The verification set** whole, then `/verify`.

*Run over this tree at stage 3, 2026-10-13:* `--check` reports 48 answer rows whose first cell
opens with no `**A<n> <name>**`, the document's whole answers table as it stands before
`.0040`; `--coverage` renders nothing. U1 carries those 48 into every `/maintain` here until then.

## Limits

A suspect question counts by its state alone. Clearing a link back to its ancestor's is not a
call; a wrong link is rewritten. The window never shows a link; a person sees coverage only by
asking.

## Verification

a fixture showing all three coverages, and over this tree printing nothing.
