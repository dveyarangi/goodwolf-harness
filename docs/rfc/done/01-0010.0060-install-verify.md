# Install /verify — implementation plan

**Authored:** 2026-09-06
**Last amended:** 2026-09-06

Implements [01-0010.0060](../../tickets/done/01-0010.0060-install-verify.md): install
`/verify` from Meteoscape `review-impl`, reconciled with repair-and-report, and
use it once on a landed harness slice.

## Scope

Install one skill folder, `.agents/skills/verify/`, the same recipient layout as
`/spec`. First use verifies [01-0010.0035](../../tickets/done/01-0010.0035-install-spec.md)
against its ticket, RFC and governing docs. `/implement` and `/maintain` are not
installed.

## Shapes

- Folder name `verify`, frontmatter `name: verify`. Hosts discover it the same
  way they discover `spec`.
- Body is Meteoscape `review-impl` with selected names: `/verify`, `/plan`
  (not `/review-impl` or `/plan-impl`). `/improve-comments` stays in the body.
  `/verify` is the verification of landed work: ticket, RFC if any, governing
  docs, and the [verification set](../../process.md#verification). An absent RFC
  is not a defect of this skill.
- Repair follows [autonomy and repair](../../process.md#autonomy-and-repair) and
  the `repair` switch in `AGENTS.md`. This project is `repair=report`: a clear
  violation of an explicit rule inside authorized work is fixed and reported.
  Forecast Collector's "do not make changes until requested" and its
  "use `/implement` to amend" are not imported.
- `/align` when the repair policy says to escalate. Do not rewrite a governing
  rule to make a violation disappear.
- `/sync-arch` is `/maintain`. This slice does not install `/maintain`; a
  verify pass does not start a whole-tree maintenance.
- `<project-local>` points at [Verification](../../process.md#verification), tickets,
  RFCs, `AGENTS.md`, and the repair-policy pointer. Commands are not inlined.

## Stages

1. Write this RFC. Record `Plan:` on the ticket.
2. Write `.agents/skills/verify/SKILL.md`. Point `AGENTS.md`, `docs/process.md`
   and `.agents/README.md` at the install.
3. First use: `/verify` on 0035. Record the run on that ticket. The paired
   `done/` move is [TICKET-FORMAT](../../../.agents/skills/ticket/TICKET-FORMAT.md#one-basename-per-work-item)
   and `/maintain`'s; this install does not close the reviewed ticket.
4. Prove this ticket's boxes: catalog path, first-use record, grep of `.agents`
   for `/review-impl` and `/plan-impl`, `AGENTS.md` installed list, then
   `/verify` on this ticket.

No tests. Proof is the files and `.claude/skills/verify/SKILL.md` through the
existing link.
