# A fresh tree arrives with a delivery status to read — implementation plan

**Authored:** 2026-09-23
**Last amended:** 2026-09-23

Implements [01-0010.0165](../../tickets/done/01-0010.0165-a-fresh-tree-has-a-delivery-status.md): the
ticket mechanism declares what its queue says before anything has happened in it, and an install
writes that into a tree that has none.

## Governing boundaries

- **One owner per record.** [mechanism/SKILL.md](../../../.agents/skills/mechanism/SKILL.md) —
  *writing an entry into a record is not mechanism work; it belongs to the skill that owns the
  entry*. The delivery status is the ticket mechanism's, governed by **P8** in
  [ticket.rules.md](../../../.agents/mechanisms/ticket/ticket.rules.md). So harness places the text
  and never composes it.
- **A mechanism's directory holds two files and nothing else**
  ([MECHANISM-FORMAT](../../../.agents/skills/mechanism/MECHANISM-FORMAT.md)), and a rules file
  installs blocks into anchored targets. Neither can hold a file's initial contents. The home that
  can is a shelf beside the skill. It is `QUEUE-ARRIVAL.md` and not a section of
  `TICKET-FORMAT.md`: the format shelf is read at every ticket a session writes, and this is read
  once, by the install, so carrying it there would charge every ticket pass for a one-time fact
  *(the user, 2026-09-23, after the first cut put it in the format shelf)*.
- **A painted door is reserved, not necessarily created** ([glossary](../../../.agents/glossary.md),
  amended at this `/plan`): some arrive with content where their owner declares it, the rest come
  into being when the first record is written.
- **What a recipient receives is what a commit holds** ([architecture](../../architecture.md)). The
  arrival state must therefore be read from the shipment, never from the origin's disk.
- **Every refusal writes nothing.** All refusals precede `_write`; this write sits inside the
  writing phase, so the invariant holds unchanged.

## Hidden edges

1. **`report.own` is the wrong field and would have stayed empty.** `_ref_gate` builds `own` from
   paths **under `.agents/`** absent from the shipment. `docs/tickets/README.md` is outside core,
   so an existing delivery status could never appear there. Reporting goes through `written` when
   written and `notes` when left alone.
2. **The fixture breaks for the same reason `.0155`'s did.** `seed_source` builds a core without
   `QUEUE-ARRIVAL.md`; a refusal on its absence turns every `TwoTrees` case red until the fixture
   has one. That change goes inside the stage that adds the refusal.
3. **Harness gains a ship-time dependency on another mechanism's file.** Legitimate — *relies on,
   does not own*, like the injector and the citation reader — but the doc's table must say so, or
   the next person to trim `QUEUE-ARRIVAL.md` breaks installs with no warning.
4. **Install-only would not rescue the customer.** ai-game-1 holds core and has no delivery
   status; an install-only rule never reaches it and no update would either.
5. ~~The block ships inside a `.md` file, so an arrival state naming anything else under `docs/`
   would refuse the install with a message about citations.~~ **Wrong, checked at the second
   pass.** [`_without_fences`](../../../.agents/scripts/gw/docs_corpus.py) blanks every fenced block
   before either the citation scan or the path-literal scan runs, so a fenced arrival state is
   inert to the leak rule whatever it names. That is the *reason* the declaration is a fence and
   not indented prose, and it is now load-bearing rather than incidental.
6. **The fixture needs a `ticket/SKILL.md`, not just a `QUEUE-ARRIVAL.md`.** `_skills` iterates
   every directory under `.agents/skills/` and asks who claims it; a `ticket` directory with no
   `SKILL.md` is an unclaimed skill and the target's shape gate exits 1. This is the third time
   this lesson has come up — the harness skill in `.0155`, and twice here — so the fixture gets
   both files with a claim line, stated rather than rediscovered.

## Shapes

### The arrival state is declared where the record's shape is

`QUEUE-ARRIVAL.md` holds one fenced block: what the queue says in a tree where core has arrived
and nothing is in flight. It is prose a person could have written by hand, in a shelf nothing
reads at session time.

**The block is found by its info string**, not by "the first fence after a heading" — one regex,
order-independent, and unbothered by anyone adding prose or another example above it. The fence
is also what makes the block inert to the citation reader (hidden edge 5), so the container is
part of the design rather than a formatting choice.

**One substitution, and it is named:** the announced ref. Everything else is written through
verbatim. Harness fills that one placeholder and composes nothing — the same relation it has to
the announce line, which it also stamps without authoring.

The ticket mechanism owns the words. Changing them changes what a fresh install writes, with no
code touched — which is the criterion that tells this design from a constant in the script.

### Harness places it, and reads it from the shipment

The text is taken from `shipment.files[TICKET_FORMAT]`, which the run already holds in memory. It
is never read from the origin's disk: what a recipient receives is what the commit holds, and a
run from a clone at another ref must write that ref's words.

**Refusal:** a ref whose `QUEUE-ARRIVAL.md` is missing, or carries no such block, is refused at
the ship in the same breath as one whose entry file has no announce line — the declaration is a
relied-on part, and a missing one is not a silent no-op.

**The shipment carries the arrival state**, read when it is built and beside the two checks that
already live there. Reading it at write time instead would put the refusal *after* core was on
disk, which is how `/implement` found this: a ref with no shelf refused, and the target was full.
`Shipment` is what a recipient receives, and this is part of it.

### Written whenever absent, and never twice

The write sits in `run()` immediately after `_write`, not inside it: `_write` is about the
manifest and what left it, and the delivery status is neither. That is still the writing phase —
after every refusal, before the gate — so the invariant holds and the gate judges a finished tree.
`--check` returns before any of it.

It happens on **install or update**, whenever the path is absent — an update is how the trees that
already hold core get one, and ai-game-1 is the case.

An existing path is left byte-identical and reported in `notes`. Nothing merges, nothing
overwrites: from its first line the record is the instance's. **`--overwrite` does not reach
it** — that flag is about core files a recipient edited, and this is not a core file.

## Flows

**Install into a fresh tree.** …refusals → ship → write core → **write the delivery status from
the shipped declaration** → links → inject → gate. The first session there runs `/recall`, finds
the queue, and reads that core arrived at this ref with nothing in flight.

**Update of a tree that has one.** Same path; the file exists, so it is left and noted. Its rows
are the project's history and no install has an opinion about them.

**Update of a tree that has none.** The file is written. This is the ai-game-1 case, and it is the
only way an existing recipient acquires one.

## Stages

1. **The declaration exists and is read.** Add the block to `QUEUE-ARRIVAL.md`; add the reader and

   `SKILL.md` and a `QUEUE-ARRIVAL.md`. Red inside the stage between the refusal and the fixture,

2. **The delivery status is written when absent.** The write in the writing phase, on install and

3. **The doc catches up.** The Moments row narrowed to writing the delivery status and its

   Green; `mechanisms.py --check` is the proof.

## Tests

- An install into an empty tree writes `docs/tickets/README.md`, and its text is the shipped
  declaration's — asserted by **changing the declaration in the fixture's core** and seeing the
  written file change, so a constant in the script could not pass.
- An install into a tree already holding the path leaves it byte-identical and says so in `notes`;
  the file is not in `written`.
- An **update** of a tree with no delivery status writes one — the ai-game-1 case.
- A ref whose `QUEUE-ARRIVAL.md` is missing, and one whose block is absent, are both refused at
  the ship with nothing written.
- The recipient's own `--check` afterwards still reports `arrived: true`, and does not report the
  delivery status as an edit or as `own`.
- A refusal earlier in the run leaves no delivery status behind.
- `--update --overwrite` over a tree whose delivery status has rows leaves it byte-identical —
  the flag replaces core files and has no reach here.
- An arrival state naming a path under `docs/` that is **not** a painted door still installs,
  because the fence is blanked before the leak rule reads; asserted so the reasoning in hidden
  edge 5 is held by a test and not by my reading of `_without_fences`.

## Second pass, 2026-09-23

- **Hidden edge 5 was wrong** and is struck above. Fences are blanked before either citation scan,
  so the block is inert whatever it names — which promotes the fence from formatting to design.
- **The fixture needs a claimed `ticket/SKILL.md`**, not only the shelf file. Third appearance of
  the same lesson; written down so the stage does not discover it.
- **Found by info string, not by position.** The first draft said "a fenced block under a named
  heading", which would break the moment anyone put an example above it.
- **One named substitution.** The first draft said "a placeholder the writer fills" without
  saying who fills it or how many there are; unbounded substitution would have made harness an
  author again.
- **Placement stated exactly:** after `_write` in `run()`, not inside `_write`, and never on
  `--check`.
- **Probed and left alone:** `QUEUE-ARRIVAL.md` is in the manifest (`files()` archives all of
  `.agents/`); the recipient's `--check` cannot report the record, since `_ref_gate` compares
  manifest files and builds `own` from paths under core only.

## At `/implement`, 2026-09-23

- **The refusal was in the wrong phase, and a test found it.** Reading the declaration inside
  `_write_delivery_status` put it after `_write`, so a ref with no shelf refused with core already
  written — *every refusal writes nothing*, broken. The arrival state is now a field of
  `Shipment`, read where the entry file and harness skill are already checked. The plan had said
  "read it out of the shipment it already holds" and I had read that as *when writing*; it is
  *when shipping*.
- **The fence reasoning is now held by a test**, not by a reading of `_without_fences`: an arrival
  state naming `docs/private/plan.md` — a path that is not a painted door — installs cleanly.
- **The fixture needed both files**, as the second pass predicted, and nothing was rediscovered.

## Limitations and follow-ups

- **Nothing asserts the record later.** Once written it is the instance's, and a tree whose
  delivery status is deleted gets no complaint from any check. The ticket's open issue asks
  whether `/ticket` and `/maintain` should assert it; that is
  [01-0010.0180](../../tickets/01-0010.0180-harness-names-its-maintenance.md)'s natural home, since
  it is exactly what harness would name to `/maintain`.
- **One record, one seam.** No general facility for mechanisms declaring arrival states. A second
  record wanting one is what would force it, and `docs/cicd.md` — written by the setup step in
  [01-0010.0170](../../tickets/01-0010.0170-arrival-becomes-a-sequence.md) — is the likeliest second
  shape. If it arrives that way, this seam generalises then and not before.
- **This is an edge change** — a behaviour a recipient's files rely on — landing before
  [01-0010.0185](../../tickets/01-0010.0185-an-edge-change-writes-its-line.md) exists to record it.
  It owes the edge record a line, written at that ticket's implement pass.
- **No TODO is owed in code.** Nothing here is a temporary shape later work dissolves.
