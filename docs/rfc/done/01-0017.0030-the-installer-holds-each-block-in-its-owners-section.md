# The installer holds each block in its owner's section — implementation plan

- **record of** what happened

**Authored:** 2026-10-26
**Last amended:** 2026-10-26

Implements [01-0017.0030](../../tickets/done/01-0017.0030-the-installer-holds-each-block-in-its-owners-section.md):
the check reports an installed block that stands outside the section its anchor heads, an install
refuses to call such a block present, and a rule's body may quote the straw-dog tag in a code span.

## Governing boundaries

- **One block per mechanism per target, at the end of the anchor's section** —
  [the architecture](../../architecture.md), *rules files and the installer*; a section runs to the
  next heading of the anchor's level or higher. Today nothing reads that a present block stands
  there: `_state` returns *present* on a byte match wherever the block is, and an install does the
  same. [Decision 8](../../questions/q-0037.0006.0024.0002-does-every-rule-of-the-entry-file-belong-to-a-mechanism-so-that-an-install-adds-the.md#decisions)
  — one section per mechanism — is held by this check or by nothing.
- **A body holds no straw dog** — [MECHANISM-FORMAT.md](../../../.agents/skills/mechanism/MECHANISM-FORMAT.md),
  *The body*: the listing blanks an installed block before it scans, so a wrapper in a body would
  be invisible wherever it landed. The listing reads prose through `without_code`, so a tag quoted
  in a code span is no wrapper to it; the refusal reads the raw body and refuses the quote too.
  The straw-dog rule of the entry file quotes the tag and could not be installed
  ([the second impact](../../questions/q-0037.0006.0024.0002-does-every-rule-of-the-entry-file-belong-to-a-mechanism-so-that-an-install-adds-the.md#impact--2026-10-26-the-second-draft)).
- **ADR-0004** — the standard library alone.

## Shapes

**The position.** A found block is in its section when it opens at or after the anchor line's end
and closes at or before the section's end — `after_anchor` and `section_end` as they stand, no new
reading of a section. Order inside the section is not read: a block placed directly after the
anchor line, as installs did before 2026-09-21, is in its section.

- `_state`: after the byte match and before the local block's *not last*, a block outside its
  section is `outside its section`; the check carries it as a diagnostic like every other state
  that is not *present*. A block standing while its anchor is gone or ambiguous reads `anchor
  missing` or `anchor ambiguous`, as an absent block's anchor does — no longer *present*.
- `_planned`, install: a found block that matches but stands outside its section is refused —
  *the block stands outside its anchor's section; retract it, then install* — rather than
  reported *present*. The position is read on the matching block alone, so a re-render or an
  overwrite still mends a block in place first; retraction is unchanged, taking a block out
  wherever it stands, which is how a block moves. The hook's line names the retraction. An install
  of a matching block whose anchor is gone refuses on the anchor, where it said *present*;
  retraction still takes the block out.

**The body.** `_body_problems` reads the straw-dog tag in `without_code(body)`; a tag in a code
span or a fence passes, a wrapper refuses as now. The other refusals keep reading the raw body.
MECHANISM-FORMAT.md's *The body* says so: *no `<straw-dog>` outside code*.

## Impact

`inject_rules.py` — `_state`, `_planned`, `_body_problems`; `test_inject_rules.py`; the one sentence
of MECHANISM-FORMAT.md. `maintain.py` and the harness's gate read `check`'s diagnostics, so a
misplaced block anywhere reaches the wake's *out of step* line through the existing path. Every
block in this tree stands in its section today; the verification set and `--check` on this tree are
the cheapest real case that would prove the reading wrong.

## Stages

1. **Red, then green — the position.** A test moves an installed block below the next heading and
   asserts the check's state *outside its section*; one asserts an install refuses it with the
   retract-then-install words and writes nothing; one asserts a block directly after the anchor line,
   before the section's own text, is *present*. Then `_state` and `_planned`.
2. **Red, then green — the body.** A test installs a rule whose body quotes
   `` `<straw-dog question="q-N">` `` in a code span and asserts the tag lands byte for byte; the
   existing refusal of a real wrapper stays green. Then `_body_problems`; the format sentence.
3. **This tree.** `inject_rules.py --check` and the verification set green.
