# An existing project gets a product document the check can read — implementation plan

- **record of** what it intends to become

**Authored:** 2026-10-14

Implements [01-0040.0035 an-existing-project-gets-a-product-document-the-check-can-read](../tickets/01-0040.0035-an-existing-project-gets-a-product-document-the-check-can-read.md).

## What it changes

The product document becomes the third record an install writes only when absent, after the
delivery status and the store's roots, in the shape the store's roots already have: the words on
the product mechanism's shelf, its script writing them, the installer calling it. And the check
stops passing a document it cannot read.

## Shape

**The shelf.** `.agents/skills/product/PRODUCT-ARRIVAL.md`: a fenced `product-document` block
holding the empty document — its title, `- **record of** what must always hold`, the four headings
of the format, and under `## Answers` a table of a header and its separator with no row. Prose
around the block says what it is for, as the other two arrival shelves do. A shelf of its own, not
a block in `PRODUCT-FORMAT.md`, for the reason `arrival_state` gives for the queue's: it is read
once, by a script, and the format is read whenever a session writes a row.

**`product.py`.** Two things, each beside what it extends:

- `seed(root)` writes `docs/product.md` from the shelf when no file is at the path and returns
  what it wrote; with a file there it writes nothing and returns nothing. `arrival_document(shelf)`
  reads the block from text, so the installer can ask it of a ref before anything is written, as
  `questions.arrival_roots` is asked.
- The check gains one diagnostic: a document with no `## Answers` heading *is not in the product
  format*. It fails the check, as every other broken form does; the empty document passes, holding
  the heading and no row.

**`harness.py`.** After `_seed_store`, `_seed_product_document` calls `product.seed` and adds what
it wrote to the report; given nothing written, it names the document left as it stands, and, when
`product.py` would find it not in the format, says so. It names no skill to bring it in: `/product`
holds that act only once 01-0010.0175 lands. While the
shipment is built, a ref whose shelf cannot say the document is refused before anything is
written, beside `_refuse_unless_the_roots_are_said`. No word of the document is in the installer
*(the user, 2026-10-09)*.

**What stays.** Overwrite does not reach the document: it is the instance's from its first line, as
the delivery status is. Retraction and removal do not take it.

## Stages

Each keeps the suite green.

1. **The check, test first.** A document with no answers heading fails as not in the format; this
   tree's and a fixture's in-format document pass.
2. **The shelf and the seed, test first.** `seed` writes the shelf's document where none is, and
   the check passes it; `seed` leaves an existing file byte for byte, in the format or not.
3. **The install, test first.** The fixture core gains the shelf; a fixture install into an empty
   tree and an update of a tree with no document each leave one the check passes; an update of a
   tree with a document in another form leaves it byte for byte and its report names it; a ref
   with no shelf is refused before anything is written.
4. **The docs.** Product and harness docs as above; `mechanisms.py --check` passes.
5. **`/verify`.**

## Limits

- Bringing a document into the format is 01-0010.0175's; until it lands the report and the check
  say what is wrong and point nowhere.
- A document holding `## Answers` but in another shape is diagnosed row by row by the existing
  checks, not as one *not in the format*.
