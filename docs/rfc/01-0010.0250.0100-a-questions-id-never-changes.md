## The shape

**The id.** `q-` and six characters of the lowercase base32 alphabet of RFC 4648, `a`–`z` and
`2`–`7`, holding at least one letter and one digit, so no new id reads as a dotted one or as a
word after `q-`. Drawn from the operating system's randomness; one already in the store is drawn
again (decision 6; the architecture's *one already taken is drawn again*). The draw is passed in,
so a test can force a repeat. The pattern lives in `docs_corpus.py`, which `questions.py` already
imports, and every reader takes it from there — `questions._ID`, `TODO_QUESTION`, `tickets.py`'s
`_NAMED`, `sessions.py`'s row grammar, `harness.py`'s shear. While both forms are read (stages 4
and 5) it is one group, `(?:new|dotted)`, followed by `(?![a-z0-9.])`, so the patterns built on
it keep their groups and `_FIRST_ID` never reads a new id's digits as a dotted one.

**The file.** `docs/questions/<id>.md`; its title line `# <id> <the question>`. A reword changes
the title line and nothing else. Wherever a listing showed a question by its file's slug —
`tickets.py`'s table among them — it takes the words from the title line.

**The place.** `part of` alone, as today. A new part, `opened`, the second the question was opened
in UTC, written by `open` once and never again: the later of now and one second after the latest
`opened` among its siblings, so siblings never tie, a seed keeps its shelf's order, and two opens
in one second still sort as made. The tree is walked from the roots down, a parent before its
children, siblings keyed by whether they hold `opened`, then `opened`, then today's positions for
a dotted id or the id itself — a key that holds for every mix of entries between stages 1 and 6.
The window, `--tree`, `--path`, the wake, `product.py`'s listing and every other listing take
that walk; the window's *open questions under this root* is indented by depth instead of read off
ids. No address is shown or kept. `opened` lands in
[QUESTION-FORMAT.md](../../.agents/skills/questions/QUESTION-FORMAT.md) with stage 7's text.

**A move.** `move` rewrites the moved question's `part of` and nothing else; the cycle refusal
stays. `open --between` rewrites the lower question's `part of` and nothing else. A subtree is
whatever `part of` reaches: `_within` walks `_ancestry` over the whole index, finished entries
included, so `--path`'s counts, its dependents and the straw dogs bound to finished questions stay
as today.

**A finished subtree.** A closed question stays where it is. An entry is *finished* by today's
condition for the move to `done/`, every clause kept (`movable`, `questions.py`): it and every
question below it is neither open, deferred nor suspect, and no question held open depends on any
of them. It is computed once in `_entries`/`read_store` over the whole store, cycle-safe, and kept
as the attribute `archived` that `product.py` and the others read; the window, the wake and every
live listing leave finished entries out. That is not quite what `done/` does today: an entry that
sits in `done/` though the rule would keep it — `q-0037.0006.0020.0010`, closed and suspect, is
one — comes back into the window's suspects, the wake and the check's twins and rungs, where it
belongs. `close` moves no file.

**What goes.** In `questions.py`: the dotted pattern, `_next_free`, `_parent_of`, `_positions`,
`_misplaced`, `_relative_ids` and its finding and `_leans`' refusal of a relative id, `_seat`'s
renames, `_renames_below`, `_name_renamed_ids`, `_archive_finished`, `_ready_for_done`,
`_ready_roots`' finding, the slug budget, `_fitted_slug` and `_name_problems`' slug check, the
rename's file moves in `_rewords`, `Written`'s renamed and archived lists and their lines,
`_existing`'s word that an id changes on a move; `sessions.py`'s `renamed`. `_carry_renames`,
`_rewrite_ids`, `_records_naming_ids` and `_outside_fences` stay until stage 6 — a reword uses the
first until stage 4, the migration the rest — and then move into `migrate_ids.py`, leaving with
it. `_files_holding` globs `<id>.md`, so `recheck` still raises `Taken`. `move_doc.py` keeps
`done/` for tickets and RFCs. `mechanisms.py`'s painted doors lose the store's `done/` and gain
the frozen table.

**An old id.** `_question_id`, and `sessions.py`'s `--hold` and `--take`, look a dotted id up in
the frozen table and refuse it with the new id, so a running session that names one is told where
it went. The store's check reports a dotted id in the store, the rows and the `TODO`/straw-dog
bindings, naming its new id from the table — so a branch made before the migration and merged
after is caught, and the migration re-run on it. The table itself, and prose examples elsewhere,
are not read for it.

## The migration

A script of its own, `.agents/scripts/gw/migrate_ids.py`, run once in this tree and once in each
of the person's other trees, with a `TODO q-0037.0017.0005.0001.0019` at its top: it leaves once
every tree has run it.

1. Read every entry, live and in `done/`, and the frozen table if one exists.
2. Give each dotted id the new id the table already holds, and draw one by the rule above for a
   dotted id the table lacks; the table gains those pairs. A re-run on a branch made before the
   migration so gives each question the id it already got.
3. Move every entry to `docs/questions/<new id>.md` with one `move_doc.perform` over all the
   pairs: it re-points every citation into the store at the citing file's depth, keeping its
   fragment, and rebases each moved entry's own outgoing links, `done/`'s one level up among them.
   Then set each entry's title, `opened` — the second of the commit that first added its file
   (`git log --diff-filter=A --follow`), the run's own where none did — and the ids in its header
   and body. Remove `done/`.
4. Only after the links, rewrite the bare ids through the table, in the scope today's rename
   keeps (`_rewrite_ids`): every record under `docs/` outside fenced blocks, the rows, the
   `TODO`/straw-dog bindings outside `docs/`, and the entry file; the frozen table left out.
   Evidence that is not a record — research results in `.txt`, `.json`, `.diff` — and test
   fixtures stand as they are. In this tree that rewrites the bindings in `.agents/` too; the
   prose example ids of the shipped text wait for stage 7. In the person's other trees the
   installed core under `.agents/` carries no binding, the shear having stripped them; there
   `local.rules.md` is rewritten and its local block re-installed, so the entry file and the rules
   file agree.
5. Write the frozen table, `docs/questions/former-ids.md`, one row per question: the old id, the
   new, the question's words. `_entry_files`, `seed`, the rewrite and the old-id finding pass it by
   name.
6. Walk every citation of the tree through `docs_corpus.citations` and `cited_record`, and say any
   that resolves to nothing; run every script's `--check`.
7. Leave `/maintain`'s sweep where it should start: the sweep is run through the migration's
   parent first, and then `maintain.py --mark '*' decisions <outcome> <the migration's commit>`
   moves its mark past the migration, so its some 370 rewritten entries are not read as decisions
   landed and nothing before them is skipped unread.

It runs dry first and refuses while any file the run would change is uncommitted or untracked,
naming them — the rows aside, which every running session writes as it goes — so its change is one
commit the person can read and revert. In this tree that waits on other sessions' uncommitted work
in the store, which the person clears first. Run again on a tree with no dotted id, it changes
nothing.

## Impact

- **Must change.** `questions.py`, `sessions.py`, `docs_corpus.py`, `tickets.py`, `product.py`'s
  order, `mechanisms.py`'s painted doors, `harness.py` (the seed's three roots get new-form ids
  and `opened`; the shear's pattern), as above; about 250 tests of the store and the fixtures of
  the others that write dotted ids; the text of about fifteen shipped files that say the id is the
  place, a move renames, or a closed subtree goes to `done/` — the questions skill and its format,
  the questions and session mechanisms and their rules, the maintain, conclude, verify and ticket
  skills, the ticket, ADR and edge formats, the entry file's example ids. Those instructions sit
  on the self-improvement ladder at *a rule*, the dial: they are drafted through `/skill-up` at
  `/implement` and shown before they land.
- **Must verify.** `mechanisms.py` and `straw_dogs.py` read through `questions.read_store`; its
  answer keeps its form. The window's rendering changes, so its test against a fresh session is
  run again, as the window's docstring asks.
- **May simplify.** Everything under *What goes*.
- **Hidden edges.** A branch made before the migration carries dotted ids; the old-id finding
  catches it at merge, and the migration, re-run on it, gives the same new ids. A worktree of this
  tree, `.claude/worktrees/`, is such a branch. Old ids in commit messages resolve through the
  table alone. `opened` from `git log --follow` may name a rename's commit; among such siblings the
  order falls to the id — accepted, the order being for reading. A running session's row names old
  ids; the migration rewrites the rows, and `_question_id`, `--hold` and `--take` answer a session
  that still names one. An entry in `done/` that today's rule would keep live comes back into the
  window, as *A finished subtree* says.
- **Leave alone.** The body's sections; rung, lean, strikes; tickets' and RFCs' numbers and
  `done/`; the store's place on `main`; the server.

## Stages

Each stage keeps the tests green, test first, by [/tdd](../../.agents/skills/tdd/SKILL.md).

1. **The tree walked by `part of` and `opened`.** `open` writes `opened` by the rule above; the
   tree is walked with the mixed key; `_within` walks `_ancestry` over the whole index; the
   window's root list indented. Tests: siblings in opened order; two opens in one second in the
   order made; a seed in its shelf's order; a store of mixed entries walks as today; `--path`
   counts by `part of`, a straw dog bound to a finished question included.
2. **Finished by state.** The rule above, computed once, cycle-safe; `close` moves no file;
   `_archive_finished`, `_ready_for_done` and its finding leave. Tests: a finished subtree left out
   of the window in place; a closed question with an open child, a deferred or suspect one, or one
   an open question depends on, kept; a cycle read without recursion; the `done/` tests rewritten
   to the state.
3. **A move rewrites `part of` alone.** The move's renames go, with `_misplaced`, the relative ids,
   `Written`'s lists and `sessions.renamed`; the rename helpers stay for the reword and the
   migration. Tests: a move keeps the id, the file and every link, and the tree shows the new
   parent; a move to the root; `open --between`; a cycle refused. The move's rename tests leave.
4. **New ids at `open`.** The pattern in `docs_corpus.py` in its two-form group, with every reader
   taking it from there; the id rule, the file name, `_files_holding` on `<id>.md`; a reword keeps
   the file and `_name_problems` stops comparing the slug; listings take the words from the title.
   A `TODO q-0037.0017.0005.0001.0019` on the dotted half of the pattern leaves at stage 6. Tests:
   the form; two opens at once give two ids with the draw forced to repeat once; `_FIRST_ID` reads
   a new id whole; a `TODO` naming a new id is bound; a reword keeps the file; a ticket's listing
   shows the question's words.
5. **The migration.** The script, tested on a fixture tree holding live and `done/` entries, links
   at two depths, with a fragment and from `done/`, the store's own links, a fenced block, a straw
   dog, a `TODO`, a row, a frozen table from an earlier run and a research `.txt`: every citation
   resolves, the table holds every pair and keeps its old ids, the `.txt` and the fence are
   untouched, a second run changes nothing, a re-run on a copy taken before the migration gives the
   same ids, a file the run would change left dirty is refused. Then — the person having cleared
   the store's uncommitted work and the sweep run through the parent — run on this tree, its commit
   alone, and the sweep's mark moved past it.
6. **One form.** The dotted half of the pattern and the stage-4 `TODO` leave; the old-id finding
   and the lookups of `_question_id`, `--hold` and `--take` come in; the fixtures speak the new
   form; the painted doors follow; the dead code under *What goes* is removed and the rename
   helpers move into `migrate_ids.py`.
7. **The text.** The shipped skills', mechanisms', formats' and rules' text, `opened` in the
   question format and the prose example ids among it, through `/skill-up`, shown before landing;
   the entry file re-installed; the window's test run again.
8. **The person's other trees.** The migration run in each, its citation walk and checks clean.
9. **Close.** The architecture's two straw dogs bound to q-0037.0017.0005.0001.0019 reworded to
   the finished rule as built and unwrapped, and the question closed against this ticket at
   `/verify`.
