## The shape

**The id.** `q-` and six characters of the lowercase base32 alphabet of RFC 4648, `a`–`z` and
`2`–`7`, at least one of them a letter, so no new id reads as a dotted one of four digits. Drawn
from the operating system's randomness; one already in the store or in the frozen table is drawn
again (decision 6; the architecture's *one already taken is drawn again*).

**The file.** `docs/questions/<id>.md`; its title line `# <id> <the question>`. A reword changes
the title line and nothing else; the file keeps its name.

**The place.** `part of` alone, as today. A new header field, `opened`, the minute the question was
opened in UTC, written by `open` and never again; the tree's order is a parent before its
children, siblings by `opened`, then by id (the architecture's *siblings in the order they were
opened*). The window, `--tree`, the wake and every listing draw the tree from these two fields;
no address is shown or kept.

**A move.** `move` rewrites the moved question's `part of` and nothing else; the cycle refusal
stays. `open --between` rewrites the lower question's `part of` and nothing else.

**A closed question.** It stays where it is. An entry is archived when it is closed and no
question below it is open, deferred or suspect — what moves a subtree to `done/` today — and the
window, the wake and every live listing leave archived entries out as they leave `done/` out now.
`close` moves no file.

**What goes.** In `questions.py`: the dotted `_ID` and the patterns built on it, `_next_free`,
`_parent_of`, `_positions`, `_misplaced`, `_relative_ids` and its finding, `_seat`'s renames,
`_renames_below`, `_carry_renames`, `_rewrite_ids`, `_name_renamed_ids`, `_archive_finished`,
`_ready_for_done`, `_ready_roots`' finding, the slug budget and `_fitted_slug`, the rename's file
moves in `_rewords`, `Entry.archived`'s reading of the folder. In `docs_corpus.py`:
`with_question_bindings_retargeted`, whose only caller is the rename. `TODO_QUESTION`,
`tickets.py`'s `_NAMED`, `sessions.py`'s row grammar and `harness.py`'s shear take the new
pattern from `questions._ID`. `move_doc.py` keeps `done/` for tickets and RFCs.

**The finding for an old id.** The store's check reports a dotted id anywhere it reads, outside
the frozen table, naming the new id the table gives it — so a branch made before the migration
and merged after is caught, and the migration re-run on it.

## The migration

A script of its own, `.agents/scripts/gw/migrate_ids.py`, run once in this tree and once in each
of the person's other trees, with a `TODO q-0037.0017.0005.0001.0019` at its top: it leaves once
every tree has run it.

1. Read every entry, live and in `done/`.
2. Draw a new id for each, by the rule above; the frozen table is the pairs.
3. Write each entry to `docs/questions/<new id>.md` with its title, `part of`, `depends on` and
   every other id in its header and body rewritten through the table, and `opened` set to the
   minute of the commit that first added its file (`git log --diff-filter=A --follow`), the
   minute of the run where none did. Remove the old files and `done/`.
4. Rewrite every tracked text file of the tree through the table — `docs/`, `.agents/`, the
   entry file, the rules files, the scripts' `TODO`s, the rows: a link into the store,
   `questions/(done/)?q-<old>-<slug>.md`, becomes `questions/q-<new>.md` at the citing file's
   depth; a bare old id becomes its new one, the longest first, so no parent's id eats its
   child's. Nothing in git's history changes.
5. Write the frozen table, `docs/questions/former-ids.md`, one row per question: the old id, the
   new, the question's words. The store's check reads it and treats it as no entry.
6. Run every script's `--check` and say what fails.

It refuses on a working tree with uncommitted changes, so its change is one commit the person can
read and revert. Run again on a tree with no dotted id, it changes nothing. The installed blocks
of the entry file come from the rules files, which it rewrites with the same table, so a
re-install agrees.

## Impact

- **Must change.** `questions.py` as above; `docs_corpus.py`, `tickets.py`, `sessions.py`,
  `harness.py` (the seed's three roots get new-form ids; the shear's pattern); about 250 tests of
  the store and the fixtures of the others that write dotted ids; the text of about fifteen
  shipped files that say the id is the place, a move renames, or a closed subtree goes to `done/`
  — the questions skill and its format, the questions and session mechanisms and their rules, the
  maintain, conclude, verify and ticket skills, the ticket and ADR and edge formats, the entry
  file's example ids. Those instructions sit on the self-improvement ladder at *a rule*, the dial:
  they are drafted through `/skill-up` at `/implement` and shown before they land.
- **Must verify.** `mechanisms.py`, `product.py` and `straw_dogs.py` read through
  `questions.read_store`; its answer keeps its form, so they should pass unchanged — their tests
  say. The window's lines and the wake's report change only where they printed an id's position.
- **May simplify.** Everything under *What goes*.
- **Hidden edges.** A branch made before the migration carries dotted ids; the finding above
  catches it at merge, and the migration re-runs on it. A worktree of this tree,
  `.claude/worktrees/`, is such a branch. Old ids in commit messages resolve through the table
  alone. `opened` from `git log --follow` may name a rename's commit for a file moved before
  `--follow` could trace it; order among those siblings is then by id — accepted, the order being
  for reading. A running session's row names old ids; the migration rewrites the rows, and a
  session's own memory of an id is said by the finding the next time it names one.
- **Leave alone.** The body's sections; rung, lean, strikes; tickets' and RFCs' numbers and
  `done/`; the store's place on `main`; the server.

## Stages

Each stage keeps the tests green, test first, by [/tdd](../../.agents/skills/tdd/SKILL.md).

1. **The tree by `part of` and `opened`.** `open` writes `opened`; the order reads it, falling back
   to today's positions for an entry without one. Tests: siblings in opened order; a store with
   both kinds orders as today.
2. **Archived by state.** An entry is archived by the rule above, the folder no longer consulted;
   `close` moves no file. Tests: a finished subtree left out of the window in place; a closed
   question with an open child kept; the `done/` tests rewritten to the state.
3. **A move rewrites `part of` alone.** The renames go, with `_misplaced` and the relative ids.
   Tests: a move keeps the id, the file and every link, and the tree shows the new parent; a cycle
   refused. The rename tests leave.
4. **New ids at `open`.** The id rule and the file name; a reword keeps the file. Both forms are
   read meanwhile — a `TODO q-0037.0017.0005.0001.0019` on the dotted pattern, which leaves at
   stage 6. Tests: the form; two opens at once, two ids; a taken id drawn again; a reword keeps the
   file.
5. **The migration.** The script, tested on a fixture tree holding live and `done/` entries,
   links at two depths, a straw dog, a `TODO`, a row and an entry-file block: every link resolves,
   the table holds every pair, a second run changes nothing, a dirty tree is refused. Then run on
   this tree, its commit alone.
6. **One form.** The dotted pattern and the stage-4 `TODO` leave; the old-id finding comes in; the
   fixtures speak the new form; the dead code under *What goes* is removed.
7. **The text.** The shipped skills', mechanisms' and rules' text, through `/skill-up`, shown
   before landing; the entry file re-installed.
8. **The person's other trees.** The migration run in each, with its checks.
