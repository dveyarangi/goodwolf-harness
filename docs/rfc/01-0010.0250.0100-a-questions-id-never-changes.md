## The shape

**The id.** `q-` and six characters of the lowercase base32 alphabet of RFC 4648, `a`–`z` and
`2`–`7`, holding at least one letter and one digit, so no new id reads as a dotted one or as a
word after `q-`. Drawn from the operating system's randomness; one already in the store is drawn
again (decision 6; the architecture's *one already taken is drawn again*). The draw is passed in,
so a test can force a repeat.

**The file.** `docs/questions/<id>.md`; its title line `# <id> <the question>`. A reword changes
the title line and nothing else. Wherever a listing showed a question by its file's slug —
`tickets.py`'s table among them — it takes the words from the title line.

**The place.** `part of` alone, as today. A new part, `opened`, the second the question was
opened in UTC, written by `open` once and never again; a declaration that opens several stamps
them a second apart in the order it writes them, so a seed keeps its shelf's order. The tree is
walked from the roots down, a parent before its children, siblings by `opened`, then by id; an
entry without `opened`, read before stage 5's migration, sorts by today's positions among its
siblings. The window, `--tree`, `--path`, the wake, `product.py`'s listing and every other listing
take that walk; the window's *open questions under this root* is indented by depth instead of
read off ids. No address is shown or kept. `opened` lands in
[QUESTION-FORMAT.md](../../.agents/skills/questions/QUESTION-FORMAT.md) with stage 7's text.

**A move.** `move` rewrites the moved question's `part of` and nothing else; the cycle refusal
stays. `open --between` rewrites the lower question's `part of` and nothing else. A subtree is
whatever `part of` reaches: `_within` walks `_ancestry`, so `--path`'s counts and dependents stay
right.

**A finished subtree.** A closed question stays where it is. An entry is *finished* when it is
closed, no question below it is open, deferred or suspect, and nothing held open leans on it —
today's condition for the move to `done/`, every clause kept. It is computed once in
`_entries`/`read_store` over the whole store, cycle-safe, and kept as the attribute
`product.py` reads; the window, the wake and every live listing leave finished entries out as
they leave `done/` out now. `close` moves no file.

**What goes.** In `questions.py`: the dotted `_ID` and the patterns built on it, `_next_free`,
`_parent_of`, `_positions`, `_misplaced`, `_relative_ids` and its finding and `_leans`' refusal of
a relative id, `_seat`'s renames, `_renames_below`, `_carry_renames`, `_rewrite_ids`,
`_name_renamed_ids`, `_archive_finished`, `_ready_for_done`, `_ready_roots`' finding, the slug
budget, `_fitted_slug` and `_name_problems`' slug check, the rename's file moves in `_rewords`,
`Written`'s renamed and archived lists and their lines, `_existing`'s word that an id changes on a
move; `sessions.py`'s `renamed`. `_files_holding` globs `<id>.md`, so `recheck` still raises
`Taken`. `TODO_QUESTION`, `tickets.py`'s `_NAMED`, `sessions.py`'s row grammar and `harness.py`'s
shear take the new pattern from `questions._ID`. `move_doc.py` keeps `done/` for tickets and
RFCs. `mechanisms.py`'s painted doors lose the store's `done/` and gain the frozen table.

**An old id.** `_question_id` looks a dotted id up in the frozen table and refuses it with the new
id, so a running session that names one is told where it went. The store's check reports a dotted
id in the store, the rows and the `TODO`/straw-dog bindings, naming its new id from the table — so
a branch made before the migration and merged after is caught, and the migration re-run on it.
Prose examples elsewhere are not read.

## The migration

A script of its own, `.agents/scripts/gw/migrate_ids.py`, run once in this tree and once in each
of the person's other trees, with a `TODO q-0037.0017.0005.0001.0019` at its top: it leaves once
every tree has run it.

1. Read every entry, live and in `done/`, and the frozen table if one exists.
2. Give each dotted id the new id the table already holds, and draw one by the rule above for a
   dotted id the table lacks; the table gains those pairs. A re-run on a branch made before the
   migration so gives each question the id it already got.
3. Write each entry to `docs/questions/<new id>.md` with its title, `part of`, `depends on`,
   `owner` and every other id and citation in it rewritten, and `opened` set to the second of the
   commit that first added its file (`git log --diff-filter=A --follow`), the run's own second
   where none did. Remove the old files and `done/`.
4. Rewrite through the table in the scope today's rename already keeps (`_rewrite_ids`): every
   record under `docs/` outside fenced blocks, the rows, and the `TODO`/straw-dog bindings outside
   `docs/`; every citation into the store, the store's own links included, resolved through
   `docs_corpus.cited_record` and re-pointed at `q-<new>.md` at the citing file's depth, its
   `#fragment` kept. Evidence that is not a record — research results in `.txt`, `.json`,
   `.diff` — and test fixtures are left as they stand. In this tree the shipped skills', rules' and
   entry file's ids follow at stage 7; in the person's other trees the installed core under
   `.agents/` and the installed blocks are not touched, only `docs/`, the bindings and
   `local.rules.md`.
5. Write the frozen table, `docs/questions/former-ids.md`, one row per question: the old id, the
   new, the question's words. `_entry_files` and `seed` pass it by name.
6. Walk every citation of the tree through `docs_corpus.citations` and `cited_record`, and say any
   that resolves to nothing; run every script's `--check`.
7. Mark the migration's commit as swept for `/maintain` (`maintain.py --mark '*' decisions`), so
   the sweep does not read some 370 rewritten entries as decisions landed.

It refuses while anything under the paths it rewrites is uncommitted or untracked, naming them, so
its change is one commit the person can read and revert; in this tree that waits on other
sessions' uncommitted work in the store, which the person clears first. Run again on a tree with no
dotted id, it changes nothing.

## Impact

- **Must change.** `questions.py`, `sessions.py`, `docs_corpus.py`, `tickets.py`, `product.py`'s
  order, `mechanisms.py`'s painted doors, `harness.py` (the seed's three roots get new-form ids
  and an `opened` each; the shear's pattern), as above; about 250 tests of the store and the
  fixtures of the others that write dotted ids; the text of about fifteen shipped files that say
  the id is the place, a move renames, or a closed subtree goes to `done/` — the questions skill
  and its format, the questions and session mechanisms and their rules, the maintain, conclude,
  verify and ticket skills, the ticket, ADR and edge formats, the entry file's example ids. Those
  instructions sit on the self-improvement ladder at *a rule*, the dial: they are drafted through
  `/skill-up` at `/implement` and shown before they land.
- **Must verify.** `mechanisms.py` and `straw_dogs.py` read through `questions.read_store`; its
  answer keeps its form. The window's rendering changes, so its test against a fresh session is run
  again, as the window's docstring asks.
- **May simplify.** Everything under *What goes*.
- **Hidden edges.** A branch made before the migration carries dotted ids; the old-id finding
  catches it at merge, and the migration, re-run on it, gives the same new ids. A worktree of this
  tree, `.claude/worktrees/`, is such a branch. Old ids in commit messages resolve through the
  table alone. `opened` from `git log --follow` may name a rename's commit; among such siblings the
  order falls to the id — accepted, the order being for reading. A running session's row names old
  ids; the migration rewrites the rows, and `_question_id` answers a session that still names one.
- **Leave alone.** The body's sections; rung, lean, strikes; tickets' and RFCs' numbers and
  `done/`; the store's place on `main`; the server.

## Stages

Each stage keeps the tests green, test first, by [/tdd](../../.agents/skills/tdd/SKILL.md).

1. **The tree walked by `part of` and `opened`.** `open` writes `opened`, a declaration's opens a
   second apart; the tree is walked, siblings keyed as above; `_within` walks `_ancestry`; the
   window's root list indented. Tests: siblings in opened order; a seed in its shelf's order; a
   store of mixed entries walks as today; `--path` counts by `part of`.
2. **Finished by state.** The rule above, computed once, cycle-safe; `close` moves no file;
   `_archive_finished`, `_ready_for_done` and its finding leave. Tests: a finished subtree left out
   of the window in place; a closed question with an open child, or leaned on by an open one, kept;
   a cycle read without recursion; the `done/` tests rewritten to the state.
3. **A move rewrites `part of` alone.** The renames go, with `_misplaced`, the relative ids,
   `Written`'s lists and `sessions.renamed`. Tests: a move keeps the id, the file and every link,
   and the tree shows the new parent; a move to the root; `open --between`; a cycle refused. The
   rename tests leave.
4. **New ids at `open`.** The id rule, the file name, `_files_holding` on `<id>.md`; a reword
   keeps the file and `_name_problems` stops comparing the slug; listings take the words from the
   title. Both forms are read meanwhile — a `TODO q-0037.0017.0005.0001.0019` on the dotted
   pattern, which leaves at stage 6. Tests: the form; two opens at once give two ids with the draw
   forced to repeat once; a reword keeps the file; a ticket's listing shows the question's words.
5. **The migration.** The script, tested on a fixture tree holding live and `done/` entries,
   links at two depths and with a fragment, the store's own links, a fenced block, a straw dog, a
   `TODO`, a row and a research `.txt`: every citation resolves, the table holds every pair, the
   `.txt` and the fence are untouched, a second run changes nothing, a re-run on a copy taken before
   the migration gives the same ids, a dirty or untracked path is refused. Then, once the person
   has cleared the store's uncommitted work, run on this tree, its commit alone, and marked swept.
6. **One form.** The dotted pattern and the stage-4 `TODO` leave; the old-id finding and
   `_question_id`'s lookup come in; the fixtures speak the new form; the painted doors follow; the
   dead code under *What goes* is removed.
7. **The text.** The shipped skills', mechanisms', formats' and rules' text, `opened` in the
   question format among it, through `/skill-up`, shown before landing; the entry file
   re-installed; the window's test run again.
8. **The person's other trees.** The migration run in each, its citation walk and checks clean.
9. **Close.** The architecture's two straw dogs bound to q-0037.0017.0005.0001.0019 unwrapped,
   and the question closed against this ticket at `/verify`.
