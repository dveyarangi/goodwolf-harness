### Second pass

7. **`at` on every line — withdrawn.** The pass argued that some writes place nothing, so the
   fold would have to put the position on a concern. The user's answer: a conversation is always
   on a question. The fold's session is on the question its work serves, which the store does not
   hold yet — and attach already opens that (decision 32). So `at` stays on every line but
   `nothing`, as item 1 settled, and the fold opens the work's question first and places there
   *(the user, 2026-09-29)*.
8. **A position per session.** Raised by the user on this item's first draft: one global position
   cannot let two agents work separate areas of the tree, and a turn can be about several
   questions. **Settled** *(the user, 2026-09-29; decision 39 amended)*: each running session
   registers its position in a file for now; the wake takes its position from the person or
   estimates it, then registers it; a starting agent sees the others and picks an area that does
   not overlap; how registrations reach sessions that do not share the file, and how the picking
   is done, are open questions of the store; the file's instructions are a straw dog on 01-0010;
   tested first on several local sessions. `at` stays one id: the window around it shows the
   questions near it. See *The sessions file* below.
9. **Who attaches.** Q1's moment is *a message arrives*. A subagent spawned inside a turn reads
   the same entry file and receives its prompt as a message, so it would run the wake and
   register a session of its own, writing a position for its sub-task and racing its caller's
   writes to the same entries. **Settled** *(the user, 2026-09-29)*: only the working agent
   attaches — the one answering the party that drives the session, the person or an agent in
   the person's role in an automated run. A helper spawned to do part of a turn does not wake,
   register or declare; what it finds reaches the store through the working agent's declaration.

### Third pass

10. **One sessions file, or one file per session.** Item 8 says the registrations live in a file.
    If every session writes its line into one shared file, each write rewrites the whole file; the
    interference check would refuse session A because session B moved *its own* line a moment
    earlier — a conflict that is not one. **Settled** *(the user, 2026-09-29)*: a single sessions
    file — it is temporary, a straw dog on 01-0010. Its write re-reads the file just before
    writing and replaces only the session's own line, leaving every other line as found, so
    another session's write is never a refusal; the entries keep the full interference check. The
    exception lives with the file, under the same straw dog and a `TODO` in code.

### At `/implement`

11. **What `done/` holds.** Raised by the user before stage 1: a closed question lands in a doc
    or code, or ends as a dead end, so a file in `done/` is worth keeping only as a pointer to
    that. Deleting wholly closed subtrees instead was put and refused. **Settled** *(the user,
    2026-09-29; parent decision 43)*: subtrees move to `done/` and are kept; a question asked
    again is found by searching `done/` titles, and the window never reads `done/`; `--check`

    or heading does not exist, live or in `done/`. *Pruned* and *moot* keep a one-line reason.

## Resolved at `/plan`

- **Relations are ids; the owner and the answer are links.** An id is placement-only and never a
  path (decision 24), so *part of*, *depends on*, *merged into* and *superseded by* are written
  as ids and resolved by the script over the live directory and `done/`. The owner and the answer
  are relative markdown links, and those are what the mover repairs when a subtree moves to
  `done/` (decision 34's *links repaired by the mover*).
- **A parent's answer changed** means the parent is `closed:superseded`. Decision 24 makes a
  reopening a new closure of kind *superseded* rather than a history on the entry, so it is the
  one way an answer changes that a script can see. The maintainer reports a closed child that is
  not suspect under such a parent.
- **A closed entry with an open dependency** is reported only if it is not suspect. Decision 33
  records the dependency when an answer is decided under an open question, and the entry is born
  suspect; reporting those as well would repeat what the entry already says.
- **A deferred or suspect entry is never archived.** Decision 34 archives a wholly closed subtree
  that nothing open depends on; decision 38 has the wake list every deferred question whose
  condition may now be met, and a suspect entry waits to be re-read. Moved to `done/`, both would
  leave the live store the wake reads. So for the archive criterion, a deferred or suspect entry
  counts as open. Without this, concern 1 — deferred, no children — would be reported ready for
  `done/` the day it is written, and `.0030`'s straw dogs, all deferred, likewise.
- **The wake has a view of its own, `--wake`.** Decision 38 needs every deferred question in the
  store; decision 26 keeps the window to deferred entries on or under the path, which is what
  keeps it constant-size at every turn. So `--wake` prints the window plus every deferred entry
  with its condition and every suspect entry, and Q2 runs it; `--window` stays the per-turn view.
- **The wake lists the sessions first, then reads the queue as today.** Q2 reports the running
  sessions and the ended ones with their positions before anything else, takes its own position
  from the person's first message or estimates it from them, and does not re-rank what another
  session is on; `/recall` then reads the delivery status and recommends from the queue's order,
  as its own text says. A session's position is where a conversation stands, the queue what
  delivery takes next. They meet at `.0020`, when a ticket's goal becomes an entry.
- **`/recall` is not only the wake.** Its description also serves *where do we stand?* asked
  mid-session. Registering at every `/recall` would give one conversation two sessions. So
  `--wake` registers only when called with no tag; called with `--session <tag>` it prints the same
  read for the session that already exists. And at a session's first message the wake's
  declaration *is* that turn's attach: one declaration, not two.
- **One writer, two front doors.** The writer is one function that applies a list of clauses;
  `--declare` parses a line into that list, and the judge's typed value (`.0040`) calls it
  without parsing (decision 39).
- **Clauses apply in order, and a write checks what it read.** A line's clauses apply left to
  right to the store as the line leaves it, and `at` is checked against the result; several
  `opens` in one line take the next free ids in order. Before writing, the writer re-reads every
  file it will change and refuses if one moved since validation — the architecture's
  [interruption and recovery](../architecture.md#interruption-and-recovery) contract, which the
  mover already follows: detected interference is a failure, not authority to overwrite. It is
  also what keeps two local sessions from taking one id: a new entry's file must not exist, so
  the second writer is refused and declares again with the next id. Sessions that do not share
  the directory — branches, remote sessions — can still collide; that is part of the open
  question of how registrations are shared.
- **An example entry in core sits in a fence.** The citation reader reads code spans and blanks
  fences, so a particular entry's path written in prose or a code span is a leak. The skill's
  examples are fenced; its prose names only `docs/questions/`, `docs/questions/done/` and
  `docs/questions/sessions`.
- **A session's position is on an open question**, and `at` names it on every line but
  `nothing` (item 7). The close, branch and prune rules' *move the position* becomes the agent's
  `at`. The script refuses `at` on a closed entry instead of guessing a parent. Another session
  may close the entry this session stands on; that is shown in this session's next window, not
  refused.
- **State `installed`**, as for the ticket mechanism, which also names nothing that retires it:
  install adds the parts and uninstall could remove them. Decision 41 is about retirement, and
  `always on` would mean nothing could ever install or remove it.
- **The window is the measured rendering**, the one in
  [the window test's generator](../research/window-test/gen.py) under `render_window`, with each
  line's state, kind, flags and lean added (decision 26), closed entries shown only on or under
  the path, and a last line naming the next free id. A change to the format reruns the test
  (evidence).
- **`/align`'s record-resolutions sentence becomes ticket's P11.** Decision 15 keeps recording
  resolutions ticket's and installed. The hand sentence under that heading, *sweep the ticket
  for internal consistency at the end*, becomes a rule in `ticket.rules.md` targeting `/align`, and
  the heading stays as the anchor R5, P7 and P10 already install under.
- **`debug=on` shows the working** *(the user, 2026-09-29; decision 25 amended)*. One sentence
  in the entry file, after the switch table: `debug` is `off` unless the project sets it; `on`
  shows each mechanism's working in the reply. Not a row of the table — it decides nothing about
  proceeding — and not per mechanism. This project sets it in `local.rules.md` as L4. Q1 shows
  the declared line only under `debug=on`; the `--declare` call is made either way.
- **A mid-turn declaration shows where it happened** (under `debug=on`). The user's amendment
  to decision 39 lets the agent call `--declare` again during the turn. So that such a write can
  be corrected in the same turn, as decision 25 wants for the first line, the reply quotes each
  mid-turn line at the point in the reply where the event is reported.
- **Ids are `q-` and at least four digits**, growing past four digits rather than overflowing
  (decision 34 projects five to six figures). The slug is taken from the question's words.

## The store

`docs/questions/` is a painted door: `docs/questions/`, `docs/questions/done/` and
`docs/questions/sessions` join `PAINTED_DOORS` in `mechanisms.py`, under a `TODO` bound to
01-0017.0010, the same as the ticket records. `docs/concerns.md` leaves the list when the fold
lands.

**An entry**, `docs/questions/q-0041-which-package-manager.md`:

```md
# q-0041 Which package manager do we use?

- **part of** q-0012
- **depends on** q-0007, q-0009
- **state** open, suspect
- **owner** [01-0011.0100](../tickets/01-0011.0100-the-open-questions-are-kept-by-a-mechanism.md)
- **answer** [decision 24](../tickets/01-0011.0100-the-open-questions-are-kept-by-a-mechanism.md#decisions-landed-at-this-tickets-align) — the user, 2026-09-28
- **lean** the flat directory, for insertion cost
```

The title line carries the id and the question. Every bullet is optional except **state**, and
**answer** on a closed entry (item 11). The
state is `open` or `closed:<kind>`, where the kind is one of `decided`, `pruned`, `merged`,
`deferred`, `moot` or `superseded`, and it may carry `, suspect` after it. What the answer
carries depends on the kind: a link with provenance for *decided*; `until <condition>, meanwhile
<default>` for *deferred*; an id for *merged* and *superseded*; a reason for *pruned* and *moot*.
The format is declared as a record in the skill with its three fields (MECHANISM-FORMAT §
Records). What an entry is: one file. Its tier: read by the script, and by a person through
`/questions`. What removes one: it moves to `done/` with its wholly closed subtree, and is never
deleted.

**The sessions file**, `docs/questions/sessions` (item 8): one line per session — its tag,
`running` or `ended`, the date it last wrote, its current question and up to four recent ones.
Only the script writes it, and a session writes only its own line: it re-reads the file just
before writing and replaces that line alone (item 10).

- **The wake registers.** `--wake` mints a tag for the session, adds its line as `running` with
  no position yet, and prints the tag with the sessions and the rest of the wake's read. Every
  later call carries `--session <tag>`; the tag is in the agent's context from the wake on.
- **`at` writes this session's line.** The window is drawn around this session's position and
  lists the other `running` sessions with their positions and dates, so an agent sees what is
  taken. How it should pick is an open question of the store, not a rule here.
- **The conclude ends it.** `--end` marks the line `ended` and keeps its last position, so a later
  wake can offer to resume where it stopped — decision 41's second grading test.
- **With no file**, or no line for a session, the wake estimates from the person's first message
  and the delivery status, as `/recall` does today.
- **What a crash leaves** is a `running` line nobody ends; the check reports one that has not
  written for a week as stale — a finding, never a diagnostic, since the session may be alive.

The file lives beside the entries and is committed with them, as the position was (decision 39).
Whether that is how running sessions reach each other beyond one working directory is the open
question; so its instructions — the skill's section on it and the reader in the script — are a
straw dog bound to [01-0010](../tickets/01-0010-dev-harness-shared-and-local.md), with a `TODO` in
code, until that question is answered.

## The declared line

One line with clauses separated by `; `. Free text in a clause (a question, a reason, a
condition) may not contain `;`, and the parser refuses a line where it does.

| clause | writes |
|---|---|
| `at q-N` | this session's position; required on every line except `nothing`, and q-N must be open |
| `opens q-N: <question>` · `opens q-N under q-M: <question>` | a new open entry, a root or under q-M; q-N must be the next free id |
| `opens q-N between q-M and q-K: <question>` | the new entry under q-M, with q-K re-parented under it; q-K must be part of q-M |
| `moves q-K under q-M` · `moves q-K to root` | re-parents q-K; refused if it would make a cycle |
| `depends q-A on q-B` | adds q-B to q-A's *depends on* |
| `closes q-N: <kind>[, <pointer>]` | the state and the answer, in the form above for each kind |
| `suspects q-N` · `clears q-N` | sets or removes the suspect flag |
| `leans q-N: <line>` | the lean |
| `assigns q-N to <path>` | the owner |
| `nothing` | a turn that places nothing; this session's position is left as it is |

A prune that would leave an open child under the pruned question is refused. The children that
stand on their own are moved out first with `moves` in the same line, and the rest are closed
(decision 37). The whole line is validated against the store before anything is written, the
entries are written first and the session's line last, and a refusal writes nothing.

## The script — `questions.py`

`.agents/scripts/gw/questions.py`, standard library only, reusing `docs_corpus.py` for citations.
Modes, each named, and a bare call refuses:

- `--window --session <tag>` prints the window around the session's position, with the other
  running sessions; with no store or no position it says so and exits 0.
- `--wake` registers a new session and prints its tag, or with `--session <tag>` registers
  nothing and reads for that session; the running and ended sessions with their
  positions; every root; every deferred entry with its condition and default; every suspect
  entry. The wake's read (Q2).
- `--end --session <tag>` marks the session ended (Q3).
- `--tree [q-N]` prints the live tree, whole or under q-N: the index of decision 34, rendered and
  never committed.
- `--declare "<line>" --session <tag>` parses the line and hands its clauses to the one writer, which the judge's
  typed value will call without parsing.
- `--check` is the maintainer. It reports **diagnostics**, which fail the run: a malformed entry;
  an orphan, meaning a relation that names a missing id; a cycle in *part of*; a closed child that
  is not suspect under a superseded parent; a closed entry that is not suspect with an open
  dependency; a closed entry with no answer; a *decided* answer that is not a link, or whose file
  or heading does not exist, live or in `done/` (item 11); a malformed sessions file, or a session
  position naming a missing entry; a filename whose id or slug disagrees with its title. It reports **findings**, which do not fail the run:
  a session standing on an entry another session closed; a running session silent for a week;
  likely twins, meaning title pairs that share enough content words; and wholly closed subtrees that
  nothing open depends on and that are ready for `done/`, a deferred or suspect entry counting as
  open. It writes nothing, and a conforming
  store stays byte-identical.

## The declaration

`.agents/mechanisms/questions/questions.md`, written to MECHANISM-FORMAT. Its title names the job
(roughly *the open questions of the tree are kept in one store, with a known current question*).
`instruction` points at `.agents/skills/questions/SKILL.md`, and the state is `installed`.

- **How it works** holds the principles, cited from the rules and never installed: depth is the
  instrument against breadth; a skipped question is found by impasse or by the method's plan,
  never by walking presuppositions upward; decide at the level asked; descend-or-hold is a value
  question; the same question means the same answers; the tests for whether a question is worth
  holding. It also covers the three levels (store, judge, hook) and the retirement and grading of
  decision 41.
- **Moments**:
  - Instructed rows: placing a message, instructed by `AGENTS.md`; closing, branching or pruning,
    and tidying by hand, instructed by the skill; rendering the window, writing from a declared
    line and checking the store, all instructed by `questions.py`; the wake's read, by `/recall`;
    the conclude's write, by `/conclude`; archiving a closed subtree, by `/maintain`; installing
    with core, by `harness.py`.
  - `not yet` rows: a judge outside the generator, bound to `.0040`; detecting a shape that hides
    children, bound to `.0050`; running the window and the write without the agent, bound to
    `.0120`; tickets' open issues as entries, bound to `.0020`; straw dogs as entries, bound to `.0030`;
    removing it from a tree, bound to 01-0010.
- **Parts:** the skill, the doc, the rules file, `questions.py` and its tests.
- **Relied on:** the mover (`ticket`), the citation reader, the test harness and the installer
  (`mechanism-shape`), and the method's glossary.
- **What it produces:** the entries and the sessions file, which the script and a person read; the
  window, read by the agent at every turn; the check's report, read by `/maintain` and `/verify`;
  and the rules file, read by the installer.

## Stages

Each stage keeps the suite green; the suite runs at every stage's end.

1. **Reader and maintainer.** `questions.py --check` over a store read from disk. Tests cover each
   diagnostic in both polarities; each finding, and that findings leave the exit code at 0; a
   deferred leaf and a suspect closed subtree never reported ready for `done/`; a conforming store
   left byte-identical; a store with no directory; a *decided* answer in `done/` whose link
   resolves from there, and one whose heading no longer exists. `PAINTED_DOORS` gains the
   store. `repository.py`'s guard is extended from the live marks to `docs/questions/`, so a
   suite run that changes the live store fails the case that did it.
2. **The window, the wake and the tree.** Tests over a fixed store: path, frontier, the current
   root's open titles, one line per other root, recents, closed entries only on or under the path,
   a suspect under the path, the next free id; a deferred entry off the path absent from the
   window and present in `--wake` with its condition; the fallback without a position. Two
   sessions: each window drawn around its own position and listing the other; `--wake` minting a
   tag and registering it; `--wake --session <tag>` registering nothing; `--end` keeping the
   last position; a week-silent session a finding.
3. **The writer.** `--declare`. One test per clause writes and reads back. Refusals each name
   their reason and leave the store byte-identical: a malformed line, a `;` in free text, an id
   that is not the next one, `at` on a closed entry, a between whose lower is not part of the
   upper, a cycle, a prune that leaves an open child, a kind without its pointer, an entry changed
   on disk between validation and write, a second session taking an id the first just wrote.
   A session's `at` changes its own line and no other, and succeeds when another session wrote
   its line between the read and the write. Clauses apply in order: a line that opens two questions
   and closes the first reads back so. A round trip opens, attaches, closes and prunes, then reads
   back through `--check` clean.
4. **The declaration.** The doc, the skill, the rules file, the evidence and the architecture
   surface. The recall and conclude anchors are added, and the four blocks and P11 installed;
   P11 joins `ticket.md`'s *who decided* table, and `maintain.md`'s *disposing of a concern* row
   names the questions skill. The entry contract goes to v18, with the `debug` sentence. `mechanisms.py
   --check` and `inject_rules.py --check` are clean. The questions check joins the local
   verification set (`local.rules.md` L3), and `debug=on` is set as L4; both reinstalled.
5. **The fold**, in the order under *The fold of `concerns.md`*: the six entries through
   `--declare` and `questions.py --check` clean over them; the repointed lines; last,
   `concerns.md` deleted and its door row removed, with `mechanisms.py --check` showing no leak.
6. **The strip.** `/align` per the table above. `straw_dogs.py` lists every new wrapper as bound.
7. **`/verify`** against the ticket, this RFC and the governing docs.

**Hidden edges:**

- Every turn in this tree, and in every recipient that updates, runs two script calls: the window,
  then the declaration. A recipient with no store gets the fallback notice until its first
  declaration writes one. That is a behaviour change on the installation edge, and it has no edge
  record to land in yet
  ([01-0010.0185 an-edge-change-writes-its-line](../tickets/01-0010.0185-an-edge-change-writes-its-line.md),
  Planned).
- Q1 names the script by its filename, as P2 does. How a tree runs Python is its own business; on
  this machine it is `uv run --offline --no-project python`, and bare `python` is not on the path.
- R8: once the mechanism is `installed`, no other skill's own text may name `/questions`. The
  replacement lines name the painted door, never the skill.
- Blocks go into two skills claimed `not yet`: `/recall`, bound to 01-0020, and `/conclude`, bound
  to 01-0017. `/align` already takes blocks while it claims `not yet`, so this is allowed.
- Deleting `concerns.md` breaks anchored links. The mover cannot split one file into several
  homes, so the repointing is by hand, and the plan lists every site.
- The straw-dog lister guesses on *until* in any record under `docs/`, so every deferred entry's
  `until <condition>` is a guess — never a failure, but noise in `/verify` over touched files. One
  entry in this slice; `.0030`, which makes the straw dogs deferred entries, owns the
  reconciliation and with it this overlap.
- Helpers read the entry file too; Q1 says in its own words that they do not attach (item 9).
  Whether a helper obeys is observed only under `debug=on`, like any missing line.
- The tag lives in the agent's context. A context summary that drops it leaves the agent unable to
  name its session; it wakes again, and the old registration goes stale and is reported after a
  week. The window prints the tag at its head, which is what a summary is most likely to keep.
- Several local sessions share one working tree, so each sees the others' new entries as
  uncommitted changes. A session knows which entries it wrote — its own declarations are in its
  context — and `/commit`'s *commit the work in current session only* already covers the rest.
- Every declaration changes a file, so the store's files move with nearly every turn and
  history grows with them. Accepted for the local test; how much of it should be committed is
  part of item 8's open question.

**Leave alone:** the tickets' open issues and the straw dogs (`.0020`, `.0030`); any judge (`.0040`,
`.0050`); the hook (`.0120`); the pacer's threshold; the rules-file grammar gap; `/align`'s
