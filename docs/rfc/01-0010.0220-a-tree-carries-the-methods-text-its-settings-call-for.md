## Governing boundaries

- **The rules file's grammar** is the format shelf's
  ([MECHANISM-FORMAT.md](../../.agents/skills/mechanism/MECHANISM-FORMAT.md), *The rules file*):
  the anchor table, one section per rule, `target`, `authority`, `overrides`, the body between
  `<rule>` edges. The declaration table, the `when` line and the local file's settings table land
  there, as grammar; nothing here invents a second home.
- **The installer's contract** is the architecture's
  ([Installed blocks](../architecture.md#installed-blocks)): a named mode or a refusal; every
  target validated before anything is written; retraction byte-identical; a differing block
  refused until the caller says overwrite, then replaced whole and reported. A conditioned rule
  is one more thing the renderer reads; the contract does not move.
- **R7**: the project's answers live in `local.rules.md` and reach a file only as the local block.
  The settings table is one more thing that file authors; its values reach a file only through
  the installer.
- **R4**: an index is rendered on request and never committed beside its records. The
  consolidated settings table is an index of the declarations and the local file.
- **The entry file's *Autonomy***: the project sets each dial in its local block, and the agent
  never writes its dial — the host refuses the edit (01-0010.0125's shape).
- **The hosts edge** ([hosts.md](../edge/hosts.md)): the hook never fails the host; a problem
  becomes a line of context.
- **A document informs**: the edge record names the renderer; nothing reads the record to work.
- **Decision 2 of q-0037.0009.0021**: debugging's text reaches a tree as installed blocks of its
  own mechanism, never one text read behind a switch. This ticket supplies the switch; the
  mechanism is 01-0016.0020's.

## Impact

**Impact.** `inject_rules.py`: the parser reads tables by their header, reads a declaration table
and `when` lines, resolves settings from the local file's table or the default, renders a target's
block from the rules whose conditions hold, treats a target left with no rule as one whose block
is removed, and gains a run over every source and a call that changes a setting. Its check: a
`when` naming an undeclared setting or value, a local value no declaration holds, a setting
declared twice, a block whose content disagrees with the settings. `harness.py`'s `_install_rules`
is that run, so the install and the update read settings for free. The format shelf: three
forms. `local.rules.md` of this tree: a settings table. `/harness`: two occasions in its
description, the table shown. `/maintain`: the injector's check already reaches it as an
installed rule; a block disagreeing with its settings is one more diagnostic there, no new rule.
The hosts edge: a line at session start. Tests: `test_inject_rules.py` for every new form and
refusal, `test_harness.py` for the run.

**Hidden edges.** The anchor-table parser matches any row of two code spans, so a local settings
table of two code spans would be read as anchors: tables must be told by their header before
the first new row is written. A recipient updated before its local file has a table stands at
every default — safe, and the update's report says it. The dial's rows in the table are the
person's: the host's refusal of a dial edit must learn the table's row, or the table waits for
01-0010.0125. A run of the installer moves the entry file under running sessions
(01-0018.0010). Every mechanism's fingerprint moves at the format change. A setting's declaring
mechanism must exist before any rule can use it: `debug` has none until 01-0016.0020 builds
debugging, and the dials have none until the ladder mechanisms exist — the ticket's live
criteria have no declared setting to stand on (challenge 1).

**Leave alone.** The debug blocks' content and their move (01-0016.0020). Which method
(01-0017.0020). The host's refusal itself (01-0010.0125). The session-row writes of the hook.

**Recommendation.** Proceed as one slice, once the three challenges below are aligned: the
machinery is one contract; what is unsettled is which live setting proves it, where the wake's
line comes from, and what the edge record is.

## Taken at `/plan`

1. **Tables by header.** A rules file's preamble holds tables told apart by their header row:
   `| target | anchor |`, `| setting | values | default | set by |`, and in the local file
   `| setting | value |`. A row under no known header is prose and is not read.
2. **The declaration.** `setting` and each of `values` are code spans; `values` are separated by
   ` · `; `default` is one of them; `set by` is a rung's name as the entry file's ladders write
   it, or `the person`. A setting declared in two files is a diagnostic of the check and a
   refusal of the run.
3. **The condition.** `- **when** <setting>=<value>` beside `target` and `authority`, any number,
   all must hold; the setting must be declared and the value among its values, or the rule is
   refused as a malformed rule is — every mechanism in a tree is installed, so an undeclared
   setting is never a transient state.
4. **The value.** The local file's `| setting | value |` table; a setting absent stands at its
   default; a value no declaration holds is refused.
5. **Rendering.** A target's block holds the rules naming it whose conditions hold, in file order.
   A target named in the anchor table and left with no rule has no block: present, it is removed
   by retraction's cut and reported, as a dropped target is.
6. **The run.** `inject_rules.py --install --overwrite` with no slug installs every source in the
   harness's order — mechanisms, then local — and is `_install_rules`; the report carries each
   block replaced. Overwrite is said because a settings change makes a block differ from its
   rendering, which the contract refuses without it.
7. **The call.** `inject_rules.py --set <setting>=<value>`: refuses an undeclared name or value,
   writes the local file's row, runs the run, prints its report. It does not read `set by`: who
   may run it is the dial's and the host's.
8. **The table on request.** `inject_rules.py --settings` renders one table — setting, values,
   default, the tree's value, owner, set by — and writes nothing (R4).
9. **The check.** `--check --line` prints one line, or nothing, for the hook; `--check` adds: a setting declared twice, a `when` or a local value against the
   declarations, and a block disagreeing with the rendering under the tree's settings, which the
   existing *drifted* state already names.
10. **The dial line.** Deferred to the ladder mechanisms, a straw dog on the ticket's criterion;
    L2 stands as it is.
11. **The first declared setting** is `debug`, declared by the debugging mechanism, which this
    ticket brings to the shape with one rule — the announce line — so the live criteria stand
    on it; the settings table of this tree holds `debug` at `on`.

## Shapes

- `Rule` gains `when`, the conditions as pairs; `RulesFile` gains its declarations; a resolution
  of settings — declarations across every rules file, values from the local file — is read once
  per run and passed to `block(target, settings)`. The parser's table reading is one function
  keyed by header.
- `_installing_or_retracting` plans a removal for a target whose rendering is empty, through
  `_removal`.
- `check` gathers declarations across files before judging any file.
- `harness.py` passes settings through `_install_rules`; the rehearsal reads the local file's
  table as the copy will leave it.

## Stages

1. **Tables by header** — red: a local file whose settings rows are read as anchors; green: the
   header-keyed reader; the anchor tests unchanged.
2. **Declarations and conditions parsed** — red for each refusal of decisions 2 and 3; green.
3. **Rendering under settings** — red: a rule with `when debug=on` installed in a tree whose
   local file says `off`; a target emptied by conditions keeping a stale block; green: absent and
   removed, with the report.
4. **The run and the call** — red: `--install` with no slug refused; `--set` on an undeclared
   value writes; green. `test_harness.py`: the update runs `_install_rules` under settings.
5. **The check and the table** — the new diagnostics, the rendered table, `--settings` writing
   nothing.
6. **The format shelf, the skills and the hook** — the three forms on the shelf; `/harness`'s
   description and body; `hook.sh` running `inject_rules.py --check --line` after the wake and
   moving to mechanism-shape's parts, the hosts edge's *Wake* invariant and its validator with
   it; `test_questions.py`'s hook cases unchanged, one new case for the appended line.
7. **The live setting** — the debugging mechanism at the shape (doc, rules file, `mechanisms.py
   --check` green), its declaration and announce-line rule installed; `when debug=on` on the
   rules that said it; this tree's local table; the run, then `--set debug=off` and back, read
   live.

Every stage keeps the suite green; stage 1 changes no behaviour of a tree without a settings
table.
