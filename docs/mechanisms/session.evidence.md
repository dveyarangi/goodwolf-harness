## The prior corpus, 2026-10-22

At inception this tree's rows folder held 129 rows, 125 of them ended, the oldest from 2026-10-02:
no row had ever been removed, by the question format's own sentence — *kept by design, an ended
row lets a later wake offer to resume* — written for the single file and carried into the folder
unchanged. The wake printed every one into each session's context, 19 KB of it. Of the 125, 43
were desktop-app tags, reopenable by their conversation id; the rest were probes, Codex and

21 stayed, the oldest of them ended 2026-10-15, and the wake said nothing of it.

## Refused, 2026-10-22

- **A session as a host process.** The desktop app renames a conversation's process on every
  reopen (2026-10-09, 2026-10-10); a row keyed on it loses its position. A session is the chat,
  known by the steadiest id the host gives it.
- **The pacer taking `/recall`.** The pacer is method and owns no machinery (q-0037.0010.0012); a
  session's two ends are the session's whatever method runs between them, and the method's rules
  reach them as installed blocks.
- **The rows kept in the question format.** A format file describes a record; an instruction on a
  session's work is not a format, and the row is not a question record (rule failure 58). The row
  is declared beside `/conclude`, and the folder moved under `docs/sessions/`.
- **The code left in the question script, declared as embedded.** A part is checked by the
  mechanism's name at its head, which a shared file cannot carry.
- **The ended row's time kept at a silent ending.** The seven days would then run from the last
  `at`, not the session's last message: a long session that never moved would be gone at the wake
  that ended it. The ending writes the time the session was last seen.
- **A declaration slice and a removal slice.** The removal is a moment of the mechanism; declared
  without it the doc would say *not yet* of a rule already decided. One ticket, four stages.
