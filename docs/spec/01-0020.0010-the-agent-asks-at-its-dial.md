# The agent asks at its dial

**Status:** Draft, 2026-10-14 — developed through `/spec` from the align on
[q-0037.0013.0005](../questions/q-0037.0013.0005-which-of-the-agents-acts-need-the-persons-yes-and-which-does-it-do-on-its-own.md),
whose four decisions, three discoveries and impact it rests on and does not restate. Named for the
first of the four slices the user approved the same day; it argues for all four.

## Problem Statement

The person decides how far the agent goes alone through five switches in the entry file's autonomy
table — `commit`, `push`, `next-cycle`, `breakdown`, `repair` — each `ask` or `auto`. The switches
grew one occasion at a time and do not say what the person cares about. In this tree, on
2026-10-14:

- The installing agent must tell the person *where it stops for their yes*, while the `push`
  switch forbids any reply but `/conclude`'s to mention push. The two rules cannot both be kept.
- `push` is `auto` here, yet nothing may say so: in effect it is silent.
- Discovery found that practitioners almost never gate a local commit or a push to one's own
  branch; they gate joining the shared line. The switches guard the two acts everyone leaves free.
- A person working from two machines needs push as synchronisation after every commit, not as a
  publication held until the session ends.
- Four areas the agent acts in have no line at all: irreversible git operations, the environment,
  other sessions' work, local decisions on how to build.
- The harness's own rules change after the agent shows the text and lands it, without the
  person's yes — the heaviest area under the lightest line.
- Every switch is asked the same way of every project, and the person is asked to answer in the
  switches' own terms or in paraphrases of them.

The person does not think in switches. They think in how big a thing the agent may settle without
them.

## Solution

The agent's autonomy is a **dial on a ladder of scale**. Each area of work has a ladder, ordered by
consequence. The person sets the dial at one rung:

- **at the dial** the agent decides and asks for the person's yes before acting on it;
- **below** it the agent decides and acts on its own;
- **above** it the agent decides nothing: it lays out the options with a recommendation and the
  person decides.

It reports at its own rung, describes what it did one rung below, and says nothing of the lowest.

Two ladders now. **Development**, by consequence: code, a feature, load-bearing, a product slice,
the whole product. **Self-improvement**: a wording, a local rule, a core rule, a skill's act, a
mechanism, the method. In this tree development's dial is set by the person when the slice lands;
self-improvement's sits at a core rule.

An act that is not a decision on a ladder — `reset --hard`, a force-push, a message to a person, an
install outside the tree — is a security setting, held by a mechanical check the host enforces,
never by a rule.

The switch table goes. Commit and push follow the work: work below the dial closes with its commit,
and push follows the project's way of working with git, which is the environment's to propose.

## The rungs

A decision's rung is read from what it decides — the reach of its consequence — never from the
record that holds it: one ticket may carry a code decision, a feature and a load-bearing one *(the
user, 2026-10-14)*.

| ladder | rung | what it decides |
|---|---|---|
| development | code | how a feature is written, inside a plan, touching no contract |
| | a feature | what one piece of work delivers: its outcome and criteria |
| | load-bearing | what several parts rely on |
| | a product slice | which answer is built next, and its shape |
| | the whole product | what the project is for |
| self-improvement | a wording | words, meaning unchanged |
| | a local rule | one project's own answer |
| | a core rule | one rule every recipient receives |
| | a skill's act | what a skill does, in what order |
| | a mechanism | its parts, moments and records |
| | the method | the rings, the principles, the entry contract |

## User Stories

1. As a person starting a project, I want to say once how big a thing the agent may settle without
   me, so that I am not asked the same small question every turn.
2. As a person, I want the agent to ask me before it settles anything at the rung I chose, so that I
   stay in charge of what matters to me.
3. As a person, I want the agent to bring me options and a recommendation for anything above my
   dial, so that I decide those things myself and still have its reasoning.
4. As a person, I want the agent to do everything below my dial without asking, so that small work
   is not slowed by my attention.
5. As a person, I want to move the dial up when I trust the agent more, so that its freedom follows
   its record.
6. As a person, I want to move the dial down after a bad surprise, so that I can tighten control in
   one word.
7. As a person, I want to be told what was decided at my rung and what was done one rung below, so
   that a report is the size of my attention.
8. As a person, I do not want to hear about the lowest rung, so that a report is not a diff
   retold.
9. As a person, I want the dial named in my words when it is proposed — "I will write the code and
   commit it; I will ask you before I define a feature" — so that I never have to learn a switch's
   name.
10. As a person installing the harness into an empty tree, I want the agent to propose a dial that
    fits what I said the project is, so that I can accept it without studying it.
11. As a person installing into a tree with history, I want the proposal to say what it read from
    the tree, so that I can see why it fits.
12. As a person working from two machines, I want my work pushed as soon as it is committed, so
    that the other machine has it.
13. As a person, I want commit and push to follow my way of working with git rather than be asked
    on their own, so that they are never a decision I have to make per change.
14. As a person, I want irreversible acts refused by the host unless I lift the refusal, so that no
    instruction the agent misreads can destroy my work.
15. As a person, I want the agent never to change its own dial, so that the line I set is the line
    that holds.
16. As a person, I want the agent to change the harness's rules only at the rung I allowed, so that
    the method does not drift under me.
17. As a person, I want wording fixes in the harness done without asking, so that I am not asked to
    approve a comma.
18. As a person, I want a core rule changed only after my yes, so that every project that receives
    it was approved by someone.
19. As a person, I want mechanisms and the method changed only when I decide, so that the shape of
    my way of working is mine.
20. As a person, I want a violation of an explicit rule inside the work repaired and told to me at
    the right rung, so that repairs are neither hidden nor noise.
21. As an agent, I want one ladder and one dial to read, so that I do not reconcile five switches and
    their exceptions.
22. As an agent, I want each rung to say what a decision on it changes, so that I can tell a
    decision's rung from its content whatever record it sits in.
23. As an agent, I want a case between two rungs to fall to the higher one, so that an unclear case
    goes to the person rather than past them.
24. As an agent, I want the introduction at install to say exactly where I stop, so that the first
    thing the person hears is true for the whole session.
25. As an agent, I want acts off the ladder held by the host, so that my judgement is not the last
    line of defence.
26. As a recipient project, I want my old switches turned into a dial on update, so that I keep
    working without re-answering what I already decided.
27. As a recipient project, I want to be asked only what cannot be translated, so that an update
    costs me one answer at most.
28. As the person keeping the harness, I want the ladder to be stated once, in core, so that every
    skill reads the same line.
29. As the person keeping the harness, I want the old switch names gone from every skill, so that
    no skill reads a value that no longer exists.
30. As the person keeping the harness, I want the product document's rows on checkpoints rewritten,
    so that the account of what the harness is for matches what it does.
31. As a person reading a reply, I want the agent's own rung visible in it, so that I know what kind
    of thing I am being asked or told.
32. As a person, I want the same ladder that sets the agent's freedom to tell how much ceremony a
    change takes, if it does, so that I learn one scale rather than two.

## Implementation Decisions

- **The ladders and the dial's meaning live in the entry file's core**, replacing the autonomy
  table and the switch names in the loop's *Human checkpoints* line. A project's dial, one per
  ladder, lives in its local file. The entry contract is bumped.
- **The rung of a decision is read from what it decides**, per the table above, never from the
  record that holds it; a decision whose reach is unclear takes the higher rung. Minting a ticket
  or taking the next one has no rung of its own: it is on the rung of what the ticket decides, or
  of the order it changes.
- **Repair is not a rung** *(the user, 2026-10-14)*: mending a violation is the work of the rung
  the mended thing is on, asked, done or proposed as that rung's work is. That a repair happened is
  shown under debugging, which is a mechanism of its own (q-0037.0009.0021); the `repair` switch
  goes with the others.
- **Above the dial means proposing, not abstaining.** The agent still works there; it does not
  settle the decision. At the dial it settles and asks; above it the person settles.
- **Reporting is by rung**: a reply reports what was settled at the agent's own rung, describes the
  rung below, and is silent on the lowest. Under `debug=on` the machinery is shown as well; how the
  two meet is slice two's, against the reply form of q-0037.0016.
- **Commit and push are not decisions on the ladder.** Work closes with its commit at whatever rung
  it was settled; push follows the project's way of working with git, proposed by the environment
  (q-0037.0006.0022.0003). The `push` rule held by `/conclude` alone goes.
- **Security settings** are the acts off the ladder, held by the host's mechanical check under
  01-0010.0125 (q-0037.0006.0005). The dial itself is among them: the agent never edits its own
  dial (q-0037.0013.0005.0005).
- **The skills that read a switch read the dial**: commit, conclude, implement, ticket, verify,
  recall, questions, harness. None names a rung's number; each names the rung by what it decides.
- **Self-improvement's dial governs the Self-improvement section**: a rule failure's amendment is
  landed on the agent's own below a core rule, shown and asked at a core rule, and proposed above
  it. Its slice is 01-0019's.
- **Recipients migrate on update**: the update reads an old switches line and writes the dial it
  translates to, asking the person only what has no translation.
- **Product rows**: A13 *Human checkpoints and switches* and A14 *The project names its stopping
  decisions* are rewritten through `/product` when slice one lands.

## Testing Decisions

- A good test drives the behaviour a person sees: given a dial and a decision, the agent asks, acts
  or proposes. It does not assert wording.
- **Telling a decision's rung is judgement, not lookup**, so it is tested on cases: a set of real
  decisions from this tree's history, each with the rung the person gives it, read by an agent
  without the session's context and graded against the person's rungs.
- **The switches-to-dial translation** used on update is a pure function, tested over every switch
  combination the five recipients hold and the ones that have no translation.
- **The host check on the dial's line and on off-ladder acts** is tested in both polarities, as
  01-0010.0125's tests are.
- **Live checks**: an install into an empty folder proposes a dial in the person's words and its
  introduction states where the agent stops; one real session at a set dial is read for asks,
  acts and proposals against the rungs. Prior art: the empty-folder trial of 01-0010.0170.
- The existing checks hold: no skill names a removed switch, `inject_rules.py --check` clean,
  the entry contract's bump recorded.

## Out of Scope

- The project's way of working with git — q-0037.0006.0022.0003, the environment's.
- Where the verification set is installed — q-0037.0006.0022.0001.
- Which off-ladder acts the host refuses, beyond the dial's own line — 01-0010.0125.
- Ladders for harnesses of research or learning — none exists; the seam is left.
- Earned autonomy moved by a measured record — the person moves the dial by hand.

## Further Notes

- Discovery's warnings carried into the design: asking is not a safe default, since every ask spends
  the person's attention and frequent asks wear consent to a stamp; acts add up, so a line drawn on
  single acts misses their sum; a model update resets whatever trust a record earned.
- The families the design draws on: ends and means for the split between deciding and proposing,
  stake and reversibility for what sits off the ladder, earned autonomy for moving the dial.
