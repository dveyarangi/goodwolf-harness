# A test pays only for what it proves

- **Status:** In progress
- **Type:** HITL
- **Plan:** [A test pays only for what it proves RFC](../rfc/01-0011.0080-a-test-pays-only-for-what-it-proves.md)
  — prune first; then a guard refusing any process to an unmarked test, plain folders and an
  in-memory source for the rest, the cases whose subject is Git kept real
- **Related:** [01-0010.0130 harness-installs-into-another-tree](../spec/01-0010.0130-harness-installs-into-another-tree.md)
  — the install spec, whose Testing Decisions this changes too
- **Outcome:** A test starts a process only when Git or the gate's child process is what it
  proves, a guard fails any other test that starts one, and every behaviour the suite proves today

## Nine tenths of every test is a process start

342 tests take 320–345 s; session 13 had the suite at 68 s. Measured on 2026-09-26:

| | time | `subprocess.run` calls | in subprocesses |
|---|---|---|---|
| the slowest harness test, alone | 5.2 s | 40 | 4.8 s |
| all 40 `test_tickets` tests | 4.4 s | 46 | 3.7 s |

Timed on an idle machine, 2026-09-27, the median of three: **274 s** for 342 tests at `71aacab`;
**266 s** for the 284 left after pruning, one run — within the 263–291 s spread of the three, since
what pruning removed was not where the time goes; **40.7 s** for the 289 after the guard, the plain
folders and the in-memory source — 10 tests keep real Git and take three quarters of it; **24.2 s**
once the real ones stopped repeating the real path (one end-to-end scenario instead of three, the
target refusals asked without a clone, the recipient's script run twice on one install) and an
in-memory source stopped carrying copies of the live scripts only a real gate runs. Six tests whose
subject is a process take two thirds of what is left.

The in-suite doubling was the machine: on 2026-09-26 a game held two and a half cores, and the
slowest test took 5.2 s alone early and 10–16 s alone later, with nothing else of the suite running.
Idle, the three baseline runs spread only 263–291 s.

A `git ls-files` costs ~75 ms from Python; the gate's child-Python `--check` 323 ms. The 40 slowest
tests are 206 s of the run, 39 of them `test_harness`. The same slowest test takes 9.8 s inside the
suite — twice its time alone, unexplained.

Two sources, both in the code under test. `corpus()` in `docs_corpus.py` is the only Git call the
maintenance scripts make — a file list — and every script and test took it from the first one,
`move_doc.py`. `harness.py` reads its source only through `Source` (clone, `archive`, `cat-file`),
and its gate runs the recipient's own checks as child Pythons so what is checked is what arrived;
each harness test commits its scenario into a fresh source and then pays for both.

## What to build

- **Prune first** *(the user, 2026-09-27)*. An audit read all 342 tests against the code they
  exercise: 11 cannot fail on the regression they name, 51 repeat another test. Eight of the first
  go — three guard a real line and are strengthened by
  [01-0011.0090 a-test-catches-what-its-name-promises](./01-0011.0090-a-test-catches-what-its-name-promises.md)
  instead; the second fold their one distinct assertion into the test they repeat. The list is the
  RFC's.
- **The in-suite doubling** turned out to be the machine's load, not the suite.
- **A test whose subject is not Git reads the tree without it.** The test base lists files from the
  folder; the two tests about Git's listing — a record not yet staged, a file Git ignores — keep
  the real call.
- **A harness test takes its source's refs from memory** through a second `Source`, and runs the
  gate's checks in-process, unless its subject is what that replaces. A tree installed under
  earlier rules is held in memory too: its fixture is hand-written old content, built the way it
  came to be ([rule failure 9](../rule-failures.md)) whichever source holds it.
- **A few tests stay end to end** — real clone, real gate: an install, an update, a check, and the
  refusals Git decides.
- **The guard.** The test base refuses a process start from a test not marked as proving Git or
  the gate, so the next test written does not drift back.
- Production behaviour does not change: the real `Source`, the real gate and `git ls-files` stay
  the default.

## Out of scope

A time budget for the suite. A parallel runner. Why a Git process costs ~75 ms on this machine —
the machine's, not the suite's. A recipient's own verification set, which names or omits the
shipped suite itself.
