## Why it is one ticket and not two

The injector change and the conversion of this repository's own blocks are one act because the
conversions are what prove the injector change works: a local source that installs nothing here is
untested, and blocks converted by hand without the source are the defect this ticket exists to end.
`AGENTS.md` as a target is the seam that would split it — a target no rules file has ever named —
and it stays inside because the tier-1 rule that makes the local file binding cannot land anywhere
else. If `/plan` finds this too coarse for one RFC, it splits there.

## What to build

- **One local rules file per instance**, beside the entry file and outside `.agents/`, so a
  redeploy that replaces the core directory cannot delete it. Its entries are in installed-rules
  format — the target-and-anchor grammar the mechanism rules files use — and the injector reads it
  as one more source, with install, check and retract behaving exactly as they do for a mechanism's
  file. Rules only; `commit=ask` is a rule.
- **Local blocks install last**, after every mechanism's block in the same target, so a project's
  answer is what the reader meets after core's rule. A local entry that overrides a core rule
  **names that rule's id**; one that names none is refused with the reason.
- **`AGENTS.md` is a target.** Anchor rows name it like any skill; it takes its first installed
  block. The anchor convention is shared with
  [01-0017.0010](./01-0017.0010-terms-defined-before-they-land.md) and invented once.
- **The tier-1 rule**: every local change to a rule is written in the local file. Its teeth are the
  existing check, which fails on a block that differs from its source and on a block nothing owns —
  so a rule hand-edited into a skill is a diagnostic, not a second opinion.
- **This repository converts.** Seven `<project-local>` blocks move into the local file: the three
  in `AGENTS.md` (the glossary split, the instance-half note, the five switches), the three
  mechanism docs' `evidence` bullets, and `/maintain`'s verification-set block — **which moved
  to the entry file on 2026-09-20 under [.0140](./done/01-0010.0140-core-stands-alone.md)**, beside the
  switches, wrapped on this ticket; `/verify`'s sentence *named in the entry file's local block*
  is wrapped with it, since where the set lives after conversion is this ticket's to say. The eighth —
  `MECHANISM-FORMAT`'s template line — is a mis-tag and is deleted, not moved.
- **`<project-local>` is retired.** The tag is gone from core; the entry file's *Project-local*
  section describes the local file instead; the glossary's **Project-local** and the documents that
  describe the tag as something an author writes — `MECHANISM-FORMAT`, `/mechanism`, `/skill-up` —
  say what is now true. The *Core and instance* exemption for the tag goes with it. The entry
  contract bumps *(v9 when this was written; v12 by 2026-09-20)*.
- **The file's name, its grammar beyond the rules-file format it reuses, and how the injector tells
  a local block from a mechanism's are the RFC's** *(the user, 2026-09-10)*.
