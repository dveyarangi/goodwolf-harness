## Why this exists

[01-0011.0010](./01-0011.0010-mechanism-declared.md) ships a check that a declaration is *true* —
its parts exist, its files are distinct, its gaps name tickets. It does not check whether the three
properties actually hold, because when it lands none of them do. This slice closes that, once each
property has something to observe.

The allowlist half has its own reason. Once rules are injected, a rule can be written into a skill
that no mechanism knows about, and nothing would be able to enumerate it. A skill belonging to no
mechanism is listed with its reason, because an allowlist is how a gap stays declared instead of
becoming invisible.

## What to build

- A check reporting, per declared mechanism, the state of each property: held, or absent with which
  kind — instructed elsewhere and named, embedded in the wrong home, unowned by design, or not yet
  with its ticket.
- Failure, not a warning, on a declared gap that names no ticket, and on a doc and instruction file
  that are the same file.
- Every skill named by a mechanism or present in an allowlist with a written reason. Eleven are
  installed; only paired close is declared, so most will be allowlisted at first and that is the
  honest reading rather than a failure.
- Absences distinguished rather than counted. *Elsewhere* looks like a gap and is not; *embedded*
  looks covered and is not; they pull opposite ways and both get missed.

## Acceptance criteria

- [ ] The check reports each declared mechanism's three property states.
- [ ] A declared gap with no ticket fails the run.
- [ ] A doc and instruction file that are the same file fails the run.
- [ ] Every installed skill is named by a mechanism or allowlisted with a reason; none is silent.
- [ ] The four kinds of absence are distinguishable in the output, not collapsed into a count.
- [ ] The check is part of the project's verification set.
- [ ] Behavioral tests cover each property state, both failures, and an unlisted skill.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.
