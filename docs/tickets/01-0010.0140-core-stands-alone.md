## The origin cannot violate its own prohibition visibly

*Core and instance* has been a rule since 2026-09-07 and
[ADR-0002](../adr/0002-core-may-not-depend-on-the-instance-half.md) has recorded it since
2026-09-09. Both were obeyed by review and broken by construction: in this repository every
`docs/` reference resolves, because core and instance are the same tree. The
[frost_map probe](../research/separation-probe-frost-map.md) produced 35 diagnostics on day one,
this one defect behind 28 instances (14 of them among the 35 — corrected 2026-09-11 on the probe
record), and the probe's count *missed* the four in `/verify` and `/implement`
that a link resolver finds immediately.

The [2026-09-10 `/discover`](./01-0010-dev-harness-shared-and-local.md#discover--the-premise-2026-09-10)
named the general form as its most actionable claim, family C: a prohibition the origin environment
cannot violate visibly is not enforced by review, and the remedy is not a better reviewer but a
configuration where **origin equals recipient** — so that what resolves only because the
neighbouring tree happened to be present fails on every change rather than on every port. It is the
same reason dynamic scoping was abandoned.

**What is deliberately not a defect.** The 52 inline path conventions — `docs/tickets/`,
`docs/glossary.md`, `docs/adr/` and their siblings. *Core and instance* permits them in as many
words, and a recipient creates those paths on arrival. Nor is the instance-side `evidence` bullet:
[MECHANISM-FORMAT](../../.agents/skills/mechanism/MECHANISM-FORMAT.md) puts it inside the
`<project-local>` block on purpose. The defect is a core file naming a *particular* instance
document outside any exemption.

## What to build

- **A statement of what may reach out, before any check.** The exemption vocabulary is three things
  today — a path convention, a `<project-local>` block, a `<straw-dog>` block — and no document
  holds them as one list against which a reference can be judged. This is the align's product and
  it lands in a durable home, not in the checker's source.
- **A check in the [verification set](../process.md#verification)** that reads every file under
  `.agents/` and reports each reference reaching outside it with the exemption it claims, or none.
  It reports classes, not a count: the four kinds pull in different directions and a total hides
  which one moved.
- **The contradiction between two core documents resolved.** MECHANISM-FORMAT mandates a markdown
  link for a `not yet` referent; *Core and instance* forbids that link. One of them changes.
  [01-0011.0050](./01-0011.0050-shape-checked.md)'s align owns the referent's form and this one
  must not settle it ahead of that ticket — it takes the answer and enforces it.
- **The references that are not legitimate, removed.** The four `docs/process.md` links in
  `/verify` and `/implement` follow `/maintain`'s precedent — the same links, wrapped in a
  `<project-local>` block — and `/verify` has no such block at all today. The five grading-prose
  links in the mechanism docs are `/maintain`'s R3 (*move story out of a doc into its evidence*)
  rather than this check's, and are routed there rather than repaired here.
- **The check fails the run**, not warns. A reporting-only check is the review it replaces.

## Open issues

- **Whether the check is a link resolver or a hermetic run.** Copying `.agents/` alone into an
  empty tree and running every script there is the stronger instrument — it catches what a link
  resolver cannot, such as a script reaching for a path it builds at runtime — but `mechanisms.py`
  cannot pass in that tree today, because evidence is instance-side by design. The stronger form
  needs the align to say what a hermetic tree is *expected* to contain. Cannot be answered before
  the exemption vocabulary exists.
- **Whether a `<straw-dog>` may exempt a reference at all.** The exemption is granted in *Core and
  instance* on the grounds that a dog "is bound to a ticket and expires" — true here, false in
  every recipient, where all 14 dangle unexpirably. [01-0010.0130](./01-0010.0130-harness-installs-into-another-tree.md)
  carries this as a constraint on the installer; if it resolves there, this check inherits the
  answer rather than deciding it.
- **Whether this tree can grade the check.** By the ticket's own argument it cannot: a check
  written for separation and run in the configuration that hid the defect proves nothing about
  separation. What it *can* prove is that the count is zero and stays zero, which is the claim
  being made.

## Acceptance criteria — provisional until the align

- [ ] A durable document states which references from `.agents/` are legitimate and why, as one
      list, and the checker cites it rather than restating it.
- [ ] A check enumerates every reference from a file under `.agents/` to a path outside it, and
      reports each with the exemption it claims or as a diagnostic.
- [ ] The four kinds — path convention, `<project-local>`, `<straw-dog>`, unexempted — are
      distinguishable in the output, not collapsed into a total.
- [ ] A diagnostic fails the run; the check is in the project's verification set.
- [ ] The check reports zero unexempted references, with the four `docs/process.md` links in
      `/verify` and `/implement` repaired and the five grading-prose links routed to `/maintain`.
- [ ] A reference added to a core file outside every exemption fails the check — demonstrated by a
      behavioral test that adds one, not by inspection.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.
