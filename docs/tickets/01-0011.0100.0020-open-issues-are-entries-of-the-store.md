# The tickets' open issues are entries of the store

- **Status:** Planned
- **Type:** HITL
- **Depends on:** [01-0011.0100.0010 the-store-and-questions-writes-it](./done/01-0011.0100.0010-the-store-and-questions-writes-it.md)
  (the store to hold them)
- **Outcome:** Every open issue a live ticket carries is an entry of the store owned by that
  ticket's goal, the ticket's *Open issues* section is a view of those entries or a pointer to
  them, and a reconciliation proves the two hold one set with nothing lost.

## Parent

[The open questions are kept by a mechanism](./01-0011.0100-the-open-questions-are-kept-by-a-mechanism.md),
its second slice: the first fold-in with many entries — fourteen live tickets carry an *Open
issues* section on 2026-09-28. `/impact`:
[the inception assessment](./done/01-0012-hierarchy-coherent.md#impact--2026-09-28-the-inception).

## What to build

- Each open issue read from its ticket and written as an entry of the store, owned by the
  ticket's goal, with the relation the issue states (part of, or depends on).
- Every ticket names the question it serves — its *what for*, the question its goal answers —
  when it is minted, and a ticket that names none is reported *(parent decisions 23 and 52)*.
- `TICKET-FORMAT`'s *Open issues* section redefined as a view of, or pointer into, the store; P7
  reworded against the store, with parent decision 50's clause: landing a decision repoints every
  entry closed against it.
- A reconciliation test: the set of open issues read from the tickets and the set of entries the
  store holds for them are one set; run in the verification set until the fold is complete, and
  kept as the guard afterwards.

## Acceptance criteria — provisional, firmed at the align

- [ ] Every open issue of every live ticket is an entry of the store owned by that ticket.
- [ ] Every live ticket names the question it serves, and one that names none is reported.
- [ ] A ticket's *Open issues* section is a view of, or pointer into, the store, and
  `tickets.py --check` holds it to that shape.
- [ ] The reconciliation test passes and fails when one issue is dropped from either side.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.
