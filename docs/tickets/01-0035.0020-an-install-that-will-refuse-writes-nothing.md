## What to build

The installer composes the whole result in memory — core, the local block, every override —
and validates it before it writes anything, since a preflight refusal changes no files
([Interruption and recovery](../architecture.md#interruption-and-recovery)) and the
[harness skill](../../.agents/skills/harness/SKILL.md) promises every refusal writes nothing.
Today the local rules are parsed by the injection step, after the copy. An I/O failure after
writing has begun stays reported, not rolled back; its message, and a later `--install` meeting
the half-installed tree, point to `--update --overwrite`.

## Acceptance criteria

- [ ] A fresh target with a malformed `local.rules.md`, and one with an override naming no rule,
      are refused with the target's files byte for byte as before the run.
- [ ] A second `--install` over a tree a stopped install left behind refuses with a message naming
      `--update --overwrite`, and that command completes the install.
- [ ] A valid install and update run as before, and the installer's tests pass.
- [ ] `/verify` has been run on this ticket against its RFC and the governing docs.
