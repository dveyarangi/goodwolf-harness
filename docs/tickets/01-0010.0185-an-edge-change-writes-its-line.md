## Nothing writes the change down at the moment it is made

The align of 2026-09-21 refused deriving the release notes from the commit log and the record's
diff: that reads the change's own vocabulary, and only what its author remembered to change. So
the line has to be written at the occasion. Today nothing writes it at all — the harness
mechanism's doc names the gap in its own words, *the transformation is unguarded*, and
`.0145` is what that costs: core's scripts moved under `.agents/scripts/gw/`, every recipient's
verification set broke, and neither frost_map nor ai-game-1 was told.

## The align this ticket owns

**May core name the edge record at all?** [AGENTS.md — Core and instance](../../AGENTS.md) lets a
core file name a painted door — the directory that holds a kind of record, or a file that is one —
and forbids *a particular record inside such a directory*. `docs/edge/install.md` is one edge
record inside `docs/edge/`, the same category as one ticket inside `docs/tickets/`. So a **core**
rule installed into `/implement` and `/verify` cannot say where the line goes.

The forks, none of which the 2026-09-21 align reached:

- The core rule names only `docs/edge/`, and a local rule names the record. Then a recipient
  receives a rule pointing at a door it has no record behind.
- The occasion rule is local to this repository. Then it fires here, which is where edge changes
  are made — but a fork that develops its own core never receives it.
- `docs/edge/install.md` is argued to be *a file that is a record*, like `docs/glossary.md`, and
  core may name it. Then the door's contents are core's, which is the thing the core–instance rule
  exists to prevent.

This is the exit: the decision landed in its durable home, and this ticket rewritten in place to
the feature.

## A second line: what the change does for the product

*(The user, 2026-10-09, at the align on q-0033.0005 "How does the product document stay true as
mechanisms and work appear, without the question tree being forced into it?")*

[What the harness is for](../product.md) is the leading product document: its pains, its causes,
and every mechanism marked present, partial or absent. A partial or absent row is a straw dog
bound to the question it waits on, so its status is kept already. What nothing keeps is a new
mechanism or piece of work that has no row.

The answer chosen: the link is authored at the thing, a case of the mark back
(q-0024.0009.0004), and collecting the marks is this mechanism's work. A change writes a second
line beside its edge line, naming what it does for the product. The release collects both. This
ticket's job is the occasion rule that writes it.

Open, and not this ticket's to settle:

- **The mark's form.** The agent proposed a `Serves` field — `product` with the causes it
  answers, `structure`, or `evolution` — and the user is not sure of the values. That belongs to
  q-0033.0005.
- **Who instructs the product document's coherence in clean core.** In a recipient,
  `docs/product.md` would hold that project's own pains. A mechanism must declare it as a painted
  door and keep it coherent, possibly by rendering everything in it but the operator's seed from
  the tree (q-0033.0005). Until that mechanism exists, the product line has no declared door to
  point at.

## What to build

- The `releases` mechanism declared to the shape — doc, rules file, one instruction file — with
  `mechanisms.py --check` passing over it.
- `docs/edge/install.md` in `/edge`'s shape, the origin's, never shipped, recording what moved on
  the edge and what an instance amends. `docs/edge/` is this mechanism's painted door;
  [mechanisms.py](../../.agents/scripts/gw/mechanisms.py)'s hand-held row for it stays until

- The rule drawn against `.0145`: wide enough that a moved script path writes a line, narrow
  enough that two of the most-run skills can carry it on every pass.
- The product line, written by the same occasion rule in the form q-0033.0005 settles.
