## Nothing registers an ownership change when it happens

The update path as landed can say that a rule left — `harness.py`'s injector refusal names an
override *naming a rule this ref no longer sends there* — and that a part left — its `deleted`
list — and cannot say where either went, because nothing wrote that down at the moment it moved.
The version record for the entry file ([entry-contract-findings](../research/entry-contract-findings.md))
is a release record for one file, hand-kept, in the instance half, and does not ship; mechanism
evidence records what was refuted, not what moved. The harness mechanism's own doc names the
gap: *the transformation is unguarded*.

The user's shape *(2026-09-21)*: this is a mechanism. Something owns **what the product is and
what its installation edge is** — the rule ids, anchors, parts and script paths a recipient's
local file and verification set depend on — and **how a change to that edge is extracted**; it
installs a rule into `/edge` so edge changes are collected as they are made; and the harness's
update reads them as trackable changes with a migration.

## What to build

The alignment exit, then the feature. At the exit: the four decisions below are landed in their
durable homes — the mechanism's declaration, the architecture's install contract, the spec's
parked item closed — and this ticket is rewritten in place to the feature. The feature: a
mechanism that registers a change to the edge at the moment core makes it, a `--update` whose
report carries what moved, where it went and what the recipient amends, and one real recipient
that took such an update and needed nothing the report did not say.

## Decisions this ticket's align owns

- **What the product is, and what its installation edge is** — stated as a test a change can be
  held to, not a list.
- **Where a collected change lives so that it ships.** An edge record at `docs/edge/` is the
  instance half's and does not travel; a recipient needs the change at the ref it updates to.
  Candidates: a trace at the rule's authored home (*moved from ticket P8*, *retired*) that the
  injector reads; the repository's commits and tags between the two refs, which the update
  already holds in one clone; a core file of collected changes. Fewest parts that does the job.
- **Whether the mechanism is *releases*, *product*, or what either generalises to** — and
  whether it declares `/edge`, a skill with `Mechanism: not yet` and `docs/edge/` a painted door
  nobody declares.
- **What `--update` says.** The report's shape for a migration: what moved, where, what the
  recipient amends; and whether an update with unamended local rules is a refusal, a pending
  step like a refused link, or lands with the report.
