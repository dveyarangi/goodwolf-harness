# A project can remove the harness

- **Status:** Ready
- **Type:** AFK
- **Related:** [01-0010.0150](./01-0010.0150-harness-meets-a-tree-with-a-method.md) — an install
  that carries a project's own method into core leaves something an uninstall must give back;
  whichever of the two lands second owes the other a case
- **Outcome:** A project runs one command and the harness is gone — everything the announced
  version shipped and the loader links it made removed, the project's local file and records under
  `docs/` left as they are — or the command refuses, writes nothing, and says why.

## Parent

[Shared harness across projects](./01-0010-dev-harness-shared-and-local.md), whose
[front page](./01-0010-dev-harness-shared-and-local.md#front-page--2026-09-26) holds the `/impact`.
Minted at the front-page align of 2026-09-26: *can I get it out again* is among the first things a
cautious adopter asks, and today `harness.py` installs, updates and checks, and nothing removes it.

## What to build

- **An uninstall mode of the harness script.** What it removes is exactly what the tree's
  announced ref shipped, read the way an update reads it, plus the loader links the install made —
  a link removed, never what it points at.
- **What it leaves:** the local file, everything under `docs/` — the delivery status included,
  which is the project's from its first line — and any file under `.agents/` the ref did not ship,
  reported as the project's own, as an update reports it.
- **It refuses over an edited core file**, as an update does, naming the file; and over a tree
  that announces no ref, since then there is nothing to say what was shipped. Every refusal writes
  nothing.
- **The harness skill says it in one line**, beside install, update and check.

## Open issues

- Whether an edited core file has an override, as an update's `--overwrite` is, or is always the
  person's to resolve by hand before removing. Decide at `/plan`.

## Acceptance criteria

- [ ] In a tree installed from a ref, the command leaves the tree as it was before the install,
      apart from the local file and what was written under `docs/` since.
- [ ] Files under `.agents/` that the ref did not ship are left and reported as the project's own.
- [ ] A loader link is removed and its target is untouched.
- [ ] An edited core file, or a tree that announces no ref, is refused and nothing is written.
- [ ] The harness skill names the command beside install, update and check.
- [ ] `/verify` passes against this ticket, the RFC and the governing docs.
