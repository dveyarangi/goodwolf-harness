## What to build

The row's life — register, arrive, tend, seen, end, hold, take, release, the reading of the rows —
goes through the coordinator, which runs the session script's same functions over the `sessions`
table of `gw.sqlite` in the common Git directory, beside the interpreter record; nothing reaches a
row any other way, so the same calls carry over to a network. A take that moves a unit is one
transaction. The sign of life becomes a field of the row; the window memory stays the hook's
cache. The rows' folder under `docs/sessions/rows/` is carried into the database once and leaves
git, in this tree and in a recipient at its update; S3's commit of rows another wake changed
retires. The session mechanism's doc, the architecture's row and the row's declaration beside
`/conclude` are rewritten to what then holds; the session record `/conclude` writes stays a file
under `docs/sessions/`.

## Acceptance criteria

- [ ] Two sessions, one in the main checkout and one in a worktree, each see the other's position
      in its window and the wake's read, with no file under `docs/sessions/rows/` written and no row
      in any commit.
- [ ] A unit one holds shows as held in the other's window; a take moves it, all or nothing.
- [ ] A session silent past the limit is ended by the next wake in either folder, and one that
      keeps talking is not.
- [ ] A tree with rows in the old folder carries them into the database once, and a recipient's
      update does the same, its rows leaving git; nothing of a row is lost, and an older branch's
      folder brings none back.
- [ ] `/verify` passes against this ticket and the governing docs.
