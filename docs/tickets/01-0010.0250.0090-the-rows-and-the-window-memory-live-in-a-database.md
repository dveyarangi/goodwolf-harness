## What to build

Decisions 1 and 2 of q-0037.0017.0005.0003: the session script's functions over a row — register,
arrive, tend, seen, end, hold, take, release, the reading of the rows — work over one database
file in the common Git directory, beside the interpreter record; a take that moves a unit is one
transaction. The window memory, keyed today by the tree's path in the system's temp folder, and
the sign of life move there too, so every worktree of a project shares them. The rows' folder
under `docs/sessions/rows/` is carried into the database at the first call and leaves git, in
this tree and in a recipient at its update; S3, the maintain pass committing rows a wake changed,
retires. The session mechanism's doc and the row's declaration beside `/conclude` are rewritten
to what then holds. The session record `/conclude` writes stays a file under `docs/sessions/`.

## Acceptance criteria

- [ ] A session registers, holds, takes and ends, and its window and the wake's read show the others
      as before, with no file under `docs/sessions/rows/` written and no row in any commit.
- [ ] Two worktrees of one project share one window memory and sign of life: a session silent past
      the limit is ended, one that keeps talking in a worktree is not.
- [ ] A tree with rows in the old folder carries them into the database at its first call, and a
      recipient's update does the same, its rows leaving git; nothing of a row is lost.
- [ ] `/verify` passes against this ticket and the governing docs.
