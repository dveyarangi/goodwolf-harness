## What to build

- A row records when it last changed to the minute, `YYYY-MM-DDTHH:MMZ` like the entries' —
  three hours cannot be read off a date *(the user, 2026-10-10)*.
- Every wake ends each other running row silent for three hours or more, and says nothing of it:
  the rows serve autonomous agents mostly, and a person running sessions by hand reads them as
  noise *(the user, 2026-10-10)*. No row is removed; an ended row keeps its position.
- A session's message turns its own row running again, so ending a live session costs one
  message: in Claude Code and Codex the message hook draws the window, and Cursor's message hook,
  which can inject nothing, records the session as seen — its agent does not draw the window by
  the rule in practice.
- Silence is measured from the session's last sign of life the harness sees, so a session working
  long on one question is not ended while it works; whether that sign is its message or its write
  is the RFC's, weighed against a committed file changing on every message.
- A row in the date-only form is read as before and rewritten in the new form on its next write, so
  a tree holding core migrates without a refusal.
- The week-silent finding goes: a silent row no longer waits for a person.
- The behaviour is a straw dog bound to q-0034 at its authored homes — the skill's paragraph and a
  `TODO` in the script — until a session mechanism takes the sessions file.

      never ended by its own wake. *(2026-10-10)*
- [x] A session whose row was ended reads running again after its next message, in each of Claude
      Code, Codex and Cursor. *(2026-10-10: each row ended by hand, then one message — Cursor
