## Why this exists, and why it is not this tree's first idea

The re-check rule is already stated three times in this tree as prose — `/mechanism`'s *Amend and
retire*, the spec's *Re-check on governing change*, and `docs/process.md:91` — and nothing gives
*since* a meaning. Life built this mechanism from a specimen: records that carried evolution
inline, against a sidecar rule that arrived after they existed, with nothing scheduling the re-check
of the consuming end once the producing end moved. Its evidence records why the design is what it
is: a mark and not fire-on-edit, because a rule firing at the moment of the edit lands in the busy
session that made the edit, measured at ~8%; a hash and not a count, because the thing to catch is
an edit that bypassed the amend procedure; two levels, because a mechanism's own rules govern its
records the way the meta-rules govern its rules.

Until this lands, `/maintain`'s body carries an interim rule inside a straw dog bound to this
ticket: every declared mechanism in a pass's scope is due at every pass.

**What this is for: re-checks that are missed, not rereading that costs** *(the user,
2026-09-27)*. A pass that closes one ticket is scoped to that work item, so the interim rule never
reaches a mechanism doc: the six maintain passes from 2026-09-21 to 2026-09-27 touched tickets, the
queue and a spec, while fifteen commits moved `/mechanism` or a mechanism doc. When R8 landed on
2026-09-27, eight skills already breaking it were found by hand; on 2026-09-07 *Core and instance*
made four skills violators the moment it was written. The clock's job is to raise, in whatever pass
runs next, the re-check that pass's scope would skip. Cost — rereading twenty mechanisms once
[01-0017](../01-0017-io-graph-coherent.md) declares the rest — follows, and is not the reason.

## What to build

Two triggers *(the user, 2026-09-27)*. Only `/maintain` writing a mechanism's row counts as
maintaining it; no edit does.

| level | what is due | when |
|---|---|---|
| `rules` | every mechanism's doc | the meta-rules moved since its mark |
| `output` | a mechanism's records | its own doc, rules file or skill directory moved since its mark |

**The skill directory is on the `output` row** *(the user, 2026-09-27, at `/plan`)*: a record's
format is declared in the mechanism's shelf where it has one, and a shelf sits beside the
instruction file — `TICKET-FORMAT.md` changed on 2026-09-09, when `Type` became required and
`Kind` was retired, and with the doc and rules file alone that edit made nothing due. The skill
directory is read from the declaration's `instruction` bullet. **Which records a due `output`
owes** *(the user, 2026-09-27)*: the live ones; historical records too where they can be changed
mechanically within sane bounds — a file in the tree, yes; tickets on a remote board, no.

<straw-dog question="q-0024.0004">
The third trigger — a mechanism's records changed enough since the mark, so they are due — is not
built: counting changed records needs each mechanism's record paths declared in a form a script
reads, and none is. The ticket records meanwhile are format-checked at every close under P5.
Handed to 01-0017 *(the user, 2026-09-27)*, with its unit: record files changed since the last
maintenance, due at N.
</straw-dog>

- **The governing surface for `rules` is the meta-rules at their three homes** *(the user,
  2026-09-27)*: `AGENTS.md`, for the rules written there; `mechanism-shape.rules.md`, where R1–R8
  live; and `/mechanism`'s skill directory, the shape every doc is written to. Installed blocks
  are excluded under R2 — the local block among them, so the entry file needs no parser of its
  own. The rules file is on the list because R8, landed 2026-09-27, reaches the skill and the
  entry file only as installed copies: without its home, R8 would have made nothing due. The entry
  file is on it because *Core and instance* landed there on 2026-09-07 and made four skills
  violators the moment it was written. It is taken whole, since fingerprinting chosen sections goes
  stale when a section moves; an edit to its loop or switches raises a re-check nobody needed,
  which is the safer error. The contract version line stays in: it changes exactly when the
  contract does.
- **Hashes normalise line endings, strip installed blocks, and exclude evidence.** Installed blocks
  are policed as injection drift, not content; story does not govern, so story cannot stale; and
  this checkout runs on Windows over an LF repository, where a hash over raw bytes reads every flip
  as an edit.
- **The mark is a record, written only by the closing step of a maintenance**, one row per
  mechanism per level, rewritten in place, bounded by the mechanism set. **A row carries the
  fingerprint of what it was checked against**, its date, and the outcome — *amended* or *nothing
  to change* — so it reads alone, without Git, and survives a rewritten history *(the user,
  2026-09-27, over taking the commit that last wrote the row as the mark, which is legible only
  through Git)*. No mark reads as
  never-maintained, loudly; nobody backfills. **Its format is written in `/maintain`'s skill**, as
  a short section `maintain.md` points at *(the user, 2026-09-27, at `/plan`: a record's format is
  never found in a doc — [rule failure 15](../../rule-failures.md) — and this one is small enough for
  the skill)*. It has a maintainer script, because a malformed row makes a mechanism silently
  ineligible rather than reporting itself.
- **Dueness is derived at every look and never stored**, so nothing can go stale and no ticket is
  created for it. It is looked at by `/maintain`, which reads it as its input at every close, and by
  the derivation's command in the verification set.
  <straw-dog question="q-0018.0004">
  The maintenance list is not announced: it is read at every close and printed by its command, and
  a tree where no slice closes is not told. It must be announced once a channel exists, and whether
  `.0030`'s ratchet shares that announcement is decided there *(the user, 2026-09-27)*.
  </straw-dog>
- **The derivation the clock hashes and the surfaces `mechanisms.py --check` parses are one
  derivation.** Life split them once and the turn report counted different rows from the wake.
- **The suite never writes the live marks**, watched failing.
- **The marks live in `docs/mechanisms/maintenance.md`**, owned by the maintain mechanism, its only
  writer *(the user, 2026-09-27)*. They are the instance's — a recipient's say when its own
  mechanisms were last maintained — so they sit in `docs/`, which an update never touches, not
  under `.agents/`, which every update replaces. One file, not a row in each evidence file, which
  is prose.
- **In a recipient, the clock runs over the recipient's own mechanisms only** *(the user,
  2026-09-27, at `/plan`)*. The harness's built-in mechanisms are maintained where core is made:
  in a tree whose entry file announces `<repository>@<ref>`, a mechanism under `.agents/` came
  with core, is not derived, and cannot be marked. The origin's marks never ship. Where a
  recipient's own mechanisms live is not settled —
  recipient-own-mechanisms, unminted, held on
  [the parent](../01-0010-dev-harness-shared-and-local.md#a-recipients-own-maintenance--2026-09-27)
  — so a recipient's clock reads an empty set until it is.
- **Never maintained counts as due**: nobody backfills, so the first re-check is the one the
  clock raises.
- **Not a Git clock** *(the user, 2026-09-27)*: a doc's last commit against the meta-rules' last
  commit reads any edit to a doc as a re-check — adding P10's row to the ticket doc on 2026-09-27
  would have cleared that doc of R8 unread.
- **`/maintain`'s straw dog bound to this ticket retires through the enumerator**, and its moments row
  *knowing a re-check is due* and its record obligation stop reading `not yet`.

## Acceptance criteria

- [x] A command reports, for every declared mechanism and each level, whether it is due and why —
  meta-rules moved, own surfaces moved — or that it has no mark *(2026-09-27)*.
- [x] A mechanism with no mark is reported as never maintained, in words distinct from *fresh*
  *(2026-09-27)*.
- [x] Moving a mark is one command, refuses a slug the mechanism set does not carry, and is the
  only writer of the marks, in `docs/mechanisms/maintenance.md`; a row carries the fingerprint of
  what was checked, the date and the outcome *(2026-09-27)*.
- [x] Editing `/mechanism`'s skill, `mechanism-shape.rules.md`, or `AGENTS.md` outside its installed
  blocks makes every declared mechanism due at `rules`; editing a mechanism's own doc, rules file,
  instruction file or format shelf makes it due at `output`; editing its evidence makes nothing
  due; a line ending flip makes nothing due; installing or retracting a block, in a skill or the
  entry file, makes nothing due *(2026-09-27)*.
- [x] The marks' format is written in `/maintain`'s skill, and a maintainer script reports a
  malformed row and leaves a conforming file byte-identical *(2026-09-27)*.
- [x] In a recipient, no built-in mechanism is reported due or accepted by the mark command, and
  the check exits clean over the empty set of the recipient's own *(2026-09-27)*.
- [x] A full suite run leaves the live marks byte-identical — the test harness fails the case
  after which they differ, watched failing once *(2026-09-27)*.
- [x] The clock and `mechanisms.py --check` read the same surfaces through one derivation,
  `declarations(root)` *(2026-09-27)*.
- [x] `/maintain`'s straw dog bound to this ticket is gone, and its doc's record
  obligation and *knowing a re-check is due* row are instructed *(2026-09-27)*.
- [x] `/verify` has been run on this ticket against its ticket, RFC, and governing docs
  *(2026-09-27)*.
