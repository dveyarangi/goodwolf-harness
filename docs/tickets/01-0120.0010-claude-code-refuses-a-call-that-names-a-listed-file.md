## What to build

The work opens with a live try — one test file, one refusal of a read seen in Claude Code —
because the refusal of a read is documented at the [hosts edge](../edge/hosts.md) and was never
seen; nothing else is built before it passes, and a try that fails goes back to the person.

Then: the project's list, one tracked file of paths; one script that answers the host's call
before a tool and refuses a call naming a listed file, its text saying why and what to do
instead; the hook entry merged into the host's committed file only where the tree keeps a list,
so a tree with none carries no call before its tools; and what the refusal does not hold, said
where an install reports. One script answers the call so that other refusals can join it later;
it is built for this use alone.

Whether the host's own search can be made to skip listed files is this slice's first open
question,
[q-5lck5x](../questions/q-5lck5x-does-the-projects-list-make-the-hosts-own-search-skip-its-files.md):
a search over a folder prints a listed file's lines and names it nowhere.

## Acceptance criteria

- [ ] A refusal of a read of one test file is seen live in Claude Code before anything else is
      built, and what was seen is written in the host's record at the hosts edge.
- [ ] In a tree that keeps a list, a read, a search that names the file, a change and a shell
      command naming a listed file are each refused in Claude Code, a subagent's call included —
      observed live by someone who did not build it.
- [ ] A call that names no listed file passes, and what the call before a tool adds to it is
      measured and recorded.
- [ ] Where the check cannot run - no interpreter recorded in the clone, a fault of its script -
      a call is refused, and the refusal says which step the person runs.
- [ ] A tree that keeps no list carries no entry for the refusal, and one that keeps a list
      carries it — the installer's test, on a fixture built the way a recipient came to be.
- [ ] What the refusal does not hold is said where an install reports.
- [ ] The hosts edge carries the promise with its validator.
- [ ] `/verify` passes against this ticket and the governing docs.
