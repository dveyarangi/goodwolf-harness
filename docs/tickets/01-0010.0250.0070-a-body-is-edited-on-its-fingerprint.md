## What to build

Decision 5 of [q-7ebz2f](../questions/q-7ebz2f-how-do-sessions-on-separate-branches-share-one-question-store-and-one-registry-of-sessions.md#decisions): the session takes the body with the fingerprint of
its version, edits it in a scratch file by ordinary means, and gives it back; the server takes it
while its body is still that version, and otherwise refuses and returns three versions — the one
begun from, the other's, this one's. The files at `docs/q/` stay read-only; the person's edit
with the flag lifted is taken on the version the server last wrote, by the same rule. The skills
that write a body say how.

## Acceptance criteria

- [ ] A body edited from a worktree lands on the store's branch through the call.
- [ ] Two sessions editing one body at once: the second is refused with the three versions, and
      its merged body then lands.
- [ ] A file at `docs/q/` changed by hand, its flag lifted, is taken on the server's last
      version, or shown as a conflict when that version has moved.
- [ ] `/verify` passes against this ticket and the governing docs.
