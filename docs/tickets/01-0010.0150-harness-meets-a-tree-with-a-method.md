# The harness meets a tree that already has a method

- **Status:** Planned (RFC authored 2026-09-21; the scripts' namespace precedes)
- **Type:** HITL
- **Plan:** [The harness meets a tree that already has a method RFC](../rfc/01-0010.0150-harness-meets-a-tree-with-a-method.md)
  — the inventory as one look over the four places; the flow as instruction, with collisions
  and a process of the project's own at `/align`, and an anchor for mechanisms' meet-blocks
- **Depends on:** [01-0010.0130](./done/01-0010.0130-harness-installs-into-another-tree.md) (the
  install, its refusals, the stamp and the skill this slice extends);
  [01-0010.0145](./done/01-0010.0145-core-scripts-under-one-directory.md) (core's scripts under a
  directory of their own, so an install into a foreign `.agents/` cannot overwrite a project's)
- **Outcome:** An install into a tree that already has a method — this harness taken by hand, or a
  stranger's entry file, stub, skills and process — ends with that method's content carried into
  the local file or a claimed skill, aligned with the user where it collides with core, or left
  where it is, never lost; and the skill says each step.

## What to build

Decided at the align of 2026-09-21 *(the user)*:

- **The refusal carries an inventory.** When `--install` meets the project's own entry file, a
  stub with content, a skill directory where a loader link goes, or a file at a path the
  manifest would write, it still writes nothing — but the refusal names everything it found, not
  the first thing in the way: each file with its size, each skill directory with its skill names,
  so the agent knows what it is integrating before it moves anything. A stranger harness is the
  same refusal with more in the inventory. **An `.agents/` of another convention is not, by
  itself, a refusal** *(the user, 2026-09-21, at `/plan`)*: the install integrates into it, and
  only a file standing where the manifest writes is a collision. So that core's scripts can never
  collide with a project's, they are namespaced under their own directory — a slice of its own,
  which this one depends on.
- **The flow is explicit in the skill**, for a tree with any existing method: run the install;
  read the inventory; for each finding, amend the instance where it is trivial — a fact or a
  convention becomes a local rule, a project skill moves under `.agents/skills/` with its claim
  line so the loader link reaches it and the shape check accepts it, the old entry file moves
  aside once every line of it has a home — and `/align` with the user where it is not: a rule
  that contradicts core's, which becomes an override naming it or a decision; **a skill that
  collides with one of core's, in either of two ways** *(the user, 2026-09-21)*: by name — the
  project's `plan` is not core's `plan` — or by responsibility — the project's `review` does what
  core's `verify` does; and **a process of the project's own**, which the flow meets step by
  step at `/align` for now, since the loop's granularity and ceremony are not yet switchable —
  the pacer's, [01-0020](./01-0020-pacer.md). Then run the install again, populate the local
  file, and check. Nothing of the project's is deleted by the script at any step, and the skill
  says so. The flow's section is an anchor: a mechanism that has said how it meets an existing
  method — the ticket mechanism first, for work tracked on a board or in another shape — installs
  its block there through its rules file, and the flow says so in one line.

## Acceptance criteria

- [ ] An install into a tree holding its own entry file, a stub with content, a skill directory
      where a link goes, or a file at a path the manifest writes, writes nothing and reports
      every one of them it found, with the skill names under each directory; an install into a
      tree whose `.agents/` holds only files the manifest does not write proceeds and reports
      them as the project's own.
- [ ] The skill states the flow for an existing tree, step by step, including what is amended
      without asking, what goes to `/align` — a rule against core's, a skill colliding by name or
      by responsibility, a process of the project's own — and that the script deletes nothing of
      the project's; its section carries the line under which a mechanism's own meet-block lands.
- [ ] Behavioural tests cover the inventory on each of the four findings, each alone and all at
      once, and an install into a foreign `.agents/` that collides on nothing.
- [ ] A real stranger tree — one of the user's estates with its own corpus — takes an install
      by the skill's flow, graded by the user in that tree.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.
