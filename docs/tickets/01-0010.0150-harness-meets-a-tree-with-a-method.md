# The harness meets a tree that already has a method

- **Status:** Ready (aligned 2026-09-21)
- **Type:** HITL
- **Depends on:** [01-0010.0130](./done/01-0010.0130-harness-installs-into-another-tree.md) (the
  install, its refusals, the stamp and the skill this slice extends)
- **Outcome:** An install into a tree that already has a method — this harness taken by hand, or a
  stranger's entry file, stub and skills — ends with that method's content carried into the local
  file or a claimed skill, aligned with the user where it contradicts core, or left where it is,
  never lost; the skill says each step; and an agent reading the skill in any tree sees which
  repository its core comes from.

## What to build

Decided at the align of 2026-09-21 *(the user)*:

- **The refusal carries an inventory.** When `--install` meets the project's own entry file, a
  stub with content, a skill directory where a loader link goes, or an `.agents/` of another
  convention, it still writes nothing — but the refusal names everything it found, not the first
  thing in the way: each file with its size, each skill directory with its skill names, so the
  agent knows what it is integrating before it moves anything. A stranger harness is the same
  refusal with more in the inventory.
- **The flow is explicit in the skill**, for a tree with any existing method: run the install;
  read the inventory; for each finding, amend the instance where it is trivial — a fact or a
  convention becomes a local rule, a project skill moves under `.agents/skills/` with its claim
  line so the loader link reaches it and the shape check accepts it, the old entry file moves
  aside once every line of it has a home — and `/align` with the user where it is not: a rule
  that contradicts core's, which becomes an override naming it or a decision, or a skill that
  overlaps one of core's; then run the install again, populate the local file, and check.
  Nothing of the project's is deleted by the script at any step, and the skill says so.
- **The README is a front page**, not a second home for the flow: what this is in two sentences,
  the clone line, and *read `.agents/skills/harness/SKILL.md` and follow it*. The flow has one
  owner.
- **The skill names the repository, and the script derives from it.** One line in the skill,
  `Repository: <url>`, is the only authored home of the URL; the script keeps no constant and
  reads its default `--from` from that line in the skill beside it; at install it stamps the
  actual `--from` into the recipient's copy of the line, as it stamps the ref into the entry
  line. An agent in any tree sees where its core comes from, a recipient needs no `--from` for
  `--update` or `--check`, and a fork edits one line and everything it installs names the fork.

## Acceptance criteria

- [ ] An install into a tree holding its own entry file, a stub with content, a skill directory
      where a link goes, or a foreign `.agents/` writes nothing and reports every one of them it
      found, with the skill names under each directory.
- [ ] The skill states the flow for an existing tree, step by step, including what is amended
      without asking, what goes to `/align`, and that the script deletes nothing of the project's.
- [ ] The README carries the clone line and a pointer to the skill and no step of the flow.
- [ ] The skill's repository line is the URL's only authored home: the script's default `--from`
      is read from it, a recipient's copy is stamped with the actual `--from`, and `--update` and
      `--check` in a recipient need no `--from`.
- [ ] Behavioural tests cover the inventory on each of the four findings, the stamped repository
      line, and a recipient's check with no `--from`.
- [ ] A real stranger tree — one of the user's estates with its own corpus — takes an install
      by the skill's flow, graded by the user in that tree.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.

## Out of scope

Deleting or rewriting a project's own skills, which stays the agent's under the flow and never the
script's. Contribution back and releases — the spec's *Out of Scope*. Whether a host reads the
loader link — [01-0010.0120](./01-0010.0120-host-delivery-surfaces.md).

## Parent scope addressed

The parent's promise that projects receive the method while preserving project-specific behavior,
taken for a project that already has some.
