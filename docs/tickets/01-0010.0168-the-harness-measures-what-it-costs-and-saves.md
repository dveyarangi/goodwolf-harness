# The harness measures what it costs and what it saves

- **Status:** Planned (decision-bearing; its own align precedes the feature)
- **Type:** HITL
- **Outcome:** What the harness measures about itself — the tokens and the human turns a unit of
  work costs, and what it saves an agent arriving cold — and how each is counted is decided and
  landed, and the feature is unblocked: a script reads the hosts' own session records into a trend
  that starts at the harness's first session and runs forward, and the trend is stated where a
  reader weighing the harness will see it.

## Asked for everywhere, measured nowhere

Four adoption panels and an outside review ([panels](../research/adoption-panel-2026-09-26.md))
asked the same two things the page cannot answer: what the process costs in tokens and time, and
what a person spends on it. The review conflated the two — process complexity with human burden —
and the user's reading is that they differ: the loop, the records, the skills are the agent's
control, not the person's load *(the user, 2026-09-26)*. Both are still real costs, and a measured
trend, expected to fall as the harness develops, is a statement by itself.

The same review named what the cost should buy, and three outcomes worth watching: an agent
arriving cold re-deciding less of what was settled; work surviving a session's end without the
person reconstructing it; drift between documents and code falling rather than documents piling up.

## The record already exists

Claude Code keeps every session of this project as a transcript under the user's profile — eighty
of them from 2026-09-05, the harness's first day, to 2026-09-26 — and every assistant message
carries its token usage: input, cache writes, cache reads, output, thinking. Every message the
person typed is there too, beside the tool results that share its `user` type and must be told
apart from it. Codex keeps its sessions likewise. So the trend need not start now: it can start
from the first session, read back, and run forward.

## The align this ticket owns

- **The unit of work** the costs are counted against — a closed ticket, a commit, a session — so a
  long session and a short one compare.
- **Which human turns are burden.** An approval at a switch set to `ask`, a decision at `/align`,
  and a correction of the agent are different costs; only the last is pure burden, and the others
  are what the switches exist to trade.
- **The outcome proxies** for the three the review named, each from a record that already exists —
  corrections of the *we already decided* kind, the turns a session spends re-establishing where
  it stands, `/maintain`'s findings per pass and the straw-dog count over time.
- **What leaves the machine.** Transcripts are the person's and private; what is published is an
  aggregate, and where it lives — this repository's instance half, or the front page.
- **Which hosts** are counted, and whether the trend is this project's alone or every recipient's
  that opts in.
- **When it runs** — at `/conclude`, at a release, on request — and so who reads it.
