# The first install's last step becomes a sequence

- **Status:** Planned
- **Type:** AFK
- **Related:** [01-0010.0165](./done/01-0010.0165-a-fresh-tree-has-a-delivery-status.md) — the
  dependency dissolved at that slice's 2026-09-23 `/plan`: it no longer creates the directories
  this sequence writes into, because a record's parent is made on the way in. Ordering only, and
  both touch the same install
- **Outcome:** A first install ends with a local file whose verification set names the project's
  own checks or states that it has none, instead of falling back to core's gates.

[Shared harness across projects](./01-0010-dev-harness-shared-and-local.md), whose

## One instruction ran before its inputs existed

[`harness/SKILL.md`](../../.agents/skills/harness/SKILL.md)'s *After the first install* jumps from
*the tree has core and no answers* to *write `local.rules.md`*, and tells the writer to read the
verification set *off its own toolchain*. ai-game-1 had no toolchain. The one command the section
names concretely is `harness.py . --check`, so that is what the set became — three harness
self-checks and `git diff --check`, a set that looks complete and verifies nothing of the game.
frost_map escaped this only because it arrived with `docs/cicd.md` already written.

The rules in a local file do not share a clock: identity and the switches are inputs to setup,
the verification set is an output of it. One extraction cannot serve both.

## What to build

- **The refusals gain the missing bullet.** `harness.py` refuses a tree that is not the top level
  of a git work tree, and the skill's *Refusals* section does not list it, though every other
  refusal there carries what to do. The bullet is `git init`, then run again. The script keeps
  refusing rather than initialising: `git init` is a write.
- **The extraction splits.** L1 and L2 are written and injected **before** setup — identity so the
  step knows what it is reading, the switches so it has defined authority for the writing,
  committing and remote-creating it is about to do. L3 is written **after**.
- **`setup-devops` is invoked as relied-on**, not absorbed: named with its owner, not a part. Its
  clause *Setup initial GitHub/chosen provider repository if missing* narrows to offer-only — a
  remote is created on an accepted offer and never by default, because nothing downstream needs
  one, the step runs when `push=` was written minutes earlier, and deciding to have a remote is
  its own occasion.
- **L3 is a pointer**, to `docs/cicd.md`'s local-verification section, not an inline command list.
  frost_map converged on this form by itself; ai-game-1's inline form already names
  `.agents/scripts/` and breaks on its first update past
  [01-0010.0145](./01-0010.0145-core-scripts-under-one-directory.md).
- **Core's own gates are additive.** `harness.py . --check` may join a project's set and may never
  constitute it. A project with no checks of its own gets an empty local-verification section that
  says so: an empty verification set is a stated state, not a slot to fill with whatever runs.
- The mechanism's doc gains the Moments rows — the setup step `elsewhere` to `setup-devops`, the
  two extractions — and the skill's *After the first install* is rewritten as the ordered sequence.

## Acceptance criteria

- [ ] A fresh install into a tree with no toolchain ends with a local file whose L3 names no
      command from `.agents/scripts/`.
- [ ] That tree's `docs/cicd.md` exists with a local-verification section stating it has no checks
      yet, and L3 points at it.
- [ ] Running `--install` against a directory that is not a git work tree produces a refusal whose
      text names `git init` as the step.
- [ ] L1 and L2 are present and injected before any setup work is done; a run that reaches setup
      with unwritten switches fails.
- [ ] `setup-devops` creates no remote without an accepted offer.
- [ ] frost_map's existing pointer-form L3 still reads correctly against the rewritten
      instruction, unchanged.
- [ ] `/verify` passes against this ticket, the RFC and the governing docs.
