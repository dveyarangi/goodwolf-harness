## What to build

At the reply's end the hook reads each header that proposes text — 🧩, ⚓ or ✏️, which names the
file — and holds it like an edit of that file, `/skill-up` loaded besides where the file is an
instruction file; register entry 50's two strikes in a reply are what no edit hook sees. Before a
shell command the hook meets the agent's `git commit` and refuses it while a staged declared file's
skill is not loaded, which catches a write through the shell at the one place every write passes.
The header is the reply-layout rule's, still a straw dog under
[q-l36vii](../questions/q-l36vii.md),
so the plan reads it where that rule stands at the time.

## Acceptance criteria

- [ ] A reply proposing a rule for a skill's instruction file, `/skill-up` not loaded, is sent
      back with the skill named — observed live by someone who did not build it.
- [ ] A `git commit` staging the root README written through the shell, `/product` not loaded, is
      refused before it runs; once loaded, it goes through — observed live by someone who did not
      build it.
- [ ] A reply with no proposing header, and a commit of no declared file, are never held.
- [ ] `/verify` passes against this ticket and the governing docs.
