## What to build

- A running session whose entry file changed since its context last took it in is shown the
  change at the start of its next turn: it comes with the message that starts the turn, never as
  a turn of its own, since a message between sessions about such a change costs its receiver a
  turn.
- The notice carries the changed lines, each as it was and as it is now, never a request to read
  the file again: the old text stays in the session's context, so the notice says which line
  replaced which; reading the whole file again puts about 4,700 words in a second time, and
  replacing the head of the context loses the prompt cache where adding to its end keeps it *(the
  user, 2026-11-22)*.
- It is shown once, and only for a change: several changes between two turns arrive as one notice
  of what differs from what the session last held; a session whose entry file did not change is
  shown nothing, and one that starts, resumes or has its context compacted holds the file as it
  then stands.
- In Cursor, whose message hook reaches no agent, the gap is written in its sidecar of the hosts
  edge, and the rule at session start stays the floor.
- Once it lands, a message between sessions about a change of the entry file has nothing left to
  carry; the rules on such messages are the keeper's and the store's sessions', who are told.
