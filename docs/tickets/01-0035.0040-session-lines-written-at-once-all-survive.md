## What to build

Each session's line is its own file in the store's sessions folder, named by its tag, as decided in
[q-0036.0004](../questions/q-0036.0004-how-do-session-lines-written-at-once-all-survive-when-the-harness-locks-nothing.md#decision):
a session writes only its own file, so no write can undo another's, and nothing is locked
([Interruption and recovery](../architecture.md#interruption-and-recovery)). Every reader — the
wake, the window, `--check`, the conclude, a rename's rewrite of ids — reads the folder. A store
still holding the single sessions file, as every installed tree does today, is carried into the
folder at its first write, every line kept, including when two sessions make that first write at
once.

## Acceptance criteria

- [ ] Twenty sessions registered at once leave twenty session lines, in a test that starts them
      concurrently rather than in sequence.
- [ ] A store holding the single sessions file reads as before, and its first write carries every
      line into the folder; two sessions writing first at once lose none.
- [ ] The wake, the window, `--check`, the conclude and a rename read and write every session as
      before, and the store's tests pass.
- [ ] `/verify` has been run on this ticket against its RFC and the governing docs.
