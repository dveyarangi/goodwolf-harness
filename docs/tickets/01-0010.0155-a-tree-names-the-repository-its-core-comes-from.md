# A tree names the repository its core comes from

- **Status:** Planned (the scripts' namespace precedes)
- **Type:** AFK
- **Depends on:** [01-0010.0145](./01-0010.0145-core-scripts-under-one-directory.md) (where the
  script sits, and so where it finds the skill beside it)
- **Outcome:** An agent reading the harness skill in any tree sees which repository its core comes
  from, a recipient runs `--update` and `--check` with no `--from`, and a fork edits one line and
  everything it installs names the fork.

## What to build

Decided at [01-0010.0150](./01-0010.0150-harness-meets-a-tree-with-a-method.md)'s align of
2026-09-21 *(the user)*, refined at its `/plan`:

- **The skill names the repository, and the script derives from it.** One line in the harness
  skill, `Repository: <url>`, is the URL's only authored home in the tree; the script keeps no
  constant and reads its default `--from` from that line in the skill beside it. A skill that is
  missing or has no line is a refusal naming the file and `--from`.
- **At install and update the line is stamped** with the actual `--from` — a URL verbatim, a local
  path resolved to its absolute form, so a recipient installed from a clone on disk holds no path
  relative to where somebody once stood. A ref whose harness skill has no such line is refused as
  *not the harness*, as an entry file without an announce line is.
- **The line is read, never compared.** The check and the update set it aside when comparing the
  recipient's skill against the ref, as they set the local block aside: a `--check` from a clone
  at another `--from`, or an `--update` that changes the source, reads no edit in core; the
  update re-stamps. The line is the recipient's `--from` as the announce line is its ref.
- **The root README's clone line stays** — a front page at the repository naming itself, never
  shipped; *only authored home* means the only one the script derives from and the only one that
  ships.

## Acceptance criteria

- [ ] The harness skill's repository line is the URL's only authored home in core: the script's
      default `--from` is read from it, a recipient's copy is stamped with the actual `--from`,
      and a recipient's `--update` and `--check` need no `--from`.
- [ ] A recipient whose skill line names one source takes a `--check` and an `--update` from
      another `--from` without the skill being reported as an edit.
- [ ] Behavioural tests cover a URL stamped verbatim, a local path stamped resolved, a ref
      without the line refused, the line set aside by the comparison, and a recipient's own copy
      of the script checking with no `--from`.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.
