## What to build

**The guard on controlled files**, as
[q-0037.0006.0005.0001](../questions/q-0037.0006.0005.0001-which-skill-must-be-read-before-a-file-is-edited-or-a-rule-proposed-and-how-does-the.md)'s
accepted `Where it stands` says it, its decisions 1 to 6 landing here:

- Every mechanism's doc declares, in one table, the records it writes and the parts it guards,
  each with the skill that must be loaded before it is changed — each owner says its own, since no
  other can. Mechanism-shape takes `/skill-up` as its second skill and declares the instruction
  files under it. The table is also the record declaration scripts read, so the shape check's
  hand-held list of record paths retires into it.
- One generic check asks whether every skill a file's rows name is loaded in the session as the
  host keeps it, reading each host's row in `HOSTS` for the events that load a skill and its
  lifetime rule — never the transcript, whose format no host promises.
- It holds three acts: an edit, refused before it is written; a reply proposing text for a
  declared file under its 🧩, ⚓ or ✏️ header, sent back at its end; the agent's `git commit` with
  a staged declared file, refused before it runs, which catches a write through the shell.
- What each host gives stands at the [hosts edge](../edge/hosts.md), under **Edit refusal**,
  **Skill load** and **Skill lifetime**; a host that lacks one is guarded in part.

**The switches.** A commit or a push while its switch says `ask` is refused by the host, held by
q-0037.0006.0005's decision that an act off the autonomy ladder is a mechanical check, never a
rule; which hosts, and where the hook's configuration stands beside a project's own
([01-0010.0150](./01-0010.0150-harness-meets-a-tree-with-a-method.md)), are that question's still.

## Acceptance criteria

- [ ] Every mechanism's doc declares its records and guarded parts with the skill each needs,
      mechanism-shape declaring the instruction files under `/skill-up`; the shape check reads the
      tables, and holds no list of record paths by hand.
- [ ] In Claude Code, an edit to a declared file whose skill is not loaded is refused and the agent
      is told which skill; the same edit after the skill is loaded goes through — observed live by
      someone who did not build it.
- [ ] A reply proposing text for a declared file, its skill not loaded, is sent back at its end —
      observed live by someone who did not build it.
- [ ] The agent's `git commit` of a declared file whose skill is not loaded, the file written
      through the shell, is refused — observed live by someone who did not build it.
- [ ] After a compaction, the check counts as loaded only what the host's row says the compaction
      kept — observed live by someone who did not build it.
- [ ] The hosts edge's **Edit refusal**, **Skill load** and **Skill lifetime** are observed for
      Claude Code and Codex, and Cursor stands guarded in part, its skill load observed or absent.
- [ ] q-0037.0006.0005's decision on the switches — which hosts, where the configuration stands —
      is landed, and this ticket's criteria for them written in place.
- [ ] `/verify` passes against this ticket and the governing docs.

## Out of scope

- That a loaded skill was followed: no hook can see it; the formats are held by the checks at
  `/verify`.
- The project's own code, and the files of a skill with no mechanism yet beyond its instruction
  file: nothing undeclared is held, and a mechanism's declaration is
  [q-0037.0009](../questions/q-0037.0009-does-each-skill-state-only-what-it-owns.md)'s work per skill.
