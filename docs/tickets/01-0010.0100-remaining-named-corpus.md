precedent being [01-0010.0050](./done/01-0010.0050-install-implement.md), which installed `/implement`,

## Decisions this ticket's align owns

- The order and grouping of the five, and whether any belong together as one mechanism.
- Whether `/edge` arriving requires `docs/edge/` to exist, or whether the capability installs
  against an empty inventory with `/maintain`'s check explicitly unguarded until a record exists.
- Whether `/celebrate` earns installation at all — the selection says to retain the capability
  "without making celebration a completion requirement", which is close to saying it changes nothing.
- **A skill's structure, so that its rules are addressable, and a check that a mechanism's
  skill is an instruction set and not prose** *(raised by the user, 2026-09-07, at
  [01-0011.0022](./01-0011.0022-shape-survives-second-mechanism.md)'s align)*. Nothing owns
  this today: `/skill-up`'s first rule is *a skill is instruction, not story*, nothing checks it,
  and no rule says how a skill is laid out so that a rule in it can be cited by name — which
  injection needs, since a rules file names a **target** and an **anchor** in a skill whose
  layout nobody fixed. Life declares this as its `skills` mechanism, with `/skill-up` as its
  instruction file, a heuristic hook naming story prose in a `SKILL.md` on write, and layer
  labels on statements; this tree has no `skills` mechanism. It is `/skill-up`'s owed core change
  and sits here because this ticket owns those; declaring `skills` as a mechanism is
  [01-0017](./01-0017-io-graph-coherent.md)'s application of the shape. `/skill-up`'s own *blur
  wording where letting the model decide beats overfitting* is the tension the align settles.
  First instance, not a precedent: `/maintain`'s body under `01-0011.0022` is written as short
  addressable rules grouped by responsibility, A1 … E3, so a second skill can show whether that
  shape generalises.
