## What to build

- One convention, stated where the method's conventions live, naming the three cases the tree
  already has as one: a comment in code naming the doc and section that governs it, the owner on
  an installed block in a skill, the binding on a straw dog in text. A thing a script derives —
  a rendered table, a report, a mark — carries none.
- Core code marks back to its mechanism's doc, never into `docs/`, since a recipient's documents
  do not resolve from core. This project's architecture stops restating the install contract in
  its *Installing* section and points at the harness mechanism's doc, one home.
- The one gap the chain of 2026-10-07 showed is repaired: the installer's install path names
  the record that governs it.

## Acceptance criteria

- [ ] The convention is stated once, names its three cases, and says what carries no mark.
- [ ] No core file names a section of a document under `docs/`; the leak check is clean.
- [ ] The architecture's *Installing* points at the harness mechanism's doc rather than
      restating it, and the installer's install path names that doc.
- [ ] `/verify` has been run on this ticket against the spec and the governing docs.
