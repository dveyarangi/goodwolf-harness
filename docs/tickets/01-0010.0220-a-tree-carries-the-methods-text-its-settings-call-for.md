## What to build

A mechanism declares the settings it owns in its rules file — name, values, default, and who may
set it: a rung of a ladder, read by the dial as every decision is, or the person, whom the host
enforces as it enforces a dial edit *(the user, 2026-10-22)* — and any
installed mechanism's rule may name a declared setting as the condition of its installation,
`when <setting>=<value>`; the project sets its values in its local file, a setting absent there
standing at its default; the installer writes a rule into its targets only while its condition
holds and retracts it otherwise, so a changed setting brings the tree to match in one idempotent
run of the installer, because a text read behind a switch costs every session both readings and can be read wrong
*(the user, 2026-10-18)*. The dial is a setting among the others and its line in the entry file
comes from the table. A `when` on a setting no installed mechanism declares leaves its rule
uninstalled and reported; a value no declaration holds is refused, in a `when` or in the local
file. The person changes a setting by one call that refuses, writes, runs the installer and reports,
or by hand where the setting is theirs alone. `/harness` names the two occasions a session needs the
whole list — a setting changed, the harness's set-up asked about — and shows it as one derived
table: setting, values, default, the tree's value, owner, who may set it — rendered on request,
never committed; the edge record `docs/edge/settings.md` holds the contract and, in the table's
place, the pointer to what renders it *(the user, 2026-10-23)*. Declaring a setting and writing a `when`
is `/mechanism`'s, on the rules-file format shelf. The first declared setting is `debug`: the
debugging mechanism comes to the shape with this ticket, declaring it and owning one rule, the
entry file's announce line *(the user, 2026-10-23)*. The agent is the interface to a tree's
settings, never the file: a hand edit of the local file is allowed, rare, and drift, repaired by
running the installer the moment the mismatch is noticed — the wake reports it, the session runs
it before its first reply and says so, at the rung of the setting changed; `/maintain` finds what
no session met *(the user, 2026-10-23)*.

## Acceptance criteria

- [ ] A rule with a condition is installed in a tree whose local file satisfies it and absent
      from one that does not, and changing the value then running the installer moves it, in both
      directions.
- [ ] A `when` naming an undeclared setting leaves its rule out with a report; an undeclared
      value is refused in a rule and in the local file.
- [ ] <straw-dog question="q-0037.0010.0002.0005">The dial of this tree comes from its settings
      table once a ladder's mechanism declares it; until then L2 stands.</straw-dog>
- [ ] Asked in a live session to change a setting set by the person, the agent names the line and
      writes nothing; asked to change one at a rung below the dial, it changes it, and the reply
      says what the tree now carries; asked how the harness is set up, it shows the
      table, read by the person.
- [ ] The table rendered on request matches the declarations and the local file, and
      `docs/edge/settings.md` names what renders it in the table's place.
- [ ] A tree whose local file was edited by hand is brought to match by the next session before
      its first reply, which says so; `/maintain` reports one no session met.
- [ ] `/verify` passes against this ticket, its RFC and the governing docs.
