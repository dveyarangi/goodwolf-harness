## Two first-run failures read as something else

**Ownership.** The first attempt was refused with *not the top level of a git work tree; a
workspace of several is refused*. The cause was Git's `safe.directory` check — the `.git`
directory owned by one Windows identity and the run by another, as happens when an agent's sandbox
and the person's shell differ. Git said so, with the exact command to trust the directory, and the
refusal swallowed it: `_work_tree_root` reads a failed `rev-parse` as a wrong shape.

**Links.** Both loader links failed with `WinError 1314`, the pending commands were printed, the
agent's elevated attempt failed too, and the report said `arrived: true` beside
`links_resolve: false` for both. That is the harness doc's decision — `arrived` is the three gates
alone, and a link the platform refused is the person's one step — but the report let a reader take
a tree its hosts could not yet read for a finished one.

## What to build

- **The ownership refusal names its cause.** When Git reports dubious ownership, the refusal says
  so and carries Git's own command to trust the directory, and writes nothing; the other target
  shapes keep their refusals. Git's `GIT_TEST_ASSUME_DIFFERENT_OWNER` makes the case testable
  without two identities.
- **The report cannot be read as ready while a link is pending** — in the form the align settles.
- The harness skill's refusal list names the ownership case and what the person does.

## Open issues

- **What `arrived` means when the links are pending.** Keep it the three gates and say beside it,
  unmissably, that the hosts cannot read the tree yet; or make `arrived` false until the links
  resolve, which moves a platform step the script cannot perform into the verdict the harness doc
  kept free of it. The issue is new evidence against the doc's decision; this ticket's align
  decides whether it reopens it.

## Acceptance criteria

- [ ] A target Git refuses for dubious ownership is refused with that cause and Git's command to
      trust it, nothing is written, and a test proves it through Git's own ownership check.
- [ ] An install whose loader links do not resolve ends in a report that says the hosts cannot yet
      read the tree, in the form the align decided, with the decision landed in its durable home.
- [ ] The harness skill's refusal list names the ownership case and what the person does.
- [ ] `/verify` passes against this ticket, the RFC and the governing docs.
