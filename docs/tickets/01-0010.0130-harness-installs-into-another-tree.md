## Why the recipient is the grader

This tree is the one configuration in which the install's defects are invisible: core and instance
are the same repository here, and every reference resolves. A check written for separation and run
here passes and proves nothing. The install is therefore graded where it can fail —
frost_map, which has had the harness on `main` since 2026-09-09, has built on it, and has already
refused one of its checks by leaving it unrun. The first real test is an *update* into a tree with a
history, not an install into an empty one, and it is graded by the user rather than by this tree's
suite. That is the mechanism shape's own sixth step, *graded by someone who did not build it*, and
it is this ticket's last acceptance box rather than a ticket of its own.

## What to build

One mechanism, one instruction file, relying on the injector for localisation rather than owning
it. An install is the sequence below; an update is the same sequence over a tree that already has a
local file, which it never touches. Each step refuses rather than guesses.

1. **Refuse a target it cannot satisfy.** One installation is one tree: `.agents/` sits directly
   under the directory holding `AGENTS.md`, because every script computes its root as two levels
   above itself. A workspace holding several projects is refused, not guessed at.
2. **Copy the manifest** — what the allowlist and the mechanism parts tables name, nothing else.
3. **Record the revision.** The source commit, for provenance; and a content hash over the manifest
   with line endings normalised, for integrity. The hash takes the manifest as its input and is
   testable on a fixture; two trees differing only in line endings hash equal.
4. **Make the loader links.** A symlink, or stop and escalate — no junction, no copy, no substitute.
   An existing link is repointed; that is correct behaviour.
5. **Install the entry file.** `AGENTS.md` and each host's entry stub are parts of this mechanism,
   not something a person types.
6. **Shear.** A `<straw-dog>` wrapper is removed and its content stays as an ordinary rule. A
   `docs/` reference that [01-0010.0140](./01-0010.0140-core-stands-alone.md)'s check would flag
   stops the install here; it is not repaired here. The entry file's *follow a straw dog until its
   condition is visibly met* is worded so a recipient does not read it as applying to content that
   arrived unwrapped.
7. **Inject** — every mechanism's rules file, then the local file last.
8. **Verify arrival, and report done only when it passes**: the shipped tests green, the injector's
   check clean, the recorded revision matching the copy, and each loader link a symlink resolving to
   a directory of skill files. Whether the host *reads* the link is
   [01-0010.0120](./01-0010.0120-host-delivery-surfaces.md)'s and is named as unverified here.

The shipped suite is in the recipient's default verification set — its first run is the arrival
check — and a recipient overrides that in its local file if it wants. The entry contract's
hand-bumped version retires in favour of the recorded revision.

## Acceptance criteria

- [ ] Into an empty temporary tree, the manifest lands with `.agents/` directly under the directory
      holding `AGENTS.md`; a target where it would not is refused with the reason and no file is
      written.
- [ ] What is copied is what the allowlist and parts tables name; a file outside the manifest does
      not travel.
- [ ] The recipient records the source commit and a content hash; two trees differing only in line
      endings hash equal, and one differing by a byte does not.
- [ ] Each loader link is a symlink resolving to the skills directory, or the install stops and says
      which link and why; an existing link is repointed.
- [ ] `AGENTS.md` and each host's entry stub are installed by the mechanism and match their source.
- [ ] No `<straw-dog>` wrapper survives in the shipped copy and every wrapped rule's content does;
      a reference the `.0140` check would flag stops the install with the reference named.
- [ ] After install, the injector's check is clean in the recipient with every mechanism's blocks
      present and the local file's blocks last.
- [ ] The install reports done only after the shipped tests, the injector's check, the revision
      match and the link check pass in the recipient; any one failing reports the install unfinished.
- [ ] An update over a tree with a populated local file leaves that file byte-identical and its
      blocks restored, and overwrites every core-owned file.
- [ ] frost_map takes an update: its `tickets.py` override is written in its local file and
      survives; its `docs/` is untouched; its links resolve; its revision is recorded; its
      verification set passes — **graded by the user in that tree, not by this one's suite.**
- [ ] The entry contract's version line is derived from the recorded revision, or the ticket says
      what still blocks that.
- [ ] Behavioural tests, in the shape of the existing suite, cover each refusal, the revision's
      normalisation, the shear on wrapped and nested content, injection order, the arrival gate,
      and the update path.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.
