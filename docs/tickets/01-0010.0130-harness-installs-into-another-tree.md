# The harness installs into a tree that is not its own

- **Status:** Ready (aligns with 01-0010.0110)
- **Type:** HITL
- **Related:** [01-0010.0110](./01-0010.0110-project-facets-injected.md) — co-aligned on the user's
  direction, 2026-09-09: its answer says what a `<project-local>` block *is*, and this one cannot
  say what an installer localises until that is settled;
  [01-0011.0050](./01-0011.0050-shape-checked.md) — its allowlist is the question *what ships*, so
  this align may not settle the manifest's contents ahead of it
- **Outcome:** A project that is not this one receives the harness by a repeatable install rather
  than by hand: what arrived is identified by a core revision, the recipient's own facts survive
  redeployment, the shipped checks pass on arrival, and an install that cannot complete stops and
  says why instead of substituting something that fits.

## Parent

[Shared harness across projects](./01-0010-dev-harness-shared-and-local.md), whose contract
promises that projects "receive accepted changes mechanically while preserving project-specific
behavior". This takes the distribution half; `docs/architecture.md`'s *Deferred decisions* parks
cross-project distribution with "existing owners", and this is that owner arriving.
`/impact`: [the 2026-09-09 assessment](./01-0010-dev-harness-shared-and-local.md#impact--2026-09-09).

## The trip is the only thing that tests this

Twelve sessions built a harness in the one tree where every defect is invisible, because here core
and instance are the same repository and every `docs/` reference resolves. The
[frost_map probe](../research/separation-probe-frost-map.md) moved it once and produced **35
diagnostics on day one, and one defect in three costumes with 28 instances**: core references the
instance half and does not survive the trip. Two of the three were mechanisms the harness already
believed were safe. *(Counts corrected 2026-09-11 on the probe record: 14 of the 28 are among the
35; the other 14 are straw dogs, listed rather than diagnosed.)*

This is why the align cannot be graded here. A check written for separation and run in this
repository is run in the configuration that hid the defects — it passes and proves nothing. Only a
second tree grades it, which makes the grader a person with a repository, not a suite.

**What is deliberately not a defect.** `docs/`-substituted-whole and the injector both survived. The
rules-injection seam needed no repair at all, and ADR-0001 and ADR-0002 were stressed and held. What
failed was that nothing *enforced* them.

## What to build

This is the decision-bearing phase. Its `/align` produces a spec; `/ticket` then decomposes it. The
align has two named calls-to-action before it converges:

- **`/discover`**, on what an install *is* outside this estate. Shipping a file the recipient is
  expected to edit, and upgrading without clobbering the edit, is old solved ground — Debian's
  conffiles exist for exactly it, and the upgrade protocol is the famously hard part. One recipient
  is one shape; the account of separation currently in this tree is the only account it has.
- **`/align`**, run together with [01-0010.0110](./01-0010.0110-project-facets-injected.md)'s, which
  the user directed on 2026-09-09 after both were traced to one question seen from opposite ends:
  a `<project-local>` block is either core text that travels or a project's answer that must be
  preserved, and only the first can be injected.

The behavior the spec must cover, each constraint with the reason it exists:

- **What arrived is identifiable.** A content hash over the manifest, because one commit routinely
  touches both halves and so a commit tag can only ever be a label for the revision, never the
  revision.
- **The recipient records a pointer back to canonical source**, because a script maintains only the
  tree it lives in — `root = Path(__file__).resolve().parents[2]`, no CLI override — so a core-diff
  must run *from* the recipient and has nothing to compare against.
- **`<project-local>` blocks are localised by the installer**, because today nothing replaces them:
  they arrive carrying this project's facts, and the probe's three mechanism docs were missed by a
  person doing it by hand.
- **The recipient's answers survive redeployment**, under the ownership rule settled 2026-09-10 at
  [01-0010.0110](./01-0010.0110-project-facets-injected.md#ownership-is-one-axis-who-owns-the-content--2026-09-10-the-user):
  core owns the slot wherever it installs, and redeployment overwrites only where core owns the
  *content*. The instance may override, and the override survives. **The loader link is not an
  exception to this** *(the user, 2026-09-10)*: repointing it is correct, and what frost_map was
  missing is a defined deployment target — this ticket's, not an ownership question.
- **Straw dog content travels; the tag does not** *(the user, 2026-09-11)*. All 14 that ship, the
  one in `AGENTS.md` at tier 1 among them, land in a recipient as plain content: the *Straw dogs*
  rule already says what lands at an install takes the content, not the tag, so the installer
  strips the wrapper. A `<straw-dog>` whose condition and ticket a recipient cannot see met would
  dangle there; the content without it is a claim like any other.
- **Core's record formats stop demanding a second home for state the recipient keeps elsewhere.**
  21 of the probe's diagnostics were `Status`, `Type` and a `/verify` box absent from tickets whose
  delivery state lives on a Notion board — the harness asking a project to duplicate state, which
  `/maintain`'s own E1 forbids.
- **The loader link is a symlink, or the install stops and escalates** — binding, the user,
  2026-09-09. No junction, no copy, no substitute: nothing sees through a junction, and
  `git ls-files` lists everything beneath it twice, so the corpus every script shares
  double-counts. A platform that refuses is a human decision.
- **The install verifies what the host will load**, not only what it wrote. Four links were made by
  hand during the probe and one was silently wrong; a broken loader link looks installed until
  something reads it.
- **The entry contract gets an installer and a declared home.** frost_map's `AGENTS.md` existed
  because a person typed it, so the artifact carrying every tier-1 rule is the one thing outside
  every mechanism. Its hand-bumped version is scaffolding the user has already called a straw dog
  and named the successor for — a core revision derived from the manifest's content — which makes
  that retirement this ticket's rather than a loose claim.

## Decisions this ticket's align owns

- **Whether "install" is one mechanism or three** — manifest and revision, localisation, and loader
  links are three different jobs with three different failure modes. One recipient is one shape,
  and the harness's own first general rule forbids generalising from it; the align must resist
  deciding this until a second tree says.
- **What happens to a straw dog on the way out** — stripped at install, rewritten to name no
  ticket, or the exemption in *Core and instance* withdrawn so core carries none. This changes a
  tier-1 rule either way.
- **Whether a core record format may demand a field the recipient keeps elsewhere**, and if not,
  what `tickets.py` checks instead. The general form: how much of its own loop may core require of
  a project that has one.
- **What the core revision is computed over**, now that core is a directory — `.agents/` plus two
  line-level parts in `AGENTS.md`, which is very nearly but not exactly a content hash over one
  path.
- **How a recipient contributes back.** The parent promises project-originated improvements reach
  core; nothing in the install design has a return path, and the probe deliberately never pulled
  from its copy.
- **Whether an install is verifiable from inside the tree it installs into**, or whether arrival
  can only be graded by a person. The probe's answer so far is the second.

Read out of the recipient tree at the align, not reported by the probe. It replaces two open

before generalising from one.

  different things.** Nothing was deleted: the probe's *"four untracked additions, nothing

  retracted the same day at

## Resolutions — 2026-09-10, the user

Taken against the eight concrete failures of the frost_map install, each answered in turn.

- **The loader link may be repointed. What is missing is a defined deployment target.** Repointing
  a host at the arriving harness is correct behaviour, not a seizure; the defect was that the
  install had no stated place to land, so a person improvised one. The spec says where the harness
  goes in a recipient before it says anything about links. This ruling retracted the slot-ownership
  axis at [01-0010.0110](./01-0010.0110-project-facets-injected.md#ownership-is-one-axis-who-owns-the-content--2026-09-10-the-user).
- **A straw dog is sheared at deployment; its content stays.** The installer removes the
  `<straw-dog>` wrapper and leaves the text as an ordinary rule. This answers the dangling-14
  without withdrawing the exemption in *Core and instance* and without stripping meaning: a
  recipient gets the rule, not a condition it can never observe. What the entry file says about
  following a dog until its condition is met then applies only where the condition can be seen —
  the source tree.
- **Every `docs/` reference in core is sheared, strictly.** Each one is explained or accounted for,
  and none arrives in an instance. This is the mandate for
  [01-0010.0140](./01-0010.0140-core-stands-alone.md) and it is stronger than that ticket was
  written to assume: not *reported*, but *gone*, with the exemption stated per reference. Covers
  both the 11 `not yet` links and the 3 evidence bullets.
- **A project may override a core rule, and the override survives redeployment.** The harness
  asking an instance to run its loop is the whole purpose; an instance that cannot override is one
  that quietly stops running the check, which is what happened. Recorded at
  [01-0010.0110](./01-0010.0110-project-facets-injected.md#ownership-is-one-axis-who-owns-the-content--2026-09-10-the-user)
  since it is the ownership rule's second half.
- **`AGENTS.md` gets an installer.** The artifact carrying every tier-1 rule arrived in frost_map
  because a person typed it; that is the one thing outside every mechanism and it stops being so.
- **What arrived is identified by the source commit hash** *(the user's proposal)*, with one
  correction from evidence: a commit hash is **provenance** — what this was installed from — and
  cannot answer whether the copy has since been edited. A content hash answers that, but only with
  line endings normalised: frost_map's core is byte-identical to this tree's after normalising and
  differs in all 41 files without it, because its checkout is uniformly CRLF and ours is mixed. So
  the recipient records the source commit, and integrity is a normalised content hash over the
  manifest. The spec carries both or says why one suffices.
- **One installation is one tree** *(the user, 2026-09-10)*. The deployment target is the directory
  holding `AGENTS.md`, with `.agents/` directly beneath it, and an install that cannot achieve that
  stops. This is not a free choice: every script computes
  `root = Path(__file__).resolve().parents[2]` with no override, so a harness placed anywhere else
  leaves all six silently computing the wrong root — `docs_corpus.corpus()` enumerating the wrong
  tree, `move_doc.py` repairing the wrong citations. frost_map got it right by a person's luck. The
  rule writes down what the code already requires and makes the install check it.
- **A workspace-level harness is not ruled out, and is not this design.** *(the user, 2026-09-10:
  the DriftSense workspace was a temporary shape for keeping harnesses aligned; a single
  workspace-level harness whose children own none is a case worth seeing.)* The distinction that
  matters: if the children share one `docs/`, one queue, one glossary and one set of switches, then
  **they are one project in several directories** and the existing design already covers it with
  nothing new. What needs a new mechanism is children keeping *their own* instance halves and
  switches while sharing one core, because the local rules file is per-installation and nothing in
  the design can ask *which project am I in*. **The one real trial of the workspace arrangement was
  abandoned by its own recipient**: frost_map's loader pointed out of its repository into
  `workspace/agents/skills`, which left the corpus outside frost_map's version control and a clone
  of frost_map alone with no skills — and its own commit `2070530` reverses it, *"they are relative
  and resolve inside the repo, so a clone carries its own skills instead of needing a junction
  rebuilt by hand"*. Not built until a second project in one workspace needs different switches or
  a different verification set.
- **Install is one mechanism, relying on the injector rather than owning it** *(the user,
  2026-09-10)*. Localisation is already `inject_rules.py`'s work — a redeploy puts a project's
  answers back with `--install --overwrite` reading the local rules file — so it is *relied on, and
  not owned*, in the shape's own vocabulary. That collapses the three candidates to two, and
  manifest-and-revision does not separate from loader-links either: neither is useful alone, and
  frost_map's install was one person doing one sequence, failing inside it twice. The seam is
  preserved and not built: what would split this is a recipient needing to re-link without
  re-installing, or the reverse, and nothing does today.
- **Arrival is verifiable from inside the recipient, with one structural exception** *(the user,
  2026-09-11)*. The install's exit evidence is in-tree: the shipped tests green (the scripts
  arrived intact — frost_map ran them), `inject_rules.py --check` clean (installed blocks match
  their sources), the recorded source commit and normalised content hash (what arrived is what was
  sent), and the loader link resolved — a symlink, resolving, its target holding `SKILL.md` files,
  which is the check frost_map's one silently-wrong link never met. The exception is whether the
  host *reads* what was installed: nothing inside a tree can observe what a host puts in front of
  an agent, and that is [01-0010.0120](./01-0010.0120-host-delivery-surfaces.md)'s. The probe's
  verdict that only a person can grade arrival was true because nothing recorded the revision and
  nothing checked the link; both are this ticket's.
- **Contribution back stays open, with a cheap shape named.** A rule copied into every instance:
  when an instance changes a skill, it writes a pull request into core — a `pull-request.md` in a
  named directory to begin with. Under the shearing rule above this arrives as a plain rule, not a
  straw dog. Not this ticket's to build; recorded so the parent's return-path promise has a
  candidate rather than nothing.

- **The shipped suite is in the default verification set, and a recipient may override**
  *(2026-09-11, following from the override rule)*. The verification set is a local rule the
  recipient writes; core ships the suite in the default because a recipient's first run of it is
  the arrival check, and a recipient that does not want ~40s on every `/verify` overrides, and the
  override survives.
