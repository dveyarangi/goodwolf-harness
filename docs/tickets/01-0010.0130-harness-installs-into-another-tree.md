# The harness installs into a tree that is not its own

- **Status:** Ready (aligns with 01-0010.0110)
- **Type:** HITL
- **Related:** [01-0010.0110](./01-0010.0110-project-facets-injected.md) — co-aligned on the user's
  direction, 2026-09-09: its answer says what a `<project-local>` block *is*, and this one cannot
  say what an installer localises until that is settled;
  [01-0011.0050](./01-0011.0050-shape-checked.md) — its allowlist is the question *what ships*, so
  this align may not settle the manifest's contents ahead of it
- **Outcome:** A project that is not this one receives the harness by a repeatable install rather
  than by hand: what arrived is identified by a core revision, the recipient's own facts survive
  redeployment, the shipped checks pass on arrival, and an install that cannot complete stops and
  says why instead of substituting something that fits.

## Parent

[Shared harness across projects](./01-0010-dev-harness-shared-and-local.md), whose contract
promises that projects "receive accepted changes mechanically while preserving project-specific
behavior". This takes the distribution half; `docs/architecture.md`'s *Deferred decisions* parks
cross-project distribution with "existing owners", and this is that owner arriving.
`/impact`: [the 2026-09-09 assessment](./01-0010-dev-harness-shared-and-local.md#impact--2026-09-09).

## The trip is the only thing that tests this

Twelve sessions built a harness in the one tree where every defect is invisible, because here core
and instance are the same repository and every `docs/` reference resolves. The
[frost_map probe](../research/separation-probe-frost-map.md) moved it once and produced **35
diagnostics on day one, 28 of them one defect in three costumes**: core references the instance
half and does not survive the trip. Two of the three were mechanisms the harness already believed
were safe.

This is why the align cannot be graded here. A check written for separation and run in this
repository is run in the configuration that hid the defects — it passes and proves nothing. Only a
second tree grades it, which makes the grader a person with a repository, not a suite.

**What is deliberately not a defect.** `docs/`-substituted-whole and the injector both survived. The
rules-injection seam needed no repair at all, and ADR-0001 and ADR-0002 were stressed and held. What
failed was that nothing *enforced* them.

## What to build

This is the decision-bearing phase. Its `/align` produces a spec; `/ticket` then decomposes it. The
align has two named calls-to-action before it converges:

- **`/discover`**, on what an install *is* outside this estate. Shipping a file the recipient is
  expected to edit, and upgrading without clobbering the edit, is old solved ground — Debian's
  conffiles exist for exactly it, and the upgrade protocol is the famously hard part. One recipient
  is one shape; the account of separation currently in this tree is the only account it has.
- **`/align`**, run together with [01-0010.0110](./01-0010.0110-project-facets-injected.md)'s, which
  the user directed on 2026-09-09 after both were traced to one question seen from opposite ends:
  a `<project-local>` block is either core text that travels or a project's answer that must be
  preserved, and only the first can be injected.

The behavior the spec must cover, each constraint with the reason it exists:

- **What arrived is identifiable.** A content hash over the manifest, because one commit routinely
  touches both halves and so a commit tag can only ever be a label for the revision, never the
  revision.
- **The recipient records a pointer back to canonical source**, because a script maintains only the
  tree it lives in — `root = Path(__file__).resolve().parents[2]`, no CLI override — so a core-diff
  must run *from* the recipient and has nothing to compare against.
- **`<project-local>` blocks are localised by the installer**, because today nothing replaces them:
  they arrive carrying this project's facts, and the probe's three mechanism docs were missed by a
  person doing it by hand.
- **The recipient's answers survive redeployment.** A switch value is the inverse of an installed
  rule — core owns the slot, the project owns the content — so the installer that overwrites one
  must never overwrite the other.
- **No straw dog travels unexpirable.** All 14 that ship dangle in a recipient, the one in
  `AGENTS.md` at tier 1 among them, because the exemption in *Core and instance* is granted on the
  grounds that a dog "is bound to a ticket and expires" — which is true here and false everywhere
  else, while the entry file instructs the reader to follow it until its condition is visibly met.
- **Core's record formats stop demanding a second home for state the recipient keeps elsewhere.**
  21 of the probe's diagnostics were `Status`, `Type` and a `/verify` box absent from tickets whose
  delivery state lives on a Notion board — the harness asking a project to duplicate state, which
  `/maintain`'s own E1 forbids.
- **The loader link is a symlink, or the install stops and escalates** — binding, the user,
  2026-09-09. No junction, no copy, no substitute: nothing sees through a junction, and
  `git ls-files` lists everything beneath it twice, so the corpus every script shares
  double-counts. A platform that refuses is a human decision.
- **The install verifies what the host will load**, not only what it wrote. Four links were made by
  hand during the probe and one was silently wrong; a broken loader link looks installed until
  something reads it.
- **The entry contract gets an installer and a declared home.** frost_map's `AGENTS.md` existed
  because a person typed it, so the artifact carrying every tier-1 rule is the one thing outside
  every mechanism. Its hand-bumped version is scaffolding the user has already called a straw dog
  and named the successor for — a core revision derived from the manifest's content — which makes
  that retirement this ticket's rather than a loose claim.

## Findings landed here

Homeless until now, on the user's direction, 2026-09-09. Each is evidence for the align, not a
separate repair:

- **Four probe findings nothing cited.** Dangling straw dogs, the duplicate-state demand, ticket
  numbering described in [TICKET-FORMAT](../../.agents/skills/ticket/TICKET-FORMAT.md) but never
  checked by `tickets.py`, and nothing checking that the skills a host loads match the contract the
  session reads. [01-0010](./01-0010-dev-harness-shared-and-local.md) picked up the other five as
  install-script constraints; these had no home in any maintained doc.
- **Bare core→instance links in four core skills**, found 2026-09-09 while tracing who reads the
  autonomy switches: [verify](../../.agents/skills/verify/SKILL.md) at lines 10, 32 and 50, and
  [implement:37](../../.agents/skills/implement/SKILL.md), all pointing into `docs/process.md`
  outside any `<project-local>` block. `verify/SKILL.md` contains no such block at all. These are
  straight violations of *Core and instance* and [ADR-0002](../adr/0002-core-may-not-depend-on-the-instance-half.md),
  and four more links that dangle on arrival. The probe's 35 did not count them.
- **`/verify` reaches one fact three ways.** Two links into `docs/process.md#autonomy-and-repair`
  and then, at line 51, the prose *"The `repair` switch is in `AGENTS.md`."* `/ticket` reads the
  same switch set by a fourth route, by path into the block
  ([`/ticket`](../../.agents/skills/ticket/SKILL.md), line 95). Core reaches the switches ad hoc
  because they have no declared home as settings.
- **`docs/concerns.md` does not exist in this tree**, yet
  [`/align`](../../.agents/skills/align/SKILL.md) calls it *"this skill's artifact"* at line 120,
  and `/edge` points into it. Core references a missing instance document **at home**, not only in
  a recipient — the same defect the probe found travelling, sitting here unnoticed.
  [01-0017](./01-0017-io-graph-coherent.md) owns the rule that a document four skills transact
  against either exists with an owner or stops being referenced; what this ticket adds is that the
  rule has a separation reason and not only a hygiene one.

## Decisions this ticket's align owns

- **Whether "install" is one mechanism or three** — manifest and revision, localisation, and loader
  links are three different jobs with three different failure modes. One recipient is one shape,
  and the harness's own first general rule forbids generalising from it; the align must resist
  deciding this until a second tree says.
- **What happens to a straw dog on the way out** — stripped at install, rewritten to name no
  ticket, or the exemption in *Core and instance* withdrawn so core carries none. This changes a
  tier-1 rule either way.
- **Whether a core record format may demand a field the recipient keeps elsewhere**, and if not,
  what `tickets.py` checks instead. The general form: how much of its own loop may core require of
  a project that has one.
- **What the core revision is computed over**, now that core is a directory — `.agents/` plus two
  line-level parts in `AGENTS.md`, which is very nearly but not exactly a content hash over one
  path.
- **How a recipient contributes back.** The parent promises project-originated improvements reach
  core; nothing in the install design has a return path, and the probe deliberately never pulled
  from its copy.
- **Whether an install is verifiable from inside the tree it installs into**, or whether arrival
  can only be graded by a person. The probe's answer so far is the second.

## Open issues

- **The probe's own record claims "nothing modified or deleted"** while the user's account is that
  frost_map's local entries were lost. Only the `.claude/skills` symlink is recorded as destroyed.
  One of the two is wrong, and the align rests on this evidence, so it is worth settling before the
  spec cites it.
- **The probe corpus is still on `frost_map`'s `harness-probe` branch** — a second physical corpus,
  which [ADR-0003](../adr/0003-one-physical-home-for-skills-reached-by-link.md) exists to prevent.
  It is deleted when the manifest exists and is never pulled from, so this ticket's landing is what
  retires it.
- **Whether a recipient runs the shipped suite in its default verification set**, at ~70s per
  `/verify`. That the tests ship is settled; this is not, and it is an install-shaped question
  rather than a testing one.
