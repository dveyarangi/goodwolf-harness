## What to build

- **A pass writes what waits on the person into its mark.** Closing a level, the pass writes, in
  a field of its own beside the outcome, each decision it waits on; an empty field waits on
  nothing. Every mark already written gains the field empty, so the check holds the tree.
- **A script, not a model, says whether anything waits.** The maintenance script reads the field
  and lists each waiting item with its mechanism and level.
- **The wake shows it only while it holds anything**, as a bounded section, read from the marks
  as the path reads tickets and the product document.
- **`/recall` puts each line of that section to the person as a decision**, by a rule the
  maintenance mechanism installs there.
- **A line goes when it is settled, never when it is read**: whoever settles it writes the mark
  again with the field empty.

## Acceptance criteria

- [ ] A mark written with a waiting item makes the next session's wake show it, and a mark
      written with the field empty makes it go; with nothing waiting, the wake shows no section.
- [ ] Every mark in this tree carries the field, and the maintenance check passes.
- [ ] A fresh session started on a tree with one waiting item puts it to the person as a decision
      in its first report, read by a judge who did not build it.
- [ ] `/verify` passes against this ticket, its RFC and the governing docs.
