## What to build

- `/mechanism` installed under `.agents/skills/mechanism/`, carrying **use only**: the membership
  test, when to reach for it, and where the mechanics live. Not the shape tables, not the directory
  layout, not the injection rules — those are the mechanism doc's, and a skill that carries them
  breaks the split it states.
- `.agents/mechanisms/paired-close/` with its doc and evidence sidecar. The doc names every part:
  `/ticket`, `/maintain`, `move_doc.py`, `docs_corpus.py` and the five test files, marking each as
  owned or relied-on with its owner.
- Three property states in the doc — delivered, indexed, singly authored — each with the kind of
  absence it carries and, where the absence is a genuine gap, the sibling ticket that closes it.
- A check that the declaration is true, shipped with this slice rather than deferred: named parts
  exist, doc and instruction file are different files, and every declared gap names a real ticket.
  A shape asserted and unverified is the defect this spec exists to stop.

## Decisions this ticket's align owns

- What counts as a part here. `move_doc.py` is used by `/ticket` and `/maintain`; several users,
  exactly one claimant, and this ticket says which.
- Whether the evidence sidecar is a new file or whether an installed skill's existing `EVIDENCE.md`
  already does that job — `/discover` has one, and two sidecars for one mechanism is the shape this
  is meant to prevent.
- Which absences paired close actually carries today, and which of them are `not yet` rather than
  `elsewhere` or `embedded`. The taxonomy is only useful if the first application is honest.

## Acceptance criteria

- [ ] `/mechanism` is under `.agents/skills/mechanism/` and a fresh session lists it the way it
  lists `/spec`.
- [ ] `/mechanism`'s body carries no shape table, directory layout or injection rule; those live in
  the mechanism doc.
- [ ] `.agents/mechanisms/paired-close/` holds a doc and a sidecar, and the doc names every part
  with its owner.
- [ ] The doc states all three property states, and each gap names a ticket that exists.
- [ ] The check runs, reports the declaration true, and fails when a named part is absent, when doc
  and instruction file are the same file, or when a gap names no ticket.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.
