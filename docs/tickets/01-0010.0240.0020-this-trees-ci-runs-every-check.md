## What to build

- **Core's workflow file**, `.github/workflows/goodwolf.yml`: checkout, a Python set up, the
  launcher run with every check — a check of its own, beside any workflow of the project's, which it
  never touches (decision 5). It is a shipped part of core, so a recipient takes the same file.
- **Every check, every run** — at the origin eight, since `harness.py --check` compares a
  recipient's copy with the source and core's own repository is never installed into (decision 1,
  and the split's hidden edge).
- **The Python** the runner sets up: 3.13 while `inject_rules.py` calls `PurePosixPath.full_match`,
  unless the plan makes the checks run on 3.12.

## Acceptance criteria

- [ ] A push to this tree's main runs the workflow, and the run is green on a tree whose checks
      pass.
- [ ] A pull request whose branch carries a broken record shows the run red, the finding named in
      its log — observed by someone who did not build it.
- [ ] The workflow file is declared a part of the harness mechanism and ships with core.
- [ ] `/verify` passes against this ticket and the governing docs.
