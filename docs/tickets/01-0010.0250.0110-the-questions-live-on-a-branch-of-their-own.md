## What to build

Decisions 2, 3 and 13 of [q-7ebz2f](../questions/q-7ebz2f-how-do-sessions-on-separate-branches-share-one-question-store-and-one-registry-of-sessions.md#decisions): the store's branch, sharing no history
with `main`, checked out once in the clone's common Git directory; `docs/q/` in every worktree a
link to it — a junction on Windows with an absolute target, a symlink elsewhere — read-only,
ignored by the code branches, at a path no commit has held, since a checkout of an old commit
writes through a link at a tracked path (tried in the question). `questions.py` writes there and
commits by plumbing, with the session's tag and the machine's hash and no commit hook of the
project's, and pushes the branch through `pre-push`. The push's check and `/maintain`'s sweep of
decisions read the store's checkout and its history instead of `main`'s; links into the store
become `docs/q/<id>.md`. `docs/questions/` leaves `main`, kept in its history. A one-time
migration moves the store in this tree and in each of the person's others. The scripts still write; the server is [.0030](./01-0010.0250.0030-a-session-in-a-worktree-opens-a-question-through-the-coordinator.md).

## Acceptance criteria

- [ ] On `main` and in a worktree, `docs/q/` shows the same questions, a write to a file there
      fails, and the code's `git status` shows nothing of them.
- [ ] A question opened from either lands as a commit on the store's branch carrying the
      session's tag, and no code commit holds it.
- [ ] A `git checkout` of a commit from before the move, and back, leaves the store and the link as
      they were.
- [ ] A broken entry stops the store's push, and a decision landed on the store's branch is swept
      by `/maintain`.
- [ ] The migration, run in each of the person's other trees, leaves them working from
      `docs/q/`.
- [ ] `/verify` passes against this ticket and the governing docs.
