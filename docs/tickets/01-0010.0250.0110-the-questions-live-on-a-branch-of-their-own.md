## What to build

Decisions 2, 3, 13, 17, 18 and 19 of [q-7ebz2f](../questions/q-7ebz2f-how-do-sessions-on-separate-branches-share-one-question-store-and-one-registry-of-sessions.md#decisions): the store's branch, sharing no history
with `main`, checked out once in the clone's common Git directory; `docs/q/` in every worktree a
symbolic link to it, or a junction where Windows refuses one, which no script walks into —
writable until [.0070](./01-0010.0250.0070-a-body-is-edited-on-its-fingerprint.md), a hand change
committed as by an unknown hand (the user, 2026-11-18), ignored by the code branches, at a path no commit has held, since a checkout of an old commit
writes through a link at a tracked path (tried in the question). `questions.py` writes there, checks
what it writes before its commit, commits by plumbing, with the session's tag and the machine's
hash and no commit hook of the project's, and pushes the branch after every write, in the
background. A record's move repairs the links in the questions through that writer. The code's
push checks read only the code's own references into the store, against the committed
`gw/questions` branch ([q-c2qp5n](../questions/q-c2qp5n-how-do-the-harnesss-checks-run-without-the-agent-at-push-and-in-the-projects-ci-beside-its-own-gates.md)
decision 8, as narrowed 2026-11-22), and `/maintain`'s sweep of decisions reads that branch's
history instead of `main`'s; links into the store
become `docs/q/<id>-<slug>.md`. `docs/questions/` leaves `main`, kept in its history. A one-time
migration moves the store in this tree and in each of the person's others. The sessions' rows,
still files on `main` until [.0090](./01-0010.0250.0090-the-rows-live-in-a-database.md), are read and written in the main working tree from every
worktree, so a session whose hook and shell stand in two trees is one session ([q-k5r3qw](../questions/q-k5r3qw-where-does-a-session-whose-hook-and-shell-stand-in-two-trees-of-one-clone-find-its-row-and-the-store.md),
the user, 2026-11-20). The scripts still write; the server is [.0030](./01-0010.0250.0030-a-session-in-a-worktree-opens-a-question-through-the-coordinator.md).

## Acceptance criteria

- [ ] On `main` and in a worktree, `docs/q/` shows the same questions, a hand change to a file
      there is committed by the next write as by an unknown hand, and the code's `git status`
      shows nothing of them.
- [ ] A question opened from either lands as a commit on the store's branch carrying the
      session's tag, and no code commit holds it.
- [ ] A `git checkout` of a commit from before the move, and back, leaves the store and the link as
      they were.
- [ ] A broken entry is refused before its commit, a ticket closed to `done/` leaves no link in a
      question pointing at its old place, and a decision landed on the store's branch is swept
      by `/maintain`.
- [ ] A session registered by its hook in the main checkout has its calls taken from a worktree
      of the same clone, and both see one set of rows.
- [ ] The migration, run in each of the person's other trees, leaves them working from
      `docs/q/`.
- [ ] `/verify` passes against this ticket and the governing docs.
