## What to build

- A root's id is `q-NNNN`; a question under `q-P` is `q-P.NNNN`. A new id takes the next free
  position under its parent, live or in `done/`, stepping by 10 as ticket positions do.
- `move` and `open --between` rename the moved subtree in the same call: the files, every link to
  them across the tree, the ids inside entries (*part of*, *depends on*, a *merged* or
  *superseded* answer), the sessions file's positions and recent lists, and bare ids in the docs'
  prose. All of it mechanical; nothing forwards an old id.
- A call naming an id no entry holds is refused, writes nothing, and says that ids change when a
  question is re-parented and to draw the window again.
- `--check` reports an entry whose id disagrees with its *part of*.
- A path that would pass the platform's limit has its slug cut at a word boundary until it fits;
  the id is never cut.
- Every entry the store holds, live and in `done/`, renamed once to the tree as it stands.
- The questions skill and doc say the id is the place: *the id is placement and never hierarchy*
  goes.

## Acceptance criteria

- [x] `open --under q-P` gives `q-P.NNNN` at the next free position by 10; `open` with no parent
  gives the next free root. *(2026-10-03)*
- [x] After a `move` or an `open --between`, every link, every id inside an entry, every session
  line and every bare id under `docs/` names the new ids, and nothing there names an old one.
  *(2026-10-03)*
- [x] A call on an id that no entry holds is refused, writes nothing, and says to draw the window
  again. *(2026-10-03)*
- [x] `--check` reports an id that disagrees with its *part of*, and passes on the renamed store.
  *(2026-10-03)*
- [x] A rename whose path would pass the limit cuts the slug, keeps the id whole, and still
  passes `--check`. *(2026-10-03)*
- [x] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.
  *(2026-10-03)*
