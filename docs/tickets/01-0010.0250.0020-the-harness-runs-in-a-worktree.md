## What to build

Today a linked worktree runs with the harness off: the hook reads the interpreter record
through `--git-path`, which resolves inside the worktree's own Git directory, and the loader
links, ignored by git, are not there (the question's *The problem*). The record is read
through the clone's common Git directory, as the pre-push half already does; a worktree
lacking the links gets them, or the command to make them where the platform refuses, as an
install's pending links are named; the window of a session in a linked worktree of a
first-mode tree says it sees no other session (decision 12). Skills a host discovers before
the start hook makes their links load at the next session, and the notice says so.

## Acceptance criteria

- [ ] In a new worktree of this tree, the first message's window is drawn and the session is
      registered, with no step of the person's.
- [ ] The skills load in that worktree from its next session, or the command that makes their
      links is named.
- [ ] In a first-mode tree the window of a session in a linked worktree says it sees no other
      session; in the main checkout it says nothing new.
- [ ] `/verify` passes against this ticket and the governing docs.

## Out of scope

- Sibling clones, which share no Git directory: an install there, as today.
