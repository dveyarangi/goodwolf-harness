## What to build

- **The plan as open work.** Each item of the report's migration plan becomes work in the tree's
  own records — a ticket each, or one, at the grain the inventory read from the project's history —
  with what it depends on; the report's question is the store's first entry, closed decided, its
  body the report. Where the tree keeps its work on a board, the board stands in for the file, as
  the ticket format allows.
- **The method carried in**, by the flow the parent's RFC states: rules into the local file,
  skills claimed, collisions and a process of the project's own at `/align`, the script deleting
  nothing. The arrival of [01-0010.0175](./01-0010.0175-arrival-describes-what-it-finds.md) runs
  after the yes, fed by the report, and is not this slice's.
- **The second reading.** The meeting's rules run again on the tree: the same sample, the same
  key, scored the same way, the second report beside the first and its ledger beside the first's;
  taken while the migration is unfinished, it says which of the plan has landed and which has
  not, and nothing else is read from it. It is this ticket's verification, and
  [q-0038.0001](../questions/q-0038.0001-does-working-under-the-harness-deliver-software-better-than-working-without-it-measured-on-the.md)'s
  second point.
