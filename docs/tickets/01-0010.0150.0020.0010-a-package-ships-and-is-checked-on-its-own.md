## What to build

- **A manifest per package**, naming its files and the scripts it imports from outside it — `move_doc`,
  `tickets`, `product`, `inject_rules`, `mechanisms` for the first — or the seam of
  [q-0037.0006.0024.0001](../questions/q-0037.0006.0024.0001-how-does-an-installed-method-put-its-own-records-into-the-path-and-the-counters-so.md)
  standing in for them.
- **A check over a subset**: update and check compare the package's files against the ref, not core
  whole — a change to the harness's *holds core whole*, shown before it lands.
- The package's anchors that reach skills outside it — `align`, `mechanism`, `commit` — are settled.

## Acceptance criteria

- [ ] An install of the first package into an empty tree passes its check and runs its wake.
- [ ] An update of a tree holding only the first package touches nothing outside it.
