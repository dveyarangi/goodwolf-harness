## What to build

- **Written when absent.** An install or an update finding no product document writes an empty one
  in the format, beside the delivery status and the store's roots: the product mechanism's rules
  carry no condition, so a tree that has the mechanism keeps the document (q-0037.0018, decision 11).
- **The words are the product mechanism's.** The install calls its script and composes nothing, as
  it calls the store's seed *(the user, 2026-10-09: no constants in the installer)*.
- **The project's from its first line.** No update rewrites the document, overwrite included, and
  one in another form is left untouched — the update never replaces a file the project owns.
- **Named, not passed in silence.** A document with no answers table is reported by the install
  and fails `product.py --check` as not in the format, its repair the bringing-in that `/product`
  will hold.

## Acceptance criteria

- [ ] A fixture install into an empty tree, and an update of a tree with no product document, each
      leave one that `product.py --check` passes with no diagnostic.
- [ ] An update of a tree whose product document has no answers table leaves the file byte for byte
      and names it in its report; the check then fails, saying it is not in the format.
- [ ] This tree's product document is untouched by an update and its check still passes.
- [ ] `/verify` has been run on this ticket against its RFC, the spec and the governing docs.
