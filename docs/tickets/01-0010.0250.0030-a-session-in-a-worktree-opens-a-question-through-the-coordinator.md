## What to build

The tracer through the coordinator (decisions 4, 5, 7, 10, 13). The first session whose hook
finds none answering starts it as a process of its own — its lock and address in the common
Git directory, its Git environment cleaned of the worktree's, one coordinator however many
hooks race — and it stops when nobody has called it for a while. It runs the store's own code
over main's files and commits them on main, as [q-0037.0017.0005.0001.0001](../questions/done/q-0037.0017.0005.0001.0001-who-commits-the-coordinator-writes-on-main-while-main-is-checked-out-in-the.md) settles. Reads and
`open` go through it; a write it does not answer is refused plainly and the window is drawn
from main's files, marked so; every window shows that it runs. The architecture's *it locks
nothing* and its straw dog on one shared checkout, and the questions mechanism's moments, are
rewritten to what then holds.

## Acceptance criteria

- [ ] Two sessions in two worktrees of a second-mode tree open a question each at once; both
      land on main with two ids, and each session's next window shows both.
- [ ] With no coordinator running, the first hook raises one; two hooks at once raise one.
- [ ] A coordinator stopped mid-work: the write is refused with a plain message, the window is
      drawn from main's files and marked; the next step raises it again.
- [ ] Observed in this tree's `.claude/worktrees/` by someone who did not build it.
- [ ] `/verify` passes against this ticket and the governing docs.
