## What to build

Decisions 5, 9, 11 and 12 of [q-0037.0017.0005.0001](../questions/q-0037.0017.0005.0001-how-do-sessions-on-separate-branches-share-one-question-store-and-one-registry-of.md#decisions), on one machine. The first call that
finds no server starts one as a process of its own — its address, lock and log in the common Git
directory, one server however many calls race — which stops when nobody has called it for a
while, runs the main checkout's scripts and restarts when they change. Every write of a question
goes through it: it checks the entries the write touches, refuses a bad one plainly, commits by
plumbing and only then answers; the push follows. The window is drawn through it, and every window
shows that it runs. It makes the `docs/q/` link of a worktree that has none. Where no process can
be kept, `questions.py` runs the server's code in the session's own. The architecture's *it locks
nothing*, and the questions mechanism's moments, are rewritten to what then holds.

## Acceptance criteria

- [ ] Two sessions, one in the main checkout and one in a worktree, open a question each at once:
      both land on the store's branch with two ids, and each next window shows both.
- [ ] With no server running, the first call raises one; two calls at once raise one.
- [ ] A server stopped after answering a write and before its push loses nothing: the write is on
      the branch, and the next server pushes it.
- [ ] A write that breaks the store is refused with a plain message, and nothing of it is
      committed.
- [ ] A new worktree gets its `docs/q/` link at its first call.
- [ ] Observed in this tree's `.claude/worktrees/` by someone who did not build it.
- [ ] `/verify` passes against this ticket and the governing docs.
