## The one mechanism that names nothing

Maintain's **M1**, installed into `/mechanism`'s *Incept*, says an inceptor names what `/maintain`
must do for its mechanism *as rules in its rules file targeting `/maintain`*. `ticket`, `maintain`
and `mechanism-shape` each have a rules file. `.agents/mechanisms/harness/` holds only
`harness.md`. So the mechanism every recipient depends on is the one that tells maintenance
nothing — and a maintain pass had no reason to look at its declaration, which had been carrying
its script's verbs since the commit that created both.

## What to build

- A rules file at `.agents/mechanisms/harness/harness.rules.md`, in the rules-file format, naming
  what a maintain pass re-checks for harness: that the painted doors the install created are still
  there, that the announce line still matches what the tree holds, that the recipient's local file
  still resolves against the rules this ref sends, and that a skeletal record's unread sections are
  not drift.
- The doc's parts table gains the rules file, and the anchor table names its targets.
- Nothing is written into `/maintain` by hand; the block arrives through the installer.
