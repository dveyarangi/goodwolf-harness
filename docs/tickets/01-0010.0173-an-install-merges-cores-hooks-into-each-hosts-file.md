# A fresh install arrives with core's hooks merged into each host's file

- **Status:** In progress (implemented and verified 2026-10-09; its paired close is next)
- **Type:** HITL

  in the ref gate
- **Trigger:** [issue 4](https://github.com/dveyarangi/goodwolf-harness/issues/4) — every fresh
  install ends `arrived: false`, since the questions mechanism declares the three hosts' hook
  files as its parts and the install carries none of them
- **Answers:** [q-0018.0020.0005.0001](../questions/done/q-0018.0020.0005.0001-how-does-an-install-merge-cores-hook-entries-into-each-hosts-shared-file-and-take-them-out-again.md)

  `.codex/hooks.json` and `.cursor/hooks.json` beside whatever the project already has there, and
  ends `arrived: true`; an update replaces core's entries and leaves the project's own.

## What to build

- `--install` merges core's hook entries into each host's shared, committed file, creating the
  file when absent; never a local settings file *(the user, 2026-10-09)* — the shared file is
  what every clone and every collaborator reads.
- A host file holding entries of the project's own keeps them; core's entries are recognisable as
  core's, so `--update` replaces them, removes one that has left core, and touches nothing else.
- `--check` compares core's entries alone, the way it already sets aside a recipient mechanism's
  blocks; a project's own hook is never drift.
- A host file that is not valid JSON is refused naming the file, not rewritten.
- The commands keep today's form; how they find an interpreter is `.0174`'s.
- Core's entries are authored in a file under `.agents/` and ship as ordinary core; the origin's
  own host files are merged from it like any recipient's *(the user, 2026-10-09)* — read off the
  origin's host files, they would carry whatever this tree puts there for itself alone.

## Acceptance criteria

- [x] An install into an empty repository ends `arrived: true`, the three host files present and
      holding core's hooks.
- [x] An install into a tree whose host file already holds a hook of its own keeps that hook, and
      the shape check passes.
- [x] An update to a ref whose hooks changed replaces core's entries and keeps the project's own;
      an entry that left core is removed.
- [x] `--check` passes over a tree whose host file carries a project's own hook, and fails over
      one where core's entry was edited.
- [x] A host file that is not valid JSON is refused, nothing written.
- [x] `/verify` passes against this ticket, its RFC and the governing docs.
