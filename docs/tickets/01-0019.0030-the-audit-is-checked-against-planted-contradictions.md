## What to build

The audit layer: an auditor reads the amended text with the files it shares terms with and lists
the conflicts it finds. Its sensitivity is read from contradictions planted in a copy of the text,
its background from a run on the unchanged text; a finding counts only above the background. The
plants are kept as cases in `docs/` and run again when the model or the audit's own text changes.
It runs through the same staging and adapter as the behaviour cases.

## Acceptance criteria

- [ ] Planted contradictions are kept as cases, and a run reports how many of them the audit found.
- [ ] A run on the unchanged text reports its background, and an audit of a change reports only what stands above it.
- [ ] Run on the doc-rule bench's first compression, the audit reports the conflicts that bench found.
- [ ] `/verify` passes against this ticket, its RFC and the governing docs.
