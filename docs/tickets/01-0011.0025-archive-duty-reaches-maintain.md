## Why this exists

This is the slice that closes the defect the whole spec was written from. On 2026-09-06 five
tickets sat finished and unarchived. The duty that requires the move is written in `/ticket`'s
files; `/maintain` owns archiving and carries only the permission form — *a ticket moves only when
every acceptance box is checked*. Three `/maintain` passes each correctly declined to touch records
they had not examined, and nothing swept, so the backlog was invisible rather than ignored.

Writing the duty into `/maintain` by hand would fix this instance and leave the next to chance.
Installing it from `/ticket`'s rules file is what makes the fix mechanical in both directions.

**Paired close is a behavior of `/ticket`, not a mechanism.** It is not a skill, and under one
instruction file per mechanism it cannot be one. `/maintain` is not a part of it: it is the target
the rule is installed into, and it is the mechanism for maintaining mechanisms.
