# A tree's existing material becomes its glossary and a skeleton

- **Status:** Planned (narrowed at the 2026-09-23 `/impact`; the codebase half is not in scope)
- **Type:** HITL
- **Depends on:** [01-0010.0170](./01-0010.0170-arrival-becomes-a-sequence.md) (the sequence this
  step sits inside, and the doors it writes into)
- **Outcome:** An install into a tree that already holds written material ends with a glossary and
  an architecture skeleton drawn from it, and every section nobody read stamped so, rather than a
  tree that arrives undescribed.

## Parent

[Shared harness across projects](./01-0010-dev-harness-shared-and-local.md), whose

## The admission scales, not the effort

The dial the align rejected was project size. It does not survive the two recipients: ai-game-1 is
zero lines of code and six dense documents; frost_map is large and already described. Size
measures input, and the two come apart in both directions.

So the recipe is fixed and the same everywhere, and what varies is how much of the record comes
back ungrounded. A big tree gets a short skeleton and a long list of what nobody read, which costs
the same to produce and is the honest output.

That needs a third word the format does not have. **Deferred** means we looked and chose not to
specify. **Risk / open question** means we looked and found pressure. **Unread** means nobody
looked — no claim either way. Folding unread into deferred manufactures the ai-game-1 failure in a
second place: a record that reads as settled and is not.

A fourth state stays distinct and needs no stamp: **absent**, where there is nothing to describe.
A codeless tree's architecture is not unread, so no file is written at all and the lazy rule
holds. The trigger is the recipe's yield, never a classification of the tree.

**Narrowed, and why.** The read-the-codebase half of this recipe has zero real cases: frost_map
arrived described, ai-game-1 has no code. Designing it now generalises from nothing. This slice
takes the prose-sourced half only — existing documents into `glossary.md` and a
Purpose/Scope/Core-concepts skeleton — and a recipient with undescribed code is what mints the
rest.

## What to build

- One fixed recipe over what the tree already holds in `docs/` and its root: the material it can
  ground `glossary.md` and the skeleton's opening sections from, and nothing inferred past it.
- `ARCH-FORMAT.md` and `GLOSSARY-FORMAT.md` gain **unread** as a state distinct from *deferred*,
  and it is the **default** for every section the recipe did not ground — honest by construction,
  not by the diligence of whoever writes it.
- `/maintain` is told that unread is tolerated. Its **A1** holds *docs to their implementation,
  both ways*; a skeleton disagrees with the tree by construction, and the repair maintain would
  otherwise attempt is this recipe, unbounded. Without this the first maintain pass on every
  bootstrapped project reports the architecture as drift.
- Grounded nothing means no file. An all-unread architecture asserts the wrong one of the four
  states.
- The instruction is hand-written in `harness/SKILL.md` and wrapped as a straw dog, because align
  owns both formats only until [01-0017.0010](./01-0017.0010-terms-defined-before-they-land.md)
  incepts the glossary mechanism, and an undeclared mechanism cannot inject. The Moments row is
  `embedded`, naming where the instruction sits. When the owner is declared the rule arrives as
  an installed block and harness's own text does not move.

## Open issues

- What the fixed recipe's list of places actually is. The align settled that it is fixed and small;
  which places, and in what order, is `/plan`'s against the two real trees.
- Whether the glossary harvest is run without the user present or put to them term by term.
  ai-game-1's material is in Russian and its terms are a game's, not a codebase's; guessing them
  is worse than leaving them unread.

## Acceptance criteria

- [ ] An install into ai-game-1's shape produces `glossary.md` and an `architecture.md` whose
      Purpose, Scope and Core concepts are grounded in its existing documents.
- [ ] Every section that recipe did not ground carries the **unread** stamp, and no ungrounded
      section is marked *deferred*.
- [ ] An install into a tree with no material writes neither file.
- [ ] `ARCH-FORMAT.md` and `GLOSSARY-FORMAT.md` define unread against deferred and against a risk.
- [ ] A `/maintain` pass over a freshly bootstrapped tree reports no drift for an unread section.
- [ ] The straw dog binds to `01-0017.0010` and the Moments row reads `embedded` with its location.
- [ ] `/verify` passes against this ticket, the RFC and the governing docs.
