## Why this exists

**Four records already depend on an answer nobody has.**

- [01-0011.0030](./done/01-0011.0030-archive-backlog-listed.md) held its backlog as a ratchet —
  *silent at or below its mark, loud when it rises* — with no channel to be loud in. *Withdrawn
  2026-10-04 (the user): the duty it enforced is `/maintain`'s, and the ratchet was never needed;
  it no longer depends on this ticket.*
- [01-0020](./01-0020-pacer.md) promises the agent knows each turn's scope *from Tier 1 rules in
  the entry file* — a deliberately static answer that this ticket either widens or confirms.
- [01-0018](./01-0018-reachability-coherent.md) concludes that where a rule cannot reach its
  occasion, the gap is named. This is the prior question: **can** it?
- [01-0011.0010](./done/01-0011.0010-mechanism-declared.md) hit it directly. Its check has no way to
  run at wake, so it joins the verification set instead — the best available substitute, and a
  substitute is what it is.

**The glossary has framed this since inception and given it no owner.** **Tier 1** ends: *"Intended
Tier 1 placement and observed delivery are distinct facts."* That sentence is this ticket's whole
subject.

**Announcements are the evidence case.** Life declares, per mechanism, a table of blocks placed in
a session's context at a session event — each with a **mandatory quiet condition**, because a
silence with no declared meaning reads as an absence. This harness cannot build one: `.claude/`
holds only `skills`, there is no `settings.json`, and no hook exists anywhere in the tree. That is
not a gap someone forgot; it is an unexamined capability question.

## What to build

This is the decision-bearing phase. It derives the matrix first, because **what the ticket
delivers becomes clear from the matrix and not before** *(the user, 2026-09-07)*. Its `/align`
then produces the decision, and this ticket is rewritten to feature altitude or decomposed.

- **The capability matrix, from observation.** For each host: what it can place in front of an
  agent without being asked, at which events, configured how, and what it costs. Reading
  documentation is a source; a host reporting its own behavior in a live session is the evidence.
  A capability nobody watched is recorded as unobserved, not as present.
- **What each matrix cell cannot confirm.** Carried as a first-class column, not a footnote — see
  the acceptance criteria.
- **The shared subset, and the substitutes.** What all three do; what only some do; and for each
  absence, what stands in — a static line in `AGENTS.md`, a verification-set command, or nothing.
- **Capability before portability.** Establish it in the host actually in use, record what the
  other two do, and defer adapters. Conflating the two makes this unfinishable.

## Decisions this ticket's align owns

- **Whether this harness takes a dynamic tier-1 surface at all.** The alternative it would
  displace — a static line in `AGENTS.md` — has zero runtime cost and cannot lose a message.
  [The Life findings](../research/life-harness-findings.md) record the other side: *"Life's wake
  runner records multiple process launches delaying or losing delivery under load; mechanical does
  not mean free."* This cannot be answered before the matrix says what the option actually is.
- **What "control" can mean when delivery is unobservable.** The same findings record that Life's
  `rules-loaded.js` proves bytes on disk and never bytes supplied to a live session, and that
  `wake.js` cannot establish *"that the host delivered the emitted output in full, or that an agent
  used it."* If the loop cannot be closed anywhere, the honest deliverable is delivery plus a named
  limit — and the title's word *control* is then wrong.
- **Whether the shared subset is the target, or the best host is.** Building to the intersection
  costs capability; building to one host costs portability. The findings warn against the naive
  form of this — *"avoids betting the first version on three supposedly equivalent startup
  hooks"* — without settling it.
- **Whether `quiet when` is adopted independently of any of this.** Life's rule needs no runtime:
  a check that can be silent declares what its silence means. It could apply to
  `01-0011.0010`'s verification-set check today, which would make it the one part of this ticket
  with no dependency on a host feature.
- **What the three hosts are, currently.** Observed 2026-10-02: the user works in Claude Code,
  Codex and Cursor in parallel on this tree *(the user)*. Codex is the ChatGPT desktop app's
  Codex mode, the same agent as the Codex CLI, sharing `~/.codex`; the `codex` on PATH is still
  the May 2025 npm build [01-0010.0020](./done/01-0010.0020-live-alignment-across-hosts.md)
  noted, a stale CLI and not the host in use. Cursor is 3.22.7. A matrix built against a host
  nobody works in measures nothing.

`01a0fee7-f1bc-7043-9569-37ab27fb527e`, under entry contract v22. The initial test and its

The observed sequence supports pending hook approval as the earlier cause; no pre-approval

**Cursor delivery test, 2026-10-03**, in chat `s-1003-7b62`, under entry contract v22. The first

agent registered with a bare `questions.py --wake`, which minted the tag, placed the chat at

Cursor's docs: `sessionStart` is fire-and-forget; the agent loop does not wait. `additional_context`

is sent before the merge lands
([Cursor staff](https://forum.cursor.com/t/sessionstart-hook-additional-context-is-never-injected-into-agents-initial-system-context/158452)).
`env` from the same hook is the path that lands.

This chat has no host-id line in the sessions file, so a successful registration did not complete.
The event-specific payload documents `session_id`; `questions.py` reads only `conversation_id`.
Fed `session_id` alone, the script answers
`{"additional_context": "questions hook: the hook's input names no session"}` and writes nothing.
Whether the command executed at all is the Hooks output channel's. Compaction remains unobserved.

**Cursor, the cause and the fix, 2026-10-03**, read from Cursor's Hooks output channel *(the
user)*. The hook did run — exit 0 in about 1.5 s, from the project root — and Cursor's logged
input carried `conversation_id`, equal to `session_id`, so the field was never the cause. The
script answered *Expecting value: line 1 column 1 (char 0)*: it read its standard input in the
Windows code page, and what Cursor wrote did not decode as JSON there. `questions.py` now reads
the pipe's bytes and decodes them by their byte-order mark, UTF-16 or UTF-8, names unreadable
input by its length and first characters, and returns Cursor's session tag as `env`
(`QUESTIONS_SESSION`), the one start-hook output Cursor applies. In a fresh chat,
`fb978107-595f-440d-a251-4cce4f282ae8`, the hook then registered the chat under that id and
Cursor logged *Session environment updated … QUESTIONS_SESSION*. Its `additional_context` still
does not reach the agent, a host defect. Nor does the `env` reach the agent's shell:
`echo $env:QUESTIONS_SESSION` in that chat printed nothing *(the user)*, so Cursor applies it to
later hook runs alone, as its docs say. Cursor's agent therefore has no channel to its hook's tag,
and a chat holds two lines: the hook's, under the host id and unused, and the one the agent's bare
`--wake` mints and works under. That is a known limit, kin to the resume trail of a conversation
under a new id; adopting the hook's line from a bare `--wake`, or registering nothing from
Cursor's hook, are the alternatives left undecided.

## Acceptance criteria — provisional, firmed at the align

- [ ] The matrix exists in a durable home, covering all three hosts, and each cell says whether it
  was **observed** in a live session or **read from documentation** — the two are not merged.
- [ ] Every cell carries what it **cannot** confirm about delivery. A matrix that omits this
  repeats the defect it exists to fix: a mechanism that looks healthy because nothing contradicts
  it.
- [ ] The decision on whether this harness takes a dynamic surface is landed in its durable home,
  with its reason, and this ticket is rewritten to feature altitude or decomposed.
- [ ] A host's absence of a capability is recorded with its substitute, never left blank —
  absence is not clearance.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.

## Out of scope

Building an announcement mechanism, which is a later slice and only if the decision is yes.
Life's `{name, body, message}` contract and its wake runner — taking that shape before knowing our
hosts' is the mistake this ticket exists to avoid. The loader-link question, *whether
`.claude/skills` and `.cursor/skills` are needed at all*, which is the parent's and a separate
axis. Cross-project distribution, still the parent's. `AGENTS.md` as tier 1: static delivery is
the floor here, not a placeholder awaiting replacement.
