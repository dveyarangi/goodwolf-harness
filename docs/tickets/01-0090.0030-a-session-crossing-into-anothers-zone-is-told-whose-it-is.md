## What to build

A session learns today that it wrote in another's zone only when the two collide. The parent
question's accepted
[Where it stands](../questions/q-ja5mp4-does-the-method-have-one-session-direct-the-others-an-orchestrator-and-what-does-it-owe-the-sessions-it.md#where-it-stands),
*Crossing a boundary*:

- A session that edits a file in another role's path is told whose path it is. The edit is never
  refused: a crossing is information for the session and, repeated on one path, ground to
  propose shifting the zone or marking the file shared.
- It is said at the edit where the host has a hook on file edits, and at the commit where it has
  none. This tree's host settings carry no hook on a file edit yet.
- Whose a path is, is read from the roles' mechanisms and the table of who holds which. A path
  none names is the harness session's. A tree with one session, or no table, is told nothing.
  *(Overturned 2026-11-21 as to "the roles' mechanisms", here and under "Depends on": no
  mechanism is written for a role, and who holds which is one table in the local rules, a session
  by its name and the mechanisms it holds —
  [the plan](../rfc/01-0090.0020-the-cut-is-read-against-the-work.md#decided-by-the-person) of
  [01-0090.0020 the-cut-is-read-against-the-work](./01-0090.0020-the-cut-is-read-against-the-work.md),
  "Decided by the person". This ticket is rewritten once the table's form stands in that plan.)*
- An edit refused until its skill is loaded maps a path to the mechanism that declares it too
  ([01-0010.0125.0010 an-edit-waits-for-the-skill-that-keeps-its-file](./01-0010.0125.0010-an-edit-waits-for-the-skill-that-keeps-its-file.md)).
  The two read the declarations through one reader, built by whichever lands first: two readers
  would answer the same question of a path two ways.

Every instruction's text is shown to the person before it lands. Each step is written in
[the journal](../research/standing-sessions-journal.md) with what a fresh tree would need to do
the same.

## Acceptance criteria

- [ ] In this tree, a session that edits a file in another role's zone is told in that turn
      which role's it is and which session holds it, and the edit goes through; observed live by
      someone who did not build it.
- [ ] An edit inside the session's own zone says nothing, and so does an edit by the session
      that holds the harness of a path no role names.
- [ ] On a host with no hook on file edits, the same is said when the session commits the file.
- [ ] A tree with one session and no table is told nothing at an edit or a commit.
- [ ] One reader of the declarations answers whose a path is, for this telling and for the edit
      that waits for its skill; a test fails where the two disagree on a path.
- [ ] Each rule's text was shown to the person before it landed.
- [ ] `/verify` passes against this ticket and the governing docs.
