## What to build

Before the first write, an update finds every path the new ref adds that the previous ref did not
ship and that the tree already holds with other content, and treats it as it already treats an
edit in core: a refusal naming the first such path, or with `--overwrite` a replacement it
reports. The check runs with the update's other preflight checks, so a refusal writes nothing.

## Acceptance criteria

- [ ] An update whose new ref adds a path the project holds with its own, uncommitted content is
      refused, and the project's bytes stand.
- [ ] The same update with `--overwrite` replaces the file and reports it among the replaced.
- [ ] A path the tree holds with exactly what ships is not reported, and the installer's tests
      pass.
- [ ] `/verify` has been run on this ticket against its RFC and the governing docs.
