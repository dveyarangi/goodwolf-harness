## What to build

- **The launcher core tracks** is `hook.sh`, every core hook's wrapper, run by the clone's
  `pre-push`: it reads the files the pushed commits carry from the refs Git hands it, matches them
  in the shell against the method's roots, and starts no interpreter when none matches; otherwise
  `harness.py . --pre-push` checks out what the push sends into a temporary copy and runs the eight
  checks there side by side under the interpreter `--links` recorded (decisions 1, 3, 7 and 8).
- **The verdict** refuses the push on any finding in the copy: what is checked is what is sent, and
  no other session's unfinished write is in it (decision 8).
- **The hook** is one line, guarded against a tree without core, written by `harness.py . --links`
  inside the project only — its Git directory, or a hooks folder of its own work tree — in LF, only
  where none stands or the one standing is core's; beside another hook, in husky's folder, or where
  `core.hooksPath` names a folder outside the project, it writes nothing and the report gives the
  line and where it goes (decisions 4 and 9).
- The harness doc names the moments — writing the clone's hook, running the checks a push wakes
  and ruling by its files — and the hook among what it produces; mechanism-shape's and `hook.sh`'s
  own header name the `pre-push` branch, the one that refuses by design.

## Acceptance criteria

- [ ] A push whose commits carry a question, ticket or other record whose check fails is refused,
      the finding and its file named; pushed again after a commit that mends it, it goes through —
      observed live in this tree by someone who did not build it.
- [ ] A push that carries only files outside the method's roots runs no check and starts no
      interpreter.
- [ ] While another session's unstaged write fails a check, a push that does not carry it goes
      through; a record broken in the pushed commit and mended only on disk is refused.
- [ ] While the hook runs, another session's `git add` and `git commit` go through; the push's time
      is recorded on this tree's machine with sessions running.
- [ ] `--links` writes the hook where none stands, rewrites only its own, and beside another hook —
      husky's among them — leaves it byte-identical and reports the line and its place.
- [ ] The hook runs from Windows PowerShell and from Git Bash on this machine, a path in a
      non-Latin script read as written.
- [ ] `/verify` passes against this ticket and the governing docs.
