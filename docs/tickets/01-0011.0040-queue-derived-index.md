# The queue is read from the tickets rather than transcribed from them

- **Status:** Planned (the record shape precedes)
- **Type:** HITL
- **Depends on:** [01-0011.0025](./01-0011.0025-archive-duty-reaches-maintain.md) (`/ticket`
  declared, and the record shape the index is derived from)
- **Outcome:** The queue's status, type and outcome are derived from the ticket headers that own
  them, so the queue cannot contradict a ticket, and the pacing prose stays hand-written.

## Parent

[A mechanism has one home for its rules, and a derived index](../spec/01-0011-mechanism-shape.md).

## Why this exists

[TICKET-FORMAT](../../.agents/skills/ticket/TICKET-FORMAT.md) requires `Outcome` be *copied verbatim
from the ticket header* into the queue table. A copy maintained by hand is not an index; it is a
second home, and it drifts. On 2026-09-06 two rows carried paraphrased outcomes and were repaired by
hand — and the check that found them exists only because the data is duplicated.

## Decisions this ticket's align owns

- **Whether the rendered table is committed.** The spec says no, on the reasoning that an index kept
  beside its records is a copy. That reasoning was taken from a tree whose wake hooks inject state
  into every session. This harness has none, and [AGENTS.md](../../AGENTS.md) routes every session
  to the queue as the thing that *owns current state and says where to resume*. An uncommitted table
  makes that routing land on a marker. The live alternative is committed-but-generated with a
  staleness check, which is not a hand-maintained copy and does not depend on a hook we do not have.
  Until this is settled the rest of the slice cannot land.
- What a reader without the tool sees, on the repository host and in a diff.
- Whether `Last updated` survives at all, given a derived view knows when its records last moved.

## What to build

- The queue declares its own index in its own file, naming the shape and the fields it derives.
- A renderer that reads `Status`, `Type` and `Outcome` from the ticket headers, and the `done/`
  segment from where each file actually sits.
- Pacing prose stays authored. Judgment about where the work stands is not derivable and must not be
  faked by a generator.
- `TICKET-FORMAT` loses what nothing copies any more, in every place it says it — ~~all four: the
  shelf's stated ownership, the placement note, the `Outcome` verbatim rule, and the queue
  section~~ **five after `.0025`'s rewrite of the shelf, 2026-09-09:** the shelf's stated
  ownership, the placement note, the queue-row sentence under *One basename per work item*, the
  *update the queue* convention, and the queue section, now wrapped in a straw dog bound here
  with the `Outcome` verbatim rule inside it.
- `/ticket` stops amending a table; `/maintain` stops updating a queue row.
- `docs/process.md`'s pointer at the removed section is repaired.

## Acceptance criteria

- [ ] The committed-or-not question is settled and recorded here with its reason.
- [ ] The queue file declares its index, naming shape and fields.
- [ ] A rendered queue matches every ticket header it derives from.
- [ ] Editing a ticket's status changes the next render, with no other edit.
- [ ] A ticket the renderer cannot parse is reported, not omitted.
- [ ] `TICKET-FORMAT` no longer requires anything to be copied, in any of its ~~four~~ five sites.
- [ ] Neither `/ticket` nor `/maintain` instructs anyone to amend a table.
- [ ] The pacing prose is unchanged in kind: still written by whoever ran the pass.
- [ ] Behavioral tests cover derivation, reflection of an edit, and the unparseable record.
- [ ] `/verify` has been run on this ticket against its ticket, RFC, and governing docs.

## Out of scope

Indexes for any other register. Wake-time delivery of the index, which needs a hook this harness
does not have — if the align decides an uncommitted table, the reachability gap it opens is named
and owned rather than assumed away. Session records citing the old table keep their facts.
