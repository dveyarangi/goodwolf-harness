## Why this exists

`/discover` is on disk at `.agents/skills/discover/`, is named in `AGENTS.md`'s Helpers list, and
appears in its `Installed:` line as of 2026-09-06. It has never had a ticket.

It is also **not in the accepted bootstrap selection**. That selection, marked *Accepted by the
user, 2026-09-05*, enumerates 21 source capabilities from Meteoscape and Forecast Collector.
`discover` is not among them; it arrived from a different estate, carrying an `EVIDENCE.md` and a
`<project-local>` block that referenced `experiments/`, `memory/discovery/`, `docs/discovery.draft.md`
and a `/lurk` skill, none of which exist here.

So the entry file currently asserts an install that no decision authorises. Adding a 22nd member to
an accepted selection is a contract change, and
[the entry file](../../AGENTS.md) says not to reopen an accepted decision without new evidence —
which makes the evidence this ticket's first job, not an afterthought.

## What to build

- The membership decision, recorded on the selection itself: is `/discover` in, and on what
  evidence. If out, it is removed from the entry file and the catalog and the ticket closes there.
- If in: a real filing location for pass returns, replacing the generic "the project's research
  area" the skill body now says. `docs/research/` is the existing home for evidence records, but a
  discovery return is material about a shape rather than about a mechanism, so the two may not be
  the same place.
- `EVIDENCE.md` reconciled: it still cites `memory/discovery/` and a "Pass 1" numbered by the
  foreign estate.
- The catalog entry in [`.agents/README.md`](../../.agents/README.md).

## Already landed

**2026-09-06:** the `<project-local>` block was dropped at the user's direction. The
subagent-with-no-corpus rule and the filing rule were salvaged into the body, and the pass numbering
is now stated as the `/impact`↔`/discover` pair with opposite corpus permissions — pass 1 reads the
corpus, pass 2 must not.
