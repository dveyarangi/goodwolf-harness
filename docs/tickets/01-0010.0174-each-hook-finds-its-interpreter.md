# Each hook runs in every clone, finding its interpreter without uv

- **Status:** In progress (implemented 2026-10-09; the live boxes wait on each host)
- **Type:** HITL
- **Plan:** [Each hook finds its interpreter RFC](../rfc/01-0010.0174-each-hook-finds-its-interpreter.md)
  — the link step records `sys.executable`; one POSIX wrapper reads it, launched by a `git` alias
  that every host's shell reaches, as the probe of 2026-10-09 showed
- **Depends on:** [A fresh install arrives with core's hooks merged into each host's file](./done/01-0010.0173-an-install-merges-cores-hooks-into-each-hosts-file.md)
  (the merged entries whose commands this changes)
- **Answers:** [q-0018.0020.0005.0002](../questions/q-0018.0020.0005.0002-how-does-each-hook-find-a-working-interpreter-in-every-clone-under-each-hosts-shell.md)
- **Outcome:** Every core hook runs through a wrapper that reads the Python interpreter found once
  per clone, so the hooks run on a machine without `uv` and where a bare `python` is the Windows
  Store stub, under each host's shell.

## What to build

- The interpreter is found once per clone and written to a file of the clone's own, never
  committed *(the user, 2026-10-09)* — macOS and Linux often carry only `python3`, and on Windows a
  bare `python` may be the Store stub that runs nothing.
- Every core hook calls a wrapper that reads that file; with no file, the wrapper says which step
  makes it, rather than failing silently.
- Which per-clone step makes the record is the plan's; a clone that runs `--links` already has one
  step, and should not need a second.
- This tree's own three host files take the same commands; the origin needs its own interpreter
  record before its hooks run again.
- Each host's shell on Windows is checked live *(the user, 2026-10-09)*: Claude Code under Git Bash
  and without it, Codex with `commandWindows`, Cursor, whose shell is undocumented. A changed hook
  command re-asks Codex's trust once.

## Acceptance criteria

- [ ] On a clone with no `uv`, the session-start and prompt hooks of each host deliver the window.
- [ ] On Windows, each of the three hosts runs the hooks in a live session, the shell each used
      named in the ticket.
- [x] A fresh clone gets its interpreter record from its per-clone step, and a hook run before it says
      which step to run.
- [x] The interpreter record is excluded from Git in every clone.
- [ ] `/verify` passes against this ticket, its RFC and the governing docs.
