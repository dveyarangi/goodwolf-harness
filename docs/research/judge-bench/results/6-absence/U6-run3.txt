(2) Shared files: the same script, such as mechanisms.py or inject_rules.py, appears as a relied-on part of several mechanisms. The owned-parts table gives each file one owner, and the draft limits the line to files "a mechanism declared its part", so a single slug per file holds. (3) Recipient trees with their own declared mechanisms would get a new diagnostic on update. That is a migration detail settled when the check lands, and it does not change what the convention promises. (4) The slug-not-path rule keeps core from pointing into docs/, and the slug resolves to the mechanism directory that ships with core. Each of these is either already covered by the draft or can be settled locally later, so none passes the load-bearing test. The grep confirmed the draft's observation that skills with a mechanism carry no line today.
