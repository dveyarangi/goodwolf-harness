PART: The draft's premise that a script may do the deletion the agent was blocked from (the "rights" belong to the script) was never examined: the auto-permission block is on the intent of wiping the project folder, so a flag that wipes the tree the installer runs from either gets blocked the same way (the shape does not work) or works as a way around a guard the person may want, and either way it reverses the installer's written contract of refusing rather than overwriting and never writing on refusal.
CONTRACT CHANGE: Installing would stop being "into an empty tree, from a fresh clone, every refusal writes nothing, the scripts refuse rather than overwrite" and become "may destroy a non-empty tree, including its own source and .git, on a flag". That changes what the harness promises on its front page (no harm), what the manifest and refusal rule (_refuse_unless_empty) depend on, and whether the fix lives in the installer at all or in how the fresh-clone step is reached (the URL-to-clone step happens before any harness text is read).
REASONING: The draft commits to an installer mode (--replace-clone) that, on a clean clone whose HEAD equals the repository's commit, wipes the folder, runs git init and installs. I checked harness.py and harness.md: install today refuses unless the target is empty (_refuse_unless_empty), the documented contract is that every refusal writes nothing and that core arrives from a fresh clone, never a working tree, and the README promises that the scripts refuse rather than overwrite. The new mode breaks all of these, and the draft prices it only as "a branch with tests, a line in README" and a recoverable by re-clone risk. The draft also rests on the claim that deletion is something the agent lacks rights to while the script has them; that was observed only as an auto-mode block of the agent's own deletion, and nothing shows the same classifier lets a script of the same effect through, nor was it weighed that routing a blocked deletion through a script is the thing such a guard exists to stop. Other parts (the README wording, the tangle with q-0031, the flag name, the cleanness check) are local detail settled later without changing the commitment. The unexamined premise decides whether the shape works at all and what the installer promises, so it passes the load-bearing test.
