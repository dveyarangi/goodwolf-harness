PART: The proposed in-place conversion has the installer delete the very work tree it runs from, and with a flag overrides the standing refusal that the origin is never installed into. That is a destructive, boundary-crossing operation, and it is also a way to do through a script the deletion the host's permission mode just blocked for the agent. The draft does not examine this, or the non-destructive way the question's own record points to: the install needs no clone to read from, because the script clones afresh.

CONTRACT CHANGE: --install stops being a write-only-into-an-empty-or-clean-target operation that refuses the source repo. It becomes an operation that can wipe a tree, drop .git and re-init. That changes what the installer promises ("writes nothing if it refuses"; target is never the source), what the refusal text means, and who holds the delete authority (the script, not the host-gated agent). Once examined, the contract could instead be non-destructive. One such shape: the installer or skill treats a pristine clone sitting at the target as a state to relocate or re-seat, or the clone is steered elsewhere by other means. The "restorable by re-clone" risk claim also fails for unpushed commits, stashes and ignored files in a developer's own clone, which this project's own author works in.

REASONING: The draft commits to a shape: a new explicit installer flag that, on a clean clone whose HEAD equals the repo commit, clears the tree, runs git init and installs core, with a README line and a refusal line. I checked harness.py. `_work_tree_root` refuses a target whose origin is the source, with the message "the origin is never installed into". `_initialise_if_empty` is described as the run's one write outside the manifest. The shape therefore overturns a deliberate invariant and adds the installer's first deletion of pre-existing content. I also read the question record q-0018.0020 and the README. The record says the install needs no clone to read from and the clone's only use is to hold the script and skill, which suggests the draft's premise that the clone must be converted in place has not been tested against simpler shapes. The draft weighed only "convert in place" against "teach a different phrase". It did not weigh relocating, re-seating or leaving the clone alone, and it did not examine that a script can bypass a host-level delete guard. Changing those things would alter the installer's contract and what depends on the refusal, so this is not local detail. Uncertainty: the draft does mention an explicit flag, a cleanliness check and the cost. The tests and wording would be local, but the destructive boundary and the alternative of using the clone as-is are not.
