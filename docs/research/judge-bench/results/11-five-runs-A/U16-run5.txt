PART: The draft's Cursor row rests on an implied absence, that no Cursor hook besides sessionStart can place the window in the agent's context during the session, and that absence does not hold.
CONTRACT CHANGE: Cursor's row in the matrix and the "dynamic surface for the window" decision change. Cursor's hooks docs list `additional_context` on `postToolUse` and `postToolUseFailure`, and `followup_message` on `stop`. A hook can therefore deliver a per-turn window, after the turn's first tool result or as a follow-up turn, instead of leaving the window to the AGENTS.md rule. The decision would then be "which Cursor event carries the window and with what latency, and is that delivery before the reply". That changes what "the same hook everywhere" promises, what the shared subset is, and what the rule's "if already in context" clause has to cover. It also changes the registration story, because the tag must reach the agent for it to call anything itself.
REASONING: The draft commits to wiring all three hosts through one `questions.py --hook`. Codex gets `UserPromptSubmit` injection, while Cursor registers at `sessionStart` and "the window on every message" is left to the rule. I checked Cursor's current hooks documentation and found that `beforeSubmitPrompt` cannot inject, as the draft says. But `postToolUse`, `postToolUseFailure` and `stop` can add context or a follow-up message, so "only sessionStart can add context" is wrong and the Cursor row is built on it. Examining this changes the host-neutral contract: when the window is delivered on Cursor, and whether the Cursor hook table needs more events than `sessionStart`. It is not a local detail, because the table row, the dynamic-surface decision on the ticket and the shape of the Q1 clause all depend on it. A related risk is that if `sessionStart` injection fails, the agent never learns the conversation_id tag, and `/recall`'s `--wake` mints a second registration. The draft names injection as unconfirmed but does not treat that as changing the Cursor row. The unconfirmed Codex trust and desktop-hooks questions pass the counter-test. They are flagged, to be settled by live observation, and do not change the shape.
