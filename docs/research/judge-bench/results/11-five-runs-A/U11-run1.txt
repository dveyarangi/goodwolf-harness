REASONING: The draft commits to a plan for the front-page ticket whose one structural choice is to read the root LICENSE separately from the `git archive` of the core directory, entry file and host stub, and to skip it when a ref has none. I checked harness.py: `Source.files` passes `CORE, ENTRY_FILE, HOST_STUB` to one `git archive` call and raises Refused on a non-zero exit, so a missing pathspec would indeed break every existing ref. The rest of the pipeline is keyed on a path-to-text manifest: the `_write` deletion pass, the `_differs` and `_refuse_unless_updatable` edit check against the earlier ref, and the install's `_refuse_unless_empty`. A `.agents/LICENSE` key therefore flows through all of them unchanged, and a ref with no license leaves the key out of `previous.files`, so nothing is compared or deleted. The shape check reads only `.md` and non-test `.py` files, so a bare LICENSE does not touch the parts tables or the shape check. The one real hazard, an update overwriting a project's pre-existing `.agents/LICENSE` because `--update` does not check collisions for newly shipped files, is named in the draft. It is a gap that applies to every newly shipped file and not only this one, and it already has an owner (.0150's collision work). Settling it later does not change what this slice promises. Other candidates, such as the release publication in .0190 and the manifest wording in harness.md, can be settled locally without changing the contract.
