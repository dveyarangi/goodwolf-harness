CONTRACT CHANGE: The shape of a closed question's answer and of `due` changes: either the answer must address the individual line (a per-line anchor the mover carries across each move up the ancestor chain) or landing a line must rewrite every answer that cites it, or `due` must chase a pointer chain child -> list -> final home. Today `due` calls an answer landed when no link cites the owner record (questions.py, `due`), so a link into a parent's question body would count as already landed unless `due` is redefined; and a decided answer must be a resolving link to what decided it, so a question body would be standing in as the home. That alters what "decided" means for dogs bound to such a question.
REASONING: The draft commits to moving the guard from the ticket to `close`: refuse while a line has no `->`, move the line to the nearest open ancestor, root closes only when everything has landed, and the closed answer points at the list so that `due` does not fire. I checked the store script: a decided answer is "a link to what decided it", resolved by file and heading anchor only, and `due` treats an answer as landed when none of its links cites the owner ticket. Under that code a link to a parent question's `#decisions` would make `due` true at once, the opposite of what the draft wants, so `due` has to be redefined, and with a heading-level anchor it cannot tell which line is meant once the line moves up again or lands, because the heading outlives every line under it. This is a pointer-maintenance and dog-firing contract across the mover, the answer format and `due`, not a local detail.
