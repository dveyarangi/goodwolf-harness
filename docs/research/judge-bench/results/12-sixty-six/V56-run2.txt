PART: The proposal's whole safety argument is that a wrongly auto-ended live session is revived by any message of its session, but Cursor (a host the tree supports) has no per-message hook at all, so the revive path does not exist there.
CONTRACT CHANGE: The "ended is reversible, so no human is needed" promise holds only for hosts with a message hook (Claude Code, Codex). For Cursor sessions an automatic close would be permanent until a manual restart: the session drops out of other sessions' "other running sessions" lists and collision view, and its row stays wrong. The rule must then be per-host (or closing must stay human-gated for Cursor), and the message-hook revival, including refreshing the "last wrote" date that the silence test reads, becomes a host-specific contract rather than a universal one.
REASONING: The draft commits to a mechanism: the wake script auto-ends running rows silent for more than N days, and a message hook flips a row back to running. Its stated justification for dropping "only a person can tell" is that a mistaken close self-heals at the session's next message. In the tree's questions.py, the HOSTS table gives Cursor messages=None (only sessionStart and preCompact hooks are registered in .cursor/hooks.json), and the code comment says its prompt hook can only allow or block. Only _started revives an ended row, and only on session start, resume or compact; the message path just draws the window and never touches the row. Even for Claude Code and Codex the draft's change would need new write behaviour on every message, and "last wrote" currently updates only on a write such as `at`, so a live session working in one question looks silent. The threshold N, the ticketing choice and the manual closes are local detail and pass the counter-test. The Cursor gap does not, because it undoes the reversibility premise that the whole decision rests on and changes which hosts the rule can cover. I checked this directly in the tree's hook configs and in questions.py.
