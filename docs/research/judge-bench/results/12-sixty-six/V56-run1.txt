PART: The proposal rests on "a wrongly closed live session revives itself at its next message, so no human is needed", but that revival does not exist on every host (Cursor has no message hook) and the wake closing other sessions' rows breaks the sessions file's single-writer-per-line contract.
CONTRACT CHANGE: The sessions file's promise changes from "each session writes only its own line" to "any wake may rewrite any line". Revival is no longer a universal guarantee, so "ended" can no longer be trusted as a resume offer for sessions on hosts without a per-message hook. Auto-closing then needs a host-dependent rule, a different silence measure, or a different owner for closing. The reversibility argument that removes the human also changes.
REASONING: The draft commits to a shape: the message hook revives the session's own row, and the wake script closes other sessions' rows that have been silent more than N days. Its justification is that closing is reversible, so "only a human can tell" no longer applies. I checked questions.py. The Cursor host has messages=None, so a Cursor session gets no message-time revival, and a closed live Cursor row stays ended. The code and docstring also state that each session replaces only its own line and that the sessions file is outside the interference recheck. A wake that closes other rows is a cross-owner write using whole-file read-modify-write, which departs from that invariant. The draft's N-day threshold ("2 days") and its closing of five rows by hand are detail. The cross-owner write and the revival premise are not detail, because they change the contract (who may write rows, what "ended" and "running" promise) and the removal of the human check depends on them. The decision list asks about N, a ticket and manual closes, and never raises these premises. The row's date is also "the date it last wrote", not the last message, which makes "silent" itself unexamined, though that part could be settled locally.
