REASONING: The draft commits to a bounded fix of the installer's loader-link step: create the replacement under a temporary name and swap only on success, keep a link whose own text is correct, report why a link was repointed, add tests, and add one doc sentence. I read harness.py in the tree. The only place the installer deletes a link is the `repoint` branch of `_make_links`, which calls `_remove_link` before `os.symlink`. The core manifest is only `.agents/`, `CLAUDE.md` and the license, so the manifest-removal loop cannot reach `.claude/skills` or `.cursor/skills`. That makes the fix cover the one deletion path the code has, and its main promise (a refused creation leaves the old link standing) holds whatever judged the link `repoint`. I considered three weak points. First, the unproven cause, and the "last modified 23:51" evidence, which is confounded because the injector also writes `.claude/settings.json` and `.cursor/hooks.json`. The draft itself says the cause is unproven and that the fix does not depend on it. Second, whether a swap onto an existing directory symlink works on Windows. That is an implementation detail of the replace step, and the draft says the swap path is untested here. Third, the spec records that the user ruled repointing a link that resolves elsewhere correct. The fix preserves that and only changes the order of operations, so the boundary does not move. Each of these can be settled later and locally, so none changes what the draft commits to.
