REASONING: The draft commits to one shape: an explicit installer flag that, on a clean clone whose HEAD equals the repository's commit, wipes the tree, runs a fresh git init and installs core in place, with one line each in the README and in the "source itself" refusal. Its premises hold in the tree and the exchange. The agent cloned before reading anything, and the earlier turns record that deletion was blocked. The installer already refuses a target that is the origin (harness.py, _work_tree_root), which is the exact seam the flag overrides. The record also says the install script clones the repository afresh and needs no clone to read from, so removing the clone does not remove the install's source. Candidate parts I considered: (1) whether the host's auto-permission mode would also block a script that wipes the tree. That is plausible, but if it does, the person is simply asked, so it affects whether the mechanism runs smoothly and not what it promises. (2) The invariant that the origin is never installed into. The draft keeps it behind an explicit flag plus clean-and-pinned checks and names the residual risk of a developer running it by mistake, which is recoverable by re-clone. (3) Windows details such as a running script deleting its own directory or an in-use cwd. These are implementation detail inside the contract. (4) Alternatives to the flag. The draft names the other-phrase option and the README-only option and gives reasons against them. None of these would change the contract, the boundary or what depends on it, so each passes the counter-test.
