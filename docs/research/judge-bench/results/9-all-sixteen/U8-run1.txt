PART: The draft rests on the premise that moving the deletion into the installer script escapes the host's block on deleting (the agent "needs to delete nothing, the script has the rights"), and on the premise that a clean clone at the origin's HEAD is safe to wipe. Neither was examined: the script runs as the agent's own command, so the same auto-permission gate that refused the delete can refuse a command whose purpose is wiping the tree, and a flag built to route around that gate is itself a boundary decision about who authorizes a destructive act. HEAD equal to the origin's commit says nothing about local-only branches, stashes or ignored files in a harness developer's own clone.
CONTRACT CHANGE: If the host gates the script as it gated the delete, the in-place conversion does not remove the failure and the shape does nothing for the dominant path. The conversion would then need the person's own authorization or action (the person confirms or deletes) rather than an agent-run script flag. If the wipe guard is unsound, the installer's "the origin is never installed into" refusal, which protects the harness developer's tree, cannot be lifted by one flag. The guard would have to cover every state a clone can hold that the origin does not, or the conversion would have to leave the tree alone and install elsewhere. The draft's stated cost ("restorable by re-clone") is false for those states.
REASONING: The draft commits to a new installer mode, `--install --replace-clone`, which wipes a clean origin clone sitting at the target, runs a fresh git init and installs core. It also commits to a README line and a refusal line. I checked the installer: `_work_tree_root` refuses a target whose origin is the source, and the installer already clones the repository afresh into a temp dir, so the on-disk clone is only a carrier for the script. That makes wiping it the one destructive step, and the draft's whole benefit depends on that step passing a gate that already blocked the delete in two runs. The draft asserts the script "has the rights" without evidence. A command the agent launches does not carry rights of its own, and an auto-mode gate judging a flag named for replacing the tree is not shown to let it through. The risk statement for developers is also wrong in the case that matters: a developer's own clone with HEAD at the origin's head, but other local branches or a stash, loses work that a re-clone does not restore. Both premises decide whether the shape works and who may authorize the deletion. Putting the choice to the person leaves them unexamined. Details such as the flag name, the test, the README wording and how a running script deletes its own files on Windows are local and pass the counter-test.
