## The agent's draft reply

Mostly yes. Moving and keeping is what decision 34 already says, and decision 24 already makes a decided entry's answer a link to the deciding doc, ADR or code, with who decided and when. So your first message and this one agree on the important part: the answer is the doc or the code, and the entry only points to it. **Decision 34 stands unchanged.**

**One correction: the window can't include `done/`.** The window is the few dozen lines the agent reads on every message. It is kept small on purpose (decision 26): the window test found that reading a whole store stops silently at about 10,000 entries and answers anyway. `done/` will grow into the tens of thousands. So `done/` is reached by searching, not by the window. When a message looks like it asks something already closed, the agent searches `done/` titles and follows the answer link to see how it was settled. Each file's first line is its id and title, so plain grep does the job and no new script mode is needed. This is decision 29's search, and the parent ticket's walkthrough already has it ("found by title search and treated as a reopening").

**The gap your point found:** nothing currently checks that the answer really is a reference. The RFC makes every bullet optional except `state`. The writer refuses to close a question without its pointer, but `--check` never verifies that a decided entry's answer is a link, or that the link still resolves after the move to `done/`. Without that check, `done/` can fill up with prose answers or dead links, which is exactly what you want to avoid.

### Question 2

Should `--check` report these as diagnostics, meaning they fail the run?

- a closed entry with no answer;
- a *decided* answer that isn't a link, or a link whose file or heading doesn't exist, checked in both the live store and `done/`;
- a *merged* or *superseded* answer naming an id that doesn't exist (already covered as an orphan).

*Pruned* and *moot* keep a one-line reason, since a dead end has nothing to point to. If the reason deserves more than one line, it goes to the owner's record, and the answer links there instead.

**My recommendation: yes.** It's the smallest addition that makes `done/` trustworthy, and it lands in stage 1, which is the stage that builds `--check`. The alternative is to rely on the writer's refusal alone. That's cheaper, but it doesn't catch links broken later when a doc is renamed or a heading changes, and those are the links `done/` depends on.
