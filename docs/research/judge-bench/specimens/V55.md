## What the code does

- **The decision** ([harness.py:696](.agents/scripts/gw/harness.py:696)): an existing symlink is `keep` only if it resolves to the tree's `.agents/skills` and is a directory. Anything else, including any error while resolving, becomes `repoint`.
- **The damage** ([harness.py:713](.agents/scripts/gw/harness.py:713)): `repoint` deletes the old link first, then tries `os.symlink`. Without symlink privilege that fails, the link is reported `pending`, and the old one is already gone.
- **No coverage**: no test and no doc mentions `repoint` at all. It is the one branch of the link step that destroys something, and nothing exercises it.

## What I could not establish

I can't tell why your links were judged `repoint` rather than `keep`, because they are gone. In xuanxue-workshop both `.claude/skills` and `.cursor/skills` are now absent (removed at 23:51). The likely candidates are:
- the links were file symlinks rather than directory ones (made without `/D`), so the "is a directory" test failed;
- resolving them raised an error, which the code silently treats as "points elsewhere".

If you still have the update's report, the `links` entries would say `pending` with the OS error, but not the reason for the repoint. That reason is never reported, which is a second gap.

## Fix I'd make

1. Never remove before the replacement exists: create the new link under a temporary name, and only then swap it in. If creation is refused, leave the old link standing and report `pending`.
2. Say in the report why a link was judged `repoint` (where it pointed, or the error).
3. Add tests for the branch: a correct link is kept, a wrong one is replaced, and a refused creation leaves the old one in place.

## What remains possible

A link is judged `repoint` only when one of two things is false at that moment ([harness.py:827](.agents/scripts/gw/harness.py:827)):

- **It resolves somewhere else.** For example, a full-path link made when the tree lived at another path, or one pointing at a different checkout's `.agents\skills`.
