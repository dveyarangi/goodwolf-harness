## 2. Дрифт со строками сессий

**Можно ли было просто закрыть.** На пробуждении — нет, по двум причинам:
- `/recall` по своему правилу только сообщает о дрифте и ничего не чинит. (💡 [*recall: report drift*](.agents/skills/recall/SKILL.md:24))
- Механизм вопросов прямо говорит: молчащая сессия может быть жива, отличить может только человек. Скрипт сообщает о строке только после недели молчания и сам ничего не закрывает.

И это не формальность. Из десяти строк, что я назвал, две оказались живыми: 5fba085e и 01a1227f писали сегодня. Три id сессии 46 тем временем закрыл её собственный `/conclude`.

**Правило из `/maintain`, установленное в `/recall`, предлагаю не делать.** Файл сессий — запись механизма вопросов, не `/maintain`. А скрипт пробуждения и так запускается при старте каждой сессии, раньше, чем агент что-либо прочтёт. Значит, закрывать может скрипт: без правила для агента и без места в первом уровне инструкций, за который платит каждая сессия. (💡 [*Mechanical by construction*](.agents/skills/mechanism/SKILL.md:101))

**Что этому сейчас мешает.** Мешает только «отличить может только человек». Это снимается, если сделать закрытие обратимым. Сейчас строка снова становится running при старте сессии и при её собственном `at`, а от сообщения пользователя — нет. Если и любое сообщение будет её оживлять, то ошибочно закрытая живая сессия вернётся сама при следующем сообщении, и человек не нужен. (💡 [*Occam*](AGENTS.md:32))
