## The agent's draft reply

The plan for the front page is written, in [its RFC](docs/rfc/01-0010.0167-the-front-page-says-what-the-harness-is.md). Nothing is committed.

**The one real design catch:** installs can't copy the license by simply adding `LICENSE` to what gets archived. `git archive` fails outright on a path that doesn't exist in a version (I ran it: exit 128), and no existing version has a root LICENSE. So that would have broken every existing tree's update and check again, the same failure as the one we fixed earlier. The plan reads the license separately and skips it when a version doesn't have one. Everything else (install, update, check, deletion) handles the file with no new code.

**What landed alongside the plan:**
- **The license decision is in the durable docs.** [architecture.md](docs/architecture.md) and [harness.md](.agents/mechanisms/harness/harness.md) now say: one home at the root, installed as `.agents/LICENSE`, and a version without one ships none.
- **The agreed README text now lives in the RFC.** The ticket's format check rejected it inside the ticket, because the checker counted the page's `##` headings even inside a code block. That's a small checker defect worth fixing another time. The ticket keeps the decisions and the bindings table.

**Four stages:**
1. Tests first, then the code change:
   - an install places `.agents/LICENSE`, byte-identical;
   - the project's own root `LICENSE` is left alone;
   - an update carries a changed license;
   - `--check` catches an edited one;
   - an old version with no license still installs and updates;
   - an install refuses when the project already holds `.agents/LICENSE`.
2. Docs: the harness skill's line, and the harness doc's note on why the license isn't a row in its parts table (it lives at two different paths).
3. The README, and the straw-dog listing extended to it, so all eight "not yet" items are listed.
4. Live check: how GitHub actually renders the straw-dog tags, and a real install from the pushed version.

**Hidden risk, not this slice's to fix:** an update writes a newly shipped file over whatever a project already has at that path. An install checks for that; an update doesn't. Neither of your real projects has an `.agents/LICENSE`, and the gap belongs to .0150's collision work.
