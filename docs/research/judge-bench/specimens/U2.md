🧩 **Proposed change — the questions mechanism, a third relation**

> **Rests on.** A part `rests on` on an entry, a list of ids: its answer — or its lean while it is open — holds only while each listed question's answer or lean stands. It orders nothing, so it never blocks and may run in a cycle. The agent writes it with `rest q-A --on q-B` in the turn that writes an answer or lean taking another's as given, and removes it with `unrest`. When a question closes, closes again with another answer, or is marked suspect, every call that does it prints the questions resting on it; the agent reads each and marks suspect those whose assumption broke, one step at a time. A reword fires nothing. The check reports a closed entry resting on a question closed superseded, pruned or moot that is not itself suspect.

**Кто субъекты.** Ответы. Сам вопрос ничего не предполагает, предполагает его ответ. Если вопрос ещё открыт, предполагает его lean, то есть текущая позиция. Пример:
- Вопрос «Для чего проект?» сам по себе ни на что не опирается.
- Ответ «харнесс для работы с coding agents» опирается на ответ ландшафта «агенты уже пишут код, а человек теряет ведение».

Если ответ ландшафта изменится, под подозрение попадёт ответ о назначении. Сам вопрос о назначении остаётся тем же.

**Чем это отличается от depends on.**

| | depends on | assumes |
|---|---|---|
| между чем | вопросами | ответами |
| когда появляется | до любого ответа | в момент, когда пишется ответ или lean |
| что значит | этот вопрос нельзя толком задать, пока тот не отвечен | этот ответ верен, пока стоит тот ответ |
| блокирует | да | нет |
| когда исчезает | когда его снимают | вместе с ответом, который её создал |
| пример | «Какая БД?» depends on «Какие данные храним?» | ответ о назначении assumes ответ о ландшафте |

Последняя строка — главный выигрыш твоей поправки. Новый ответ заново называет свои допущения, поэтому устаревшая связь не может пережить ответ, который её сделал (💡 *Occam*).

**Что из этого следует.** Связь фиксирует, на какой именно ответ того вопроса опирались. Тогда изменения находит скрипт, а не память агента: «ответ A опирался на ответ B от такого-то числа, а у B теперь другой ответ». Сломалось ли допущение на самом деле, по-прежнему решает агент. Слово тогда — `assumes`: у него подлежащее — ответ.

Одна честная оговорка. В depends on уже есть немного assumes: проверка store жалуется на закрытый вопрос, если тот, от которого он зависит, снова открыт. Так что зависимость по построению — тоже допущение. Обратное неверно.
