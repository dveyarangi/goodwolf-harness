Let me say it more simply.

**What happened.** When the app reopened our conversation, it gave it a new number: it had been `58bf3b88` and became `d0abdc88`.

**How the store is supposed to notice it's the same conversation.** The app keeps a log of each conversation in a file. On resume it writes a new log under the new number, and that log begins with the same messages as the old one. Our script compares the two, sees the shared opening, and concludes: same conversation, keep the old position.

**Why it didn't work.** The script compares only once, at the instant the conversation opens. At that instant the app hadn't written the new log yet; it appeared about three seconds later. The script found no file and decided this was a new conversation. After that it never checked again.

**What that cost.** The old record hung around as "still running", and the new one started from nothing, with no position. Its first answer also told me "you're new, run recall from scratch".

**The fix.** Have the script check again on the next messages, while the "new" conversation still hasn't done anything. By then the log exists, the script will see they're the same conversation, and it will carry the position over.
