The place q-0037.0017.0005 decided on — one, read by a fast script at every step, for a
session's messages and the others' positions, by ways a network carries — needs a substrate.
What goes into it is q-0037.0017.0005.0001's, which waits on this one.

## What bounds it, 2026-10-25

- **Every step**: the hook runs at every message within a 30-second timeout; the window must not
  wait on a network to be drawn, and a failing prompt hook can hold back the person's message.
- **Python's standard library** is what core may require (objection 20 of
  [meeting-run4-objections.md](../research/meeting-run4-objections.md)); `sqlite3`, `urllib` and
  `http.server` are in it.
- **Measured on this machine**: `git ls-remote origin` to GitHub, 870–905 ms a call; the
  interpreter's start and one exclusive file create, about 525 ms, nearly all of it the start.
- **The cases**: xuanxue-cabinet's worktrees and sibling clones, and live-spec's lanes, are each
  on one machine; no recipient yet runs sessions of one project on two machines.
- **An id given once**: reserving an id needs an atomic act — an exclusive create, a transaction,
  or a compare-and-swap such as git's refusal of a push that is not a fast-forward.
- **A git ref, measured in a scratch repository** on this machine: a ref outside `refs/heads/`,
  written in one worktree, is read at once in another, both sharing the clone's Git directory;
  `git update-ref <ref> <new> <old>` refuses when the ref no longer holds `<old>`, so a second
  worktree's reservation of the same ref failed; from Python a `for-each-ref` takes about 87 ms
  and a batched read about 77 ms. Between clones and machines a ref travels only by a push and a
  fetch of its namespace, which git does not fetch by default.
- **Which script holds the place's contract** bears on it: the direction is decided in
  q-0037.0006.0024.0003 — the session sits on the store, which imports nothing of it — and the cut
  deferred while the store, the session and maintain install as one package, the code staying as
  it is ([session.md](../../.agents/mechanisms/session/session.md), *Delivery*; the user,
  2026-10-26). The rows' code is free to change meanwhile; the place's reads and writes go behind
  the session script, the side the cut will leave them on.

## Decisions

1. **Two machines per project, a local mode first** *(the user, 2026-10-25)*: sessions of one
   project will run on two machines; the place starts in a local mode and grows into the
   networked one.
2. **Not a folder outside the tree, not SQLite, not a server** *(the user, 2026-10-25)*: neither
   of the first two fits; a server is too heavy.
3. **A git ref carries it, to begin with** *(the user, 2026-10-25)*: the place is a namespace of
   refs outside `refs/heads/` — in the local mode read and written through the clone's Git
   directory, which its worktrees share; between clones and machines carried by a push and a
   fetch of that namespace. Taken to start with; the networked mode is thought over further later.
