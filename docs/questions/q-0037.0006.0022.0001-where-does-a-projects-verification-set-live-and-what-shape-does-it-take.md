## Decisions

1. **The local rule names where the checks are stated, never copies them** *(the user,
   2026-10-14)*: a project states its checks in its own tooling — a CI file, a `Makefile`, its
   package scripts — and its verification-set rule names the file to read for them, plus what no
   tool states, such as a check run by hand. A list of commands in the rule is a second home that
   drifts from the first: meteoscape's rule copies its CI. The harness's record checks are core's
   own and not the project's to list. Where the rule is installed — the one moment before work
   lands, against the three skills it is copied into now — is still open.
