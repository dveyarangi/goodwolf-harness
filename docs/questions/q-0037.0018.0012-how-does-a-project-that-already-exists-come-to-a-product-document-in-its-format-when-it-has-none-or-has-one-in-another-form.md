# q-0037.0018.0012 How does a project that already exists come to a product document in its format, when it has none or has one in another form?

The user: *if the mechanism is installed into an existing project, the file is either absent or
not in the format — we have to take care of it.* It follows from decision 11 of q-0037.0018 as
amended that day: installed, the mechanism creates the document, so its rules carry no condition.

## Cases

1. **No document, and nothing written about what the project is for** — an empty document in the
   format, as the install already writes the store's roots and the delivery status when absent.
2. **No document, but the purpose written elsewhere** — a README, a vision or a PRD: existing
   material, the case [01-0010.0175 arrival-describes-what-it-finds](../tickets/01-0010.0175-arrival-describes-what-it-finds.md)
   reads into a glossary and an architecture skeleton. That skeleton's *Purpose* section overlaps
   the product document.
3. **A document at the path in another form** — the project's file, which an update never
   replaces ([01-0035.0030](../tickets/done/01-0035.0030-an-update-never-replaces-a-file-the-project-owns.md)).

## Decisions

1. **The install writes only what needs no judgement** *(the user, 2026-10-14)*: with no document at
   the path it writes an empty one in the format; a document in another form it leaves as the
   project's and reports, and the check says it is not in the format instead of passing in silence.
   Bringing an existing account into the format — numbering and naming answers, which are decisions —
   is the person's and the agent's, the same recipe as reading a tree's existing material into its
   glossary and skeleton. An install cannot tell whether the purpose is written elsewhere, so case 2
   gets the empty document too, filled when that material is read.
   → [the product mechanism's moments](../../.agents/mechanisms/product/product.md)

## Impact of the split, 2026-10-14

The draft: **(1)** a new AFK slice of 01-0040 — an install or update writes an empty product
document where none is, leaves one with no answers table untouched and names it in its report, and
`product.py --check` fails such a document as not in the format; **(2)** a re-cut of
[01-0010.0175 arrival-describes-what-it-finds](../tickets/01-0010.0175-arrival-describes-what-it-finds.md):
its reading of a tree's existing material drafts the product document as well, the person naming
the rows, and the skeleton's *Purpose* goes there instead of into the architecture; `/product`
gains the act of bringing an account in another form into the format, which a failed check sends
the agent to.
