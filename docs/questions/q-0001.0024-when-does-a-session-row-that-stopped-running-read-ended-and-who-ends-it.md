# q-0001.0024 When does a session row that stopped running read ended, and who ends it?

- **part of** q-0001
- **state** open
- **owner** [01-0011.0100.0060](../tickets/01-0011.0100.0060-a-silent-session-ends-at-the-next-wake.md)
- **struck** 0, last 2026-10-09T22:36Z

Raised by the user at the wake of 2026-10-10: the wake read ten rows as running, most silent since
2026-10-07 or 2026-10-08, and `/recall` reported them as drift — *could it simply have been
closed? then probably on every wake.* Today a row ends only at its own `/conclude`, at a resume
under a new id, or by hand; the script reports a running row silent for more than a week and ends
none, since *a silent session may be alive, and only a person can tell*.

What changes that: a row already turns running again at its session's start and at its own `at`.
If every message of the session turned it running too, ending a silent row would be undone by the
session's next message, and no person would be needed to tell. Then the wake's script could end
every other row silent past a threshold itself — no agent rule, nothing installed into `/recall`
or `/maintain`. Open: the threshold, and whether a row ended while its session sits idle costs
anything a parallel session relies on.

Why the rule was written so, read in [the store's RFC](../rfc/done/01-0011.0100.0010-the-store-and-questions-writes-it.md)
(2026-10-02): a session's only sign of life was its own `at` — the hooks that now draw the window
before every message did not exist yet — so an ended live row stayed wrong until that session
moved; and each session writes its own line and no other, so two sessions' writes never meet.
The first reason lapses once drawing the window turns the row running: Claude Code's and Codex's
message hook draws it every turn, and Cursor's agent draws it by the rule. The second still holds and is bent only for a
row whose owner has been silent past the threshold, where no write of its own can meet the wake's;
the rest is [q-0032](q-0032-how-do-sessions-running-at-once-in-one-tree-keep-from-overwriting-each-others-writes.md)'s. The week was a number, not a measurement.

**Decided** *(the user, 2026-10-10)*: a running row silent for **three hours** is ended by the
next wake, **quietly** — the wake names none it ended. The rows serve autonomous agents mostly;
a person running sessions by hand knows which they run and sets priorities regardless, so for them
the rows are noise. The same day, seven rows silent past six hours were ended by hand.

What follows from it: a row holds a date alone, so three hours needs the time it last wrote —
the row's format moves to the entries' `YYYY-MM-DDTHH:MMZ`. Drawing the window turns the row
running again. The format change is agreed *(the user, 2026-10-10)*.

**Who ends it** *(the user, 2026-10-10)*: the wake, `/recall`'s moment, wrapped as a straw dog
bound to q-0034 until a session mechanism takes it.

An autonomous agent can end its own row by a hook when its session ends — Claude Code has a
`SessionEnd` event; what Codex and Cursor give is unprobed. Seen 2026-10-10: the desktop app leaves
`<id>.desktop-released.json` beside a transcript it released, `reason` `delete` — a host's own sign
that a session is gone, readable by the wake.
