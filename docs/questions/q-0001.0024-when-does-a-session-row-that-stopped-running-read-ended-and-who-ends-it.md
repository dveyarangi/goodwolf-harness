# q-0001.0024 When does a session row that stopped running read ended, and who ends it?

- **part of** q-0001
- **state** open
- **struck** 0, last 2026-10-09T22:36Z

Raised by the user at the wake of 2026-10-10: the wake read ten rows as running, most silent since
2026-10-07 or 2026-10-08, and `/recall` reported them as drift — *could it simply have been
closed? then probably on every wake.* Today a row ends only at its own `/conclude`, at a resume
under a new id, or by hand; the script reports a running row silent for more than a week and ends
none, since *a silent session may be alive, and only a person can tell*.

What changes that: a row already turns running again at its session's start and at its own `at`.
If every message of the session turned it running too, ending a silent row would be undone by the
session's next message, and no person would be needed to tell. Then the wake's script could end
every other row silent past a threshold itself — no agent rule, nothing installed into `/recall`
or `/maintain`. Open: the threshold, and whether a row ended while its session sits idle costs
anything a parallel session relies on.
