## Where it stands — 2026-10-23, the align opened

**The work.** 01-0010.0220 lets a project's settings decide which of the method's rules its tree
carries. A setting changed through the agent's call runs the installer at once. This question is
the other path: the person edits the local file by hand — the dial is theirs, and today every
setting is set that way — and starts a session. Until the installer runs, the tree's installed
blocks say one thing and its settings another.

**Necessity gate.** Customer: the person of any recipient tree, this one included. Problem: a
tree whose entry file still shows debugging after its person switched it off, or shows the dial at
yesterday's rung. Why the existing behaviour cannot satisfy it: nothing runs the installer but
being asked, `harness.py <target> --update`; `/maintain` would find the mismatch as drift, at its
own pace. The need holds while settings are edited by hand at all.

**Facts that bear.** The session-start hook (`hook.sh` → `questions.py --hook <host>`) already
writes the tree at session start — the store's session rows — and by the hosts edge's invariant
exits clean whatever happens, a problem becoming a line of context; it has never written an
instruction file. The installer refuses what it cannot satisfy and reports it (`harness.py`,
*refuse what cannot be satisfied*), which wants a reader. A session whose entry file moved under
it is told and reads it again (01-0018.0010, Ready). Two sessions may start in one tree within a
minute (the sessions list).

**The shared assumption of the fork below**: that a setting is changed by hand at all. The
alternative dissolves it: the call is the one way — the person runs it too, in a shell, since the
host refuses only an agent's call on a person-only setting — and a hand edit is drift for
`/maintain`. Put first.

**Fork — who runs the installer after a hand edit, and when:**

- **A. The hook runs it at session start.** Always matching, no step. Against: a hook writing
  instruction files silently, before any agent exists; its refusals have no reader and must
  still exit clean, so a half-applied tree goes unsaid; two starting sessions race on the same
  files; whether the host reads the entry file before or after its start hook is unverified.
- **B. The hook reports, the session's first act runs it** — recommended. The wake says the
  settings moved; the session runs the installer before its first reply, below the dial, says
  so in one line, and the change lands in its first commit; the installer's refusals reach a
  reader; the hosts edge keeps its invariant — the hook reports, never repairs. Against: a host
  without a start hook leaves it to `/recall`'s own check.
- **C. Nothing runs unasked.** The wake says *settings changed; run the update*, and the person
  says so. Against: the person already acted by editing; a second step is weight the work does
  not need, and the tree reads wrong until it is taken.

Decisive fact for B over A: the installer refuses and reports, and a hook has no one to report
to; for B over C: the hand edit was the ask.
