### Hidden edges

- **A hook that never fails the host** is the hosts edge's promise and `hook()`'s docstring; a
  guard refuses by design, so its failure semantics — a declaration unreadable, the store of loads
  missing — must be decided: fail open, as every hook today, or closed.
- **Where a load is written.** The session rows under `docs/sessions/rows/` are tracked in git, 23
  of them; a load written there on every skill call is churn in every commit. A load is the
  context's state, gone with the session, which points at something untracked beside
  `gw-interpreter` in the Git directory.
- **Records written by script.** Session rows, a question's parts and the store's moves are
  written by scripts, not by hand; the commit check would ask for a skill at every commit that
  stages them. The table needs a row that declares a record with no skill.
- **Subagents.** A subagent does not see its parent's skills; if its hooks carry the parent's
  `session_id`, its edit passes on the parent's load.
- **The reply's header** that the reply check reads is the reply-layout rule's, a straw dog under
  q-0037.0009.0021 that another session is reworking.
- **Rollout.** Claude Code reads a project's `settings.json` mid-session: the guard landed here
  turns on at once for every running session, five today; and every recipient takes it at its next
  update, its agents then refused on its tickets and questions until they load the skills.

### Leave alone

The wake and window hooks and their answers; the store's and the tickets' own checks, which hold
form and stay at `/verify`; the 15 skills with no mechanism, beyond their instruction files.

### Recommendation

Proceed with the split. The tracer is narrow enough: one record, one instruction class, one host.
Its plan aligns on the hidden edges first — failure semantics, where a load is written, a record
with no skill, subagents, rollout — since each shapes the tracer's boundary rather than a later
slice.
