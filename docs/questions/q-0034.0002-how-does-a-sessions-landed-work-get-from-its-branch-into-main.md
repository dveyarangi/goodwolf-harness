Evidence, 2026-10-12, from the session guarding `--replace-clone` in a worktree:

- A session may work in its own worktree on its own branch —
  [q-0032](done/q-0032-how-do-sessions-running-at-once-in-one-tree-keep-from-overwriting-each-others-writes.md),
  closed: locks are the host's. In this tree one did; the rest share the main checkout and its
  one local main.
- Nothing says how work goes from that branch into main. `/commit` says only *commit to the default
  branch unless already on a branch*; `push=auto` says neither where to push nor who merges.
- PR dveyarangi/goodwolf-harness#5, the guard fix in 2 commits, carried 8 more from local main not
  on origin/main: branching from local main pulled them in, pushing the branch published them.
- A session registered in the main checkout's store cannot use the store from its worktree, whose
  copy of `docs/questions` refuses every call as *not registered*.
- One session's push carried another's work the user had held back. The user asked the guard
  session to merge its branch into local main only, and it made merge `a71028b` there without
  pushing. The session that opened this question then committed `040e052` on that same main.
  Under `push=auto` it pushed main whole, and the merge went to origin with it. That published the
  fix and marked PR #5 as merged. `push=auto` pushes a branch with whatever it holds, so no
  session's push is its own alone once two sessions commit to one branch.

lean, and the id-collision risk deferred in

Here rather than under q-0033.0004: the case arises with one person, not only a team.

The align, 2026-10-12, read the two publishing cases in git's logs. The worktree branch was cut
from local main at `ae968bf`, seven commits ahead of origin; `git worktree add -b` takes HEAD, and
those seven were verified work `push=auto` would have published within minutes — noise in the PR,
no harm. The harm was one held-back merge standing on a shared branch: every session commits to
the one local main, so any session's push is everyone's. A check refusing a push over another
session's commits was weighed and dropped: commits interleave, so it would stall every push, and
it would treat every other session's commit as held back when one was. Separate branches per
session isolate each push, but in one checkout a branch means a worktree, and a worktree has its
own copy of the store: sessions stop seeing each other, ids are minted blind, the hand-bumped entry
contract version conflicts on merge.

The PR as the unit of verified work, the guard session's candidate, waits with separate branches.

- Whatever stands on the shared main may be published; work the person holds back stays on its
  own branch until they release it — the user, 2026-10-12
