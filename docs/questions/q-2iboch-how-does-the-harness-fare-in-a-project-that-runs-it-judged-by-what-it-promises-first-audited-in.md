## The method, 2026-11-27

DriftSense's own audit method, its q-vxes7i, turned on the harness: rounds, a verdict that says
whether it was read, tested or measured, a finding written once per cause. Its audit session's
critique of a first draft, 2026-11-27, is taken in.

**Round 0, the baseline, by script and no reader.** What is already held — DriftSense's
rule-failure register, the 17 lessons it sent core, its 15 local rules — each marked fixed in core
since `ed0f4e1d`, open in core, or not yet sent. The rounds then go where nobody has looked.

**Then one aspect per round,** listed whole, a row for each part, the good ones too. In this order:
1. Cost — tokens, turns and tool calls per session; the share spent on the method's own steps
   against product work; commits by step; messages between sessions, duplicates and unneeded ones.
2. The person's load — requests to explain, words the agent made up, decisions pending and their age.
3. Rules reaching their occasion — the register's strikes, the store's struck counts, fresh readers
   asked what a rule makes them do, overridden rules first.
4. Records about code in sibling repositories — whether a cited line still says what is claimed, and
   what in the harness would notice.
5. Safety — values printed, processes left running, the person's word relayed.
6. Fit — what the project switched off or overrode because a core script could not take its practice.

**The standard is the person's.** Where nothing written says what working means, a round
describes, the person sets the standard, and the next round judges.

**Evidence.** Measured is a script that prints counts, never a transcript's line; read names the
file and commit; tested runs core's checks read-only there. Serious findings are read by two readers
apart, a share of the good ones. Each helper is told which folders it may read, and runs bounded
commands. Not read: transcripts except through that script, `scripts/readonly-db-access-grant.md`,
any `.env`, the product's settings and config files that hold keys, the user's mail.

**What it leaves.** A health record per round; each finding in the core question that owns its
cause, with that zone's session told; a summary to DriftSense's harness session; and a line per round
on what it taught about auditing a project's harness. Polling DriftSense's role sessions, and writing
to its harness session, wait on the person's yes when a round needs them.
