a group name is not an address, so membership must be declared from both ends, the rules file
naming the group and each member declaring what file and anchor the group means *in it*. This
ticket ships on explicit targets and does not wait for it.

## Decisions

1. A rules file names a group by a row of its anchor table whose target is a path pattern —
   `.agents/skills/*/SKILL.md` — and whose anchor is the heading a member holds; a file the pattern
   matches is a member exactly when it holds the anchor, and the rest are passed over, not refused.
   Membership is declared from both ends, the pattern at the mechanism's, the heading at the
   member's *(the user, 2026-10-25; the voice, q-0037.0009.0021.0002, its first consumer)*. Not: a
   named group each member also declares by a mark of its own — a member would declare itself
   twice. Edge: a pattern sees only where it looks; a recipient keeping its own skills elsewhere
   needs a wider pattern or a second row.
