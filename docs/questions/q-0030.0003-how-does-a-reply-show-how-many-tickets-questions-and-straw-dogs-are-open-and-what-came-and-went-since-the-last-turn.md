## Impact — 2026-10-12, one slice

**Impact.** The window, `questions.py --window`, which every host's prompt hook draws and Cursor's
agent draws by the rule: it gains the counters, and its memory outside the tree keeps the names
it counted besides its fingerprint. The entry file's reply rule, q-0030's straw dog, gains the
row. The questions mechanism's doc says what the window prints, so it moves with it.

**Hidden edges.** The window's one-line *unchanged* answer must still carry the counters: a
ticket or a straw dog can move while no entry does. The store already lists straw dogs for the
wake (`question_bindings`); the count reads the same scan, cached per file by its fingerprint so
a turn rescans only what moved. Tickets are read from `docs/tickets/`, a directory the ticket
mechanism declares, so core names no record of this tree. A compaction empties the memory: the
next window counts with nothing to compare, and says so rather than counting everything as come.

**Leave alone.** The wake's report, the store's format, the sessions file, the straw-dog listing's
own output.

**Recommendation.** Proceed as one AFK slice: one script, its tests, one doc and one rule line, no
decision left open.

## The cost, measured — 2026-10-12

On this tree, nothing moved, the window drawn in thirty alternating pairs with and without the
counters, the machine loaded by four other sessions: median 189 ms against 173 ms, a difference of
16 ms in-process. A hook's fresh process also imports the ticket script, 25–35 ms. About 50 ms a
turn in all, within the ticket's tenth of a second. The first draft cost 116 ms: a second `stat`
of every record, which Windows' directory listing already carries, and the memory rewritten on
every turn; both removed. A session's first window reads every record once, about 450 ms.
