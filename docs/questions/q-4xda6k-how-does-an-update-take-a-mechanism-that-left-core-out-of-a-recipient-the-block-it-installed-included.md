## What was found — 2026-11-16

Found by the judge of
[01-0010.0260 a-projects-own-mechanism-is-told-from-a-shipped-one](../tickets/01-0010.0260-a-projects-own-mechanism-is-told-from-a-shipped-one.md),
and older than that work. Where a later ref no longer ships a mechanism that has a rules file,
an update deletes the mechanism's files in a recipient and leaves the block it installed in a
core skill: the comparison takes the block for the recipient's own, because its rules file
stood in the tree and the new ref does not ship it. The gates then fail — the ref, on the skill
that differs, and the injector, on a block nothing owns — with no refusal and the tree already
written. Removing a mechanism from core does it; so does declaring one `local` after it
shipped, which that ticket made a one-line change. Seen ways: tell such a block by the earlier
ref having shipped its rules file, and take it out with the files; or refuse the update and say
which block to retract first.
