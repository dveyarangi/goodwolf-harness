## Align, 2026-10-07

1. **The environment is a mechanism of the method, and the necessity gate passes whole** *(the
   user)*: setting up tooling, the verification set, running the application, the pipeline and
   the account of them are one mechanism. No failure is recorded in setting up tooling because it
   has never been exercised — no install has set up a toolchain from nothing, and none has
   adapted an existing one to the method — so the absence is not evidence against the need.
2. **The environment owns the verification set** *(the user)*: what the set is, its shape, when
   it is declared and how it is kept true as the tooling changes. Acceptance consumes it, as do the
   work and the maintenance pass. No conflict of interest follows: the set measures the work
   produced, never the tooling. The conflict that does exist is the implementer weakening the
   set its work is measured by — a rule on changing the set, not a question of its owner.
3. **The set's home is the project's local rules file, delivered by injection to each skill that
   runs it, and to no document** *(the user, revising the same day an answer that also injected
   it into the document describing the project's engineering)*: an agent can tell the person
   about the environment from the authoritative sources when asked, so no special file is
   needed for it; and a person who reads a copy in a document may try to change it there, where
   it is not authoritative.
