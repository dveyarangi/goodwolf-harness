**The shape leaned on, the user, 2026-10-11** — the project itself to be thought through later:

- **Twin projects from scratch**, one spec, run side by side with and without the harness: the one
  comparison that reaches the harness's own promise, decisions holding across sessions, which a
  single paired task cannot show. Hard to run, the user's attention paid twice.
- **Without the harness is not bare**: a sound `AGENTS.md`, found rather than written here, so the
  comparison is fair. The candidate found: the starter template of GitHub's study of over 2,500
  repositories (Matt Nigh, 2025-11-19) — commands, testing, project structure, code style, git
  workflow, boundaries — filled with the project's facts only, the same facts the harnessed twin
  holds, as an ETH study (Gloaguen et al., arXiv 2602.11988) advises: a human-written context file
  should state minimal requirements, its LLM-generated ones lowering success and raising cost over
  20%. Taken, the user, 2026-10-11, no newer primary source being found: the 2026 guides derive
  from these two, and the study's constraint rides on the template — written by a person, facts
  only, short.
- **The harness version may grow** during the run, recorded at each milestone rather than pinned.

What the design must still answer: the person carrying one twin's decisions into the other, the
twins diverging so that tasks stop matching — compared by milestone, each with acceptance tests
written before the start — and a cold agent's answers about each twin at each milestone as the
measure of what holds.

**Harness² as a measuring instrument, the user, 2026-10-20** — Google Research's
[Harness²](https://github.com/google-research/harness2) (arXiv 2610.14224, released 2026-10-06)
measures what this question asks, for its own benchmarks: it runs the same task under a base
harness and under edited ones, and a model chooses among the outputs. Read for its method, not
taken as a peer; what it gives this question's design:

- **The judge is blind and outside the method.** The selector sees anonymized deliverables, never
  the harness that made them, and the scoring module is imported by nothing the method runs. The
  cold agent this question already names as its measure must likewise not know which twin is
  harnessed.
- **The base kept is a recorded outcome, not a failure.** Its composer may answer KEEP_BASE —
  "adaptation that the evidence does not argue for is a regression: it costs context and buys
  nothing" — and the judge records whether the chosen output was the base's. The twins' comparison
  needs the same column: at which milestones the unharnessed twin stood equal or better.
- **A judge failure is excluded, never scored zero.**
- **Effect size.** Its memory between tasks — the per-domain library of adopted harnesses and one
  lesson each — is worth 1.8 to 3.1 points removed, and 0.5 to 2.9 carried into another benchmark;
  harness edits made without evidence underperform the base in seven of twelve configurations.
  Memory between sessions, this harness's promise, is a few points on their scale. One pair of
  twins cannot show a few points; the twins measure decisions holding, not a score, and the
  milestones are the sample.
- **A rule that did not fire changed nothing**, "whatever it says on paper": its reflector grades
  each edit `helped`, `hurt`, `no observed effect` or `confounded`, and declines a lesson that rests
  on confounded rows alone. The same yardstick reads a milestone: a rule counts only where the
  transcript shows it fired.

What it holds under other names, confirming rather than adding: always-on text as the expensive
form and a skill on demand the cheap one (*Tier is paid by every session*); evidence served as
files and the prompt a pointer (*A capable reader*); a skill unnamed in the always-on text is never
opened (q-0037.0011); its two edit dimensions, how the agent works and what a practitioner knows,
are core and instance.

**The cold quiz as the first milestone, the user, 2026-10-23** — accepted in place of the twins
as the first measurement; the twins stay as the far milestone, for pain 1, which the quiz does not
reach.

- **The instrument.** A fresh agent, blind to whether the harness is installed, reconstructs the
  repository's state: five settled decisions and why, three items in flight, three undecided —
  sampled from the repository on the day of the quiz, never a fixed list, or the harness learns the
  list; answers scored, tokens counted. It measures C4 and C6: the exploration space lost, and what
  was decided drifting from what was built.
- **Three points.** Before install, the baseline: what the tree tells a cold reader by itself.
  After arrival and before any session: grades the arrival alone, and closes
  [01-0010.0175](../tickets/01-0010.0175-arrival-describes-what-it-finds.md) only where it beats the
  baseline — on a bare instance the harness has no instruments, so an equal score says the arrival
  built nothing. After N sessions, on a fresh sample: the question's first answer, the final check.
- **The subject.** xuanxue-cabinet, a NestJS and React monorepo with a method of its own: a 579-line
  Russian rules file, 185 ADRs, a 3427-line plan, no session records, an outside coordinator — the
  repository of [goodwolf-harness#6](https://github.com/dveyarangi/goodwolf-harness/issues/6).
  Point 1 can be taken before any work on
  [q-0037.0006.0020.0001](q-0037.0006.0020.0001-how-does-an-install-meet-a-tree-that-already-has-a-method-without-losing-it.md);
  point 2 waits on it.

**Point 1 taken, 2026-10-23** — before any install, on xuanxue-cabinet at `20128fbd`: a fresh
agent on Opus, blind to the harness, answered 11 of 11 from the repository alone, 151,675 tokens,
34 tool uses, 205 seconds; on one question the key was wrong and the agent right. Sample, key and
the run's findings:
[cold-quiz-xuanxue-cabinet](../research/cold-quiz-xuanxue-cabinet.md). The facts are all in the
tree — ADRs with a status line each, a plan that carries state — and reaching them is what the
tokens paid for: written is not accessible, and the cost is the measure. So points 2 and 3 score
four columns: hits; the cost of the reconstruction; the drift the cold reader met that nobody had
caught (five places, listed in the record); and what no record explains (a green PR abandoned
twenty days). Hits alone would read as nothing to gain, and that reading would be wrong.

**Point 2 is optional, and what the method asks of a change is a column, the user, 2026-10-23**
— the post-migration re-run of the same sample is its own stage, not owed by an install; it is
taken where the person wants to see whether the cost of entry moved, and what the method asks of a
change and what that buys. It is structure, not ceremony — the project gets accuracy and savings
for it. It is counted, never claimed: rules read per session, CI jobs and steps per PR, checklist
items, PR body length, ADRs per merged PR — in the ledger before, and the same way after. The ledger measures one thing, the
cost of recovering the project's state on eleven questions, and the install says so plainly; what
it does not reach — decisions holding over weeks, sessions not overwriting one another, the
person's attention per change — stays with the twins. The specimen report, with its ledger as an
appendix: [cold-quiz-xuanxue-cabinet](../research/cold-quiz-xuanxue-cabinet.md).

**Two more groups in the sample, the user, 2026-10-23** — eleven questions on what is written test
recall, and accuracy wants more. The sample gains: **important contradictions and drift**, which the
reader must find unprompted — asked about the topic, never about the discrepancy — scored found or
missed; and **strong but hidden or implicit invariants and structures** — what the code enforces and
no record states, what the tree's shape implies — scored recovered or not. Point 1 on
xuanxue-cabinet lacks both; a supplementary run on the same tree adds them before point 2, so point
2's sample holds them from the start. The key for both groups is built from the code and the
records before the run, and corrected only where the reader proves it wrong.
