How the installer carries each host's hook wiring into a recipient tree, and what a recipient
without a store sees from it — the harness work on
[01-0010](../tickets/01-0010-dev-harness-shared-and-local.md); the wiring itself is decision 44's. The
rest of the capability matrix — every other event, and what delivery cannot confirm — stays
[`.0120`](../tickets/01-0010.0120-host-delivery-surfaces.md)'s.

Found 2026-10-04, installing this tree's core at `7ecb62a` into an empty repository: the install's
shape gate fails, since the questions mechanism declares `.claude/settings.json`,
`.codex/hooks.json` and `.cursor/hooks.json` as its parts and the install does not carry them —
every fresh install ends `arrived: false` on this alone, whatever else it did.

The interpreter, 2026-10-09: on this tree's Windows machine a bare `python` is the Microsoft Store
stub, which runs nothing, and macOS and Linux often carry only `python3`. The user's proposal: the
interpreter is found once per clone and written to a file of the clone's own, and every hook runs
through a wrapper that reads it.

What each host's documentation says, read 2026-10-09:

- **Claude Code** ([settings](https://code.claude.com/docs/en/settings),
  [hooks](https://code.claude.com/docs/en/hooks)): `.claude/settings.json` is the shared project
  file, meant to be committed; `.claude/settings.local.json` is the personal one, kept out of git,
  and hook entries merge across the levels rather than replacing each other. A command runs under
  `sh -c` on macOS and Linux, Git Bash on Windows, or PowerShell where Git Bash is absent; a hook
  may name its `shell`, and one with `args` runs with no shell at all, its `command` found on `PATH`.
- **Codex** ([hooks](https://learn.chatgpt.com/docs/hooks)): user and project `hooks.json`, with no
  local file; commands run in the session's working directory; `commandWindows` gives a hook a
  command of its own on Windows; the shell is not documented; a project hook runs only once its
  exact definition is trusted.
- **Cursor** ([hooks](https://cursor.com/docs/hooks)): the project `hooks.json` is committed to share
  it, and its commands run from the project root; the Windows shell is not documented, and Cursor's
  staff advise a `cmd /c` prefix there
  ([forum](https://forum.cursor.com/t/hooks-intermittently-non-functional-on-windows-pretooluse-worked-then-stopped-after-hooks-json-edit/154608)).
