Opened 2026-10-25 on the user's *what are we, in that sense? research it*, after a session brought
the runtime reading of the word: a harness is the runtime that makes a model act — tools, the call
syntax, the parser, results returned; an agent is harness and model; agents differ as harness
configurations. The front page's line *a harness for your own harnesses* stands on the wider
reading of [the method's glossary](../../../.agents/glossary.md).

## Two passes, 2026-10-25

**An outside reading** — a fresh process, the repository unread, given the situation in plain words
and the runtime definition. Eight families, as it returned them:

1. *Software engineering* — a configuration distribution on a host, as oh-my-zsh to zsh; framework
   of conventions, hosted, owning no runtime. Fails by host API churn, local edits clashing with
   upstream redeploys, plugin pile-up paid in tokens.
2. *Knowledge management* — a curated personal knowledge base with an editorial process; schema and
   curation above the notes. Fails by the collector's fallacy and curation outgrowing the work.
3. *Organisational learning* — a management system with corrective action, double-loop, aiming at
   deutero-learning unproven. Fails by espoused theory against theory-in-use: the written rule and
   the behaviour diverge.
4. *Cognitive architecture* — an executive, metacognitive layer added to an existing architecture.
   Fails by the utility problem and prospective-memory failure: the intention does not fire at its
   cue.
5. *Operating systems* — a distribution over a kernel. Fails by upgrade breakage, config merges,
   shared state without locks.
6. *Programming languages* — a metalanguage for prose programs, with reflection, at M2/M3, its
   interpreter stochastic. Fails by rule conflicts, feature interaction, no static checking.
7. *Legal theory* — a constitution with secondary rules (Hart): rules of change, recognition,
   adjudication. Fails by legalism, interpretive drift, amendment fatigue.
8. *Cybernetics* — Beer's viable system, S2–S5 for one S1.

In the runtime vocabulary it found *harness* a category error and *meta-harness* or *a harness for
your harnesses* absurd — a runtime that runs runtimes; *framework* read as SDK code, *agent OS* as
overclaiming; *harness configuration* accurate and flat; *context-engineering layer* accurate and
current. Lands: *a self-correcting instruction set for the agent you already use*; *project memory
and method as plain files, on top of Claude Code or Codex*. What the tasking smuggled, by its
reading: that the thing is one, where it may be two on different rungs — a development method, and
a kit for authoring methods; generality asserted and not shown; that people want to author their
own method, where most want to use one; plain files as a virtue, where they are also the ceiling —
it can ask the model, not enforce.

**The landscape, as of 2026-10-25** — a web scan of what the layer above coding-agent runtimes calls
itself. Method or methodology: obra/superpowers, BMAD. System, the commonest and vaguest: Agent OS,
GSD, Task Master. Toolkit: Spec Kit. Plugin, skill, open format: the runtimes' and standards'
packaging words (Claude Code plugins, Agent Skills, AGENTS.md). Layer: mem0, Zep. Harness for the
layer on top, rising: claude-flow renamed Ruflo, *an agent meta-harness*; Miessler's PAI, now
LifeOS, *the universal AI Harness*, general, life and work; *harness engineering* as the practice
(HumanLayer, Osmani, LangChain's *agent = model + harness*). One primary source separates the two:
Böckeler on martinfowler.com, 2026-04-02 — the vendor's *builder harness* and the *user harness*,
the outer ring built for one's own case, split into guides acting before the agent and sensors
feeding back after. Theo's October post, not opened by the scan, was read by another session in
its browser the same day, paraphrased: a harness is what lets a model act — tools, a text syntax
for calling them, a parser that runs them, a way back for the result, the list of tools; the
interface is not the harness — Claude Code's TUI over the Agent SDK, Codex over its App Server;
harnesses reused across apps; an agent is harness and model, agents often only harness
configurations — tools, instructions, MCP servers; a kitchen, the model its chef. Under it the
harness here is no harness: its hooks inject context at session start and before each message and
see no tool call, the host parsing and running every one. No accepted term; general-purpose projects either
borrow *harness* or *OS*, or avoid a product noun (Karpathy's *idea file*). Almost every
methodology product stays coding-only.

## Decisions

1. **The name stays, and *harness* is meant as the user harness** *(the user, 2026-10-25)*: the
   instructions, records and scripts around an agent's runtime, built for one's own work —
   Böckeler's *user harness*, not the runtime that runs the model and its tools. GoodWolf Harness
   keeps its name. → [the method's glossary](../../../.agents/glossary.md), *Harness*.
